## 範圍

- 這次包含：
  - 與維護者確認「後端單一入口清單」的內容與每一項入口的位置（Q1、Q2）
  - 用 import-linter 契約擋住清單以外的寫法，沿用現有 `[tool.importlinter]` 設定與 CI 既有的 `uv run lint-imports` 步驟（Q3–Q6）
  - 把清單寫進 `backend-agent-rules.mdx`，並把相關規則文件的檢查方式改成實際指令（Q7）
  - 對刻意違規的樣本證明新契約會失敗（Q9），再提交
  - 既有 import 的處理：實測現況**沒有違規**（見「現況盤點」），待決的是豁免機制要不要預先設計（Q6）
- 這次不包含：
  - T9 的七個 gate、#506 的 CI 骨架、#561（大小與複雜度，已合併）、#562（自我 mock 禁令，已合併）、#564（定期架構盤點，已 closed）
  - 實際實作任何入口（寄信、OIDC、認證 dependency、HTTP 客戶端）；`app/` 目前一個都沒有，這些屬於各自的功能 change
  - 前端（F10、A6 已有 ESLint 檢查；本 change 只做後端）
  - 修改 `docs/specs/`、PRD、`design/prototype/`（沒有業務需求涉及）
  - 任何 UI 畫面與 API 變動（無 UI、無 API；`ui-design`、`api-contract` 只需寫「無」）

## 業務流程

不適用：本 change 沒有對應的 `docs/specs/` 規格，也沒有使用者或產品角色的業務流程。它只改變開發與審查流程中「後端程式繞過單一入口會被機械擋下」這一點，流程本身沿用 `AGENTS.md` §Development Workflow 與 `backend-agent-rules.mdx` B1 的 CI 檢查，不另畫一份。

涉及的「角色」只有開發者與審查者（人或 agent）：開發者在 `backend/app/` 新增或修改 import，CI 的 `backend-sqlite` job 跑 `uv run lint-imports`，違反契約即失敗；審查者不必再靠肉眼找第二份實作。沒有權限差異，也沒有被遮蔽或唯讀的資料。

### 在 import-linter 2.17 上實測的限制

這些限制決定哪些選項做得到，是本 change 的硬性事實，不是偏好。實驗用的設定檔放在 session 暫存目錄，沒有改動 repo。

| 限制                 | 實測結果                                                                                                                                                                                                                                                                                                                 | 影響                                                                                                                                                                                       |
| :------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 外部套件只認根套件   | `forbidden_modules = urllib.request` 直接報 `subpackages of external packages are not valid`；`sqlalchemy.exc`、`urllib.parse` 在圖中都併成 `sqlalchemy`、`urllib`                                                                                                                                                       | 無法「只擋 `from sqlalchemy import text`」（B5 的待建置提議）、也無法擋 `urllib.request` 而放行 `urllib.parse`（擋 `urllib` 會命中 `core/config.py` 1 處）。契約只能擋整個套件，不能擋名稱 |
| 禁止清單是黑名單     | 擋 `httpx`、`resend`、`authlib`、`smtplib`、`requests`：即使 `resend` 未安裝，契約結果仍是 `KEPT`，命中 0                                                                                                                                                                                                                | 可以在套件還沒進相依之前先寫；但新加一個沒列在清單的套件（例如另一個寄信套件）契約看不見，需要配套（Q4）                                                                                   |
| 不存在的模組         | 契約引用不存在的 `app.integrations.mail` 報 `Module 'app.integrations.mail' does not exist.`，整個 `lint-imports` 失敗                                                                                                                                                                                                   | 入口模組還不存在時，不能先把它寫進 `source_modules`／`forbidden_modules`；`ignore_imports` 指向不存在的 import 預設也會報錯（`unmatched_ignore_imports_alerting = "error"`）（Q3）         |
| `protected` 契約可用 | 2.17 內建 `protected`、`private_modules`、`acyclic_siblings`、`independence`、`layers`、`forbidden`。實測 `protected_modules = app.modules.*.service／repository／schemas`、`allowed_importers = app.modules.*` 命中 0；`protected_modules = app.modules.*.router`、`allowed_importers = app.main, app.modules.*` 命中 0 | 「模組內部只准同模組 import」做得到，不必自己寫檢查（Q5）                                                                                                                                  |
| 只看 `root_package`  | `root_package = "app"`，測試不在圖中                                                                                                                                                                                                                                                                                     | 契約約束的是 `app/`，不約束 `tests/`；測試端的替身邊界屬於 #562 的 Semgrep（Q8）                                                                                                           |
