## 目標

| 目標 | 誰受益 |
| :--- | :--- |
| 讓:ref[標記員]{id="term.annotator"}一次只面對一筆資料，題目、作答控制項與任務說明**同時在畫面上**，不必在頁面之間來回 | 標記員——減少翻頁造成的標記偏差 |
| 讓任務說明**翻筆之後還在**，而且在手機上也拿得到 | 標記員與:ref[審核員]{id="term.reviewer"}——說明一消失，標準就會各憑記憶 |
| 讓工作區**完全由任務發布時凍結的設定驅動**，不替任何任務寫死特例 | 專案負責人——改設定就能改作業方式，不必等系統改版 |
| 讓網址**一直指著畫面上的那一筆**，重新整理、加書籤、貼給別人都回到同一個地方 | 需要互相對照同一筆資料的人 |
| 讓標記員在這一頁接觸不到:ref[標準答案]{id="term.ground-truth"}，**連樣本的識別鍵都不顯示** | 整個標記品質管線——答案一旦外洩，這個任務的資料就不能用了 |

## 使用角色

| 角色 | 這一頁能做什麼 | PRD §權限矩陣的上限 |
| :--- | :--- | :--- |
| :ref[標記員]{id="term.annotator"} | R／C／E，**只限被指派給自己的資料** | 「04 標記清單與標記工作區（產出標記）」給標記員 `R/C/E (o)` |
| :ref[審核員]{id="term.reviewer"} | R／E | 「04 標記清單與標記工作區（審核與仲裁）」給審核員 `R/E` |
| :ref[專案負責人]{id="term.project-leader"} | 只處理:ref[審核員]{id="term.reviewer"}收不掉的例外（階段五），**不產出標記** | 同一列給專案負責人 `R` |

- 工作區的作用角色只有標記員與審核員兩種；專案負責人進得來的是**最終例外池的處置畫面**，它共用這一頁的外殼但不是標記畫面（麵包屑第 1 層因此有第三種字面，見[§入口麵包屑的第三層](#入口麵包屑的第三層)）
- 專案負責人在這一頁的處置動作由階段五撰寫；本階段只寫到外殼層面會看到的差別
- **這裡有一處超出 PRD 的上限，本頁不默默放寬**：PRD §權限矩陣「04 標記清單與標記工作區（審核與仲裁）」那一列給專案負責人的上限是 `R`，而最終例外池的收尾（採標記員值／採審核員值／填自訂答案／排除這筆）是**寫入動作**。PRD 另有一句「專案負責人在標記工作區只處理審核員無法收斂的例外，不產出標記」，說的是**範圍**不是權限字母。本頁依[規格 07-01](../07-shared/01-sidebar.mdx)的做法明寫這個落差，**不把那一列改成 `R/E`**；PRD 的改動由 Issue #85 處理。階段五寫處置動作時要再引一次這一條
- 這個落差與[規格 04-01 §待釐清](./01-annotation-list.mdx#待釐清) Q1 是同一個缺口的兩半：那一題問的是專案負責人進不進得了標記清單，這一條管的是他進到工作區之後做的事超不超出上限
- :ref[系統管理員]{id="term.system-admin"}沒有任務角色時進不來，和[規格 04-01](./01-annotation-list.mdx)一樣

### 進入工作區並開始作業

1. 使用者從儀表板的快速入口、[標記清單](./01-annotation-list.mdx)的某一列，或**直接貼一個深連結**進來
2. 系統解析網址帶來的任務、那一筆、角色與標記階段
3. 查任務**發布時凍結**的設定，查得到嗎？
   - 查得到 → 載入那一筆樣本、說明檔案與進度，三欄就位
   - 查不到 → 導回標記清單，**不得以任何預設的輸出類型或空白控制項呈現工作區**，流程結束
4. 這個任務要求先讀說明嗎？
   - 要求，而且目前這個:ref[指引版本]{id="term.guideline-version"}還沒被確認過 → 顯示說明彈窗，使用者按確認才開始
   - 不要求 → 直接開始（替代流程 A1）
5. 使用者在中欄作業，必要時翻到上一筆或下一筆；每次翻筆都把網址改寫成畫面上的那一筆
6. 替代流程 A1：任務沒要求先讀說明 → 跳過第 4 步的彈窗，右欄的說明仍然常駐
7. 替代流程 A2：使用者在手機上 → 說明改由底部抽屜承載，翻筆時抽屜維持原本的開合狀態
8. 例外流程 E2：網址沒帶那一筆 → 導回標記清單，流程結束
9. 例外流程 E3：網址帶的那一筆查不到 → **回退到第一筆**，並把網址改寫成實際顯示的那一筆，回到第 5 步

## 規格

本階段寫的是**外殼**：版面、挑筆、翻筆、說明與檔案、進場的說明確認、網址同步與快捷鍵。中欄裡面**實際怎麼作答**（八種輸出類型）由階段二寫，**審核卡**由階段四寫。

### 工作區的外殼：三欄與行動版

<PrototypeFrame page="annotation/annotation-workspace" caption="標記工作區" client:idle />

1. 工作區是**單筆作業頁**：一次只處理一筆，整頁**沒有頁首**，最上面只有一條[入口麵包屑](#入口麵包屑的第三層)
2. 桌機固定三欄：

| 欄 | 承載什麼 |
| :--- | :--- |
| 左欄 | [標記清單](#左欄標記清單)與目前定位 |
| 中欄 | 上方[樣本導覽與進度](#中欄上方樣本導覽與進度)、主體[題目卡與標記卡](#中欄主體題目卡與標記卡)、下方[操作列](#中欄下方操作列) |
| 右欄 | [說明與檔案、操作紀錄](#右欄說明與檔案操作紀錄)雙頁籤 |

3. 右欄在桌機**可以收合，收合後可以再展開**
4. 手機（寬度 767 以下）只留精簡的目標列與主操作區，說明與檔案改放**底部抽屜、預設收合**
5. 手機必須**主操作優先**：抽屜是輔助資訊，**不得遮蔽核心的標記區**
6. 抽屜**只承載說明與檔案**；「操作紀錄」頁籤是桌機右欄才有的（見 [§已確認決議](#已確認決議) Q6）
7. 翻到下一筆時：桌機右欄**不收起、內容不重置**；手機抽屜**維持目前的開合狀態**
8. 中欄**不得出現任務標題卡**——任務名稱的標頭與卡內的語言切換鈕都不行，標記員與審核員都一樣
9. 任務名稱**只由右欄「任務說明」的摘要呈現**，而且要優先用這個任務實際的名稱，只有在缺任務上下文時才退回輸出類型層級的預設文案
10. 語言切換由側欄提供，和其他頁面一致（見[規格 07-01](../07-shared/01-sidebar.mdx)）
11. 要驗的螢幕寬度是 375、768、1440 三種
12. 來源要求的「固定任務目標列」在畫面上只有一部分落地，**任務目標與操作指引沒有落點**，見 [§待釐清](#待釐清) Q1

#### 這一頁讀得到什麼、不得改什麼

1. 工作區讀的是任務**發布時凍結**的那一份設定：輸出類型與它們的順序、欄位各自的用途（舉證、題目輸入、作答產出）、配對任務的兩邊標題、說明檔案清單
2. 樣本來源**鎖定在發布時凍結的那一份資料快照**，工作區**不得自己重算或覆寫切分**——:ref[試標]{id="term.dry-run"}與:ref[正式標記]{id="term.official-run"}都一樣
3. 說明檔案來自**當前回合釘住的那個:ref[指引版本]{id="term.guideline-version"}**；之後把說明另存新版，**不會改到已經開始的回合**
4. 工作區**不得為個別任務寫死邏輯**：有幾個輸出類型、是哪幾種、什麼順序，一律照設定來
5. 資料敏感度：這一頁讀得到的樣本內容是**任務資料**，可能含個資，只有被指派的人進得來；:ref[標準答案]{id="term.ground-truth"}**不屬於標記員讀得到的範圍**（階段二會把這條寫成卡控）
6. 設定本身在這一頁是**唯讀**的——要改設定得回[規格 03-03 任務詳情](../03-task-management/03-task-detail.mdx)

### 入口麵包屑的第三層

<PrototypeFrame page="annotation/annotation-workspace" caption="標記工作區" client:idle />

麵包屑的前兩層與「深連結和站內點進來要長得一樣」這條總規則寫在[規格 04-01 §入口麵包屑](./01-annotation-list.mdx#入口麵包屑)；工作區**多出第 3 層**，而且第 1 層在這一頁有第三種字面。

1. 工作區的麵包屑**有三層**，第 3 層就是目前層級：

| 層級 | 顯示 | 連到哪 |
| :--- | :--- | :--- |
| 第 1 層 作業區 | 審核員「審核作業」、標記員「標記作業」、專案負責人處理例外時「例外處置」 | **儀表板** |
| 第 2 層 任務 | 「〈任務名稱〉（〈標記階段〉）」 | 標記清單，**回帶任務、角色與標記階段** |
| 第 3 層 目前單位 | 依角色不同，見第 2 條 | **不帶連結，它就是目前層級** |

2. 第 3 層依角色分流，這是**資料公平性的硬性規則**：

| 角色 | 第 3 層顯示 |
| :--- | :--- |
| 審核員 | `審核單位 {sample} · {annotator}`——那一筆的識別碼與**受審標記員的帳號** |
| 標記員 | **只顯示佇列位置** `樣本 {i} / {n}`，**不得顯示那一筆的識別碼，也不顯示自己的帳號** |
| 專案負責人（例外處置） | `例外項目 {sample} · {annotator}` |

3. 標記員那一層**不得顯示識別碼**的理由寫在來源裡：有些資料集拿**沒有被指派用途的欄位**當記錄識別鍵，把它渲染進標記員看得到的地方就等於洩漏答案線索；標記員自己的帳號對標記員而言是零資訊，也不重複顯示（見 [§已確認決議](#已確認決議) Q7）
4. 麵包屑要**跟著換筆與換語言一起重畫**，不能只在進場時畫一次
5. 第 2 層一定要**回帶身分參數**：帶著標記員身分進來的，返回清單的網址也要帶同一個身分；**沒帶身分進來的就不得補上**（否則「缺值套用預設」這件事在兩頁之間就不再是共識）
6. 身分參數要和清單的四個檢視狀態**併存**，不能只轉發一種（見 [規格 04-01 §清單檢視狀態往返工作區](./01-annotation-list.mdx#清單檢視狀態往返工作區)）
7. 麵包屑在窄螢幕**不會被隱藏**，但標記員帳號在它的尾端，需要橫向捲動才看得到——窄螢幕下審核單位的身分就由這一層承載

### 左欄：標記清單

<PrototypeFrame page="annotation/annotation-workspace" caption="標記工作區" client:idle />

1. 左欄的標題**固定是「標記清單」**，**不得附加回合標籤**——不能變成「試標回合 R2」「正式標記清單」之類的字面
2. 回合是靠[麵包屑第 2 層](#入口麵包屑的第三層)講的，位置在三欄主體之上，兩者不衝突
3. 標題旁的**筆數仍然要按當前回合的清單規模顯示**：試標顯示這一回合建立的筆數，正式標記顯示正式清單的筆數
4. 當前標記階段**還沒有已建立的清單筆數**時，筆數**回退顯示該任務資料集的筆數**
5. 審核員的筆數單位是**審核單位**而不是樣本（同一筆由 N 位標記員標記就是 N 個單位），算法見階段六
6. 每一列的組成：**序號徽章 + 文本摘要（必要時加摘要標籤）+ 完成狀態標籤**
7. 文本摘要和[標記清單](./01-annotation-list.mdx)用**同一套算法**，不另立一套：見 [規格 04-01 §文本摘要怎麼來](./01-annotation-list.mdx#文本摘要怎麼來)
8. **摘要標籤只有工作區左欄會顯示**，標記清單那一頁沿用前綴、不顯示標籤。摘要取自對話串形態時，摘要**旁邊**要加標籤：

| 條件 | 標籤 |
| :--- | :--- |
| 任務設定指定了對話串欄位，而且摘要就是取自對話串形態 | 「〈則數〉 則發言」（則數就是那一串的筆數） |
| 再加上任務設定指定了發言者子欄位，而且不重複的非空發言者數至少 1 位 | 再加「〈人數〉 位發言者」 |

9. 標籤要出現在**工作區左欄的三個地方**：標記員的每一列、審核員的分組表頭、例外處置的分組表頭
10. 標籤**不得依任務編號或欄位名稱寫死**、**不得讀用途是輸出的欄位**，也**不得從實體、關係或文字裡的 `@名字` 去猜**——和前綴同一套限制
11. 搜尋比對的字串**不含前綴也不含標籤**（搜尋本身在[標記清單](./01-annotation-list.mdx)那一頁）
12. 標記員視角的完成狀態標籤是**三態**，而且儲存草稿或提交之後要**即時更新**那一列：

| 標籤 | 什麼時候 |
| :--- | :--- |
| 已提交 | 這一筆已經提交 |
| 已儲存 | 存了草稿、還沒提交 |
| 待標記 | 還沒動過 |

13. 目前在看的那一列要**高亮**，而且必須是網址帶進來的那一筆，**不得固定落在預設的第一筆**
14. 點某一列就切到那一筆
15. 審核員視角的一列是**一個審核單位**、狀態標籤換成審核單位的三態，而且同一筆的多個單位要包在該筆的分組容器裡——這一段連同分組表頭承載什麼，由**階段五**撰寫
16. 專案負責人的例外處置清單列的是**待處置的例外項**，不是一般樣本，由**階段五**撰寫

### 中欄上方：樣本導覽與進度

<PrototypeFrame page="annotation/annotation-workspace" caption="標記工作區" client:idle />

1. 中欄頂部是導覽列：**「上一筆」按鈕 + 進度摘要（含進度條）+「下一筆」按鈕**
2. 位在**首筆或末筆**時，對應的那個按鈕**停用**
3. 進度摘要依角色分流：

| 角色 | 文字 |
| :--- | :--- |
| 標記員 | `{已提交} / {總筆數} 已提交` |
| 審核員 | `我的審核提交 {已提交} / {總筆數} 個審核單位`——分子是自己已送出審核的單位數，分母是審核單位總數 |

4. 提交之後進度要**即時更新**，不必重新整理
5. 審核員的「筆」是**審核單位**，所以導覽與分母都按審核單位算（算法見階段六）；標記員的「筆」就是樣本
6. 翻筆時右欄的說明**不收起、不重置**（見[§工作區的外殼](#工作區的外殼三欄與行動版)第 7 條）

### 中欄主體：題目卡與標記卡

<PrototypeFrame page="annotation/annotation-workspace" caption="標記工作區" client:idle />

這一段只寫**卡片怎麼切**；卡片裡面實際的作答控制項由**階段二**撰寫。

1. 題目內容與標記控制項**以獨立卡片區隔**：題目卡承載舉證內容與題目輸入，標記卡承載**依設定順序逐一排出**的各個輸出類型
2. 卡片怎麼切，**依欄位用途與輸出類型的結構決定**，**不得依任務名稱或個別輸出類型寫死分支**
3. 輸出類型自己就把原文內嵌在標記區裡時（例如要在文本上圈選的那幾種），**題目卡可以省略**
4. **卡片邊框是題目／標記區塊的唯一外框**：
   - 題目卡裡的輸入內容**直接呈現，不得再包一層內框**
   - 標記卡裡**不得殘留水平分隔線**，包含區塊分隔線與「無法判定」選項上方的虛線（那個選項在畫面上的字面是「無法判定 (Bypass)」，它本身由階段二撰寫）
   - 兩種輸出類型合併成整合標記模式時，整合預覽區塊**不得在卡片裡再包一層外框**
5. **「無法判定」選項自己的虛線外框是刻意設計，要保留**
6. 這條規則**一體適用所有輸出類型**，不得逐類型寫死

### 中欄下方：操作列

<PrototypeFrame page="annotation/annotation-workspace" caption="標記工作區" client:idle />

1. 中欄底部是操作列：**左側是自動儲存狀態指示，右側是「儲存草稿」與提交按鈕**
2. 自動儲存的三態文字與它們**什麼時候才會變**，由**階段三**撰寫——那一條的重點是「指示必須誠實」，所以放在提交與草稿那一段一起寫
3. 提交按鈕**靠右對齊是兩種角色共同的契約**：審核員視角的自動儲存指示會隱藏，但送出按鈕**不得因為左側元素消失就掉到左邊**
4. 審核員視角**不提供「儲存草稿」**（按鈕隱藏，而且沒有綁行為）
5. 這個操作列是**唯一的提交位置**：審核員的「送出審核」、仲裁的「送出仲裁」都固定在這裡、**不隨中欄內容捲動**，卡片裡**不得再放一顆送出按鈕**；它們互斥顯示的規則由階段四、五撰寫

### 右欄：說明與檔案、操作紀錄

<PrototypeFrame page="annotation/annotation-workspace" caption="標記工作區" client:idle />

1. 桌機右欄是**兩個頁籤**，標記員與審核員看到的一樣，**預設停在第一個**：

| 頁籤 | 承載什麼 |
| :--- | :--- |
| 說明與檔案 | 「任務說明」摘要 + 說明檔案清單 |
| 操作紀錄 | 目前這一筆的操作時序，標記員與審核員的事件合併後依時間排 |

2. 第二個頁籤的名稱在來源與畫面不一致（來源寫「歷程」、畫面是「操作紀錄」），見 [§待釐清](#待釐清) Q2
3. 「操作紀錄」裡面放什麼、誰看得到哪些、耗時與理由怎麼呈現，由**階段五**撰寫（清單側已寫在 [規格 04-01 §處理狀況](./01-annotation-list.mdx#處理狀況)）
4. **說明與檔案是這個模組強制常駐的資訊**，不能只在進場的彈窗裡出現一次
5. 「任務說明」的標題**帶一個提示圖示**
6. 檔案清單每一列要顯示**對應檔案類型的小圖示**，並在檔名右側顯示**動作提示文字「預覽」**
7. 圖示與動作提示**由檔案類型驅動，不得依任務別寫死**；動作提示要**跟著語言切換即時更新**
8. 說明檔案的連結失效時，**不影響標記主流程**，但要顯示一則可追蹤的錯誤訊息

### 說明檔案的三種預覽

<PrototypeFrame page="annotation/annotation-workspace" caption="標記工作區" client:idle />

1. 說明檔案至少支援三種類型的**頁面內預覽彈窗**，標記員與審核員共用同一套面板與行為：

| 類型 | 點下去會怎樣 |
| :--- | :--- |
| 圖片 | 置中彈窗顯示**大圖**；**不得只用右欄底部的小圖預覽頂替** |
| PDF | 置中彈窗**在頁面內嵌入顯示**；**不得開新分頁** |
| Markdown | 置中彈窗顯示**排版後的內容**；**不得用面板底部的純文字區塊頂替** |

2. 三種彈窗都要能關掉，而且**三條關閉路徑都要有**：關閉按鈕、點背景遮罩、按 `Esc`
3. 三種彈窗都要**管好鍵盤焦點**：開啟時焦點移進彈窗、`Tab` 侷限在彈窗內、關閉後焦點**還給觸發它的那個元素**
4. PDF 與 Markdown 彈窗的**標題顯示檔案名稱**
5. Markdown 的排版至少要支援：標題、段落、有序與無序清單、粗體、斜體、行內程式碼、連結、程式碼區塊、表格與圖片
6. 安全規則（使用者看得到的結果）：
   - 說明檔案裡夾帶的網頁標記**一律當文字顯示**，不照它排版；程式碼區塊裡的內容也只當文字
   - 連結與圖片的位址**只接受一般網址、信件位址、站內相對位置與同頁錨點**，其他一律降級成純文字
   - 連結**一律開新分頁**，避免把人帶離工作區
7. 排版後的每個標題都要**帶一個由標題文字推導出來的錨點**，而且：
   - 同一份沒改過的說明，**每次排版都要得到同一組錨點**
   - 同一份說明裡**兩個文字相同的標題，要得到互不相同的錨點**
   - 錨點**不得只靠標題的出現順序決定**
8. 第 7 條不是排版細節：**審核員在修正理由裡引用某個說明段落**時，引用就是跳到這個錨點，而**點它的人是標記員**——他在試標歷史回饋裡讀那則理由（清單側見 [規格 04-01 §試標歷史回饋](./01-annotation-list.mdx#試標歷史回饋)；審核員怎麼寫引用由階段四撰寫）。錨點的順序一變，舊的引用就會指錯地方
9. 進場的說明彈窗**用同一個排版器**，不另外維護一份

### 指引閘門：第一次進來先讀說明

<PrototypeFrame page="annotation/annotation-workspace" caption="標記工作區" client:idle />

1. 任務設定可以要求**先讀說明才開始標記**（開關在[規格 03-03 任務詳情](../03-task-management/03-task-detail.mdx)）
2. **這個開關沒開，彈窗在任何情況下都不得出現**，也不受下面的確認紀錄影響（**依建議撰寫、待維護者確認**，見 [§待釐清](#待釐清) Q4）
3. 開關開著時，進場顯示說明彈窗，使用者按確認按鈕才開始；確認後**同一台裝置對同一個任務的後續進入（含重新整理）不得再顯示**（同 Q4）
4. 彈窗的內容**和右欄「說明與檔案」同一個來源**，取其中 Markdown 類型的全文顯示；沒有 Markdown 類型時**退回顯示檔名清單**——**不得為彈窗另外維護第二份說明文字**
5. 彈窗與右欄**必須是同一個:ref[指引版本]{id="term.guideline-version"}**
6. 確認紀錄**以任務為鍵各自獨立**：確認了 A 任務**不得抑制** B 任務的彈窗；換任務就要**從頭重新判定**
7. 確認紀錄還要**比對當前回合釘住的指引版本**：
   - 已經確認過**這個版本**的不再顯示
   - 第一次遇到**另一個版本**而且開關開著時，**必須重新確認**
   - 之後把說明另存新版，**不得改寫舊回合的指引，也不得讓舊版本的確認失效**
   - 歷史回合的版本**不得從任務的當前版本、最後一個試標回合或相同的回合顯示號去猜**
8. 確認紀錄要綁在**帳號**還是**裝置**上，來源明寫留待後端接上時定義，見 [§待釐清](#待釐清) Q3
9. 來源另有**三處**未被註銷的規則說「每次進入都顯示一次」，與第 2、3 條相矛盾，而來源沒有裁決句，見 [§待釐清](#待釐清) Q4

### 網址一直指向目前這一筆

<PrototypeFrame page="annotation/annotation-workspace" caption="標記工作區" client:idle />

1. 網址必須**持續指著畫面上正在看的那一筆**：每次換筆或換受審標記員，都要把它寫回網址
2. 這樣的話，**重新整理、加書籤、把連結貼給別人，都會回到畫面上的那一筆**，而不是回到最初進來的那一筆
3. 同步的範圍：

| 參數 | 誰要同步 |
| :--- | :--- |
| 那一筆的識別碼 | **所有角色** |
| 受審標記員 | **只有審核員視角**（它是審核單位的另一半） |

4. 標記員視角翻筆時身分不會變，所以**不得在網址裡新增它原本沒有的參數**
5. 改寫要**原地取代**，**不得每翻一筆就在瀏覽器的上一頁堆一筆**——否則走過 N 筆之後要按 N 次上一頁才離得開工作區
6. 改寫必須**就地更新既有的網址參數**，**不得照已知的鍵重建一份**——重建會把這一頁不讀的參數**靜默丟掉**
7. 網址帶的那一筆**查不到而回退到第一筆**時，網址也要改寫成**實際顯示的那一筆**，讓重新整理的結果穩定不漂移

### 鍵盤快捷鍵

<PrototypeFrame page="annotation/annotation-workspace" caption="標記工作區" client:idle />

1. 側欄快捷鍵總覽（見[規格 07-01](../07-shared/01-sidebar.mdx)）在「工作區」分類列出的四個快捷鍵**必須全部真的可用**，不能只是文案：

| 快捷鍵 | 做什麼 |
| :--- | :--- |
| `Ctrl/Cmd + S` | 儲存草稿 |
| `Ctrl/Cmd + Enter` | 提交目前這一筆 |
| `Alt + ←` | 上一筆 |
| `Alt + →` | 下一筆 |

2. 每個快捷鍵都要**走它對應的那顆按鈕本身的行為**，不得另開一條繞過按鈕既有條件的路：
   - 按鈕**隱藏或停用時，快捷鍵就無作用**——首筆按 `Alt + ←` 不得回捲到末筆，審核員按 `Ctrl/Cmd + S` 不得寫入草稿
   - 理由是按鈕上已經帶著角色配置與首末筆的停用狀態，另推一次就會出現**第二份會漂移的事實來源**
3. `Ctrl/Cmd + Enter` **依角色分流**：標記員觸發「提交」、審核員觸發「送出審核」，兩者都要**照各自既有的完整性驗證走**，不得繞過
4. 這四個都是**修飾鍵組合、不產生文字**，所以**焦點在輸入框裡時照常生效**——最需要「儲存草稿」的時機正是在長文作答途中
5. 必須**攔住瀏覽器的預設行為**（`Ctrl/Cmd + S` 會開「儲存網頁」、`Alt + ←` 在瀏覽器是上一頁），而且**要在判斷按鈕可不可用之前就攔**，否則隱藏或停用的目標會漏出瀏覽器的預設動作
6. 審核卡還有不帶修飾鍵的單鍵快捷鍵，和這四個的規則不同，由**階段四**撰寫

### 進不來的時候：導回清單

<PrototypeFrame page="annotation/annotation-workspace" caption="標記工作區" client:idle />

1. 網址**查不到已發布的任務設定**時，**導回[標記清單](./01-annotation-list.mdx)**，並且**不得以任何預設的輸出類型或空白控制項呈現工作區**
2. 清單那一側對應的規則寫在 [規格 04-01 §路由上下文與回退](./01-annotation-list.mdx#路由上下文與回退)；這一條是**工作區這一側**的導回
3. 網址**沒帶那一筆**時，**不得載入作業區**，一樣導回標記清單
4. 角色與標記階段的缺值回退和清單一致（角色回退成標記員、標記階段回退成試標）
5. 任務設定讀到了、但**輸出類型是空的或缺必要內容**時：顯示任務設定錯誤並**阻擋提交**，**不得用任一輸出類型的預設控制項頂替**
6. 這一頁**沒有從本機記憶體還原上下文**這條路——上下文只從網址來
7. 導回時要**保留同一個任務的上下文**

## 卡控機制

本階段的卡控都列在這裡；階段二到六會往下加。

| 條件 | 結果 |
| :--- | :--- |
| 網址查不到已發布的任務設定 | 導回標記清單，**不得以預設輸出類型或空白控制項呈現工作區** |
| 網址沒帶要處理的那一筆 | **不得載入作業區**，導回標記清單 |
| 網址帶的那一筆查不到 | 回退到第一筆，並把網址改寫成實際顯示的那一筆 |
| 任務設定的輸出類型是空的或缺必要內容 | 顯示任務設定錯誤並**阻擋提交**，不得用預設控制項頂替 |
| 角色缺值或是不認得的值 | 回退成標記員 |
| 標記階段缺值或是不認得的值 | 回退成試標 |
| 左欄標題 | **固定「標記清單」**，不得附加任何回合標籤 |
| 麵包屑第 3 層、角色是標記員 | **不得顯示那一筆的識別碼，也不顯示自己的帳號**；只顯示佇列位置 |
| 麵包屑第 2 層、進來時帶了身分參數 | 返回網址要**帶回同一個身分**，並與清單的四個檢視狀態併存 |
| 麵包屑第 2 層、進來時沒帶身分參數 | 返回網址**不得**補上身分參數 |
| 翻筆 | 網址**原地取代**，不得在瀏覽器的上一頁堆疊；其餘參數**就地保留** |
| 翻筆、角色是標記員 | **不得**在網址新增它原本沒有的受審標記員參數 |
| 位在首筆或末筆 | 對應的導覽按鈕停用；該方向的快捷鍵**無作用**，不得回捲到另一端 |
| 按鈕隱藏或停用 | 對應快捷鍵無作用，但**瀏覽器預設行為仍須被攔住** |
| 角色是審核員 | **不提供「儲存草稿」**；`Ctrl/Cmd + S` 不得寫入草稿 |
| 任務沒開「先讀說明」 | 說明彈窗**在任何情況下都不得出現**（待 Q4 確認） |
| 任務開了「先讀說明」、這個指引版本沒確認過 | 進場顯示彈窗，按確認才開始 |
| 任務開了「先讀說明」、這個指引版本已確認過 | **不得重複顯示**（含重新整理）（待 Q4 確認） |
| 確認過 A 任務後進入 B 任務 | B 任務**從頭重新判定**，不得被 A 的確認抑制 |
| 遇到另一個指引版本 | **必須重新確認**；舊版本的確認**不得失效** |
| 說明彈窗的內容來源 | **必須與右欄同一來源與同一指引版本**，不得另維護第二份文字 |
| 說明檔案沒有 Markdown 類型 | 彈窗退回顯示檔名清單 |
| 點說明檔案（PDF） | **頁面內嵌入預覽，不得開新分頁** |
| 點說明檔案（圖片） | 置中彈窗顯示大圖，不得只用底部小圖頂替 |
| 點說明檔案（Markdown） | 彈窗顯示排版後內容，不得用純文字區塊頂替 |
| 任一預覽彈窗 | 關閉按鈕、點遮罩、`Esc` **三條路都要能關**；焦點進得去、出得來 |
| 說明檔案裡夾帶網頁標記 | **一律當文字顯示** |
| 說明檔案的連結位址不是一般網址、信件位址、相對位置或錨點 | **降級成純文字** |
| 說明檔案的連結 | 一律開新分頁 |
| 同一份說明重複排版 | **錨點必須相同**；同名標題的錨點必須互不相同 |
| 翻到下一筆（桌機） | 右欄**不收起、內容不重置** |
| 翻到下一筆（手機） | 抽屜**維持原本的開合狀態** |
| 手機版 | 抽屜**不得遮蔽核心標記區**；抽屜**不含操作紀錄頁籤** |
| 中欄 | **不得渲染任務標題卡**（含卡內語言切換鈕），兩種角色都一樣 |
| 卡片內 | 題目卡**不得再包內框**；標記卡**不得殘留水平分隔線**；整合預覽**不得再包外框**；「無法判定」自身的虛線框**要保留** |
| 送出按鈕的位置 | 固定在底部操作列右側、不隨內容捲動；卡片內**不得再放一顆** |
| 工作區讀到的樣本切分 | **不得重算或覆寫**，只能用發布時凍結的那一份 |
| 說明另存新版 | **不得改寫已開始回合的指引** |

## 邊界情況（Edge Case）

| 情況 | 使用者看到什麼 |
| :--- | :--- |
| 網址什麼參數都沒帶 | 導回標記清單（清單那一側會顯示「未指定任務」，見[規格 04-01](./01-annotation-list.mdx#空的與找不到)） |
| 網址帶了不存在的任務 | 導回標記清單，**不會看到半套的工作區** |
| 網址帶了不存在的那一筆 | 停在第一筆，網址同步成第一筆——重新整理不會再跳一次 |
| 任務設定的輸出類型是空的 | 任務設定錯誤的訊息，提交被擋住 |
| 這個任務只有一筆 | 「上一筆」與「下一筆」兩顆都停用 |
| 停在第一筆按 `Alt + ←` | 沒有任何反應，**不會跳到最後一筆**，也不會觸發瀏覽器的上一頁 |
| 說明檔案清單是空的 | 右欄只有「任務說明」摘要，沒有檔案列；標記主流程不受影響 |
| 說明檔案的連結失效 | 一則可追蹤的錯誤訊息，標記主流程**照樣能走** |
| 說明沒有 Markdown 類型、但任務要求先讀 | 彈窗顯示檔名清單（不是空白彈窗） |
| 說明檔案裡有兩個文字一樣的標題 | 兩個標題各自跳得到，不會互相搶 |
| 作業中途換語言 | 麵包屑、頁籤名稱與動作提示文字即時跟著換；作答內容不受影響 |
| 在手機上翻筆 | 抽屜維持原本的開合，不會自己彈開也不會自己收起 |
| 把右欄收起後翻筆 | 翻筆**不會自行改變收合狀態**；收起後要展開得自己點（來源只禁止「自動收起或清空」，沒有定義手動收起之後的保存，見 [§待釐清](#待釐清) Q8） |
| 從深連結直接進來（沒經過站內導覽） | 麵包屑三層都在，和站內點進來一模一樣 |
| 任務在試標第 2 回合 | 左欄標題還是「標記清單」，回合由麵包屑第 2 層講 |
| 回合換了指引版本 | 再次進場要重新確認一次說明 |
| 同一個人在兩個分頁開同一筆 | 以版本號檢查為準：衝突時阻擋覆寫並提示手動合併（細節見階段三） |

## 待釐清

本階段開了 5 題（Q1 到 Q4，以及 Q8）。題號**只增不減**，之後的階段從 Q9 接下去；一題在待釐清與已確認決議之間搬動時**保留原本的題號**。

### Q1. 來源要求的「固定任務目標列」，任務目標與操作指引要放哪？

- **來源怎麼寫的**：桌機介面必須提供三欄工作區與**固定任務目標列**，該列的必要元素是任務目標、操作指引、已標記數量、總量、當前階段、微型進度視覺
- **畫面上實際有什麼**：最上面只有一條麵包屑；已標記數量、總量與進度條在**中欄上方的導覽列**，當前階段在**麵包屑第 2 層**。**任務目標與操作指引沒有任何落點**——右欄「任務說明」的摘要位置放的是**任務名稱**，而且來源的行為規則還明文禁止中欄渲染任務標題卡
- **我的建議**：把「任務目標」與「操作指引」收進右欄「說明與檔案」的任務說明區，不要在頂部另立一列。工作區的垂直空間是標記效率的主要瓶頸，而這兩段內容在整個作業期間都不變，常駐在右欄比固定在頂部划算；且麵包屑已經承擔了「我在哪個任務、哪個階段」
- **影響**：[§工作區的外殼](#工作區的外殼三欄與行動版)第 12 條、[§右欄：說明與檔案、操作紀錄](#右欄說明與檔案操作紀錄)第 5 條
- **誰決定**：維護者（這是畫面與來源不一致，依 `spec-migration.md` 列入待釐清）

### Q2. 右欄第二個頁籤叫「歷程」還是「操作紀錄」？

- **來源怎麼寫的**：右欄是「說明與檔案」／**「歷程」**雙頁籤，而且來源通篇用「歷程事件」「歷程可追溯」描述這個概念
- **畫面上實際是什麼**：頁籤的字面是**「操作紀錄」**
- **我的建議**：頁籤字面用畫面的「操作紀錄」（對使用者更直白），但**概念名稱**在規格與術語表裡統一用「歷程」，因為責任鏈那一段（階段五）通篇要講「歷程事件」。兩者如果都要統一，建議統一成「操作紀錄」並同步改掉來源的概念名稱
- **影響**：[§右欄：說明與檔案、操作紀錄](#右欄說明與檔案操作紀錄)第 1、2 條；階段五的歷程章節；未來可能要加的術語表條目
- **誰決定**：維護者

### Q3. 「已經讀過說明」這件事要記在帳號上還是裝置上？

- **來源怎麼寫的**：確認紀錄必須**以任務為鍵**獨立記錄，但**「確認紀錄的儲存實體（使用者帳號綁定或裝置綁定）留待後端接上時定義」**——來源自己把這一題留著，只鎖定「逐任務可獨立追蹤」這個契約
- **差別在哪**：綁帳號的話，換一台電腦不必重讀；綁裝置的話，同一個人換瀏覽器就要再讀一次，而共用電腦的兩個人會互相抑制彼此的彈窗
- **我的建議**：綁**帳號**。這個閘門的目的是「確定這個人讀過說明」，那是人的屬性不是機器的屬性；共用電腦的情境下綁裝置會讓第二個人直接跳過說明，正好違背設定這個開關的目的
- **影響**：[§指引閘門](#指引閘門第一次進來先讀說明)第 3、6、8 條
- **誰決定**：維護者

### Q4. 說明彈窗到底是每次進入都顯示，還是每個任務確認一次？來源有五處規則、分成兩派、沒有裁決句

- **互相矛盾的五處**（全部都**沒有被劃掉**，前兩列是一派、後三列是另一派）：

| 來源位置 | 說的是 |
| :--- | :--- |
| `FR-066` 第 1 點（v4.16.0） | 任務沒開「先讀說明」時，彈窗**在任何情況下都不得渲染** |
| `FR-066` 第 3 點（v4.16.0） | 確認過之後的後續進入（含重新整理）**不得重複顯示** |
| `FR-021` | 原型頁**每次進入都必須顯示一次**說明彈窗 |
| 規格常數 `GUIDELINE_MODAL_BEHAVIOR` | 值就是「每次進入顯示一次」 |
| 使用者故事 2 的行為規則（未編號散文） | 「原型入場時**固定顯示**說明 modal 一次」 |

- **為什麼不能自己結案**：`FR-066` 第 1 點的「於任何情況下」看起來像裁決句，但它後面緊接的限定詞是「**不受第 2、3 點之確認狀態影響**」——指名的是 `FR-066` 自己的第 2、3 點，處理的是這一條內部的優先順序（閘門開關壓過確認紀錄），**沒有觸及 `FR-021`**。而且 v4.16.0 的變更紀錄自述第 1 到 3 點只是「既有原型行為之正式化…**不改變任何既有版面呈現**」，這句話正好否認它推翻了既有規則
- **我的建議**：照 `FR-066`——它版本最新，而且任務設定那一側（`force_guideline` 開關）已經定義了觸發行為，沒有開關卻強制每個人每次進來都讀一次說明，與那個開關的存在意義衝突
- **影響**：[§指引閘門](#指引閘門第一次進來先讀說明)第 2、3、9 條與[§卡控機制](#卡控機制)裡的四條閘門規則；若改採「每次都顯示」，`FR-066` 的整套確認紀錄（含逐任務、逐指引版本）就沒有消費端
- **誰決定**：維護者

### Q8. 使用者**手動**把右欄收起之後再翻筆，要維持收起還是回到展開？

- **來源怎麼寫的**：只有三處沾到，而且三處講的都是**不得自動收起**，沒有一處定義手動收起之後的狀態保存——`FR-019`「面板必須於翻筆後持續可見，不可自動收起或清空」、`AC-5.1`「右欄說明不收起且內容不重置」、`SC-005`「翻筆後內容維持，Desktop 可收合／展開」
- **為什麼需要決定**：`FR-019` 的「持續可見」和「維持使用者收起的狀態」字面上互相拉扯——照字面讀，手動收起後翻筆應該要自己展開回來，但那會讓收合鈕在翻筆流程裡形同無效
- **我的建議**：**維持使用者收起的狀態**。收合鈕的用途就是把中欄的空間讓出來，如果翻一筆就彈回來，這顆鈕在實際作業中沒有價值；`FR-019` 的本意是禁止系統自己收起，不是禁止使用者收起
- **影響**：[§工作區的外殼](#工作區的外殼三欄與行動版)第 3、7 條、[§邊界情況](#邊界情況edge-case)那一列
- **誰決定**：維護者

## 已確認決議

### Q5. 左欄標題可不可以帶回合標籤？（已定案，沿用舊來源）

- **結論**：**不行**。標題固定「標記清單」，回合由[麵包屑第 2 層](#入口麵包屑的第三層)承載；但**筆數仍然要按當前回合的清單規模顯示**
- **依據**：來源使用者故事 1 的行為規則明文禁止在左欄標題附加回合標籤，並同時要求筆數照回合顯示；`FR-080` 第 5 點又特別聲明麵包屑不改變這條約束，兩者位置不同、不衝突
- **為什麼**：同一個畫面上把「這是哪個回合」講兩次，是資訊重複；而回合放在三欄主體之上，讀者第一眼就看得到
- **影響**：[§左欄：標記清單](#左欄標記清單)第 1 到 4 條

### Q6. 手機版有沒有「操作紀錄」？（已定案，沿用舊來源）

- **結論**：**沒有**。手機的底部抽屜只承載「說明與檔案」，操作紀錄是桌機右欄才有的
- **依據**：來源的規格常數明寫「Mobile 底部抽屜僅承載『說明與檔案』，不含歷程頁籤」，使用者故事 2 的介面定義也寫「`歷程` 頁籤為 Desktop 右欄功能」
- **為什麼**：手機要主操作優先，抽屜不得遮蔽核心標記區；操作紀錄是回顧用的資訊，不是作答必需
- **影響**：[§工作區的外殼](#工作區的外殼三欄與行動版)第 6 條

### Q7. 標記員看不看得到那一筆的識別碼？（已定案，沿用舊來源，來源標為不可協商）

- **結論**：**看不到**。麵包屑第 3 層對標記員**只顯示佇列位置**，不顯示那一筆的識別碼，也不顯示標記員自己的帳號
- **依據**：來源 `FR-080` 第 3 點標為 **NON-NEGOTIABLE**，理由是有些資料集用**沒有被指派用途的欄位**當記錄識別鍵，把它渲染進標記員看得到的地方就會違反來源的兩條資料公平性條文（標記員可見之處不得出現答案；用途是輸出的欄位不得被當成可讀內容）
- **為什麼**：識別碼本身可能就是答案線索；而標記員自己的帳號對標記員是零資訊
- **影響**：[§入口麵包屑的第三層](#入口麵包屑的第三層)第 2、3 條、[§卡控機制](#卡控機制)

## Q&A

### Q. 為什麼左欄標題不准帶回合標籤，這不是多此一舉嗎？

因為工作區是一個會停留很久的畫面，而「我在哪個回合」這件事只需要一個地方講。來源把它放在三欄主體**之上**的麵包屑，而不是左欄標題裡，理由是視線進入畫面時第一個落點在上方；標題如果也講一次，讀者就得確認兩處是不是同一件事。真正不能省的是**筆數**——它會因回合而不同，所以標題固定、筆數照回合變。

### Q. 為什麼標記員的麵包屑連那一筆的識別碼都不給看？

因為識別碼不一定只是流水號。來源點出有些資料集拿**沒有被指派用途的欄位**當記錄的識別鍵，那個欄位可能本身就帶著答案線索；一旦渲染進標記員看得到的地方，測試集保護就破了。這條在來源被標成不可協商，而且它換來的成本很低——標記員需要知道的是「我做到第幾筆、還剩幾筆」，那個識別碼對他本來就是零資訊。

### Q. 為什麼翻筆要把網址改寫成「原地取代」，不是正常地新增一筆瀏覽紀錄？

因為工作區的「下一筆」是作業動作，不是導覽動作。一個 5 筆樣本 × 3 位標記員的任務有 15 個審核單位，若每翻一筆都堆一筆瀏覽紀錄，審核員看完全部之後要按 15 次上一頁才離得開這一頁。原地取代同時保住了另一件事：重新整理、加書籤、把連結貼給別人，拿到的都是**畫面上的那一筆**，而不是最初進來的那一筆。

### Q. 為什麼說明彈窗的內容一定要和右欄同一份？

因為這個閘門的目的是「確定這個人讀過這一版說明」。如果彈窗另有一份文字，使用者確認的就不是他後續會對照的那一份，閘門只剩下儀式。同一個理由延伸到版本：彈窗與右欄必須是同一個指引版本，而換了版本就要重新確認——否則「已讀」這個紀錄會指向一份已經不適用的說明。
