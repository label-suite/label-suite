### 人工驗收步驟（留作紀錄）

本 change 沒有畫面與 API，不需啟動前後端、不需登入任何角色。

1. **啟動**：不需啟動應用程式。前置是 Docker 可用、已 `pnpm install`、`backend/` 已 `uv sync`。所有指令在 repo 根目錄（或註明的 `backend/`）執行，不設 `DATABASE_URL`。
2. **用什麼身分登入**：不適用。
3. **要跑哪幾個指令**：
   1. 三個 Semgrep 指令（與 CI 逐字相同）：
      - `docker run --rm -v "$PWD:/src" -w /src semgrep/semgrep:1.186.0 semgrep --test .semgrep/`
      - `docker run --rm -v "$PWD:/src" -w /src semgrep/semgrep:1.186.0 semgrep scan --error --config .semgrep/label-suite.yml backend/ frontend/ e2e/`
      - `docker run --rm -v "$PWD:/src" -w /src semgrep/semgrep:1.186.0 semgrep scan --error --x-ignore-semgrepignore-files --config .semgrep/test-boundaries.yml backend/`
   2. `cd backend && uv run pytest tests/integration/test_harness_parity.py tests/unit/test_semgrep_exemptions.py`
   3. `pnpm test:scripts`
   4. 想跑整套本機自查時：本機沒有 `semgrep` 執行檔，建一個 repo 外的 shim，內容為 `exec docker run --rm -v "$PWD:/src" -w /src semgrep/semgrep:1.186.0 semgrep "$@"`，`chmod +x` 後 `PATH=<shim 目錄>:$PATH pnpm run check --with-semgrep`；要跑 PostgreSQL 那一輪，先 `docker run -d --rm --name qa-pg -e POSTGRES_PASSWORD=qa -p 55432:5432 postgres:16`，再加 `TEST_DATABASE_URL=postgresql+asyncpg://postgres:qa@localhost:55432/postgres`
4. **每一步預期看到什麼**：
   - 樣本驗證印 `7/7: ✓ All tests passed`；既有掃描印 `Ran 2 rules on 104 files: 0 findings.`；邊界檢查印 `Ran 5 rules on 13 files: 0 findings.`；三者結束碼皆 0。邊界檢查若印 `on 0 files`，代表掃描目錄不是 git repo，結果不可信
   - 兩支 pytest 印 `26 passed`
   - `pnpm test:scripts` 印 `# fail 0`
   - 整套自查最後一行 `check: all 14 steps done`，最後一步是 `PASS Semgrep test boundaries`
5. **刻意要試的失敗路徑**（試完一律 `git checkout -- <檔>` 還原）：
   - 在 `backend/tests/conftest.py`、`backend/tests/probe.py` 檔尾各加一個函式，內容一行 `monkeypatch.setattr("app.main.x", 1)`；在 `backend/tests/integration/test_health.py` 檔尾加 `session = MagicMock()` → 邊界檢查 exit 1，列出三個檔案與行號，規則為 `label-suite-test-self-mock-string`、`label-suite-test-mock-objects`
   - 同樣兩行加在 `backend/tests/unit/` 的檔案 → 不被列出（範圍外）
   - 在 `conftest.py` 的 `app` fixture 回傳前加 `application.user_middleware.pop()` → `test_harness_parity.py` 失敗，訊息 `middleware classes or order differ:` 並列出兩邊清單
   - 在 `test_health.py` 某行尾加 `# nosemgrep`（不帶規則 id 與理由）→ `test_semgrep_exemptions.py::test_backend_tests_hold_no_bad_marker` 失敗，列出 `tests/integration/test_health.py:<行號>`
6. **收尾**：`git status --porcelain` 必須為空；`docker stop qa-pg`（有起 PostgreSQL 時）；刪掉 shim。`pnpm run check` 會產生 `backend/test-results/`、`backend/.coverage.*`、`frontend/coverage/`，都已被 `.gitignore` 忽略，不必清。

### 缺陷

無阻斷缺陷。以下兩點是驗收中觀察到、不違反任何 Scenario 的行為，記下供日後參考，不需修正：

1. **觀察 1：同一行被兩條規則列出**。以 `monkeypatch.setitem(app.dependency_overrides, …)`、`monkeypatch.context()` 別名的 `setitem`、`mocker.patch.dict(app.dependency_overrides, …)` 寫在接收 `app` fixture 的函式裡時，該行同時列出 `label-suite-test-dependency-overrides` 與 `label-suite-test-self-mock-object`（因為 `app` 名稱被當成 `app` 套件）。Scenario 只要求列出依賴覆寫那條規則的 id，已滿足；影響是日後若真要放行這種寫法，例外標記要以逗號列兩個 id（格式本來就允許）。
   - 對應 Scenario：dependency_overrides 寫入被擋
   - 重現：檢查範圍內 `def f(app, monkeypatch): monkeypatch.setitem(app.dependency_overrides, k, v)`，以邊界檢查指令掃描
   - 負責角色：無（不需動作）
2. **觀察 2：掃描非 git 目錄時 0 個檔案**。錨定的 `paths.include` 只在 git repo 內生效；在 repo 外的暫存複本未 `git init` 時，Semgrep 掃 0 個檔案並以 0 結束。CI 與 repo 根目錄不受影響；已寫進上面的人工步驟，提醒日後抽查者。
   - 負責角色：無（不需動作）
