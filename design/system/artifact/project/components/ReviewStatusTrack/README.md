審核進度軌：顯示一筆標註單元從待審到定稿走的路，包含「答案未修改」與「答案有修改後進入爭議」兩條分支。

## 何時使用

- 審核頁、標註單元詳細頁，告訴審核員與標註者這一筆目前停在哪一步。
- 每個單元只有一位審核員（FR-093），所以主線只有三個節點：待審、爭議中（分支）、已定稿。
- 不要用線性的 Step Indicator 表示審核（FR-051）；審核會分岔，Step Indicator 表達不了。

## 結構與使用方提供的內容

- `.review-track`：`role="list"`，7 欄 2 列的格線。
- `.review-track-node`：每個節點。走過的加 `.done`；目前所在的加 `.current` 與 `aria-current="step"`，並在文字前放 `.review-track-marker`（「目前：」）。
- `.review-track-fork`：分岔處的 SVG，`aria-hidden="true"`。
- `.review-track-branch[data-branch]`：分支標籤，值為 `same`（答案未修改）、`differing`（答案有修改）、`arbitrated`（仲裁後）。
- `.review-track-rail`：節點之間的軌道。
- 使用方決定哪些節點是 `.done`、哪個是 `.current`，以及走的是哪條分支。

## 變體

- 只有一種結構；差別只在走過的路徑。
- 剛建立：停在待審，兩條軌都沒走。
- 走差異軌：待審已完成，經「答案有修改」進入爭議中。

## 狀態

- 不只靠顏色：目前節點字重 600，加「目前：」前綴；走過的軌道與分岔線比較粗。
- 分支標籤沒有用 ARIA 連到對應的軌道（G-20），報讀器只會唸出節點清單。
- 全部用 token，暗色主題自動跟著換。

## 該做／不該做

- 該做：同一時間只有一個 `.current`。
- 該做：保留「目前：」前綴，不要只用顏色標示所在位置。
- 不該做：改成四個以上的節點或多位審核員的流程；那不符 FR-093。
- 不該做：拿 Step Indicator 取代它。
