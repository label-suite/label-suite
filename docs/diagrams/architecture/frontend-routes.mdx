# 前端路由與骨架

這份記 `main` 上的 `frontend/` 現在長怎樣：每條路由用哪個頁面元件、對到哪一份規格與哪個 Logic Flow 節點，加上前端骨架；**只寫已合併的程式有的東西**。
要照著做的規則在 [技術架構的前端](../../development/architecture.mdx#前端)，為什麼這樣決定在 [ADR-005](../../development/adr/005-frontend-architecture.mdx)；畫面長相以 `design/prototype/pages/` 為準，頁面怎麼被進入與離開以各模組 `index.mdx` 的 Logic Flow 為準。
本文與程式不一致時，是本文錯了：以程式為準，並回頭改本文。

各節的收合區塊是實作或規劃時才要查的細節，預設收起。

## 誰改、什麼時候改

規劃時先改本文，change 的 `ui-design.md` 只寫本文的路徑與異動摘要，不重抄本文的內容。

| 時機 | 誰 | 做什麼 |
| :--- | :--- | :--- |
| 規劃（寫 `ui-design.md`） | `ui-ux` | 新頁面加進 [§路由](#路由) 與 [§頁面與功能元件](#頁面與功能元件)；動到骨架時改 [§前端骨架](#前端骨架)。`ui-design.md` 的「常駐文件異動」節寫出本文路徑與異動摘要 |
| 規劃審閱 | `design-reviewer` | 核對本文與這次的 `ui-design.md` 一致 |
| 實作後 | `frontend-developer` | 實作出來的路由、頁面元件、規格編號或 Logic Flow 節點和設計不同時，依程式校正本文；動到前端骨架的改 [§前端骨架](#前端骨架) |
| 程式審查 | `code-reviewer` | 再核對一次本文與實作一致；不一致時列為審查意見 |

change 的 `ui-design.md` 仍然寫這次頁面的元件樹、資料來源、畫面狀態與 design token；本文留下的是合併之後全系統的路由與頁面。

## 路由

登入頁、Google 回調、儀表板與 `/` 在開發模式與正式建置都註冊，經守門判定後才顯示；兩個開發用頁面只在開發模式註冊，不經守門。登入後的路由都包在登入後外殼這個 layout 裡，側欄畫在這一層（見下方表格後的說明）。

| 路由 | 頁面元件 | 註冊於 | 對應的規格 | Logic Flow 節點 |
| :--- | :--- | :--- | :--- | :--- |
| `/account/login` | `LoginPage`（`pages/account-login/`）；包在 `PublicOnlyRoute` 裡，已登入時以取代歷史紀錄的方式導向落點 | 開發模式與正式建置 | 規格 01-01 §登入頁、§用 Email 與密碼登入、§用 Google 帳號登入、§語言切換 | 帳號模組 P1；D1 是 → X5 |
| `/account/google/callback` | `GoogleCallbackPage`（`pages/google-callback/`）：沒有自己的畫面，只畫頁面底色；把 Google 帶回來的 `code`、`state` 交給後端一次後導走；包在 `PublicOnlyRoute` 裡 | 開發模式與正式建置 | 規格 01-01 §用 Google 帳號登入、E1、E2 | 帳號模組 X1 → D3；D3 是 → X5，D3 否 → P1 |
| `/dashboard/dashboard` | `DashboardPage`（`pages/dashboard/`）：畫在登入後外殼裡。由上而下是頁首（主標題、副標題，每一種版面都有）、擋下說明（只在被側欄擋下帶回來時出現一次）、版面區。系統管理員看全平台版面，目前只有「平台使用者統計」一個區塊：四張指標卡都是語言檔固定的 `0 人` 與一行示範值標示，不送請求；平台成員依任務角色來源的狀態決定一種版面：讀取中顯示骨架、讀取失敗顯示錯誤說明與重試（不改版面、不登出、不導向登入頁；按重試回到骨架、焦點移到骨架的狀態提示）、一個任務角色都沒有時顯示三張行動入口卡，專案負責人、審核員、標記員三種版面目前只有頁首。系統角色不在允許清單裡時不畫版面、只導向登入頁，不另外登出 | 開發模式與正式建置；需要登入 | 規格 02-01 §這一頁顯示哪一種版面、§還沒有任務角色的人看到什麼、§系統管理員看到的四個區塊 第 1、2、4 條、§審核概況那三張卡是示範值 第 6–8 條；規格 07-01 §進入模組的條件 第 3、4 條；規格 01-05 §從這一台登出 | 帳號模組 X5；儀表板模組 S → D1 → P1、D1 否 → X1、P1 → X2（卡 A）、P1 → X3（卡 B、C）；共用模組 P1、X1；登出 X5 → X7 → P1 |
| `/` | `RootRedirect`：不顯示內容，依登入狀態以取代歷史紀錄的方式導向：已登入 → 落點，未登入 → `/account/login` | 開發模式與正式建置 | 規格 01-01 §登入頁 第 9 條、Q3 | 帳號模組 S → D1 |
| 其他路徑 | 以取代歷史紀錄的方式導向 `/`，再依登入狀態導向；不顯示找不到 | 開發模式與正式建置 | 無；規格 07-03 的找不到只涵蓋網址定址到的那一筆，不涵蓋未註冊的網址 | 無 |
| `/dev/health` | `DevHealthPage`（`pages/dev-health/`） | 開發模式 | 無 `docs/specs/` 規格；行為見 `openspec/specs/dev-health-page/` | 無 |
| `/dev/gallery` | `DevGalleryPage`（`pages/dev-gallery/`） | 開發模式 | 無 `docs/specs/` 規格；行為見 `openspec/specs/component-gallery/` | 無 |

**登入後外殼**：`RequireAuthRoute` 底下包一層沒有自己 path 的 layout route，元素是 `AppShellLayout`（`src/app/`），它向 `features/auth` 取登入者與登出、向 `features/app-shell` 取導覽項模型與收合狀態，交給 `components/app-shell/` 的 `AppShell` 畫側欄，頁面畫在它的 `<Outlet>`。每一條包在外殼裡的路由都在 route 的 `handle` 宣告自己屬於哪個導覽項（`navKey`）；系統管理的頁另外宣告次選單項（`adminSubKey`）與角色標示覆寫（`roleIndicator`）。外殼讀最深一層的宣告標出目前位置，缺宣告時測試失敗。

側欄的導覽項與儀表板的行動入口卡一律連到最終路徑（規格 07-shared 模組索引 §Logic Flow 的 X1～X8、規格 02-dashboard 模組索引 §Logic Flow 的 X2、X3）；那些頁還沒註冊時，照「其他路徑」那一列經 `/` 回到儀表板。「標記作業」的連結帶入口標記 `entry=nav`；儀表板行動入口卡的「開始標記」「開始審核」連到同一頁，帶入口標記與角色（`entry=nav&role=annotator`、`entry=nav&role=reviewer`），「開始建立任務」連到任務列表 `/task-management/task-list`；三者都不帶任務、任務類型或輸出類型，也不經側欄的擋下判斷，按下去不出現擋下說明。擋下說明以 router 的 navigation state 帶到落點，不進網址。

路由表在 `src/app/router.tsx` 的 `createAppRouter()`：每一條路由（含兩個開發用頁面與其他路徑）都包在一層沒有 path 的根 layout `AppRoot`（`src/app/app-root.tsx`）底下，它只畫 `<Outlet>`，換頁時不卸載，供外殼判斷要不要重查登入狀態（見 [§登入狀態與守門](#登入狀態與守門)）。兩個開發用頁面以 lazy route 放在 `import.meta.env.DEV` 分支，正式建置時這個分支連同兩頁的程式與文案一起被移除。路徑常數 `LOGIN_PATH`、`GOOGLE_CALLBACK_PATH`、`LANDING_PATH` 與三個守門元件都從 `features/auth` 匯出。路徑沿用 prototype 的頁面識別（`docs/prototype/navigation.mdx`），讓 02-01 外殼只換頁面元件、不改路由與導向。

:::note{title="健康檢查頁的四種狀態" collapsible}
- `HealthStatusPanel` 用 `toHealthViewState` 把查詢結果轉成四種狀態之一：載入中、正常、後端錯誤（任何錯誤外層）、連不上
- 後端回的 `message`、`code`、`traceId` 與錯誤種類原樣顯示，不再翻譯
- 兩頁都在進入時設定 `document.title`
:::

:::note{title="登入相關頁面的行為" collapsible}
- 登入頁：登入頁設定回來前、或取不到時，Google 按鈕、「或」分隔線與「前往註冊」都不畫，也不顯示橫幅；`googleEnabled` 為假時不畫 Google 按鈕與分隔線，`selfRegistrationEnabled` 為假時不畫「前往註冊」整列
- 錯誤橫幅的文字依 `LoginNotice` 取 `auth` 語言檔的 `login.error.*`，不顯示後端的 `message`；五種：`invalidCredentials`、`googleRejected`、`sessionExpired`、`sessionInvalid`、`unavailable`
- 登入頁開啟時顯示的那一句：導覽狀態帶來的（Google 回調的 E2、沒有回應）優先，其次是守門查詢帶的；讀一次就清掉，同一次造訪重開登入頁不再出現
- Google 回調：網址有 `error`、或缺 `code`、`state` 時不呼叫後端，安靜回登入頁；`ACCOUNT_GOOGLE_FLOW_INVALID` 安靜回登入頁（E1），`ACCOUNT_GOOGLE_REJECTED` 帶 Google 那一句（E2），其他失敗帶「沒有回應」那一句；同一組 `code`、`state` 只送一次，回調網址一律以取代的方式離開歷史紀錄
- 登出：側欄的登出鈕（桌機、已收合、手機三個位置共用一個送出狀態）經 `useSignOut` 送出，送出期間不再接受按鍵；不論結果都清掉其他查詢快取、把登入狀態記成未登入，由守門帶回登入頁
- 登入頁與落點在進入時設定 `document.title`
:::

## 前端骨架

一條請求由頁面走到後端只有一條路：功能元件 → Orval 生成的 hook → `apiFetch` → `fetch`。分層與允許的 import 由 `frontend/eslint.config.js` 檢查，規則本體見 `docs/development/rules/frontend-agent-rules.mdx` 的 F1。

### 目錄

```text
frontend/
├─ orval.config.ts          唯一的 Orval 設定：讀 ../backend/openapi.json
├─ vite.config.ts           開發伺服器固定 5173 port，不設 proxy
├─ build/extract-tokens.ts  Vite 外掛：從 tokens.css 與 data-palette.css 取出 CSS 變數
├─ public/theme-init.js     第一次繪製前套用外觀；index.html 在模組腳本之前載入，不經打包
└─ src/
   ├─ main.tsx              啟動：檢查 API 設定、決定語言、接手外觀、render
   ├─ app/                  router、根 layout AppRoot、外殼組合層 AppShellLayout、providers、QueryClient
   ├─ pages/<page>/         頁面：組合功能元件與原語
   ├─ features/<feature>/   功能元件與它的狀態轉換
   ├─ components/           跨 feature 共用的元件（品牌標誌、語言切換、外觀切換、無權限與找不到的整頁畫面、app-shell/ 側欄外殼）
   │  └─ ui/                shadcn/ui 原語，匯出 variant 陣列
   ├─ api/                  mutator.ts（唯一出口）、session-refresh.ts、ApiError、外層判定、錯誤分類、config
   │  └─ generated/         Orval 產物，禁止手改
   ├─ lib/                  i18n、theme（外觀偏好）、date（day.js 唯一入口）、abort、utils、route-paths（全站共用的路由位址）
   ├─ styles/               theme.css：shadcn 變數對到 tokens.css 的變數名
   └─ test/                 Vitest setup、MSW server、外層 fixture
```

| 目錄 | 放什麼 | 判斷方式 |
| :--- | :--- | :--- |
| `pages/` | 一條路由一個資料夾 | 被 `router.tsx` 掛上去 |
| `features/` | 一個功能一個資料夾，對外只從 `index.ts` 匯出 | 會送請求，或有自己的狀態轉換 |
| `components/`（`ui/` 以外） | 共用元件：用到它的產品畫面分屬一個以上 feature 的設計系統元件，不認識業務 | 依 `docs/development/rules/frontend-agent-rules.mdx` 的 F5，由 `scripts/check-component-reuse.mjs` 檢查 |
| `components/ui/` | 沒有業務的原語 | 換一個頁面也照樣能用 |
| `api/`、`lib/` | 全站共用的基礎建設；`lib/route-paths` 是側欄與儀表板共用的路由位址（儀表板、任務清單、標記清單，與帶入口標記和選用角色的標記入口連結，不帶任務或任務類型） | 不 import `pages/`、`features/` |

### 單一 HTTP 邊界

`src/api/mutator.ts` 的 `apiFetch` 是前端唯一的 HTTP 出口，也是 Orval 的 mutator：base URL、cookie、`Accept-Language`、CSRF 標頭、逾時、取消、`401` 之後的延續，以及把每一種失敗轉成 `ApiError`，都只在這裡。理由見 `docs/development/rules/api-agent-rules.mdx` 的 A6。

| 結果 | `apiFetch` 回傳或丟出 |
| :--- | :--- |
| 成功外層 | `{ data, meta }`，`meta` 是外層的 `traceId` 與 `timestamp` |
| `204` | `undefined` |
| 錯誤外層 | `ApiError`，`kind: "http"`，帶 `status`、`code`、`message`、`traceId`；`422` 另帶 `fieldErrors` |
| 回應不是外層 | `ApiError`，`kind: "invalidResponse"`，`traceId` 取自 `X-Correlation-ID` 標頭 |
| 連不上 | `ApiError`，`kind: "network"` |
| 逾時 | `ApiError`，`kind: "timeout"` |
| 呼叫端取消 | `ApiError`，`kind: "aborted"` |

失敗一律不自動重試：`apiFetch` 只在 `401 AUTH_REQUIRED` 時延續登入狀態後重送（見 [§登入狀態與守門](#登入狀態與守門)），其他失敗不重試；`createQueryClient()` 把查詢與寫入的 `retry` 都關掉。元件與 hook 只會看到 `ApiError`，不會看到原生的 `TypeError`、`DOMException` 或 `Response`。

:::note{title="apiFetch 的細節" collapsible}
- `VITE_API_BASE_URL`：空字串代表同源相對路徑；否則必須是結尾沒有 `/` 的絕對 `http(s)` URL。`main.tsx` 啟動時先呼叫 `readApiConfig()`，不合格就不 render
- 每個請求都 `credentials: "include"`，`Accept-Language` 取目前的介面語言；有 body 時設 `Content-Type: application/json`
- `POST`、`PUT`、`PATCH`、`DELETE` 讀得到 `__Host-ls_csrf` cookie 時，把它的值放進 `X-CSRF-Token` 標頭
- `ApiFetchOptions.skipSessionRefresh` 讓請求只送一次、不延續；只有延續請求本身設它
- 預設逾時 15 秒，可用 `ApiFetchOptions.timeoutMs` 逐次覆寫；TanStack Query 傳進來的 signal 與逾時合成一個
- query 參數用 `URLSearchParams` 組，`null` 與 `undefined` 略過，陣列重複同一個 key
- 外層只驗外層本身的欄位，`data` 裡面的形狀交給生成的型別
- 非 `http` 的 `ApiError.message` 是英文診斷字串，不含回應內容或原生錯誤的訊息
- `isAuthError()` 只認錯誤外層的 `401`；`403` 不算
- `api-error.ts` 的錯誤分類 `classifyRejection()` 把任何丟出來的值分成三種（`RejectionKind`）：`403 PERMISSION_DENIED` 是無權限、`404 NOT_FOUND` 是找不到，其他（含 `403 CSRF_FAILED`，以及不是 `ApiError` 的值）一律是其他；狀態碼與錯誤碼要同時吻合，只分類，要不要畫成無權限或找不到的整頁畫面、返回去哪裡由各頁決定
- 語言：`main.tsx` 呼叫 `initI18n()`，讀 `localStorage` 的 `labelsuite.lang`；值不是 `en`、讀不到或沒有時是 `zh-TW`，不看瀏覽器語言，並把 `<html lang>` 設成同一個值。登入頁頁首與側欄的 `LanguageToggle` 經 `changeInterfaceLanguage` 切換、記住並更新 `<html lang>`。啟動時預載 `common`、`auth`、`appShell`、`dashboard` 四個 namespace，開發用頁面的 namespace 由各自的入口註冊；英文缺某個鍵時顯示繁體中文原文（`fallbackLng` 是 `zh-TW`），不顯示鍵名
- 外觀：`index.html` 在 `<head>`、模組腳本之前以同源外部腳本 `<script src="/theme-init.js">` 載入 `public/theme-init.js`，它在第一次繪製前讀 `localStorage` 的 `label-suite-theme`（淺色、深色、跟隨系統；無效、讀不到或沒有時當跟隨系統），把解析後的值寫到 `<html data-theme>`；不用內嵌腳本，所以內容安全政策 `script-src 'self'` 不必放寬。之後由 `lib/theme` 接手：`main.tsx` 呼叫 `initTheme()` 套用並在跟隨系統時訂閱作業系統的變化，`ThemeToggle` 經 `useResolvedTheme` 讀、經 `setThemeChoice` 寫。兩份解讀規則以同一張案例表測試，不會各走各的。登入頁與登入後的每一頁都照它呈現，登出不清這個鍵
:::

### 登入狀態與守門

所有守門都讀同一個「目前的登入狀態」查詢；任何請求回 `401 AUTH_REQUIRED` 時，由 `apiFetch` 先延續登入狀態再重送，頁面不必自己處理。只做授權四步的第 1、2 步，角色能看到什麼由後端決定。

| 元件 | 在哪裡 | 做什麼 |
| :--- | :--- | :--- |
| `useSessionState`、`sessionQueryOptions` | `features/auth/session-query.ts` | 以生成的 `getGetCurrentSessionQueryKey()` 為 key 查 `getCurrentSession`，`staleTime` 無限、視窗取得焦點不重查；查詢**不會失敗**：除了取消，每一種拒絕或沒有回應都轉成 `{ kind: "signedOut", notice }`，守門只看資料分支。回 `200` 但 `data.user.role` 不是生成的 `SessionUserDataRole` 值（`user`、`super_admin`）時也轉成 `{ kind: "signedOut", notice: null }`：不登出、不送 `DELETE /api/v1/current-session`，三個守門與儀表板對同一個登入者給出同一個判定，只導向登入頁一次、不在登入頁與落點之間來回 |
| `RequireAuthRoute`、`PublicOnlyRoute`、`RootRedirect` | `features/auth/route-guards.tsx` | 查詢回來前只畫頁面底色，避免頁面閃一下再跳走；之後以取代歷史紀錄的方式導向登入頁或落點 |
| `sendWithSessionRefresh`、`refreshSession` | `src/api/session-refresh.ts` | 延續是 single-flight：同一時間只有一個 `createSessionRefresh`，其他被拒的請求共用它；整個流程延續至多 2 次、重送至多 2 次 |
| `AppRoot` | `src/app/app-root.tsx` | 沒有 path、包住每一條路由（含開發頁與其他路徑）的根 layout，只畫 `<Outlet>`；整頁重新載入才重來。以 context 提供一個 ref：外殼上一次檢查登入狀態時的 `location.key`（`checkedKey`）、pathname（`checkedPathname`），與之後路由是否到過別的 pathname（`leftSince`）。目前的 pathname 不等於外殼記下的 `checkedPathname` 時把 `leftSince` 設為 true，比對的是外殼記下的值，不是它自己上一次看到的 pathname |
| `AppShellLayout` | `src/app/app-shell-layout.tsx`、`session-check.ts` | 外殼的組合層：向 `features/auth` 取登入者與 `useSignOut`，向 `features/app-shell` 取導覽模型、收合、快捷鍵與擋下，交給 `components/app-shell` 畫。依 `location.key` 與 pathname 判斷要不要在背景重查登入狀態：這次頁面載入第一次到達只記下、不重查（守門剛查過）；同一個 key（StrictMode 重跑或重新渲染）不動；key 不同而 pathname 不同或 `leftSince` 為 true（換了頁，含經外殼以外的轉址回到同一頁）時以 `refetch({ cancelRefetch: false })` 重查一次；key 不同但 pathname 相同又沒離開過（清擋下說明的 state、已在落點時再被擋）只記下。所以 StrictMode 重跑不會多查，視窗取得焦點也不重查。重查在 effect 之後的 microtask 送出，避開 StrictMode 模擬卸載時查詢沒有觀察者而被取消。重查回來之前側欄維持上一份資料；得到未登入時由守門帶回登入頁 |
| `App`、`AppProviders` | `src/app/app.tsx`、`providers.tsx` | 可選的 `queryClient`（`AppProviders` 的屬性名是 `client`）讓測試換成新的快取；沒給時用整頁共用的那一個 |

:::note{title="延續的步驟與登入頁的句子" collapsible}
- 延續：延續成功就重送一次；延續回 `409 ACCOUNT_REFRESH_CONFLICT`（另一個分頁剛延續過）時等 300 毫秒再重送一次；那次重送仍回 `401 AUTH_REQUIRED` 時再延續一次，成功就再重送一次；其他失敗原樣交給呼叫端。延續請求本身帶 `skipSessionRefresh`，不會再觸發延續
- 守門查詢失敗時登入頁顯示的句子（`noticeForSessionError`）：`ACCOUNT_SESSION_EXPIRED`、`ACCOUNT_SESSION_INVALID` 各對到一句被動登出；`AUTH_REQUIRED` 與用完的 `ACCOUNT_REFRESH_CONFLICT` 不顯示句子；連不上、逾時、回應不是外層或 `5xx` 顯示「沒有回應」那一句
- 登入成功後重查登入狀態，守門自己把頁面帶到落點，一律去落點、不帶回原本要去的頁面
- `403` 不在這裡處理，交給各頁
- Google 登入不用 `302`：授權網址由後端以 JSON 回給前端，前端整頁導覽過去；Google 回到前端的 `/account/google/callback`，再由前端把 `code`、`state` 送給後端
:::

### 生成的 hooks 與 MSW mock

`pnpm --filter frontend api:generate` 讀已提交的 `backend/openapi.json`，把 TanStack Query 的 hooks、型別與 MSW mock 產生到 `src/api/generated/`；每次產生前會先清空這個資料夾，所以裡面不能手改或手加檔案。為什麼用 Orval 見 [ADR-003 的 D6](../../development/adr/003-backend-architecture.mdx#d6-前端-client-用-orval-產生)。

| 檔案 | 內容 | 誰可以 import |
| :--- | :--- | :--- |
| `label-suite.ts` | 每個 operationId 一個請求函式與 hook，例 `getHealth`、`useGetHealth`、`getGetHealthQueryKey` | 功能元件 |
| `label-suite.schemas.ts` | API 文件裡的型別，例 `HealthDataResponse`、`ErrorResponse`、`ErrorDetail` | 任何層 |
| `label-suite.msw.ts` | 每個 operationId 一個 MSW handler，回 faker 產生的資料 | 只有測試 |
| `label-suite.faker.ts` | faker 產生的回應 | 只有測試 |

測試共用一個 MSW server（`src/test/msw-server.ts`），預設掛生成的 handler，只用來證明請求有被攔到；要固定內容的測試用 `server.use()` 疊上 `src/test/envelope-fixtures.ts` 的 fixture。沒被攔到的請求直接讓測試失敗。

:::note{title="漂移檢查與測試替身的邊界" collapsible}
- 漂移檢查的指令見 `openspec/config.yaml` 的 `operations.apply`（前端契約漂移那一條）：重新產生後 `src/api/generated/` 不能有任何差異或新檔
- `msw`、`@faker-js/faker`、`src/test/` 與生成的 `*.msw.ts`、`*.faker.ts` 只有測試檔能 import，ESLint 擋住其他地方，測試替身不會進到正式 bundle
- UI 層（`pages/`、`features/`、`components/`）不能直接用 `fetch` 或 `axios`
:::

### 元件展示頁

`/dev/gallery` 把 `src/components/ui/` 每個原語宣告的 variant、尺寸與狀態各列一次，取代 Storybook；理由見 [ADR-005 的 D3](../../development/adr/005-frontend-architecture.mdx#d3-元件庫用-shadcnui)。

| 組成 | 做什麼 |
| :--- | :--- |
| `variant-catalog.ts` | 每個原語的展示清單；有匯出 variant 陣列的原語用 `satisfies` 綁住，原語加了 variant 這裡不跟著加就型別錯誤 |
| `completeness.test.tsx` | 兩層：清單的 key 等於原語匯出的陣列；畫面上每個宣告的值各有一個 `[data-gallery-item]`，而且 `components/ui/` 的每個原語檔都有一節 |
| `ThemeToggle` | 取自 `components/` 的共用外觀切換，和側欄是同一個元件、讀寫同一份外觀偏好；記住選擇，離開展示頁不還原 |
| `TokenMappingSection` | 列出 `styles/theme.css` 的對照；只有這一頁可以把 `theme.css` 讀成原始文字 |

目前的原語：`alert`、`badge`（含角色變體 `role`）、`button`（含送出中的 `loading`）、`card`、`dialog`、`empty`、`input`、`label`、`metric`（指標卡：標籤在上、數值在下）、`separator`、`skeleton`（脈動與光帶兩種動畫）。新增原語時，展示頁要有它的一節，否則完整性測試失敗。

原語以外，展示頁另有一節「無權限與找不到」（錨點 `#blocked`，排在「Skeleton · Empty」與「Token 對照」之間），由 `blocked-section.tsx` 的 `BlockedSection` 畫 `components/blocked-screen.tsx` 的 `BlockedScreen` 三個樣本：找不到、無權限，以及識別碼很長的找不到，各帶 `data-gallery-item="blocked-screen:kind:<值>"`（值為 `notFound`、`denied`、`longIdentifier`，宣告在 `variant-catalog.ts` 的 `blockedSampleValues`）。返回去處是儀表板，字面是展示頁自己的示意文字（`devGallery` 的 `blocked.*`），識別碼是 `variant-catalog.ts` 的固定示意值，樣本標題是二級、不移焦點。正式路由還沒有任何頁面畫這兩種畫面，所以這一節是看得到它們的唯一地方。

樣本的返回連結是 React Router 的 `Link`，所以展示頁要在 Router 裡畫：執行時由正式路由提供，測試一律經 `render-gallery.test-helper.tsx` 的 `renderGallery()` 以 `MemoryRouter` 包住，不直接 render `DevGalleryPage`。

:::note{title="design token 怎麼進到元件" collapsible}
- `build/extract-tokens.ts` 在開發與建置時讀 `design/prototype/assets/tokens.css` 與資料色 `design/prototype/assets/data-palette.css`（`tokens.css` 在前），只取 `:root` 與 `html[data-theme="dark"]` 的 `--*` 宣告，以虛擬模組 `virtual:design-tokens.css` 提供，不寫檔；資料色淺深兩組都有
- `main.tsx` 直接 import 它、不放在 `@layer` 裡，所以 `tokens.css` 的值會蓋過 Tailwind 同名的主題變數
- `styles/theme.css` 只寫變數名，把 shadcn 的語意變數指向 `tokens.css` 的變數，沒有任何色值；理由見 [ADR-005 的 D4](../../development/adr/005-frontend-architecture.mdx#d4-design-token-寫一層對照)
- 資料色（`--data-*`，例如儀表板行動入口卡的角色色 `--data-role-*`）不進 `styles/theme.css` 的對照，`components/ui/` 的原語也不讀；只由需要它的功能元件直接引用，所以 shadcn 的語意色仍只有 `tokens.css` 一個來源
:::

## 已知限制

已落地的前端有登入、守門、登入後外殼（側欄）與儀表板的外殼；下表是它還沒有的東西與風險。

| 還沒有 | 風險 | 追蹤 |
| :--- | :--- | :--- |
| 側欄導覽項與儀表板行動入口卡的多數落點頁 | 點了經 `/` 回到儀表板；「資料集分析」被擋下時要去的任務列表也不存在，所以那句擋下說明目前看不到 | 規格 02-01、03-01、04-01、05-01、06-01、06-02、01-04 各頁的實作 |

| 定址到那一筆的頁面（任務詳情、標記清單） | 無權限與找不到的整頁畫面與錯誤分類沒有產品頁面使用，只在元件展示頁看得到；正式環境也還沒有端點會回這兩種拒絕 | 規格 03-03、04-01 的實作 |
| 前端的錯誤追蹤與監控 | 使用者端的錯誤只有使用者回報的 `traceId` 可查 | [ADR-008 的 D4](../../development/adr/008-deployment-and-operations.mdx#d4-觀測性只做-ai_runs監控與錯誤追蹤本期不做) |
