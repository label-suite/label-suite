# 本機開發

本文管 clone 之後怎麼把前後端跑起來、怎麼跑測試、`.env` 怎麼設；API 改了之後怎麼同步前端，見 [API 契約日常流程](api-contract-workflow.mdx)。
為什麼資料庫分兩層、為什麼用 Compose，見 [ADR-003 的 D7](../adr/003-backend-architecture.mdx#d7-資料庫分兩層) 與 [ADR-008 的 D1](../adr/008-deployment-and-operations.mdx#d1-compose-加-nginx-當-runtimecloudflare-可選)；部署細節見 [architecture.mdx 的 §部署與維運](../architecture.mdx#部署與維運)。
與 `AGENTS.md`、ADR 或 architecture.mdx 說法不同時，以它們為準（優先序見 [ADR 索引](../adr/index.mdx#衝突時以誰為準)），並回報維護者。

## 第一次設定

clone 之後做一次，之後只要 `.env` 有改才需要回來看：

```bash
pnpm run bootstrap             # 下面前三步的合併：setup.sh、pnpm install、uv sync
cp .env.example .env           # 本機設定，.env 已被 Git 忽略；bootstrap 不會做這一步
```

`pnpm run bootstrap` 等於依序跑 `scripts/setup.sh`（啟用 commit-msg 與 pre-commit 兩個 Git hook）、`pnpm install --frozen-lockfile`（根目錄、frontend、e2e 的 JavaScript 相依）與 `cd backend && uv sync --locked`（後端的 Python 相依，裝進 `backend/.venv`）。
它不複製 `.env`，也不套 migration，也不起任何服務。

`.env` 的預設值不必改就能跑 Lite 層（SQLite）；每個變數的用途見 [§環境變數](#環境變數)。

## 選一種跑法

| 跑法 | 適合 | 資料庫 | 入口 |
| :--- | :--- | :--- | :--- |
| Docker Compose | 試用、看整套行為、驗證部署設定 | Lite：SQLite；正式：PostgreSQL | `http://localhost:8080` |
| 前後端分開起 | 改程式、要熱重載 | 預設 SQLite 檔 | 前端 `http://localhost:5173`，後端 `http://localhost:8000` |

## 用 Docker Compose 起整套

Lite 層一條指令起 migrate、後端與前端，只有前端容器對外開埠：

```bash
docker compose up --build --wait --wait-timeout 300
curl http://localhost:8080/api/v1/health   # data.status 與 data.database 都是 "ok"
docker compose down -v                     # 停掉並刪掉資料 volume
```

正式層另有一份獨立的編排檔，多一個 PostgreSQL 容器，要先在 `.env` 填 `POSTGRES_PASSWORD`：

```bash
docker compose -f docker-compose.prod.yml up --build --wait --wait-timeout 300
docker compose -f docker-compose.prod.yml down -v
```

起好之後，建立第一位系統管理員（Seeder 管理員），才有帳號能登入：

```bash
docker compose run --rm -it backend python -m app.scripts.create_seeder --email <Email> --name <顯示名稱>
```

正式層在 `docker compose` 後面加 `-f docker-compose.prod.yml`。這支指令的行為見 [§建立第一位系統管理員](#建立第一位系統管理員)；它建的帳號存在資料 volume 裡，`docker compose down -v` 會連帳號一起刪掉。

Compose 最低版本是 v2.20.0，原因見 [architecture.mdx 的 §部署與維運](../architecture.mdx#部署與維運)的「Compose 最低版本」列。
`8080` 被占用時改 `.env` 的 `FRONTEND_PORT`，並把同一個埠加進 `CORS_ALLOWED_ORIGINS`。

## 前後端分開起

先套 migration 建出資料庫檔，建立第一位系統管理員，再一次起兩個開發伺服器：

```bash
(cd backend && uv run alembic upgrade head)
(cd backend && uv run python -m app.scripts.create_seeder --email <Email> --name <顯示名稱>)
pnpm run dev
```

建立系統管理員那一步只要做一次，行為見 [§建立第一位系統管理員](#建立第一位系統管理員)。

`pnpm run dev` 會讀根目錄 `.env`，起後端（uvicorn，`--reload`，埠 `BACKEND_PORT`）與前端（Vite，固定 `5173`），任一個結束就把另一個也停掉，Ctrl-C 兩個一起停。
也可以分兩個終端機各起一個，指令與它執行的相同：

```bash
# 終端機一：後端
(cd backend && CORS_ALLOWED_ORIGINS=http://localhost:5173 uv run uvicorn app.main:create_app --factory --reload --port 8000)

# 終端機二：前端
VITE_API_BASE_URL=http://localhost:8000 pnpm --filter frontend dev
```

只有 `pnpm run dev` 會讀根目錄 `.env`；分開起時兩個終端機都要自己帶變數：後端沒有 `CORS_ALLOWED_ORIGINS` 不會啟動，前端沒有 `VITE_API_BASE_URL` 會把 API 請求打到 `5173` 自己（Vite 沒有 proxy）。
Lite 層的資料庫檔預設在 `backend/data/label_suite.db`，已被 Git 忽略；刪掉它就是重置資料。

## 建立第一位系統管理員

沒有任何端點能建立帳號；第一位系統管理員只能由初始化指令 `app.scripts.create_seeder` 建立，兩種跑法各一行指令，見 [§用 Docker Compose 起整套](#用-docker-compose-起整套) 與 [§前後端分開起](#前後端分開起)。

| 項目 | 行為 |
| :--- | :--- |
| 密碼 | 指令會詢問兩次，輸入時不顯示；兩次不同就不建立。不收命令列參數或環境變數，也沒有預設密碼 |
| 密碼規則 | 至少 8 個字元，含大寫、小寫與數字 |
| 建出的帳號 | 啟用中的系統管理員（`super_admin`），標記為 Seeder 管理員；之後用這組 Email 與密碼在登入頁登入 |
| 再跑一次 | 同一個 Email：印出已存在、不問密碼、什麼都不改，退出碼 `0`。另一個 Email 已是 Seeder 管理員，或這個 Email 屬於一般帳號：拒絕、不寫入，退出碼 `2` |
| 讀哪些設定 | 只讀資料庫設定（`DATABASE_URL` 或 `SQLITE_PATH`），與 migration 相同；資料庫要先跑過 migration |

:::note{title="給自動化用：從標準輸入讀密碼" collapsible}
- 加 `--password-stdin`，指令改從標準輸入讀一行密碼、不詢問；例：`printf '%s\n' "$PW" | uv run python -m app.scripts.create_seeder --email <Email> --name <顯示名稱> --password-stdin`
- 標準輸入不是終端機、又沒帶 `--password-stdin` 時，指令拒絕並以退出碼 `2` 結束
- 在容器裡用管線送密碼時，把 `-it` 換成 `-T`
- 任何輸出都不含密碼或它的雜湊；成功印 `Created the Seeder admin <Email>.`，錯誤以 `create_seeder: ` 開頭寫到標準錯誤
:::

## 跑測試

測試分兩輪：SQLite 是預設，PostgreSQL 在設了 `TEST_DATABASE_URL` 時才跑。兩輪都要過，CI 的 `backend-sqlite` 與 `backend-postgres` 各跑一輪。

```bash
# SQLite 輪（沒設 TEST_DATABASE_URL；postgres 標記的測試會跳過）
(cd backend && uv run pytest)

# PostgreSQL 輪：先起一個拋棄式的資料庫，埠選一個沒被占用的
docker run -d --name label-suite-test-pg -e POSTGRES_PASSWORD=devpass -p 55432:5432 postgres:16
(cd backend && TEST_DATABASE_URL=postgresql+asyncpg://postgres:devpass@localhost:55432/postgres uv run pytest)
docker rm -f label-suite-test-pg
```

PostgreSQL 輪不應該有任何測試被跳過；CI 會用 `scripts/check-junit-skips.mjs` 檢查。
`pnpm run check` 依序跑 CI 的同一批檢查（格式、規格、前端 lint、型別與測試、契約同步、後端 lint、型別、import 契約、兩輪測試），第一個失敗就停；它在沒設 `TEST_DATABASE_URL` 時會說明跳過 PostgreSQL 輪。

## 環境變數

必填的有三個：`CORS_ALLOWED_ORIGINS` 沒設，兩層都起不來；`POSTGRES_PASSWORD` 與 `AUTH_SECRET` 沒設，正式層起不來（Lite 層不讀 `POSTGRES_PASSWORD`，`AUTH_SECRET` 可以不設）。`.env.example` 列出所有會被讀的變數，後端程式碼只讀其中標示「後端」的幾個；建立第一位系統管理員的指令不需要另外的變數。

| 變數 | 用途 | 預設值 | 誰讀 |
| :--- | :--- | :--- | :--- |
| `CORS_ALLOWED_ORIGINS` | 允許的瀏覽器來源，逗號分隔；每項是 `http(s)://host[:port]`，不得含路徑或 `*`，至少一項 | 無（必填）；`.env.example` 給 `http://localhost:5173,http://localhost:8080` | 後端、兩份編排檔 |
| `CORS_ALLOW_CREDENTIALS` | CORS 回應是否允許帶憑證 | `true` | 後端、兩份編排檔 |
| `API_DOCS_ENABLED` | 是否提供 `/docs`、`/docs/oauth2-redirect`、`/redoc`、`/openapi.json` | `true`；正式層編排檔固定為 `false` | 後端（Lite 編排檔不傳它，只影響容器外跑的後端） |
| `SQLITE_PATH` | Lite 層的資料庫檔位置，相對路徑以後端工作目錄為準 | `./data/label_suite.db` | 後端、migration、Lite 編排檔（`migrate` 與 `backend`） |
| `DATABASE_URL` | 設了就改走 PostgreSQL；接受 `postgresql`、`postgresql+asyncpg`、`postgres` 三種 scheme，一律轉成 `postgresql+asyncpg` | 未設（Lite 層）；正式層編排檔不讀它，自己用下面三個變數組 | 後端、migration |
| `POSTGRES_USER` | 正式層資料庫容器建立並讓後端連線的角色 | `label_suite` | 正式層編排檔 |
| `POSTGRES_PASSWORD` | 正式層資料庫密碼；含 URL 保留字元（`@ : / ? #`）要百分比編碼 | 無（正式層必填；`.env.example` 刻意留空） | 正式層編排檔 |
| `POSTGRES_DB` | 正式層資料庫容器建立的資料庫名 | `label_suite` | 正式層編排檔 |
| `VITE_API_BASE_URL` | 本機開發伺服器呼叫 API 的位址，須為空或不帶結尾斜線的絕對 http(s) URL；前端映像在建置時固定為空，走同源 | 未設等同空；`.env.example` 給 `http://localhost:8000` | 前端開發伺服器 |
| `FORWARDED_ALLOW_IPS` | 後端信任哪些代理位址的 `X-Forwarded-For` 與 `X-Forwarded-Proto`；逗號分隔的單一 IP 或 CIDR，不得為 `*` 或涵蓋全部位址的網段，非法值讓後端拒絕啟動。後端只驗證，比對由 uvicorn 做 | 未設時只信任 loopback（`127.0.0.1,::1`），所以本機 `pnpm run dev` 不需設定，`.env.example` 也把它註解掉；兩份編排檔傳入並預設為 `frontend` 的固定位址 `10.77.250.10` | 後端、兩份編排檔 |
| `AUTH_SECRET` | 簽登入用的 access token、CSRF 值與 Google 登入流程 cookie 的祕密，至少 32 字元；空字串等同沒設 | Lite 層可以不設：後端第一次啟動時產生一把，存成 `SQLITE_PATH` 同目錄的 `auth_secret`（權限 `0600`；容器裡在資料 volume），之後重用，刪掉 volume 或這個檔案等於所有人登出。正式層必填：`docker-compose.prod.yml` 沒有它就不建任何容器，設了 `DATABASE_URL` 的後端沒有它就拒絕啟動。`.env.example` 刻意留空 | 後端、兩份編排檔 |
| `GOOGLE_CLIENT_ID`、`GOOGLE_CLIENT_SECRET`、`GOOGLE_REDIRECT_URI` | Google 登入；三個一起設或都不設，只設一部分時後端拒絕啟動。`GOOGLE_REDIRECT_URI` 是前端的回調頁，例 `http://localhost:8080/account/google/callback` | 都不設：登入頁不顯示 Google 按鈕；空字串等同沒設 | 後端、兩份編排檔 |
| `RESEND_API_KEY` | 寄信服務的金鑰；後端目前只看它有沒有設，有設時登入頁提供「前往註冊」 | 不設；空字串等同沒設 | 後端、兩份編排檔 |
| `FRONTEND_PORT` | 前端容器在主機上公開的埠，是兩層唯一公開的埠 | `8080` | 兩份編排檔 |
| `BACKEND_PORT` | `pnpm run dev` 啟動本機後端的埠；編排檔不讀，容器內的後端不對主機開埠 | `8000` | `scripts/dev.mjs` |

測試另外讀 `TEST_DATABASE_URL`（見 [§跑測試](#跑測試)）；它只給測試用，不放進 `.env`，後端應用程式不讀它。
密碼只放 `.env`（`AGENTS.md` Hard Rule 8），`.env` 不進 Git，也不進映像。
