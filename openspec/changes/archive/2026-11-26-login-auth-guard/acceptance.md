#### spec 沒描述但實作出現的行為

1. 未登入的訪客開任何受保護或只給未登入的人的頁面時，守門查詢收到 `401 AUTH_REQUIRED` 後會再送一次 `POST /api/v1/session-refreshes`（同樣回 `401 AUTH_REQUIRED`），才判定未登入。這是 frontend-api-client「`AUTH_REQUIRED` 時延續並重送原請求」的直接結果，不是額外行為；記下來是因為 frontend-routing「正式建置開啟根路徑依登入狀態導向」寫的是「只送出 `GET /api/v1/current-session` 一個查詢登入狀態的請求」，延續不是查詢，兩條不衝突
2. 登入失敗訊息依 `Accept-Language` 本地化（英文 `Invalid email or password`），符合 `design.md` D7 的對照表

### 人工驗收步驟（留作紀錄）

1. **啟動**（擇一）
   - **前後端分開起（開發用，預設 SQLite，不設 `DATABASE_URL`）**：
     ```bash
     pnpm run bootstrap                     # 第一次才需要
     (cd backend && uv run alembic upgrade head)
     # 終端機一：後端 http://localhost:8000
     (cd backend && CORS_ALLOWED_ORIGINS=http://localhost:5173 uv run uvicorn app.main:create_app --factory --reload --port 8000)
     # 終端機二：前端 http://localhost:5173
     VITE_API_BASE_URL=http://localhost:8000 pnpm --filter frontend dev
     ```
     或複製 `.env.example` 為 `.env` 後 `pnpm run dev`（同樣是後端 `8000`、前端 `5173`）。`AUTH_SECRET` 不設，後端第一次啟動會在 `backend/data/auth_secret` 產生一把（權限 `0600`）。
   - **Docker Compose Lite 層**：`cp .env.example .env && docker compose up --build --wait --wait-timeout 300`，對外只有 **`http://localhost:8080`**（前端與 `/api/v1` 同源；後端不對主機開埠）。
   - 一定要用 `localhost` 開，不要用區網 IP：`__Host-` 加 `Secure` 的 cookie 只在 HTTPS 或 `localhost` 存得進瀏覽器。
2. **用什麼身分登入**
   - **系統管理員（Seeder）**：沒有任何端點能建帳號，以初始化指令建立，密碼會被問兩次且不顯示：
     - 分開起：`(cd backend && uv run python -m app.scripts.create_seeder --email admin@example.com --name 系統管理員)`
     - Compose：`docker compose run --rm -it backend python -m app.scripts.create_seeder --email admin@example.com --name 系統管理員`
     - 密碼由你在提示時輸入（至少 8 字、含大小寫與數字）；不在任何檔案或環境變數裡。再執行一次是冪等的；資料庫已有另一位 Seeder 時退出碼 `2`
   - **平台成員**：本次還沒有邀請或註冊，驗收用 `e2e/shared/account_db.py` 直接在資料庫建立（分開起的情況）：
     ```bash
     cd backend
     printf '%s\n' '<你選的密碼>' | PYTHONPATH=. uv run python ../e2e/shared/account_db.py add --email user@example.com --name 王小明
     ```
     停用、改角色、讓登入狀態變舊：`account_db.py set --email user@example.com --active false`、`set --role super_admin`、`age --email user@example.com --started-days-ago 90 --seen-days-ago 0`
3. **要點開哪幾個畫面**
   - `http://localhost:5173/`（Compose 為 `:8080`，下同）→ 被帶到 `/account/login`
   - `/account/login`：以 Seeder 或平台成員登入 → `/dashboard/dashboard`
   - 在落點按「登出」→ `/account/login`
   - `/dev/health`、`/dev/gallery`（只有分開起的開發模式有）
4. **每一步預期看到什麼**
   - 開 `/`：先只有頁面底色（判定中），接著網址變成 `/account/login`，**沒有**任何紅色橫幅
   - 登入頁（這個部署沒有寄信服務也沒有 Google 時）：頁首左邊品牌、右邊只寫 `ZH` 的語言鈕；卡片標題「Label Suite」、副標「登入你的帳號」，第一個欄位就是「電子郵件」，**沒有**「使用 Google 帳號繼續」、**沒有**「或」、**沒有**「還沒有帳號？ 前往註冊」、**沒有**「記住我」；密碼欄標籤右邊有「忘記密碼？」；瀏覽器分頁標題「Label Suite — 登入」
   - 什麼都不填按「登入」：兩欄下方各自出現「請輸入電子郵件」「請輸入密碼」；在 Email 欄打一個字，那一欄的說明立刻消失
   - 點 `ZH`：整頁立刻變英文、不重新載入，鈕變 `EN`，分頁標題「Label Suite — Sign In」；重新整理仍是英文；再點切回中文
   - 打錯密碼：卡片上方紅色橫幅「帳號或密碼錯誤，請再試一次」，兩欄內容都還在；在任一欄打字，橫幅消失
   - 填對後按「登入」：按鈕短暫變成轉圈（讀屏念「載入中」），整頁控制項都不能點；接著到 `/dashboard/dashboard`
   - 落點：卡片標題「你已登入」，下一行「王小明（user@example.com）」，角色標籤「平台成員」（Seeder 顯示「系統管理員」），說明「儀表板還在建置中，完成後登入會直接帶你過去。」，一個「登出」鈕；**沒有**側欄；分頁標題「Label Suite — 你已登入」
   - 登入後再開 `/account/login`：直接回到落點，看不到登入卡；按瀏覽器上一頁不會回到登入頁
   - 開發者工具：Application › Cookies 有 `__Host-ls_at`、`__Host-ls_rt`（勾 HttpOnly）與 `__Host-ls_csrf`（沒勾 HttpOnly）；Local Storage 只有 `labelsuite.lang`，Session Storage 是空的；Console 輸入 `document.cookie` 只看得到 `__Host-ls_csrf`
   - 按「登出」：回到 `/account/login`，三個 cookie 都不見；Network 裡的 `DELETE /api/v1/current-session` 是 `204`、帶 `X-CSRF-Token`
5. **刻意要試的失敗路徑**
   - 沒登入直接開 `/dashboard/dashboard`：網址變成 `/account/login`（沒有 `?` 後面的東西），沒有橫幅；上一頁不會回到落點
   - 開 `/no-such-page`：同上，回登入頁
   - 開 `/account/google/callback?error=access_denied`：安靜回登入頁，沒有橫幅
   - 登入後用 `account_db.py set --email user@example.com --active false` 停用自己，重新整理落點：回到登入頁，橫幅「驗證失敗，請重新登入」（英文介面 `Authentication failed, please sign in`）；再重新整理一次，橫幅消失
   - 登入後用 `account_db.py age --email user@example.com --started-days-ago 90 --seen-days-ago 0`，重新整理：橫幅「登入已過期，請重新登入」（英文 `Session expired, please sign in again`）
   - 同一帳號用兩個瀏覽器（或一般加無痕）登入，A 按登出：B 重新整理仍在落點
   - 停掉後端再按「登入」：橫幅「平台暫時沒有回應，請稍後再試。」，兩欄內容都還在
6. **收尾**
   - 分開起：Ctrl-C 停兩個終端機；要清資料就刪 `backend/data/label_suite.db` 與 `backend/data/auth_secret`（刪 `auth_secret` 等於所有人登出）
   - Compose：`docker compose down -v`（連資料 volume、帳號與 `auth_secret` 一起刪）；刪掉 `.env`
7. **API 驗收的重做方式（本次 64 項的來源）**：在步驟 1 的分開起環境另外以 `RESEND_API_KEY=re_test` 起一個後端（A），再以三個 `GOOGLE_*`（值可為假，`GOOGLE_REDIRECT_URI=http://localhost:5173/account/google/callback`）起另一個（B），兩者用不同的 `SQLITE_PATH`；以步驟 2 建立 Seeder 與數個平台成員（含 `--inactive`、`--anonymized`、`--no-local-password --google-subject g-sub-1`），再以手動管理 cookie 的 HTTP 用戶端（`__Host-` cookie 在 http 上 `curl` 與 Python `cookiejar` 不會自動送）逐條打 Decision Table #1–#41。寬限期外重用要真的等 31 秒以上
8. **正式建置的檢查**：`VITE_API_BASE_URL=http://localhost:8000 pnpm --filter frontend exec vite build --outDir <暫存目錄>`，`grep` 輸出找不到 `/dev/health`、`/dev/gallery`、`DEV ONLY`、「系統健康檢查」、`msw`、`faker`；`vite preview --outDir <暫存目錄> --port 4173`，後端 `CORS_ALLOWED_ORIGINS=http://localhost:4173`，開 `http://localhost:4173/` 與 `/dev/health` 都回登入頁，Network 只有一次 `GET current-session`（加一次回 `401` 的延續）；登入後只導覽到落點一次
