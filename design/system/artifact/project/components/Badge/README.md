帶框的小標籤，標示任務狀態、使用者角色或任務型別；只用來看，不能點。

## 何時使用

- 任務清單、詳細頁上標示任務目前的狀態。
- 成員列表標示角色（審核員）。
- 標示任務屬於哪一種標註型別。
- 填答狀態（已提交、已儲存、未開始）不用 Badge，用 Status Pill，兩者是不同的元件。

## 結構與使用方提供的內容

- `.badge` 加一個語意類別；內容是一個短詞。
- 型別 badge 另外載入 `task-type-badge.css`，而且必須排在 `.badge` 之後：`.badge` 的 `border` 簡寫會把 `border-color` 重設掉。

## 變體

**任務狀態**

| 類別 | 文案 |
| --- | --- |
| `draft` | 草稿 |
| `dry-run-status` | 試標中（顏色寫死） |
| `iaa` | 審核中 |
| `in-progress` | 進行中 |
| `completed` | 已完成 |
| `error` | 已退回 |

**角色**：`.badge-role`，膠囊形，主色。

**任務型別**（`task-type-badge.css`）：單一標籤、單維度、序列標註、關係識別、自由文字、其他。六種型別共寫死 36 個顏色值，另有一組暗色主題值（G-02）。

## 狀態

- 靜態，沒有 hover、focus、disabled。
- 暗色主題下，任務狀態與角色 badge 透過 token 自動換色；型別 badge 用自己的暗色組。

## 該做／不該做

- 該做：文案用資料裡的固定詞，不自創同義詞。
- 該做：顏色之外還有文字，讓色弱使用者也能分辨。
- 不該做：把 Badge 做成可點的篩選器；需要可點的標籤用 Chip。
- 不該做：在各頁再寫一份 `.badge`（現況各頁各自重做，不要擴大）。
- 不該做：為新的型別直接加寫死色；先回報 G-02。
