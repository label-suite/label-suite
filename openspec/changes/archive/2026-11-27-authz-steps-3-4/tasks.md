# Tasks

依相依順序排列：系統管理組的資料表與遷移 → 共用層的白名單與授權判斷 → `admin` 的矩陣提供者、組裝與整合測試 → 關鍵路徑清單與架構文件。每個群組單獨提交後都能 build 並通過自己的測試。測試與實作在同一個 task（TDD，architecture §測試分層）；Python 以 `uv`、JavaScript 以 `pnpm` 執行，不用 `pip install` 或 `npm install`。行為以 `specs/` 為準，做法以 `design.md`、`system-design.md` 為準，錯誤契約以 `api-contract.md` 為準；本次沒有新增或修改端點，前後端產生的契約都不應變動。

每個 `.py` 檔在 400 行內（`backend/tests/unit/test_size_limits.py`）；測試照 design D9 的檔案切分，接近上限時再拆新檔，不加豁免。

兩種資料庫的後端測試指令（`openspec/config.yaml`，在 `backend/` 執行）：SQLite 為 `uv run pytest`（回報 skipped 數量），PostgreSQL 為 `TEST_DATABASE_URL=postgresql+asyncpg://... uv run pytest`（應為 0 skipped）。

契約漂移檢查指令（`openspec/config.yaml`，在 repo 根目錄執行）：

- 後端：`cd backend && uv run python -m app.scripts.export_openapi && git diff --exit-code -- openapi.json ../docs/diagrams/architecture/api.openapi.json && test -z "$(git status --porcelain -- openapi.json ../docs/diagrams/architecture/api.openapi.json)"`
- 前端：`pnpm --filter frontend api:generate && git diff --exit-code -- frontend/src/api/generated && test -z "$(git status --porcelain -- frontend/src/api/generated)"`
