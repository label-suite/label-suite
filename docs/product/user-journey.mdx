# 使用者旅程

這份文件畫的是 :ref[專案負責人]{id="term.project-leader"} 現在用 Label Studio 加上自己寫的程式走完一次標記的經驗，並附上把它填起來的訪談大綱。它不畫 :ref[標記員]{id="term.annotator"} 與 :ref[審核員]{id="term.reviewer"} 的旅程，也不改 PRD；痛點與目標的說法以 [PRD §專案概述](../specs/00-prd.mdx#專案概述) 為準。

:::warning{title="目前是骨架"}
所有內容格都是「待訪談」，還沒有任何受訪者的回饋。七個階段是依 [PRD 第一個目標](../specs/00-prd.mdx#目標) 的流程推出的提案，不是訪談結果，訪談前後都可以調整。
:::

## 旅程圖

旅程分七個階段，每個階段有五層內容，最後一列是從各階段得出的洞見，標出它預計對應的 PRD 目標。目標代號 G1～G6 依 [PRD §目標](../specs/00-prd.mdx#目標) 表格的順序，和 [產品路線圖](roadmap.mdx#目標) 相同。

## 訪談設計

訪談要回答的是：專案負責人現在走完一次標記時，每個階段做了什麼、碰到什麼、感覺如何。這一節可以直接當訪談大綱用。

### 對象

實驗室裡做過標記的研究人員，而且至少負責設定過一次標記任務，也就是在那次任務裡擔任專案負責人的角色。只當過標記員的人不在這次的對象內，因為這張圖畫的是專案負責人的旅程。受訪人數與招募方式未決，見 [§待決](#待決) 第 1 列。

### 進行方式

一對一進行，請受訪者回想**最近一次完整做完的標記任務**，照時間順序講。

1. 開始前取得錄音同意，說明這是了解現況，不是評估受訪者
2. 先請受訪者用一兩句話說那次任務在標什麼、用了哪些工具、有幾個人參與
3. 依七個階段逐一問 [§每個階段都問](#每個階段都問) 與該階段的問題；受訪者沒經過某個階段就記「沒有經過」，不硬問
4. 受訪者的實際順序和七個階段不同、或多出一個階段時，照受訪者的說法記，事後再決定要不要調整階段
5. 結束前問：整個過程裡最想改掉的是哪一件事

### 紀錄方式

每個階段的五層都依下表記錄；原話一律保留逐字稿的出處，摘要和原話分開寫。

| 層 | 記什麼 | 怎麼記 |
| :--- | :--- | :--- |
| 行為 | 受訪者在這個階段實際做了哪些事 | 動詞開頭的條列，照發生順序 |
| 接觸點 | 用到的工具、檔案、文件與找過的人 | 名詞條列，工具寫名稱，自己寫的程式寫用途 |
| 受訪者原話 | 能代表這個階段經驗的原句 | 逐字引用，後面標受訪者代號與逐字稿時間點 |
| 情緒 | 受訪者在這個階段的整體感受 | -2 到 +2 的分數，請受訪者自己給，再記一句他給這個分數的原因 |
| 亮點與痛點 | 順利的地方與卡住的地方 | 分兩欄條列，每條連到它所根據的原話 |
| 洞見 | 從多位受訪者的同一階段歸納出的結論 | 訪談全部結束後才寫，一條洞見至少有兩位受訪者的原話支持，並標出對應的 PRD 目標 |

### 每個階段都問

這四題在每個階段都要問，分別對應行為、接觸點、情緒與亮點痛點。

1. 這個階段你做了哪些事？可以照順序講一次嗎？
2. 用了哪些工具、檔案，或找了誰幫忙？
3. 如果用 -2 到 +2 給這個階段的感受打分數，你會給幾分？為什麼？
4. 這個階段最順利、和最卡的地方各是什麼？

### 找工具與評估

- 這次為什麼選這些工具？還考慮過哪些？
- 決定之前花了多少時間了解或試用？

### 建任務與寫設定

- 把研究任務變成工具裡可以標的任務，經過哪些步驟？
- 設定有沒有需要請別人幫忙，或自己寫程式補？

### 試標

- 試標的資料怎麼挑、怎麼分給標記員？
- 試標結果出來之後，你怎麼決定下一步？

### 確認一致性

- 你怎麼知道標記員對規則的理解一致？用什麼方法算？
- 發現不一致的時候怎麼處理？

### 正式標記

- 正式標記期間，你怎麼知道進度與品質？
- 標記員遇到問題時，怎麼回報給你？

### 審核

- 誰負責審核？怎麼決定哪些結果要改？
- 審核的修改怎麼記下來？

### 匯出與分析

- 結果怎麼從工具拿出來？拿出來之後還要做哪些整理？
- 研究需要的統計是在哪裡算的？

## 填入訪談結果

訪談結果只填進 `.notecraft/components/user-journey-data.ts`，旅程圖自動跟著更新，本文與元件都不另寫一份。

| 要填的 | 改哪裡 |
| :--- | :--- |
| 五層內容 | 該階段的 `layers`，取代「待訪談」 |
| 情緒分數 | 該階段的 `emotion`，填多位受訪者的平均；全部階段都有分數後，虛線佔位就會變成實線 |
| 洞見與對應目標 | 該階段的 `insight` 與 `goals` |
| 增刪或改名階段 | `STAGES` 陣列，並同步改 [§訪談設計](#訪談設計) 的階段問題 |
