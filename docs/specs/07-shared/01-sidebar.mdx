# 07-01 側欄導覽

:badge[已定案]{variant="success"} :badge[變更 #249]{variant="info" href="https://github.com/label-suite/label-suite/issues/249"} :badge[共用介面]{variant="neutral"}

> 來源：舊 repo `specs/shared/008-sidebar-navbar-shared/spec.md`（100 條）、`specs/foundation/000-foundation/spec.md` 的 6 條業務規則（依 [搬移設計文件](../../development/spec-migration.md) 的 D4）
> 參考畫面：無獨立頁面，不嵌入 `PrototypeFrame`。側欄出現在每一個登入後頁面裡，畫面以 `design/prototype/pages/shared/sidebar.js` 與 `sidebar.css` 為準（[§已確認決議](#已確認決議) Q5）
> 相關規格：[規格 07-02 工作頁籤](./02-workspace-tabs.mdx)、[規格 06-01 使用者管理](../06-admin/01-user-management.mdx)

## 目標

- 提供每一頁都相同的側欄導覽，讓所有登入後的使用者不必重新學習就知道自己在哪個模組、還能去哪些模組
- 提供語言與外觀的快速切換，讓 :ref[平台成員]{id="term.platform-member"} 與 :ref[系統管理員]{id="term.system-admin"} 不必離開目前的工作就能調整
- 用導覽的可見性與進入條件，讓使用者不會走進自己沒有權限的頁面而撞上錯誤
- 提供 :ref[通知]{id="term.notification"} 入口，讓使用者看得到與自己有關的事情發生了

## 使用角色

:::tip{title="權限代號"}
R：Read（可讀取）　C：Create（可新增）　E：Edit（可編輯）　D：Delete（可刪除）　(o)：只限自己的資料　—：無權限
:::

側欄本身只有讀取與切換自己的偏好，沒有新增、編輯或刪除任何資料。

- :ref[平台成員]{id="term.platform-member"}：R；對自己的語言、外觀、側欄收合狀態與通知已讀狀態為 E (o)
- :ref[系統管理員]{id="term.system-admin"}：R／E (o)；同上，另外看得到「系統管理」導覽項
- :ref[Seeder 管理員]{id="term.seeder-admin"}：R／E (o)；與系統管理員相同
- 未登入的訪客：無權限；側欄只出現在登入後的頁面

PRD §權限矩陣目前給「07 共用介面」的上限是 R。上面的 E (o) 只作用在使用者自己的偏好與已讀狀態，不碰任何業務資料；
依 [§已確認決議](#已確認決議) Q1，PRD 會放寬到 `R／E (o)`，改動由 Issue #85 處理。

:ref[任務角色]{id="term.task-role"} 不影響導覽項的可見性，只影響「標記作業」與「資料集分析」能不能進去，見 [§進入模組的條件](#進入模組的條件)。

- **從側欄進入模組**
  - 觸發：使用者想從目前的頁面換到另一個模組
  - 前置條件：使用者已登入，側欄已顯示
  - 主流程：
    1. 使用者點側欄的導覽項 → 系統確認這個項目對這個使用者是否看得到
    2. 系統確認這個模組是否需要 :ref[任務角色]{id="term.task-role"} → 不需要就直接進入該模組的頁面
    3. 系統把該導覽項標成目前位置
  - 替代流程：
    - A1（第 1 步）使用者在桌機、側欄未收合時點「系統管理」→ 展開次選單，點「角色設定」直接進入角色設定頁，不經過使用者管理頁，回到第 3 步
    - A2（第 2 步）模組需要任務角色、使用者也有 → 進入該模組的頁面，回到第 3 步
  - 例外流程：
    - E1（第 1 步）這個項目對這個使用者看不到 → 側欄不顯示它，使用者點不到，流程結束（見 [§卡控機制](#卡控機制)）
    - E2（第 2 步）模組需要任務角色、使用者沒有 → 擋下進入；「標記作業」回到儀表板，「資料集分析」回到任務列表，並顯示說明，流程結束（見 [§進入模組的條件](#進入模組的條件)）
  - 結果：使用者停在新模組的頁面，側欄的目前位置指向該模組；被擋下時停在說明過的落點，不會留在錯誤頁

- **切換語言**
  - 觸發：使用者要把介面換成另一種語言
  - 前置條件：使用者已登入
  - 主流程：
    1. 使用者點語言切換 → 側欄與目前頁面的文字同時換成新語言
    2. 系統記住這個選擇 → 使用者之後進入任何一頁都用新語言
  - 替代流程：無
  - 例外流程：
    - E1（第 1 步）某個名詞缺少新語言的文字 → 該處顯示備用文字，其餘照常切換，流程結束（見 [§邊界情況（Edge Case）](#邊界情況edge-case)）
  - 結果：整個介面是同一種語言，重新整理或換頁都保持

- **登出**
  - 觸發：使用者要離開平台
  - 前置條件：使用者已登入
  - 主流程：
    1. 使用者點登出 → 系統結束這次的登入狀態
    2. 系統把使用者帶回登入頁
  - 替代流程：無
  - 例外流程：無
  - 結果：回到登入頁；原本的登入狀態失效，詳細規則見[規格 01-05 登入狀態與安全](../01-account/05-login-state.mdx)

## 規格

### 導覽項目與可見性

所有登入後的頁面都用同一套側欄，導覽項的清單、順序與名稱在每一頁都一樣。

1. 使用者進入任何登入後的頁面 → 側欄依序顯示：儀表板、任務管理、標記作業、資料集分析、系統管理（條件顯示）、個人設定
2. 使用者的 :ref[系統角色]{id="term.system-role"} 是平台成員 → 看到五個導覽項，沒有「系統管理」
3. 使用者的系統角色是系統管理員 → 看到六個導覽項，多出「系統管理」

4. 使用者在目前任務是 :ref[審核員]{id="term.reviewer"} → 第三個導覽項讀作「審核作業」
5. 使用者在目前任務是 :ref[專案負責人]{id="term.project-leader"} → 第三個導覽項讀作「例外處置」
6. 使用者在目前任務是 :ref[標記員]{id="term.annotator"}，或目前沒有任務角色 → 第三個導覽項讀作「標記作業」

- 導覽項對應的模組依 [規格總索引的模組地圖](../index.mdx)：儀表板對 02、任務管理對 03、標記作業對 04、資料集分析對 05、系統管理對 06、個人設定對 01-04
- 第三個導覽項的名稱依任務角色變化（[§已確認決議](#已確認決議) Q3），但它指向的模組不變，都是 04；切換語言時三個名稱各有對應的英文
- 使用者晶片上的角色標示也依任務角色解析：審核員讀作「審核員」、專案負責人讀作「專案負責人」、標記員讀作「標記員」、完全沒有任務角色時讀作「一般使用者」（[§已確認決議](#已確認決議) Q2）
- **頁面另有明確指定的角色標示時以該指定為優先**，不受上一條影響；例如系統管理的頁面固定顯示「系統管理員」（`shared:FR-020A` 明文保留這個覆寫入口）
- 「系統管理」展開的次選單子項（使用者管理、角色設定）不算在導覽項的數量裡，見 [§系統管理的次選單](#系統管理的次選單)
- 側欄的版面、圖示、顏色、使用者名稱與縮寫的呈現以 prototype 為準，不寫進規格

### 目前位置

使用者在任何一頁都看得出自己在哪個模組，包括模組底下的次層頁面。

1. 使用者停在某個頁面 → 側欄把該頁所屬的模組標成目前位置，而且全站同一時間只有一個
2. 使用者停在新增任務或任務詳情 → 目前位置是「任務管理」
3. 使用者停在資料集分析列表或資料集分析詳情 → 目前位置是「資料集分析」
4. 使用者停在使用者管理或角色設定 → 目前位置是「系統管理」
5. 系統管理員展開次選單、停在角色設定 → 次選單裡「角色設定」也標成目前項，與「系統管理」的目前位置並存，不互相取代

### 進入模組的條件

「標記作業」與「資料集分析」要有對應的任務角色才進得去；沒有的時候系統擋下並把使用者帶到一個講得通的落點。

1. 使用者點「標記作業」→ 系統確認使用者在目前的 :ref[任務]{id="term.task"} 是 :ref[標記員]{id="term.annotator"}、:ref[審核員]{id="term.reviewer"} 或 :ref[專案負責人]{id="term.project-leader"} → 是就進入標記清單
2. 使用者點「資料集分析」→ 系統確認使用者在目前的任務是 :ref[專案負責人]{id="term.project-leader"} 或審核員 → 是就進入資料集分析列表
3. 條件不成立 → 系統擋下，「標記作業」回到儀表板、「資料集分析」回到任務列表，並顯示說明
4. **第 3 條有一個例外**：使用者是從[規格 02-01 §還沒有任務角色的人看到什麼](../02-dashboard/01-dashboard.mdx#還沒有任務角色的人看到什麼)那三張行動入口卡進來的時候**不擋**，讓模組的入口頁自己顯示空狀態（[§已確認決議](#已確認決議) Q13）
5. 第 4 條只放寬**那三個入口**；從側欄點導覽項仍然照第 3 條擋下

- 「沒有任務角色」包含兩種：使用者在這個任務裡不是成員，或者目前沒有任何任務的上下文
- 第 4 條那個例外的理由：會看到那三張卡的人，定義上就是沒有任務角色的人；照第 3 條擋下的話，他在儀表板上按了按鈕又回到同一頁，什麼也沒發生
- 系統管理員如果在某個任務裡沒有任務角色，同樣進不去該任務的標記與分析
- 專案負責人進得去標記作業，但只處理審核員無法收斂的例外，不產出標記（PRD §權限矩陣與其條列）
- 點導覽項**不預選任何任務**：進到的是該模組的清單頁，由使用者在清單上挑一個任務（[§已確認決議](#已確認決議) Q6）

### 系統管理的次選單

系統管理員在桌機、側欄未收合時，可以從「系統管理」一次點到角色設定，不必先落在使用者管理。

1. 系統管理員點「系統管理」→ 展開次選單，內容恰為「使用者管理」與「角色設定」兩項
2. 系統管理員點「角色設定」→ 直接進入角色設定頁
3. 系統管理員再點一次「系統管理」、點次選單以外的地方，或按 `Esc` → 次選單收起
4. 次選單可以用鍵盤打開、移動與關閉，而且使用者看得出目前焦點在哪一項
5. 使用者在手機，或在桌機已把側欄收合 → 點「系統管理」直接進入使用者管理，不展開次選單

- 這個次選單是額外的直達入口，使用者管理頁內原有的分頁切換（見 [規格 06-01 §規格](../06-admin/01-user-management.mdx#規格) 的「存取與分頁切換」）照舊，不被取代

### 語言切換

使用者可以在側欄切換繁體中文與英文，整個介面一起換，而且換頁或重新整理都保持。

1. 使用者點語言切換 → 側欄的導覽項、次選單、通知清單、快捷鍵總覽、使用者角色標示全部換成新語言
2. 同時，使用者目前所在的模組頁面內容也換成新語言，不會只換側欄
3. 系統記住這個選擇 → 使用者進入任何一頁、或重新整理，都維持同一種語言
4. 圖示型的控制項（語言、外觀、通知、快捷鍵、登出）的說明文字也隨語言切換，讓只用鍵盤或讀螢幕的使用者拿到同一份資訊
5. 日期、時間與數字依目前語言呈現，不寫死某一種語言的格式

- 平台只提供繁體中文與英文兩種語言（PRD §範圍外排除第三種語言）
- 使用者**從來沒有切換過語言**時（含第一次登入）呈現繁體中文，不讀瀏覽者裝置的語言設定（[§已確認決議](#已確認決議) Q7）
- 時間顯示的時區依瀏覽者的裝置，與 [規格 06-01 §已確認決議](../06-admin/01-user-management.mdx#已確認決議) Q2 一致

### 外觀切換

使用者可以在側欄一鍵切換淺色與深色，立即生效並跨頁保持。

1. 使用者目前是淺色、點外觀切換 → 立即變成深色，控制項改為指向「切回淺色」
2. 使用者目前是深色、點外觀切換 → 立即變成淺色，控制項改為指向「切回深色」
3. 系統記住這個選擇 → 換頁或重新整理都維持
4. 控制項同一時間只呈現一個方向的提示，不會同時出現兩個外觀圖示

- :ref[外觀模式]{id="term.appearance-mode"} 有三種值：淺色、深色、跟隨系統；側欄只做淺色與深色的快速切換，三種值的完整設定在 [規格 01-04 個人設定](../01-account/04-profile.mdx)
- 「跟隨系統」**跟著使用者作業系統的設定變化**（[§已確認決議](#已確認決議) Q14 取代 Q10）

### 通知

使用者在側欄看得到有幾件未讀的事，點開可以看清單並一次全部標為已讀。

1. 使用者有未讀通知 → 通知入口顯示未讀的數量
2. 未讀數量超過九 → 顯示「9+」
3. 使用者沒有未讀通知 → 不顯示數量
4. 使用者點通知入口 → 展開通知清單，清單上有「全部標為已讀」
5. 使用者點「全部標為已讀」→ 未讀數量歸零、不再顯示
6. 每一則通知顯示發生了什麼事、相關的任務、是誰做的，以及多久以前發生（相對時間）
7. 使用者再點一次入口或點清單以外的地方 → 清單收起

- 通知清單不提供通知偏好設定的入口；偏好設定在 [規格 01-04 個人設定](../01-account/04-profile.mdx)
- 手機與桌機的未讀數量與展開狀態一致，不會一邊有一邊沒有
- **哪些事件會產生通知不由這一頁定義**：本頁只定義側欄看得到的部分（未讀數量、清單、全部標為已讀），通知的資料由所在頁面提供（[§已確認決議](#已確認決議) Q4）

### 快捷鍵總覽

桌機使用者可以查看目前頁面能用的快捷鍵；手機完全不提供這個入口。

1. 使用者在桌機、側欄未收合 → 側欄底部有快捷鍵總覽的入口
2. 使用者點該入口或按 `?` → 顯示目前頁面可用的快捷鍵清單
3. 使用者按 `Esc` 或點清單以外的地方 → 關閉
4. 使用者在桌機把側欄收合 → 快捷鍵入口隱藏，外觀與通知入口仍然看得到
5. 使用者在手機 → 沒有這個入口，按 `?` 也不會打開

- 清單只列跨任務共用的快捷鍵，不列某一種標記類型專屬的作答快捷鍵
- 每個動作各自一列，不把兩個動作併成一列（例如「上一筆」與「下一筆」要分開）
- 「審核」那一組只有「通過目前結果」與「退回目前結果」兩列，沒有整批通過或整批退回——一次審核只涉及一位標記員，沒有可以整批處理的對象
- 「頁籤」那一組列出切換頁籤、關閉作用中的頁籤、重開剛關閉的頁籤三列；這些快捷鍵按下去會發生什麼由 [規格 07-02 工作頁籤](./02-workspace-tabs.mdx) 定義，本節只規範總覽上列出什麼

### 登出

使用者在任何登入後的頁面、任何螢幕寬度、側欄展開或收合，都能從側欄登出。

1. 使用者點登出 → 結束這次的登入狀態，回到登入頁
2. 手機與桌機都有登出控制項，使用者在任何螢幕寬度都登得出去

- 登入狀態失效的詳細規則見[規格 01-05 登入狀態與安全](../01-account/05-login-state.mdx)

### 工作頁籤的位置

側欄同時承載 :ref[工作頁籤]{id="term.workspace-tabs"} 列。頁籤本身的行為由 [規格 07-02 工作頁籤](./02-workspace-tabs.mdx) 定義，本節只規範屬於側欄自己的焦點移動：

1. 使用者關閉作用中的頁籤，而它不是最右邊的 → 焦點移到原本緊鄰右邊的那個頁籤
2. 使用者關閉作用中的頁籤，而它是最右邊的 → 焦點移到原本緊鄰左邊的那個頁籤
3. 使用者關閉後已經沒有任何頁籤 → 沒有頁籤可以移焦，頁籤列顯示空狀態
4. 使用者關閉的不是作用中的頁籤 → 焦點與目前頁面都不變

### 不同螢幕寬度的呈現

使用者在手機、平板或桌機都拿到同樣的導覽能力。

1. 使用者在較寬的螢幕 → 左側固定側欄，含品牌、導覽項、底部的工具入口與使用者資訊
2. 使用者在較窄的螢幕 → 上方品牌列（含語言、外觀、通知與登出）加下方主導覽；品牌列不顯示使用者姓名，也沒有快捷鍵入口
3. 任何螢幕寬度下，頁面的主要內容不被導覽遮擋，文字不重疊也不被截斷到看不懂，而且不需要左右滑動
4. 每個控制項都能用鍵盤操作，而且使用者看得出目前焦點在哪裡

- 具體的螢幕寬度分界、尺寸與間距以 prototype 為準，不寫進規格

### 側欄收合

桌機使用者可以把側欄收成只有圖示，讓主要內容有更寬的空間。

1. 使用者在桌機點側欄的空白處 → 側欄在完整寬度與收合寬度之間切換
2. 使用者點導覽項、語言切換或登出 → 只執行那個功能，不會順便收合
3. 系統記住收合狀態 → 使用者換頁或重新整理都維持
4. 使用者在手機 → 不提供收合，維持上方品牌列加下方主導覽

- 收合後導覽項仍看得出是哪個模組，目前位置也仍然看得見

### 資料欄位

:::note{title="資料規劃入口"}
這一頁的「資料欄位」已在[資料欄位盤點總帳](../../diagrams/architecture/data-field-inventory.mdx#07-01-側欄)逐列分類過（要不要存、存在哪一層）。字典裡**沒有任何一張表把本頁列為規格來源**，所以這裡沒有表清單；全站的候選表與關聯見[候選資料表字典](../../diagrams/architecture/data-table-dictionary.mdx)與 [ER 圖](/view/diagrams/architecture/database-schema.er)。

**那是候選規劃，不是已落地的資料庫**；而且規格是它的依據，兩邊不一致時以規格為準（共用表的權威頁寫在字典各組開頭）。
:::


側欄自己不持有業務資料，只讀取與記住使用者的偏好。

| 欄位 | 型別 | 必填 | 規則 | 使用者看到 |
| :--- | :--- | :--- | :--- | :--- |
| 語言 | 單選：繁體中文、英文 | 是 | 沒設定過或值無效時為繁體中文（[§已確認決議](#已確認決議) Q7） | 側欄的語言切換；整個介面的文字 |
| 外觀模式 | 單選：淺色、深色、跟隨系統 | 是 | 沒設定過或值無效時當成「跟隨系統」，**而「跟隨系統」讀作業系統的設定**（[§已確認決議](#已確認決議) Q14） | 側欄只做淺色與深色的一鍵切換；三種值的完整設定在 [規格 01-04 個人設定](../01-account/04-profile.mdx) |
| 側欄收合狀態 | 是／否 | 是 | 只在桌機生效；沒設定過時為展開 | 側欄是完整寬度還是只有圖示 |
| 未讀通知數量 | 整數，零或正整數 | 是 | 超過九顯示「9+」；零不顯示 | 通知入口上的數量，只有本人看得到 |
| 使用者姓名與角色標示 | 文字 | 是 | 角色標示依任務角色解析：審核員／專案負責人／標記員／一般使用者（[§已確認決議](#已確認決議) Q2） | 側欄的使用者資訊，只顯示給本人 |

## 卡控機制

| 條件 | 結果 |
| :--- | :--- |
| 使用者的系統角色是平台成員 | 側欄不顯示「系統管理」，使用者點不到 |
| 使用者在目前任務不是標記員、審核員，也不是專案負責人，**而且是從側欄點導覽項進來的** | 擋下進入標記作業，回到儀表板並顯示說明 |
| 承上，但使用者是**從儀表板行動入口卡**進來的 | **不擋**；讓標記作業的入口頁自己顯示空狀態（[§進入模組的條件](#進入模組的條件)第 4 條） |
| 使用者在目前任務不是專案負責人也不是審核員 | 擋下進入資料集分析，回到任務列表並顯示說明 |
| 同一頁同時有兩個以上導覽項想標成目前位置 | 只標一個，依 [§目前位置](#目前位置) 的模組對應 |
| 使用者在手機 | 不提供快捷鍵總覽入口，按 `?` 也不開啟 |
| 使用者在桌機已收合側欄 | 隱藏快捷鍵入口，保留外觀、通知與登出入口；使用者姓名不佔用登出的位置 |
| 使用者在手機或已收合側欄時點「系統管理」 | 不展開次選單，直接進入使用者管理 |
| 系統要向使用者顯示錯誤 | 只顯示使用者看得懂的說明，不出現系統內部的資料結構、路徑或原始錯誤內容 |

## 邊界情況（Edge Case）

| 情況 | 使用者看到什麼 |
| :--- | :--- |
| 某個導覽項在新語言下的文字特別長 | 文字仍然看得懂，不被截斷到無法辨識 |
| 某個名詞缺少目前語言的文字 | 該處顯示備用文字，導覽照常可以點，不會中斷 |
| 外觀模式記住的值不是三種之一 | 當成「跟隨系統」處理，**依作業系統的設定呈現**，不出現錯誤畫面 |
| 使用者在深色下重新整理 | 載入時不會先閃一下淺色畫面，一開始就是深色 |
| 使用者在作業系統關閉了動態效果 | 側欄收合、次選單展開與通知清單展開都不播動畫，操作本身照常可用 |
| 使用者的系統角色在側欄開著的時候被改掉 | 側欄維持原本的導覽項，從使用者下一次操作起才依新角色顯示（與 [規格 06-01](../06-admin/01-user-management.mdx) 一致） |
| 從來沒設定過外觀 | 當成「跟隨系統」處理，**依作業系統的設定呈現** |
| 從來沒設定過語言 | 呈現繁體中文，不讀裝置的語言設定 |
| 未讀通知數量為零 | 不顯示數量 |
| 未讀通知數量超過九 | 顯示「9+」 |
| 通知清單載入失敗 | 入口仍可點，清單顯示載入失敗的說明，不影響其他導覽 |
| 使用者觸發需要等待的操作 | 很短的時間內就看到進行中的提示，不會以為沒反應 |
| 手機的下方主導覽與頁面的主要操作重疊 | 主要操作不被遮擋，使用者點得到 |
| 關閉後已經沒有任何工作頁籤 | 頁籤列顯示空狀態，沒有焦點要移動 |
| 使用者只用鍵盤操作側欄 | 可以走到每一個控制項，而且看得出目前焦點在哪裡 |

## 驗收標準

| Scenario | Given | When | Then |
| :--- | :--- | :--- | :--- |
| 平台成員看不到系統管理 | 以平台成員登入 | 查看側欄導覽項 | 顯示五項，沒有「系統管理」 |
| 系統管理員看到系統管理 | 以系統管理員登入 | 查看側欄導覽項 | 顯示六項，含「系統管理」 |
| 審核員看到審核作業 | 使用者在目前任務是審核員 | 查看第三個導覽項 | 讀作「審核作業」，且與標記工作區的入口麵包屑第一層一致 |
| 專案負責人看到例外處置 | 使用者在目前任務是專案負責人 | 查看第三個導覽項 | 讀作「例外處置」 |
| 標記員看到標記作業 | 使用者在目前任務是標記員 | 查看第三個導覽項 | 讀作「標記作業」 |
| 標記員的角色標示讀作標記員 | 使用者在目前任務是標記員 | 查看使用者晶片的角色標示 | 讀作「標記員」 |
| 沒有任務角色時角色標示讀作一般使用者 | 使用者不在系統管理的頁面，而且在目前任務沒有任何任務角色 | 查看使用者晶片的角色標示 | 讀作「一般使用者」 |
| 系統管理頁的角色標示不被任務角色蓋掉 | 系統管理員停在系統管理的頁面，而且在目前任務沒有任何任務角色 | 查看使用者晶片的角色標示 | 讀作「系統管理員」，不是「一般使用者」 |
| 角色標示切換語言後也換 | 使用者在目前任務是標記員、語言為繁體中文 | 切換為英文 | 角色標示一起變成英文，不留中文 |
| 每頁只有一個目前位置 | 停在任一登入後頁面 | 查看側欄 | 恰有一個導覽項被標成目前位置 |
| 在任務詳情頁時任務管理是目前位置 | 停在任務詳情 | 查看側欄 | 目前位置是「任務管理」 |
| 在角色設定頁時系統管理是目前位置 | 系統管理員停在角色設定 | 查看側欄 | 目前位置是「系統管理」，次選單內「角色設定」也是目前項 |
| 沒有任務角色時點擊標記作業 | 使用者在目前任務沒有任何任務角色 | **從側欄**點「標記作業」 | 回到儀表板並顯示說明，沒有進入標記清單 |
| 從儀表板行動入口卡進入不被擋下 | 使用者沒有任何任務角色 | 按儀表板上卡 B 的 `開始標記` | 進到標記作業的入口頁，由那一頁顯示它自己的空狀態，**沒有**被退回儀表板 |
| 專案負責人進得去標記作業 | 使用者是目前任務的專案負責人 | 點「標記作業」 | 進入標記清單 |
| 點標記作業進到的是清單頁 | 使用者在目前任務是標記員，而且之前標記過 | 點「標記作業」 | 進入標記清單，沒有預先選定任何任務或輸出類型 |
| 沒有任務角色時點擊資料集分析 | 使用者在目前任務不是專案負責人也不是審核員 | 點「資料集分析」 | 回到任務列表並顯示說明，沒有進入資料集分析列表 |
| 展開系統管理次選單 | 系統管理員在桌機、側欄未收合 | 點「系統管理」 | 展開次選單，內容恰為「使用者管理」與「角色設定」 |
| 展開系統管理次選單直達角色設定 | 次選單已展開 | 點「角色設定」 | 直接進入角色設定頁，沒有經過使用者管理頁 |
| 按 Esc 關閉系統管理次選單 | 次選單已展開 | 按 `Esc` | 次選單收起 |
| 手機點擊系統管理直接進入使用者管理 | 系統管理員在手機 | 點「系統管理」 | 直接進入使用者管理，沒有展開次選單 |
| 切換語言後整頁一起換 | 使用者停在任一模組頁且語言為繁體中文 | 點語言切換 | 側欄與該頁內容同時變成英文 |
| 第一次登入預設繁體中文 | 使用者從來沒有切換過語言 | 第一次載入登入後頁面 | 介面是繁體中文 |
| 重新整理後語言保持 | 使用者已切換為英文 | 重新整理 | 仍然是英文 |
| 換頁後語言保持 | 使用者已切換為英文 | 換到另一個模組頁 | 仍然是英文 |
| 術語缺少翻譯時顯示備用文字 | 某個名詞沒有英文文字 | 切換為英文 | 該處顯示備用文字，其餘正常切換，導覽仍可點 |
| 切換外觀立即生效 | 目前是淺色 | 點外觀切換 | 立即變成深色，控制項改為指向切回淺色 |
| 重新整理後外觀保持 | 使用者已切換為深色 | 重新整理 | 仍然是深色 |
| 重新整理時不閃淺色 | 使用者目前是深色 | 重新整理 | 載入過程中不會先出現淺色畫面 |
| 外觀設定值無效 | 記住的外觀值不是三種之一 | 載入任一登入後頁面 | 當成跟隨系統、**依作業系統的設定呈現**，沒有錯誤畫面 |
| 跟隨系統依作業系統呈現 | 外觀設為跟隨系統，作業系統為深色 | 載入任一登入後頁面 | **呈現深色** |
| 從來沒設定過外觀 | 使用者從未切換過外觀 | 第一次載入登入後頁面 | 當成跟隨系統、**依作業系統的設定呈現** |
| 關閉動態效果時不播動畫 | 使用者在作業系統關閉了動態效果 | 收合側欄或展開次選單 | 不播動畫，操作本身照常可用 |
| 角色被改掉時側欄不立刻變 | 使用者的系統角色在側欄開著的時候被改掉 | 繼續停在目前頁面 | 側欄維持原本的導覽項，從下一次操作起才依新角色顯示 |
| 每一則通知顯示發生了什麼 | 使用者有未讀通知 | 展開通知清單 | 每一則都看得到事件、相關任務、是誰做的與多久以前 |
| 沒有未讀通知 | 使用者沒有未讀通知 | 查看通知入口 | 不顯示數量 |
| 未讀通知數超過九 | 使用者有十二則未讀通知 | 查看通知入口 | 顯示「9+」 |
| 全部標為已讀 | 使用者有未讀通知且通知清單已展開 | 點「全部標為已讀」 | 未讀數量歸零、不再顯示 |
| 載入通知失敗 | 通知清單無法載入 | 點通知入口 | 顯示載入失敗的說明，其他導覽不受影響 |
| 桌機開啟快捷鍵總覽 | 使用者在桌機、側欄未收合 | 按 `?` | 顯示目前頁面可用的快捷鍵清單 |

### Q2. 使用者角色標示對標記員要顯示哪一個名詞？（已定案，維護者裁定 2026-11-08）

- [x] 標記員讀作「標記員」（en: `Annotator`）；**完全沒有任務角色**時讀作「一般使用者」（en: `General user`）

## Q&A

:::tip{title="為什麼平台成員不是「看得到但點不進去」，而是完全看不到「系統管理」？" collapsible}
看得到卻點不進去會讓使用者以為自己該有這個權限、只是壞了。直接不顯示，使用者的心智模型就只有「我有的功能」，不會去追一個永遠打不開的入口。
:::

:::tip{title="為什麼進不去標記作業要回到儀表板，資料集分析卻回到任務列表？" collapsible}
兩個落點都要能讓使用者繼續往下走。標記作業是「我該做什麼」的起點，儀表板本來就彙整這個；資料集分析要先選一個任務，任務列表才是能挑任務的地方。回到使用者接下來真的會用的那一頁，而不是一律丟回首頁。
:::

:::tip{title="為什麼「跟隨系統」改成真的跟著作業系統？" collapsible}
舊規格把「跟隨系統」解析成平台預設的淺色，不讀作業系統的設定——那會讓三個選項裡的第三個和「淺色」**行為完全一樣**，使用者選了也看不出差別。那條決定（Q10）自己就寫了「規格 01-04 個人設定落地時重新確認一次」，而 01-04 就是外觀偏好三個選項真正落地的地方。2026-11-09 重新確認的結果是跟著作業系統，三個選項因此真的有三種行為。
:::

:::tip{title="為什麼側欄收合後快捷鍵入口會不見，外觀與通知卻留著？" collapsible}
收合後只剩圖示的寬度，三個入口擠在一起會變得難點。快捷鍵總覽是輔助查詢、不常用，外觀與通知是隨時可能要用的，所以保留後兩個。
:::
