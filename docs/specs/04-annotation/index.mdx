## Logic Flow

標記作業模組只有兩頁：挑一筆的標記清單、動手做的標記工作區。兩頁之間只有兩個方向——挑一筆或走快速入口把人送進工作區，工作區完成、查不到東西或使用者主動返回時把人送回清單；麵包屑第 1 層與側欄則隨時把兩頁的人都送回儀表板。依規格 04-01，專案負責人不走清單，入口是任務詳情頁的最終例外池，單向進工作區處置例外；規格 07-01 說法相反，側欄的「標記作業」把專案負責人也放進標記清單，所以圖上的 D8 照 07-01 列出三種角色。本節不裁定，見下方的缺口二。從儀表板行動入口卡進來的人在標記清單上看到哪一種畫面，兩份規格也說法相反，同樣不裁定，見下方的缺口三。

這一節只畫頁面之間怎麼走，以及決定往哪一頁走的判斷；同一頁裡的操作細節（例如審核卡、仲裁版面、例外處置畫面怎麼呈現）看規格 04-02 自己的業務流程與規格內文。連線依方向分三類判：離開本模組一律畫，進入與返回只在本模組自己的規格定了那個入口、或定了「回來之後這一頁顯示什麼」時才畫，模組內兩頁之間的移動本來就要畫。每一條連線都對回規格的條文，規格裡找不到出處的連線不畫，理由逐條寫在下方的缺口摺疊區塊；唯一沒有規格出處的是起訖連線（S 接上的那一條），它只標出流程從哪裡開始。這個模組沒有 E 結束節點：使用者在標記清單與標記工作區之間來回，工作區完成、查不到東西或使用者主動返回都送回清單，清單頁另有回儀表板的出口（沒帶任務或任務查不到時靠頁內入口），但那是離開，不是兩頁來回的終點。

### 節點

同一個節點出現在不同分段時用同一個編號。

- 起訖
  - S 開始：使用者直接貼一個深連結進入工作區
- 頁面（矩形）
  - P1 [04-01 標記清單](./01-annotation-list.mdx#業務流程)
  - P2 [04-02 標記工作區](./02-annotation-workspace.mdx#業務流程)
- 判斷（菱形）
  - D1 網址有帶任務嗎？
  - D2 任務查得到嗎？
  - D3 網址有帶要處理的那一筆嗎？
  - D4 那一筆查得到嗎？
  - D5 任務設定查得到已發布的那一份嗎？
  - D6 任務查得到已發布的設定嗎？（快速入口）
  - D7 有可處理的審核單位嗎？（審核員快速入口）
  - D8 在目前任務是標記員、審核員或專案負責人嗎？（側欄導覽項的卡控）
- 其他流程或外部系統（雙邊框）
  - X1 [07-01 側欄導覽](../07-shared/01-sidebar.mdx#業務流程)
  - X2 [02-01 儀表板](../02-dashboard/01-dashboard.mdx#業務流程)

### 分段一：進入清單

1. X1 → D8（側欄點「標記作業」，系統先確認任務角色；07-01 §進入模組的條件 第 1 條；04-01 §開清單 觸發）
2. D8 否 → X2（系統擋下，「標記作業」回到儀表板並顯示說明；從側欄點導覽項不適用第 4 條的放寬；07-01 §進入模組的條件 第 3、5 條；07-01 §驗收標準「沒有任務角色時點擊標記作業」）
3. D8 是 → D1（進入標記清單；07-01 §進入模組的條件 第 1 條；04-01 §開清單 主流程第 1～2 步）
4. X2 → D1（儀表板任務列的非快速區點進來；04-01 §開清單 觸發；§兩種入口並存 第 2 條）
5. X2 → P1（儀表板「還沒有任務角色」版面的行動入口卡 B「開始標記」或卡 C「開始審核」點進來，不被任務角色擋下，去的是標記模組的入口頁；他在這一頁看到哪一種畫面見下方的缺口三；02-01 §還沒有任務角色的人看到什麼 第 2、3、7 條；02-01 §驗收標準「三張卡的按鈕都走到模組入口頁」；07-01 §進入模組的條件 第 4 條；07-01 §驗收標準「從儀表板行動入口卡進入不被擋下」；04-01 §兩種入口並存 第 1 條）
6. D1 否 → P1（顯示「未指定任務」與回儀表板的入口；04-01 §開清單 E1；§路由上下文與回退 第 6 條）
7. D1 是 → D2（04-01 §開清單 主流程第 3 步）
8. D2 否 → P1（顯示「找不到這個任務」與回儀表板的入口；04-01 §開清單 E2；§路由上下文與回退 第 7、8 條）
9. D2 是 → P1（顯示任務資訊卡與資料清單；04-01 §開清單 主流程第 3 步、結果）
10. P1 → X2（麵包屑第 1 層／回儀表板；04-01 §入口麵包屑 第 3、5 條；沒帶任務或任務查不到時麵包屑零個連結，回儀表板靠的是頁內入口，§入口麵包屑 第 8 條、§路由上下文與回退 第 6～8 條）

### 分段二：挑一筆進工作區

1. P1 點某一筆 → D3（標記員點清單裡的某一筆；04-01 §在清單裡挑一筆進工作區 主流程第 1～2 步）
2. P1 點「編輯」或「仲裁」→ D3（審核員點那一列的動作按鈕；04-01 §每列的動作：編輯或仲裁 第 24、26、30 條）
3. P1 點「尚未提交」說明列入口 → D3（審核員點它，不帶標記員身分；04-01 §沒有人提交的樣本 第 36～38 條）
4. P1 點試標回饋的有效引用連結 → D3（帶到該樣本並定位指南段落；04-01 §試標歷史回饋 第 5、6 條）
5. S → D3（起訖連線，無規格條文；04-02 §進入工作區 觸發的三個入口之一）
6. D3 否 → P1（導回標記清單；04-02 §進入工作區 E2；§進不來的時候：導回清單 第 3 條）
7. D3 是 → D4（04-02 §進入工作區 主流程第 3 步）
8. D4 否 → D5（回退到第一筆並把網址改寫成實際顯示的那一筆，接回設定檢查；04-02 §進入工作區 E3；§網址一直指向目前這一筆 第 7 條）
9. D4 是 → D5（04-02 §進入工作區 主流程第 3 步）
10. D5 否 → P1（導回標記清單，不得以任何預設的輸出類型或空白控制項呈現工作區；04-02 §進入工作區 E1；§進不來的時候：導回清單 第 1 條）
11. D5 是 → P2（載入樣本、說明檔案與進度，三欄就位；04-02 §進入工作區 主流程第 4 步）
12. P2 點說明彈窗的「返回標記清單」→ P1（不記下確認，下次進來照樣顯示彈窗；04-02 §指引閘門：第一次進來先讀說明 第 3 條）

### 分段三：快速續做與快速審核

1. X2 點「快速繼續／快速審核」→ D6（04-01 §從儀表板直接續做 觸發、主流程第 1～2 步）
2. P1 點任務資訊卡的「快速繼續／快速審核」→ D6（04-01 §在清單裡挑一筆進工作區 A1；§兩種入口並存 第 6 條）
3. D6 否 → P1（那個任務查不到已發布的設定，導回標記清單；04-01 §從儀表板直接續做 E1）
4. D6 是、而且是標記員 → P2（帶著最新未完成的那一筆直接進入工作區；04-01 §從儀表板直接續做 主流程第 3 步；§兩種入口並存 第 4、5 條）
5. D6 是、而且是審核員 → D7（目標改成下一個可處理的審核單位；04-01 §從儀表板直接續做 A1；§沒有可處理的審核單位 第 76～80 條）
6. D7 是 → P2（進到工作區時落在那個可處理單位；04-01 §沒有可處理的審核單位 第 78～80 條）
7. D7 否 → P1（導回清單，不帶樣本，顯示「沒有可處理」的空狀態；04-01 §沒有可處理的審核單位 第 82～87 條）

### 分段四：作業完成後的去向

1. P2 → P1（標記員提交成功、任務全部已提交，自動導回清單，那一筆顯示為已提交；04-02 §提交之後往哪 第 2、3 條）
2. P2 → P1（審核員或仲裁送出成功、這次送出沒有讓單位定稿、而且這個任務已經沒有可處理的單位，自動導回清單並帶「已無可處理單位」的提示；讓單位定稿的那一次送出必須停在原單位、不導頁；04-02 §審核員送出之後往哪 第 1、2、9、11 條）
3. P2 → P1（定稿卡剩餘量為 0 時，使用者主動點那顆唯一的回清單連結；04-02 §定稿卡上的剩餘可處理量與歸零去向 第 11～13 條）
4. P2 → P1（側欄的「標記作業」連結、或麵包屑第 2 層，逐字沿用或轉發檢視狀態與身分；04-02 §提交之後往哪 第 4 條；§入口麵包屑的第三層 第 5、6 條）
5. P1 → X2（麵包屑第 1 層；04-01 §入口麵包屑 第 3 條）
6. P2 → X2（麵包屑第 1 層；04-02 §入口麵包屑的第三層 第 1 條）

### 分段五：專案負責人的例外處置入口

1. X3 → P2（專案負責人在任務詳情的最終例外池，點某一項的「進入處置畫面」，帶著完整的審核單位身分與爭議項識別；03-03 §最終例外池 第 6 條；04-02 §最終例外池是最後一道出口、§例外處置畫面的外殼）
2. P2 → X2（麵包屑第 1 層在例外處置時顯示「例外處置」，仍連儀表板；04-02 §入口麵包屑的第三層 第 1 條）

<details>
<summary>缺口：規格裡找不到出處、所以沒畫的連線</summary>

- **缺口一**：專案負責人在最終例外池的處置畫面，把全部待處置例外項收尾完之後，或中途想離開時（麵包屑第 1 層回儀表板以外），去向沒有規格條文。04-02 §最終例外池是最後一道出口、§例外處置畫面的外殼都沒有寫「全部收尾後導向…」；03-03 §最終例外池也只寫「每一列提供進入處置畫面的動作」，沒有寫返程。
- **缺口二**：專案負責人進不進得了標記清單，兩份規格說法相反。**本頁不裁定，待維護者決定。**
  - 07-01 §進入模組的條件 第 1 條把專案負責人列為「是就進入標記清單」的三種任務角色之一；同一節的條列另有一句「專案負責人進得去標記作業，但只處理審核員無法收斂的例外，不產出標記」；07-01 §驗收標準 的 Scenario「專案負責人進得去標記作業」也把 Then 寫成「進入標記清單」。
  - 04-01 §使用角色 那張表給專案負責人的是「進不了這一頁」，底下的條列也寫「這一頁的作用角色只有標記員與審核員兩種」；04-01 §已確認決議 Q1（維護者 2026-11-08 裁定）勾的就是「進不了」那一個選項。
  - 同一個矛盾的第二個表現在 04-02 §入口麵包屑的第三層：第 1 條那張表的第 1 層字面已經涵蓋「專案負責人處理例外時」，而第 2 層「任務」一律連到標記清單、**沒有依角色分流**（第 2 條只分流第 3 層）。嚴格讀起來，專案負責人在例外處置時也有一條第 2 層回標記清單的線，這同樣撞到 04-01 §已確認決議 Q1。
  - 本節的處理：分段一的 D8 照 07-01 §進入模組的條件 第 1 條的原文列出三種角色，不改寫成兩種；分段五只畫麵包屑第 1 層回儀表板，不畫第 2 層回標記清單。哪一邊才對由維護者決定。
- **缺口三**：從儀表板三張行動入口卡進到標記清單的人（沒有任務角色、網址也不帶任務）在這一頁看到什麼，兩份規格說法相反。**本頁不裁定，待維護者決定。**
  - 02-01 §還沒有任務角色的人看到什麼 第 7 條說卡片「都是真的入口，分別去各自模組的入口頁；沒有任務可做時由那一頁顯示自己的空狀態，不在這一頁先擋」；第 8 條指出這需要 07-01 §進入模組的條件 網開一面，而 07-01 §進入模組的條件 第 4 條（§已確認決議 Q13，維護者 2026-11-09）確實補上了那條例外。
  - 04-01 §開清單 的 `觸發` 沒有列入行動入口卡；`前置條件` 仍要求「使用者已登入，而且在這個任務裡有標記員或審核員的角色」；`E1` 把「網址沒帶任務」的落點定成「未指定任務」與回儀表板的入口；`結果` 還明寫那個畫面「**不是一張空白清單**」。
  - 側欄導覽項是同一型的落差，而且更常走：07-01 §進入模組的條件 的條列寫「點導覽項**不預選任何任務**：進到的是該模組的清單頁，由使用者在清單上挑一個任務」（07-01 §已確認決議 Q6），07-01 §驗收標準 的 Scenario「點標記作業進到的是清單頁」也把 Then 寫成「進入標記清單，沒有預先選定任何任務或輸出類型」。照這兩條，分段一第 3 條的 `D8 是 → D1` 一定走到 `D1 否`，落點就是 04-01 §開清單 E1 與 §路由上下文與回退 第 6 條的「未指定任務」錯誤頁，而 04-01 §開清單 的 `結果` 明寫那不是一張空白清單。一併交維護者裁定。
