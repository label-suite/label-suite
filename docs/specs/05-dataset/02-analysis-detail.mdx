## 目標

| 目標 | 誰受益 |
| :--- | :--- |
| 讓:ref[專案負責人]{id="term.project-leader"}與:ref[審核員]{id="term.reviewer"}在**同一個任務上下文**底下對照看統計與品質，不必在兩個頁面之間來回帶著任務代號 | 兩種角色——分開成兩頁的話，每次切換都要重新確認「我現在看的是哪個任務」 |
| 讓從儀表板的「:ref[IAA]{id="term.iaa"} 待確認」提醒點進來的人**直接落在品質監控**，不必再自己切一次 | 被提醒叫來做品質決定的專案負責人 |
| 讓網址**一個連結就說完「哪個任務、哪個分頁」**，重新整理與分享都還在原處 | 需要互相對照同一個畫面的人 |
| 讓**切換分頁不打斷閱讀**：各自的捲動位置分開記 | 在長表格裡逐列比對的審核員 |
| 讓這一頁**只讀、碰不到任何答案內容** | 整個標記品質管線——分析頁若能讀到標準答案，測試集保護就破了 |

## 使用角色

:::tip{title="權限代號"}
R：Read（可讀取）　C：Create（可新增）　E：Edit（可編輯）　D：Delete（可刪除）　(o)：只限自己的資料
:::

| 角色 | 這一頁能做什麼 | PRD §權限矩陣的上限 |
| :--- | :--- | :--- |
| :ref[專案負責人]{id="term.project-leader"} | R | 「05 資料集分析」給專案負責人 `R` |
| :ref[審核員]{id="term.reviewer"} | R | 同一列給審核員 `R` |
| :ref[標記員]{id="term.annotator"} | **進不來** | 同一列給標記員 `—` |

- 這一頁**完全唯讀**，沒有任何新增、編輯或刪除；畫面上唯一會改變資料的入口在[規格 03-03 任務詳情](../03-task-management/03-task-detail.mdx)，由階段四的建議行動導過去
- 能不能進來，**只看使用者在那一個任務的:ref[任務角色]{id="term.task-role"}**：任務角色是專案負責人或審核員才進得來
- 進來之後，**兩個分頁各有一道自己的任務層級權限**：統計總覽的資料讀取要「**看任務統計**」、品質監控的資料讀取要「**看品質分析**」。這兩個名字由[規格 05-01](./01-analysis-list.mdx#使用角色)定名，這一頁沿用
- 這一頁不是作業頁，所以兩道權限都取使用者在**那一個任務**各個**生效**成員身分的允許聯集；**受邀但還沒生效的成員身分視同不存在**
- 這兩項權限是 PRD §權限矩陣「05 資料集分析」那一格的**細化、不放寬**（依 `spec-migration.md` 的 D10）；種子設定只開給專案負責人與審核員，與上一條的任務角色條件一致，所以上線初期**兩道條件的結果相同**
- :ref[系統管理員]{id="term.system-admin"}沒有任務角色時進不來，和[規格 05-01](./01-analysis-list.mdx#使用角色)、[規格 03-03](../03-task-management/03-task-detail.mdx) 一樣

### 進入某個任務的分析詳情

- 觸發：使用者從[規格 05-01 分析列表](./01-analysis-list.mdx#點任務列進入分析詳情)點任務列，或從儀表板的「IAA 待確認」提醒點進來
- 前置條件：使用者已登入
- 主流程：
  1. 系統驗**任務代號**與**成員資格** → 兩者都過才繼續
  2. 系統載入**任務上下文**：任務代號、任務名稱、任務的輸出類型清單 → 上下文就位
  3. 系統依**網址上的分頁參數**決定落在哪個分頁 → 統計總覽或品質監控
  4. 系統渲染**共用外殼**：頁首、麵包屑、分頁列 → 兩個分頁共用這一層
  5. 系統顯示該分頁的內容 → 依該分頁自己的狀態顯示載入中、空、就緒或錯誤
- 替代流程：
  - A1（第 3 步）沒帶分頁參數，或參數不是兩個合法值之一 → 落在**統計總覽**，回到第 4 步
- 例外流程：
  - E1（第 1 步）任務代號不存在，或使用者在那個任務沒有專案負責人或審核員的成員資格 → **導回分析列表**並顯示提示，流程結束（見 [§卡控機制](#卡控機制)）
  - E2（第 2 步）任務的輸出類型取不到、是空的、缺少、或含認不得的鍵 → 兩個分頁都顯示**可重試的錯誤**，外殼與分頁列仍在，流程結束（見 [§卡控機制](#卡控機制)）
- 結果：使用者停在某一個任務的某一個分頁上，網址同時說明了這兩件事

### 在同一頁換分頁

- 觸發：使用者點分頁列上的另一個分頁
- 前置條件：任務上下文已就位
- 主流程：
  1. 使用者點另一個分頁 → 系統先記住**目前分頁的捲動位置**
  2. 系統換掉顯示中的分頁與**選取狀態** → 只換內容，不離開這一頁
  3. 系統更新**網址上的分頁參數** → 連結可直接分享到這個分頁
  4. 系統**還原目標分頁上次的捲動位置** → 回到上次停下的地方
- 替代流程：
  - A1（第 4 步）目標分頁沒有上次的位置 → 從**頂端**開始，流程結束
- 結果：任務上下文沒有重建，網址指向新的分頁

## 規格

### 這一頁讀得到什麼、不得改什麼

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

這一頁是**一個任務的分析結果**，給專案負責人與審核員看。

1. 這一頁讀得到的，只有**聚合後的統計與品質指標**：筆數、比例、分布、一致性數值、排名、偏離次數
2. 這一頁**讀不到也不得顯示**任何一筆標記的**答案內容**，也不得顯示:ref[標準答案]{id="term.ground-truth"}；一致性最低樣本清單（階段四）只顯示樣本識別、分歧度數值與**文本摘要**，不顯示任何標記員填的答案
3. 這一頁**沒有任何編輯**：指標區與分析區全部唯讀
4. 這一頁**不是**[規格 03-03 任務詳情](../03-task-management/03-task-detail.mdx)。匯出對話框、匯出入口與匯出紀錄表都在那一頁；這一頁只定義**匯出時怎麼從標記推導出序列**（階段五）
5. 兩個分頁的內容分屬四個階段：統計總覽的逐型內容在階段二，品質監控的 IAA 報告在階段三，標記員與樣本層分析在階段四

### 兩個合法入口

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

這一頁只有兩個入口，而且**各自決定落在哪一個分頁**。

1. 從[規格 05-01 分析列表](./01-analysis-list.mdx#點任務列進入分析詳情)點任務列 → 進入**那個任務**的分析詳情，落在**統計總覽**
2. 從儀表板的「IAA 待確認」提醒點進來 → 進入那個任務的分析詳情，**直接落在品質監控**
3. 第 2 條是深層連結，它**必須把任務上下文一併載入**，不得只是切到分頁卻沒有資料
4. 品質監控除了第 2 條，也可以**從統計總覽切過去**
5. 這一頁的網址要同時說明**哪一個任務**與**哪一個分頁**：任務代號是網址的一部分，分頁由下面的分頁參數決定

### 進來先驗兩件事：任務代號與成員資格

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

不管從哪個入口進來，系統都先驗任務代號與成員資格，**過不了就不渲染任何內容**。

1. 任務代號**不存在** → 導回[分析列表](./01-analysis-list.mdx)並顯示提示
2. 使用者在那個任務**沒有專案負責人或審核員的成員資格** → 同樣導回分析列表並顯示提示
3. 上面兩種情況是**同一個觸發**，使用者看到的是**同一句提示**：`找不到指定的任務，或您沒有該任務的存取權限。`（英文：`The requested task could not be found, or you do not have access to it.`）
4. 第 3 條刻意不分辨「任務不存在」與「沒有權限」——分辨了就等於告訴外人這個任務存在
5. 提示由**分析列表那一頁顯示**（錯誤樣式的浮動提示），但**提示要不要出現是這一頁決定的**；這一頁導回去時要讓那一頁知道這是一次被擋下的進入
6. 任務角色**缺少或認不得**時一律視為第 2 條，**失敗即關閉**；不得退回成任何預設角色
7. 驗不過時**不得**悄悄換成某個預設任務再顯示出來

### 兩個分頁各有一道自己的權限

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

上一項過了只代表**進得來**；兩個分頁的**資料讀取**另外各有一道任務層級的權限。

1. 統計總覽的資料讀取要「**看任務統計**」；品質監控的資料讀取要「**看品質分析**」
2. 這兩道都**疊在**「任務角色是專案負責人或審核員」**之上**，不取代它
3. 權限取使用者在**那一個任務**各個**生效**成員身分的**允許聯集**
4. **受邀但還沒生效**的成員身分**視同不存在**，而且在**兩道判定裡都視同不存在**
5. 第 4 條的兩道判定**結果不同，不得混為一條**：

| 哪一道判定 | 什麼情況 | 結果 |
| :--- | :--- | :--- |
| 能不能**進來** | 去掉未生效的身分之後，**一個生效身分都不剩** | **進不來**，導回分析列表（見[§進來先驗兩件事](#進來先驗兩件事任務代號與成員資格)） |
| 某個分頁的**資料讀取** | 還有生效身分，但這些身分的允許聯集**不含那個分頁的權限** | 只**拒絕那一個分頁的資料讀取**，另一個分頁照常可讀 |

6. 匯出檔的下載另有一道「**匯出資料**」權限，種子設定只開給專案負責人；但匯出入口不在這一頁，在[規格 03-03](../03-task-management/03-task-detail.mdx)
7. 「看任務統計」與「看品質分析」兩項是 PRD §權限矩陣「**05 資料集分析**」那一格的**細化、不放寬**；「匯出資料」對應的是**另一格**——「**03 匯出標記結果**」（專案負責人 `C`），由[規格 03-03](../03-task-management/03-task-detail.mdx)承接，不在這一頁的那一格之內

### 頁首與麵包屑

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

頁首固定寫**頁面的用途**，任務名稱寫在麵包屑的第二段。

1. 頁首大標固定是 `任務詳情`（英文 `Task detail`），**不得用任務名稱取代**
2. 頁首副標固定是 `檢視統計總覽與品質監控`（英文 `Review statistics and quality monitoring`）
3. 麵包屑固定是 `資料集分析 › 〈任務名稱〉`（第一段英文 `Dataset Analysis`），第一段連回[分析列表](./01-analysis-list.mdx)
4. 麵包屑**放在頁首標題區塊的下方**，**不得放在大標前面**——放前面會把整個頁首往下推，與其他頁的標題基準線不齊
5. 語系切換時，麵包屑第二段要顯示**當前語系的任務名稱**
6. 第 1 條與第 2 條都隨語系切換

### 分頁列與網址上的分頁參數

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

分頁列只有兩個入口，切換是**頁內切換**。

1. 分頁列有兩個：`統計總覽`（英文 `Statistics`）、`品質監控`（英文 `Quality Monitor`）；同一時刻恰好一個是**選取**狀態
   - 英文的 `Statistics` 刻意**不是**「統計總覽」的直譯，**不得**自行補成 `Statistics Overview`
2. 切換是**頁內切換**，**不得**導向分析列表、也不得整頁重新載入
3. 網址上的分頁參數**只允許兩個值**，分別對應**統計總覽**與**品質監控**
4. **沒帶**分頁參數時一律落在**統計總覽**
5. 分頁參數不是那兩個值之一時，**回退成統計總覽**
6. 切換分頁時要**更新**網址上的分頁參數，讓連結可以直接分享到某一個分頁、重新整理後也還在同一個分頁
7. 分頁參數**只決定選取哪個分頁**，**不得**用來覆寫任務代號或任務的輸出類型

### 任務上下文載入一次，切換分頁不重建

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

兩個分頁共用同一份任務上下文，這是這一頁做成雙分頁而不是兩頁的全部理由。

1. 任務上下文至少包含：**任務代號**、**任務名稱**、**任務的輸出類型清單**（每一筆是一個:ref[輸出類型]{id="term.output-type"}與它的設定）、使用者在這個任務的成員角色
2. 任務的輸出類型**由任務資料決定**，**不得**由網址決定
3. 切換分頁**不得重建**任務上下文
4. 外殼（頁首、麵包屑、分頁列）為兩個分頁**共用**，不隨分頁切換重新產生
5. 複合任務的輸出類型要**保留原本的順序**：階段二與階段三的逐型區塊依這個順序並列

### 兩個分頁各有一組自己的狀態

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

兩個分頁的狀態**數量不同**，而且各自**互斥**：同一時刻恰好成立一種。

1. 統計總覽有**四種**：

| 狀態 | 什麼時候 |
| :--- | :--- |
| 載入中 | 資料還沒到位 |
| 空 | **還沒有任何已提交的標記** |
| 就緒 | 有統計可看 |
| 錯誤 | 載入失敗 |

2. 品質監控有**六種**：

| 狀態 | 什麼時候 |
| :--- | :--- |
| 載入中 | 資料還沒到位 |
| 試標進行中 | :ref[試標]{id="term.dry-run"}還沒跑完 |
| 報告待產生 | 試標跑完、報告還沒排到 |
| 報告產生中 | 報告正在算 |
| 就緒 | 有報告可看 |
| 錯誤 | 載入失敗 |

3. 品質監控的**試標進行中、報告待產生、報告產生中三種都歸在空狀態集合**——它們的共同原因是「試標還沒完成」，所以都不是「就緒」
4. 但第 3 條的三種**各有自己的標題與說明**，**不得共用一組文案**：使用者要能從畫面上看出現在等的是「標記員還沒標完」、「排到了還沒開始算」還是「正在算」。三組文案寫在階段三
5. 第 3 條的三種狀態**不得**與「載入中」混用：前者是**還沒有東西可算**，後者是**算好了還沒到畫面上**
6. 四種與六種狀態**不得互相代用**，也不得只用一個布林值表示
7. 「載入中」是來源明文要求的狀態，但**目前的畫面兩個分頁都沒有實作它**。與[規格 05-01 §四種互斥的頁面狀態](./01-analysis-list.mdx#四種互斥的頁面狀態)第 4 點同一類：**來源有明文就照寫**，畫面補不補由[規格 04-01 §待釐清](../04-annotation/01-annotation-list.mdx#待釐清) Q8 一併決定
8. 空狀態與錯誤狀態下，**外殼與分頁列都還在**，使用者仍可切到另一個分頁

### 載入失敗只換掉內容區

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

某個分頁的內容載入失敗時，壞掉的是**內容**，不是整頁。

1. 錯誤狀態顯示在**該分頁的內容區**：標題 `資料載入失敗`、說明 `無法載入此面板的內容，請稍後再試。`，另有 `重新載入`
2. 頁首、麵包屑、分頁列**不受影響**；另一個分頁**不受影響**
3. `重新載入` 是**重試**，不是回到列表
4. 任務的輸出類型**取不到、是空的、缺少、或含認不得的鍵**時，**兩個分頁都**落到這個錯誤狀態
5. 第 4 條**不得**用猜的補上：不得挑一個預設輸出類型、不得猜一個組合、不得只渲染認得的那幾個

### 兩個分頁的捲動位置分開記

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

在長表格裡比對到一半切去另一個分頁，切回來要**還在原處**。

1. 兩個分頁**各自記住自己的捲動位置**，互相獨立
2. 切換分頁時**不得重設**捲動位置
3. 目標分頁還沒有記錄過位置時，從**頂端**開始

### 語系切換不重新載入

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

1. 語系切換要**即時**更新全頁文案，**不得**觸發整頁重新載入
2. 要跟著換的至少包含：頁首大標與副標、麵包屑兩段、兩個分頁的名稱、空狀態與錯誤狀態的文案
3. 統計總覽要跟著換的還有**圖表標題、軸標籤、圖例與說明文字**（逐型內容見階段二）
4. 品質監控要跟著換的還有**指標名稱、圖例與說明文字**（見階段三、四）
5. 第 1 條的「不重新載入」帶來兩個後果：目前所在的**分頁不變**、**捲動位置不變**

### 不同螢幕寬度的呈現

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

1. 在 **375、768、1440** 三種寬度下，進入任一分頁、切換分頁與閱讀指標**都要能完成**，關鍵內容不得被截斷
2. 手機版（寬度 **767 以下**）欄位空間不足時：**允許橫向捲動**
3. 第 2 條至少要涵蓋這些比較寬的內容：**維度間的散布圖**、**多標籤共現矩陣**、**IAA 報告表格**、**標記一致性偏離分析表格**、**標記員分析表格**
4. 橫向捲動**不得造成整頁水平捲動**

### 這一頁的外殼碰不到的東西

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

1. 外殼**不決定**任何一個分頁的內容要顯示什麼指標——那是輸出類型與分頁各自的規則
2. 外殼**不改**任務設定、不改成員身分、不改標記
3. 外殼**不產生** IAA 報告，也不決定報告何時算完
4. 匯出的對話框、入口與紀錄表**不在這一頁**

## 卡控機制

- 任務代號不存在 → 導回分析列表，顯示 `找不到指定的任務，或您沒有該任務的存取權限。`
- 使用者在那個任務沒有專案負責人或審核員的成員資格 → 同上，與前一條是同一個觸發、同一句提示
- 使用者在那個任務的任務角色缺少或認不得 → 視同沒有成員資格，**失敗即關閉**，導回分析列表
- 使用者在那個任務**唯一的**成員身分是「受邀但還沒生效」 → 視同不存在，等於沒有生效身分，依前一條處理
- 使用者還有其他生效身分，但聯集後不含某個分頁的權限 → 只**拒絕那一個分頁的資料讀取**，**不得**整頁擋掉
- 標記員身分進入這一頁 → 進不來，依第二條處理
- 驗證不過 → **不得**退回成任何預設任務再渲染內容
- 「看任務統計」不成立 → **拒絕統計總覽的資料讀取**；不得改成顯示空統計
- 「看品質分析」不成立 → **拒絕品質監控的資料讀取**；不得改成顯示空報告
- 任一分頁的權限不成立 → 只拒絕那一個分頁，**不得**整頁擋掉
- 網址上的分頁參數不是那兩個合法值之一 → **回退成統計總覽**
- 沒帶分頁參數 → 落在統計總覽
- 網址試圖指定任務的輸出類型 → **忽略**，輸出類型只由任務資料決定
- 任務的輸出類型取不到、是空的、缺少、或含認不得的鍵 → 兩個分頁都顯示**可重試的錯誤狀態**；**不得**猜一個預設輸出類型、不得猜組合、不得只渲染認得的那幾個
- 切換分頁 → **不得**導向分析列表、不得重新載入整頁、不得重建任務上下文
- 切換分頁 → **不得**重設任一分頁的捲動位置
- 語系切換 → **不得**整頁重新載入、不得改變目前所在的分頁
- 任一分頁的內容載入失敗 → 只換掉**該分頁的內容區**，頁首、麵包屑、分頁列與另一個分頁不受影響
- 這一頁的任何位置 → **不得**顯示任何一筆標記的答案內容或標準答案

## 邊界情況（Edge Case）

- **進入**
  - 直接貼網址、帶著品質監控的分頁參數進來 → 落在品質監控，而且任務上下文**一併載入**，不是空的分頁
  - 從儀表板的提醒進來，但該任務的試標還沒完成 → 落在品質監控的**空狀態**，外殼與分頁列都在
  - 網址只有任務代號、沒有分頁參數 → 落在統計總覽
  - 網址帶著這一頁不認得的其他查詢條件 → 來源沒有定義要保留還是移除，見[§待釐清](#待釐清) Q4
- **兩個分頁之間**
  - 在統計總覽捲到底再切到品質監控，再切回來 → **回到原來的位置**，不是頂端
  - 第一次切到品質監控 → 從**頂端**開始
  - 在品質監控時重新整理 → **還在品質監控**
  - 在品質監控時切語系 → 還在品質監控，捲動位置不變
  - 兩個分頁同時都空（還沒有標記、也還沒有試標） → 兩個分頁各自顯示**自己的空狀態**，文案不得互換
- **權限**
  - 使用者在同一個任務有兩個生效的成員身分 → 權限取**聯集**
  - 兩個生效身分裡只有一個帶「看品質分析」 → 品質監控**讀得到**
  - 唯一的成員身分是「受邀但還沒生效」 → **進不來**
  - 進來之後成員資格被移除、或任務被封存 → 來源沒有定義已載入的畫面要怎麼處理，見[§待釐清](#待釐清) Q5
- **載入與錯誤**
  - 任務上下文載入失敗 → 兩個分頁都顯示可重試的錯誤
  - 任務的輸出類型是空陣列 → 可重試的錯誤，**不是**空狀態——空狀態的意思是「還沒有人提交」，不是「這個任務沒有輸出類型」
  - 任務的輸出類型含一個認不得的鍵、其餘認得 → 整個分頁都落到錯誤，**不得**只渲染認得的那幾個
  - 某一個分頁的內容載入失敗 → 另一個分頁照常可用
- **螢幕寬度**
  - 手機版進入品質監控 → 比較寬的表格**橫向捲動**，不造成整頁水平捲動
  - 768 寬度 → 關鍵內容不得被截斷

## 待釐清

### Q1. 切換分頁要不要留在瀏覽器的「上一頁」歷程裡？

- [ ] 不留（目前畫面的作法）：切換分頁只改寫網址，不新增一筆歷程；按「上一頁」會離開這一頁，回到進來之前的地方
- [ ] 留：每次切換分頁都新增一筆歷程；按「上一頁」回到前一個分頁，要離開這一頁得按兩次以上
- [ ] 其他（請說明）

> 建議：第一個。來源只要求網址上的分頁參數能支援深層連結與重新整理後還原狀態，兩種作法都滿足；而分頁切換是同一頁的檢視切換，把它堆進歷程會讓「上一頁」變得難以預期。

## Q&A

### Q. 為什麼統計與品質要做成一頁兩個分頁，而不是兩頁？

因為兩邊問的是**同一個任務**的兩個問題：「標了多少、分布長什麼樣」與「標得一致不一致」。做成兩頁的話，每次切換都要重新帶任務代號、重新確認成員資格、重新建立上下文，而使用者實際的動作是在兩組數字之間來回對照。做成一頁兩個分頁，任務上下文只建立一次，捲動位置各自記住，網址一個連結就說完「哪個任務、哪個分頁」。

### Q. 為什麼統計總覽是四種狀態，品質監控卻是六種？

因為品質監控多出三種「還沒有東西可算」的情況：試標還在跑、試標跑完但報告還沒排到、報告正在算。統計總覽只要有人提交就算得出來，所以它的「空」只有一種原因。這三種都歸在空狀態集合、都**不是**「載入中」——載入中的意思是算好了還沒到畫面上；但它們**各有自己的標題與說明**，因為把它們壓成一組文案，就沒辦法回答「現在到底在等什麼」。

### Q. 為什麼任務代號不存在與沒有權限要顯示同一句話？

分辨了就等於告訴外人「這個任務存在，只是你看不到」。這一頁的使用者是專案負責人與審核員，任務之間本來就有:ref[資料隔離]{id="term.data-isolation"}；把兩種情況合成一句 `找不到指定的任務，或您沒有該任務的存取權限。`，外人就無法用網址逐個試出哪些任務代號是真的。

### Q. 兩個分頁各一道權限，那沒有「看品質分析」的人進來會看到什麼？

他進得來，統計總覽照常可讀，切到品質監控時**那一個分頁的資料讀取被拒絕**。擋的是分頁的資料，不是整頁——因為能不能進這一頁是任務角色決定的，而兩道分頁權限是那一格之內的細化。上線初期種子設定把兩道權限都開給專案負責人與審核員，所以實際上不會有人只拿到一半。
