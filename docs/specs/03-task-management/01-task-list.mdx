# 03-01 任務列表

:badge[草稿]{variant="warning"} :badge[任務管理]{variant="neutral"}

> 來源：舊 repo `specs/task-management/010-task-list/spec.md`（54 條），釘在 `singyichen/label-suite@faf83356`，見 `docs/specs/legacy/03-01-task-list.ids` 的首行
> 參考畫面：`design/prototype/pages/task-management/task-list.html`
> 相關規格：規格 03-02 新增任務（未撰寫）、規格 03-03 任務詳情（未撰寫）、規格 02-01 儀表板（未撰寫）、[規格 07-01 側欄導覽](../07-shared/01-sidebar.mdx)、[規格 01-05 登入狀態與安全](../01-account/05-login-state.mdx)
>
> 這一頁是任務管理模組的進入點：側欄點「任務管理」就到這裡。
> **本頁不替 8 種輸出型別定名**——依搬移設計文件的 D3，那是規格 03-02 新增任務的工作，本頁只引用，見 [§待釐清](#待釐清) Q4。

## 目標

- 讓這一頁當任務管理模組的進入點：側欄點「任務管理」就到這裡，從這裡才分岔到新增任務與任務詳情
- 讓使用者在一個畫面裡找到自己要處理的任務，不必記得任務叫什麼名字
- 讓 :ref[平台成員]{id="term.platform-member"} 只看得到自己參與的任務，:ref[系統管理員]{id="term.system-admin"} 看得到所有任務
- 讓一個任務同時產出多種結果時，列表照實呈現每一種，而不是壓縮成一個名字
- 讓使用者把查到的結果分享給別人、或重新整理之後，看到的還是同一批任務

## 使用角色

:::tip{title="權限代號"}
R：Read（可讀取）　C：Create（可新增）　E：Edit（可編輯）　D：Delete（可刪除）　(o)：只限自己的資料　—：無權限
:::

**依系統角色**（決定看得到哪些任務）

- :ref[平台成員]{id="term.platform-member"}：R (o)（只有自己參與的任務）／C（新增任務）
- :ref[系統管理員]{id="term.system-admin"}：R（所有任務）／C（新增任務）／D (o)（見下方的警示）

**依任務角色**（只決定那一列有沒有可用的「刪除」）

- :ref[專案負責人]{id="term.project-leader"}：D (o)（只有自己負責的任務，而且只有草稿；見下方的警示）
- :ref[審核員]{id="term.reviewer"}：無權限（任務角色不會讓他在這一頁多任何操作）
- :ref[標記員]{id="term.annotator"}：無權限（同上）

- 看得到哪些任務**只看系統角色**；任務角色在這一頁只影響一件事——那一列有沒有可用的「刪除」
- 任務角色真正決定的是**點進去之後**能不能看任務詳情（規格 03-03，未撰寫）
- 系統管理員看得到所有任務的列表，但**沒有任務角色時進不了該任務的詳情**（PRD §權限矩陣的註記），見 [§點任務進入任務詳情](#點任務進入任務詳情)
- 這一頁沒有任何角色可以編輯任務內容；「編輯」只是前往任務詳情的另一個入口

:::warning{title="刪除任務整件事超出 PRD"}
上面兩個 `D (o)` 都**沒有 PRD 依據**：**PRD §權限矩陣 對「03 任務列表」只給 `R (o)` 與 `R`，整個 03 模組的四列（任務列表、新增任務、任務詳情、匯出標記結果）沒有任何一格有 `D`**，§專案範圍 的範圍內與範圍外也都沒有提到刪除任務。
PRD 明寫「規格書的『使用角色』只能比這張表更嚴，不能更寬」，所以**這兩格是本頁已知超出 PRD 的地方**，不是本頁自行放寬的決定——來源的條文完整（見 [§已確認決議](#已確認決議) Q15），所以本頁照實寫出來並把它交回去，見 [§待釐清](#待釐清) Q5。
Q5 選「這一版不做刪除」時，這兩格與 [§刪除任務](#刪除任務) 整節一起改標為不適用。
:::

- **找到要處理的任務**
  - 觸發：使用者從側欄點「任務管理」
  - 前置條件：使用者已登入
  - 主流程：
    1. 使用者進入任務列表
    2. 系統依使用者的系統角色決定載入哪些任務：平台成員只載入自己參與的，系統管理員載入所有的
    3. 使用者輸入關鍵字或套用篩選
    4. 列表當場更新、回到第一頁，查詢條件同時寫進網址
    5. 使用者在列表上看到要處理的那一筆
  - 替代流程：
    - A1（第 2 步）使用者是系統管理員 → 載入所有任務，畫面上**沒有**「我的任務／全平台任務」切換，回到第 3 步
    - A2（第 4 步）篩選後沒有任何符合的任務 → 保留表頭，表格內顯示找不到符合條件的任務與「清除所有篩選」；使用者點它就回到沒有篩選的列表，流程結束（見 [§空狀態與載入失敗](#空狀態與載入失敗)）
    - A3（第 2 步）使用者完全沒有任何任務 → 保留表頭，表格內顯示尚無任務，**只保留頁面上那一顆「新增任務」**，流程結束
  - 例外流程：
    - E1（第 2 步）列表載入失敗 → 保留表頭，表格內顯示載入失敗與「重試」，**不顯示成空資料**，流程結束
  - 結果：使用者看到他要處理的那幾筆任務；查詢條件留在網址上

- **離開這一頁**
  - 觸發：使用者在列表上點了某個操作
  - 前置條件：列表已經載入
  - 主流程：
    1. 使用者點任務列，或點那一列的「編輯」
    2. 系統確認使用者看不看得了這個任務的詳情
    3. 看得了 → 前往該任務的任務詳情（規格 03-03，未撰寫）
  - 替代流程：
    - A1（第 1 步）使用者點「新增任務」→ 前往新增任務（規格 03-02，未撰寫），流程結束
    - A2（第 1 步）使用者點「刪除」→ 顯示確認視窗；確認後任務移到封存、從列表消失，並顯示已移至封存，流程結束
    - A3（A2 的確認視窗）使用者點「取消」→ 任務完全不變，回到列表，流程結束
  - 例外流程：
    - E1（第 2 步）使用者看不了這個任務的詳情 → **停在這一頁**並顯示無權限檢視任務詳情，不跳頁，流程結束
    - E2（第 1 步）任務不是草稿，或使用者沒有刪除權限 → 那一列**不顯示可用的刪除**；若刪除仍被觸發則擋下並顯示對應提示，流程結束
  - 結果：使用者前往下一頁，或任務被移到封存；任何被擋下的情況都不會改變任務

## 規格

### 頁面的內容

<PrototypeFrame page="task-management/task-list" caption="任務列表" client:idle />

1. 使用者進入這一頁 → 頁首顯示主標題「任務列表」與副標題「查看與管理所有標記任務」
2. 標題下方一列：三個篩選器、「清除篩選」、搜尋框，最右邊是「新增任務」
3. 其下是任務表格，欄位依序為任務名稱、輸出型別、標記階段、狀態、更新時間、操作
4. 表格下方是分頁列：顯示共幾筆與第幾頁，可切換每頁筆數，以及上一頁、下一頁

- 搜尋框固定在篩選器列**最右側**
- 整頁只有**一個**「新增任務」入口，在上面那一列

### 誰看得到哪些任務

<PrototypeFrame page="task-management/task-list" caption="任務列表" client:idle />

1. :ref[平台成員]{id="term.platform-member"} 進入 → 只看得到**自己有參與**的任務
2. :ref[系統管理員]{id="term.system-admin"} 進入 → 預設就看得到**所有**任務
3. 系統管理員的畫面上**沒有**「我的任務／全平台任務」切換，不需要也不能切
4. 已經移到封存的任務 → 任何人在這一頁都看不到

- 平台成員看不到自己沒有參與的任務，連任務名稱都看不到
- 這和 PRD §權限矩陣 的「03 任務列表：平台成員 R (o)、系統管理員 R」一致

### 搜尋

<PrototypeFrame page="task-management/task-list" caption="任務列表" client:idle />

1. 使用者在搜尋框輸入關鍵字（提示文字「搜尋」）→ 列表只顯示符合的任務
2. 比對範圍是**列表上的每一欄**：任務名稱、輸出型別、標記階段、狀態、更新時間
3. 比對方式是**部分符合、不分大小寫**
4. 輸出型別、標記階段、狀態這三種欄位 → **目前語言顯示的文字也算**，不是只比對內部的值

- 第 4 條的意思是：使用者用畫面上看到的字去搜，就搜得到；切換語言後用另一種語言的字去搜，也搜得到
- 一個任務有多種輸出型別時，**任何一種**符合關鍵字就算符合
- 畫面另外還比對了任務的內部編號與**兩種語言的任務名稱**（所以在中文介面輸入英文名也搜得到），來源沒有這條，見 [§待釐清](#待釐清) Q9

### 輸出型別篩選

<PrototypeFrame page="task-management/task-list" caption="任務列表" client:idle />

1. 篩選器的第一個選項是「全部輸出型別」，不帶條件
2. 其後是**正好 8 個**輸出型別選項
3. 使用者選一種 → 只要任務的輸出型別**有任何一項**是它，這個任務就會出現
4. 所以一個同時產出多種結果的任務，會**同時出現在多個**輸出型別的篩選結果裡

- 8 種輸出型別的中文名由規格 03-02 新增任務定名（搬移設計文件的 D3），本頁只引用，見 [§待釐清](#待釐清) Q4
- 畫面上這個篩選器與欄位目前寫的是「輸出類型」，不是「輸出型別」，見 [§待釐清](#待釐清) Q3
- 篩選**不是**「輸出型別組合完全相同」，也不是「只看第一種」

### 標記階段篩選

<PrototypeFrame page="task-management/task-list" caption="任務列表" client:idle />

1. 篩選器的第一個選項是「全部標記階段」，不帶條件
2. 其後是 :ref[試標]{id="term.dry-run"} 與 :ref[正式標記]{id="term.official-run"}
3. 畫面上還有一個「未建立清單」（排在試標之前），而且任務是草稿時，標記階段欄顯示的就是它
4. 使用者選一種 → 只顯示在那個階段的任務

- 第 3 條**來源沒有定義**：來源的標記階段只有試標與正式標記兩種，見 [§待釐清](#待釐清) Q2

### 狀態篩選

<PrototypeFrame page="task-management/task-list" caption="任務列表" client:idle />

1. 篩選器的第一個選項是「全部狀態」，不帶條件
2. 其後是 :ref[任務]{id="term.task"} 的五個狀態：草稿、試標中、等待 IAA 確認、正式標記中、已完成
3. 使用者選一種 → 只顯示在那個狀態的任務

- 五個狀態的名稱以 PRD §共用狀態機 為準（搬移設計文件的 D5）
- **畫面上有三個狀態的字和 PRD 不一樣**，而且畫面自己的篩選器與列上的標籤也不一致，見 [§待釐清](#待釐清) Q1

### 清除篩選

<PrototypeFrame page="task-management/task-list" caption="任務列表" client:idle />

1. 關鍵字或任一個篩選器有條件時 → 篩選器列上才出現「清除篩選」
2. 完全沒有任何條件時 → 這顆按鈕**不顯示**，因為沒有東西可以清
3. 使用者點它 → 關鍵字與三個篩選器都回到沒有條件，列表回到第一頁，按鈕自己也跟著消失
4. 篩選後沒有任何結果時 → 表格內另外提供一個「清除所有篩選」，作用相同

### 排序與分頁

<PrototypeFrame page="task-management/task-list" caption="任務列表" client:idle />

1. 列表預設依**更新時間由新到舊**排列（**畫面目前沒有做到**，見 [§待釐清](#待釐清) Q9）
2. 每頁預設 20 筆，可以改成 50 或 100
3. 分頁列顯示共幾筆、目前第幾頁、總共幾頁，有上一頁與下一頁，中間還有幾個頁碼可以直接點（以目前頁為中心，最多五個）
4. 已經在第一頁 → 「上一頁」不能點；已經在最後一頁 → 「下一頁」不能點；結果只有一頁 → 兩個都不能點
5. 使用者換頁 → **篩選與關鍵字都保留**，只有頁次變
6. 使用者改變關鍵字或任一個篩選器 → **回到第一頁**
7. 使用者改變每頁筆數 → 也**回到第一頁**，用新的筆數重查

### 查詢條件保留在網址

<PrototypeFrame page="task-management/task-list" caption="任務列表" client:idle />

1. 關鍵字、三個篩選器、每頁筆數與頁次 → 都**寫進網址**
2. 使用者重新整理，或離開這一頁再回來 → 看到的是同一批結果
3. 使用者把網址貼給同事 → 對方看到同樣的查詢條件（看得到哪些任務仍依他自己的權限）
4. 網址上的條件無效（例如每頁筆數不在 20、50、100 之內，或某個篩選值不存在）→ **忽略它、改用預設值**，並把網址更新成整理過的樣子
5. 第 4 條不會讓頁面報錯，使用者看到的是一個正常的列表

### 任務列的欄位

<PrototypeFrame page="task-management/task-list" caption="任務列表" client:idle />

1. 每一列顯示任務名稱、輸出型別、標記階段、狀態、更新時間，最後是操作
2. 輸出型別欄 → **依任務設定的順序，每一種各顯示一個唯讀標籤**；一個任務有幾種就顯示幾個
3. 多個標籤在欄寬不夠時 → **在格子裡換行**，不截斷文字、不互相重疊，整頁也不會需要左右滑動
4. 標籤用**看得見的文字**表達型別，顏色只是輔助
5. 整組標籤要能被當成**一份完整的清單**讀出來（例如「輸出型別：實體辨識、關係識別」），讓不看畫面的人也知道這個任務有幾種、是哪幾種
6. 操作欄的按鈕由左至右是「刪除」、「編輯」

- 複合的任務**不會**被合併成一個自訂的名字，也不會只顯示第一種
- 這一頁顯示的全是任務本身的資訊，**不包含任何標記結果或** :ref[標準答案]{id="term.ground-truth"}

### 點任務進入任務詳情

<PrototypeFrame page="task-management/task-list" caption="任務列表" client:idle />

1. 使用者點任務列 → 顯示「前往任務詳情…」，然後前往該任務的任務詳情（規格 03-03，未撰寫）
2. 使用者點那一列的「編輯」→ **同樣**前往該任務的任務詳情，不是另一個畫面
3. 使用者看不了這個任務的詳情 → **停在這一頁**，顯示「無權限檢視任務詳情」，不跳頁
4. 使用者從任務詳情因為權限被退回這一頁 → **也要顯示同一句提示**，不能讓他看到一次沒有說明的跳轉

- 第 3 條最常見的情況是系統管理員看得到列表、但在那個任務裡沒有任務角色；:ref[標記員]{id="term.annotator"} 也一樣
- 點進去只帶「哪一個任務」，**不帶輸出型別**；複合的任務不會被當成它的第一種輸出型別

### 新增任務

<PrototypeFrame page="task-management/task-list" caption="任務列表" client:idle />

1. 使用者點「新增任務」→ 前往新增任務（規格 03-02，未撰寫）
2. 整頁只有這一個入口；**完全沒有任務時也不會多出第二顆**

### 刪除任務

<PrototypeFrame page="task-management/task-list" caption="任務列表" client:idle />

:::warning
這一節的權限超出 PRD §權限矩陣，見 [§使用角色](#使用角色) 的說明與 [§待釐清](#待釐清) Q5。
:::

1. 任務是**草稿**，而且使用者是**該任務的專案負責人**或**系統管理員** → 那一列才有可用的「刪除」
2. 使用者點「刪除」→ 顯示確認視窗，標題「確認刪除任務」，內容**指名那個任務**（確認要把那個名字的任務移到封存）並說明可以復原
3. 使用者在確認視窗點「刪除」→ 任務**移到封存**，從列表消失，顯示已移至封存
4. 使用者點「取消」、點視窗外面，或按 Esc → 視窗關閉，任務**完全不變**
5. 任務不是草稿 → 那一列沒有可用的刪除；若仍被觸發 → 擋下並顯示「此任務狀態不允許刪除」
6. 使用者沒有刪除權限 → 那一列沒有可用的刪除；若仍被觸發 → 擋下並顯示「無權限刪除任務」

- :ref[封存]{id="term.archived-task"} 的意思是**資料留著**：任務不再出現在這一頁，但保留下來供查核與復原；平台上沒有把任務真正清掉的操作
- 用舊連結直接打開已封存的任務 → 看到的是「任務不存在或無存取權限」，和不存在的任務同一句話
- **誰能復原、從哪裡復原，已經寫好的規格裡沒有一頁定義**，見 [§待釐清](#待釐清) Q7
- 確認視窗不是瀏覽器自己的那種提示，是頁面上的視窗

### 空狀態與載入失敗

<PrototypeFrame page="task-management/task-list" caption="任務列表" client:idle />

三種情況**都保留表頭**，只換表格裡的內容，讓使用者還看得出這張表有哪些欄位。

| 情況 | 表格內顯示 |
| :--- | :--- |
| 使用者完全沒有任務 | 「尚無任務」與「你目前沒有任何任務。建立第一個任務以開始標記工作流程。」；**不放第二顆「新增任務」** |
| 篩選後沒有符合的 | 「找不到符合條件的任務」與「請調整搜尋條件或清除篩選，重新查詢。」，加一個「清除所有篩選」 |
| 列表載入失敗 | 「任務列表載入失敗」與「請重試或稍後再回到任務列表。」，加一個「重試」 |

1. 這三種情況下**分頁列整條不顯示**，因為沒有可以翻的頁
2. 載入失敗**絕對不能顯示成空資料**——那會讓使用者以為自己沒有任務
3. 使用者點「重試」→ 重新載入列表
4. 系統管理員在全平台都沒有任務時 → 看到的是第一種，不是錯誤畫面

### 語言切換

<PrototypeFrame page="task-management/task-list" caption="任務列表" client:idle />

語言切換本身由 [規格 07-01 §語言切換](../07-shared/01-sidebar.mdx#語言切換) 擁有，本節只寫這一頁自己的部分。

1. 使用者切換語言 → 欄位標題、三個篩選器的所有選項、按鈕、空狀態與錯誤的文字、輸出型別標籤的文字都即時換成另一種語言
2. 切換之後 → 已套用的關鍵字與篩選**不會被清掉**，列表內容不變

### 不同螢幕寬度的呈現

<PrototypeFrame page="task-management/task-list" caption="任務列表" client:idle />

1. 使用者在手機、平板或桌機 → 搜尋、三個篩選、換頁、點任務列、點「新增任務」**都做得到**
2. 欄位放不下時 → 可以左右捲動或改成卡片，但**不能讓資訊重疊**
3. 任何寬度下 → 多個輸出型別標籤都換行而不截斷，整頁不需要左右滑動

### 資料欄位

| 欄位 | 型別 | 必填 | 規則 | 使用者看到 |
| :--- | :--- | :--- | :--- | :--- |
| 任務名稱 | 文字 | 是 | 可以重複；搜尋的比對範圍之一 | 第一欄 |
| 輸出型別 | 多選：8 種 | 是 | 依任務設定的順序逐一顯示；至少一種 | 一個或多個唯讀標籤 |
| 標記階段 | 單選：試標、正式標記 | 是 | 畫面另有「未建立清單」，見 [§待釐清](#待釐清) Q2 | 標記階段欄的標籤 |
| 狀態 | 單選：草稿、試標中、等待 IAA 確認、正式標記中、已完成 | 是 | 以 PRD §共用狀態機 為準；只有草稿可以刪除 | 狀態欄的標籤 |
| 更新時間 | 日期時間 | 是 | 預設由新到舊排序；搜尋的比對範圍之一 | 更新時間欄 |
| 是否已封存 | 是／否 | 是 | 已封存的不出現在這一頁；資料留著供查核與復原 | 不顯示；封存後該任務從列表消失 |
| 封存的人與時間 | — | 否 | 任務被移到封存時記下 | 不顯示 |

- 這一頁**不顯示也不編輯**任務設定、成員或任何標記結果
- 時間顯示的時區比照 [規格 06-01 §資料欄位](../06-admin/01-user-management.mdx#資料欄位)

## 卡控機制

| 條件 | 結果 |
| :--- | :--- |
| 平台成員要看自己沒有參與的任務 | 看不到，列表不含那些任務 |
| 系統管理員要切換成「只看我的任務」 | 畫面上沒有這個切換 |
| 使用者點的任務他看不了詳情 | 停在這一頁，顯示無權限檢視任務詳情，不跳頁 |
| 任務不是草稿 | 那一列沒有可用的刪除；被觸發時擋下並顯示狀態不允許刪除 |
| 使用者不是該任務的專案負責人、也不是系統管理員 | 那一列沒有可用的刪除；被觸發時擋下並顯示無權限刪除 |
| 使用者在確認視窗點「取消」 | 任務完全不變 |
| 網址上的每頁筆數不在 20、50、100 之內 | 忽略，用 20，並更新網址 |
| 網址上的頁次或篩選值無效 | 忽略，當成沒有篩選的第一頁，並更新網址 |
| 關鍵字或篩選改變 | 強制回到第一頁 |
| 每頁筆數改變 | 強制回到第一頁 |
| 列表載入失敗 | 保留表頭並顯示錯誤與重試，**不得顯示成空資料** |
| 用舊連結打開已封存的任務 | 顯示任務不存在或無存取權限，和不存在的任務同一句 |
| 想靠「看任務詳情」或「管理成員」之類的其他權限取得刪除 | 不行；刪除只認 [§使用角色](#使用角色) 那兩格，不能由別的權限間接得到 |

## 邊界情況（Edge Case）

| 情況 | 使用者看到什麼 |
| :--- | :--- |
| 平台成員完全沒有參與任何任務 | 保留表頭，表格內顯示「尚無任務」，不是錯誤畫面 |
| 系統管理員在全平台都沒有任務 | 同上，也不是錯誤畫面 |
| 篩選條件組合起來沒有任何結果 | 保留表頭，表格內顯示找不到符合條件的任務與「清除所有篩選」 |
| 列表載入失敗 | 保留表頭，表格內顯示載入失敗與「重試」 |
| 一個任務同時產出三種結果 | 輸出型別欄顯示三個標籤，而且它在三種輸出型別的篩選結果裡都出現 |
| 欄寬不夠放完所有標籤 | 在格子裡換行，不截斷、不重疊，整頁也不需要左右滑動 |
| 任務被別人移到封存後才按下重試 | 重新載入後那個任務已經不在列表上 |
| 用失效的任務連結進入任務詳情 | 被帶回這一頁並顯示任務不存在或無存取權限 |
| 系統管理員看得到某個任務但沒有任務角色 | 點它會停在這一頁並顯示無權限檢視任務詳情 |
| 標記員看得到被指派的任務 | 點它一樣停在這一頁並顯示無權限檢視任務詳情；他的入口是標記清單（規格 04-01，未撰寫） |
| 切換語言後再用新語言的字搜尋 | 搜得到，因為搜尋也比對目前語言顯示的文字 |
| 第二頁看到一半改了篩選 | 回到第一頁，不會停在一個沒有資料的頁次 |
| 結果只有一頁 | 上一頁、下一頁都不能點，也沒有別的頁碼 |
| 成員資格已經失效的人開這一頁 | 看不看得到原本參與的任務沒有定義，見 [§待釐清](#待釐清) Q10 |

## 驗收標準

| Scenario | Given | When | Then |
| :--- | :--- | :--- | :--- |
| 平台成員只看到自己參與的任務 | 使用者是平台成員，參與其中兩個任務 | 進入任務列表 | 只顯示那兩個任務，其他任務連名稱都看不到 |
| 系統管理員看到所有任務 | 使用者是系統管理員 | 進入任務列表 | 顯示平台上所有未封存的任務 |
| 系統管理員沒有檢視切換 | 使用者是系統管理員在任務列表 | 查看整頁 | 找不到「我的任務／全平台任務」之類的切換 |
| 關鍵字部分符合 | 列表上有任務名稱含「情緒」的任務 | 在搜尋框輸入「情緒」 | 只顯示名稱或其他欄位含有這兩個字的任務，不分大小寫 |
| 用畫面上的狀態文字搜尋 | 有任務的狀態是草稿 | 在搜尋框輸入「草稿」 | 那些任務出現在結果裡 |
| 切換語言後用新語言的字搜尋 | 使用者已把介面切成英文 | 用英文的狀態文字搜尋 | 那些任務出現在結果裡 |
| 套用篩選後回到第一頁 | 使用者正在第三頁 | 套用任一個篩選器 | 列表回到第一頁並只顯示符合的任務 |
| 選一種輸出型別 | 某任務同時產出三種結果 | 選其中任一種輸出型別 | 那個任務出現在結果裡 |
| 複合任務出現在多個篩選結果 | 某任務同時產出三種結果 | 分別用那三種輸出型別篩選 | 三次都看得到同一個任務 |
| 換頁保留篩選條件 | 使用者已套用狀態篩選且結果超過一頁 | 點下一頁 | 顯示第二頁，且狀態篩選仍然套用著 |
| 改每頁筆數回到第一頁 | 使用者正在第三頁，每頁 20 筆 | 改成每頁 50 筆 | 回到第一頁，一頁顯示 50 筆 |
| 預設依更新時間由新到舊 | 列表上有多個任務 | 進入任務列表 | 最近更新的在最上面 |
| 重新整理還原查詢條件 | 使用者已輸入關鍵字並套用兩個篩選 | 重新整理頁面 | 關鍵字與兩個篩選都還在，結果一樣 |
| 網址上的每頁筆數無效 | 網址上的每頁筆數是一個不支援的數字 | 用那個網址進入 | 以每頁 20 筆載入，網址更新成整理過的樣子，頁面不報錯 |
| 網址上的篩選值無效 | 網址上的狀態是一個不存在的值 | 用那個網址進入 | 當成沒有套用狀態篩選，網址更新，頁面不報錯 |
| 網址上的頁次無效 | 網址上的頁次是一個不存在的頁 | 用那個網址進入 | 以第一頁載入，網址更新成整理過的樣子，頁面不報錯 |
| 清除所有篩選 | 使用者已套用關鍵字與三個篩選 | 點「清除篩選」 | 關鍵字與三個篩選都清空，回到第一頁的完整列表 |
| 沒有條件時不顯示清除 | 使用者剛進入任務列表、還沒有輸入或篩選 | 查看篩選器列 | 沒有「清除篩選」這顆按鈕 |
| 有條件時才出現清除 | 使用者剛進入任務列表 | 輸入一個關鍵字 | 篩選器列上出現「清除篩選」 |
| 第一頁的上一頁不能點 | 使用者在第一頁 | 查看分頁列 | 「上一頁」不能點 |
| 最後一頁的下一頁不能點 | 使用者在最後一頁 | 查看分頁列 | 「下一頁」不能點 |
| 只有一頁時兩邊都不能點 | 查詢結果不到一頁的筆數 | 查看分頁列 | 「上一頁」與「下一頁」都不能點 |
| 點頁碼直接跳頁 | 查詢結果有五頁 | 點頁碼「3」 | 直接顯示第三頁，篩選條件保留 |
| 篩選後沒有結果 | 使用者套用的條件組合沒有任何任務符合 | 查看表格 | 保留表頭，表格內顯示找不到符合條件的任務與「清除所有篩選」 |
| 從空結果一鍵清除 | 畫面正顯示找不到符合條件的任務 | 點「清除所有篩選」 | 回到沒有篩選的列表 |
| 完全沒有任務 | 使用者沒有參與任何任務 | 進入任務列表 | 保留表頭，表格內顯示「尚無任務」 |
| 系統管理員在全平台都沒有任務 | 使用者是系統管理員，平台上沒有任何未封存的任務 | 進入任務列表 | 保留表頭，表格內顯示「尚無任務」，不是錯誤畫面 |
| 空狀態不顯示分頁列 | 畫面正顯示「尚無任務」 | 查看表格下方 | 沒有分頁列 |
| 尚無任務時只有一顆新增 | 畫面正顯示「尚無任務」 | 數一數頁面上的「新增任務」 | 只有上面那一顆，表格裡沒有第二顆 |
| 列表載入失敗 | 平台無法回傳任務列表 | 進入任務列表 | 保留表頭，表格內顯示載入失敗與「重試」，不顯示成空資料 |
| 載入失敗後重試 | 畫面正顯示載入失敗 | 點「重試」 | 重新載入列表 |
| 重試時任務已被別人封存 | 畫面正顯示載入失敗，期間有人把其中一個任務移到封存 | 點「重試」 | 重新載入後列表上沒有那個任務 |
| 輸出型別逐項顯示標籤 | 某任務同時產出三種結果 | 查看它的輸出型別欄 | 依任務設定的順序顯示三個唯讀標籤，沒有被合併成一個名字 |
| 標籤在窄欄位換行 | 某任務有三個輸出型別標籤，欄寬不足 | 查看那一格 | 標籤換行顯示，文字沒有被截斷或重疊，整頁不需要左右滑動 |
| 標籤不只靠顏色表達 | 列表上有多種輸出型別 | 只讀文字不看顏色 | 每個標籤都有看得見的型別名稱 |
| 整組標籤可以當成清單讀出來 | 某任務有兩個輸出型別標籤 | 不看畫面、只聽文字 | 聽得到「輸出型別」加上那兩種型別的完整清單 |
| 刪除不能由別的權限間接取得 | 使用者在某草稿任務有看詳情與管理成員的權限，但不是專案負責人 | 查看那一列的操作欄 | 沒有可用的刪除 |
| 點任務列進入任務詳情 | 使用者看得了某任務的詳情 | 點那一列 | 前往該任務的任務詳情 |
| 點編輯進入任務詳情 | 同上 | 點那一列的「編輯」 | 前往同一個任務的任務詳情 |
| 沒有權限時停在列表 | 使用者看得到某任務但看不了它的詳情 | 點那一列 | 停在任務列表並顯示「無權限檢視任務詳情」，沒有跳頁 |
| 從詳情被退回也要有說明 | 使用者直接打開一個他沒有權限的任務詳情 | 被帶回任務列表 | 顯示同一句無權限的說明，不是一次沒有說明的跳轉 |
| 點新增任務 | 已登入的使用者在任務列表 | 點「新增任務」 | 前往新增任務 |
| 刪除草稿任務 | 使用者是某草稿任務的專案負責人 | 點那一列的「刪除」並在確認視窗確認 | 任務移到封存、從列表消失，顯示已移至封存 |
| 刪除要先確認 | 同上 | 點「刪除」 | 先顯示頁面上的確認視窗，視窗內指名那個任務，任務還沒有變 |
| 按 Esc 關閉確認視窗 | 確認視窗已顯示 | 按 Esc | 視窗關閉，任務完全不變 |
| 在確認視窗取消刪除 | 確認視窗已顯示 | 點「取消」 | 視窗關閉，任務仍在列表上且完全不變 |
| 不是草稿時沒有可用的刪除 | 某任務的狀態是試標中 | 查看那一列的操作欄 | 沒有可用的刪除；若仍被觸發則顯示「此任務狀態不允許刪除」且任務不變 |
| 沒有刪除權限時沒有可用的刪除 | 使用者是某草稿任務的審核員 | 查看那一列的操作欄 | 沒有可用的刪除；若仍被觸發則顯示「無權限刪除任務」且任務不變 |

## Q&A

### Q. 為什麼系統管理員不需要「我的任務／全平台任務」切換？

因為他在這一頁的工作就是看全平台。他如果想看自己參與的那幾個，用篩選或搜尋就到得了，不需要一個會讓人忘記自己正在哪個視角的切換。切換還會帶來一個麻煩：他重新整理之後要記得上次在哪一邊，記錯就看到不對的列表。

### Q. 為什麼一個任務可以同時出現在多個輸出型別的篩選結果裡？

因為一個任務真的可以同時產出多種結果——例如同一批病歷既要標出實體、又要標出實體之間的關係。使用者篩「關係識別」是想找「有做關係識別的任務」，不是「只做關係識別的任務」。把它壓縮成一個固定的組合名稱，等於要求每出現一種新組合就多一個名字。

### Q. 為什麼載入失敗不能顯示成「尚無任務」？

因為這兩件事使用者該做的事完全相反。沒有任務的人該去建立一個；載入失敗的人該重試或等一下。顯示成空資料會讓一個有二十個任務的人以為自己的任務全部不見了。

### Q. 為什麼只有草稿可以刪除？

因為任務一旦進入試標，就已經有人在上面做事了——標記結果、審核紀錄、工時都掛在它底下。草稿還沒有任何人的工作成果，刪掉只影響建立它的人自己。
