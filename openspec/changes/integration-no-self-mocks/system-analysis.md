## 需求矛盾

> 解決狀態（clarification，2026-11-25）：下列矛盾已由決議處理：適用路徑與 `conftest.py`、`probe.py` 的落差由 **Q2** 解決（納入掃描範圍）；issue 例子與 T4 例外的灰區由 **Q1、Q2** 解決；T6 與其來源的 `fetch` 差異由 **Q5** 解決（前端不納入，`fetch` 4 處不列為違規）；「同構」怎麼證明由 **Q6** 解決。

- **T4 的適用路徑與它的正例範圍不一致**（`testing-agent-rules.mdx` T4）：適用路徑只寫 `backend/tests/integration/**`，但「harness 與 production 共用同一個 app 組裝函式」的主體是 `backend/tests/conftest.py`（harness 的組裝點），不在該路徑內。檢查若只掃 `tests/integration/**` 會漏掉 conftest 與 `tests/probe.py`。記為 Q2。
- **issue 的例子與 T4 的例外之間的灰區**（issue #562 工作項 1、T4 例外、T6）：issue 例子是「monkeypatch 或 `dependency_overrides` 指向 `app.` 路徑」；T4 例外允許「外部依賴換成替身」，但規則文件**沒有定義哪些是外部**：`sys.stderr`、環境變數、`export_openapi` 的輸出路徑常數都不是 `app.` 字串路徑，卻性質不同。記為 Q1、Q2。
- **T6 條文與其來源的差異**（T6 §來源列）：來源 scaffold `testing.md` 寫前端「不 mock `fetch` 本身」並標「沿用」，但 T6 的禁止格沒有這一條，現有 4 處 `vi.spyOn(globalThis, "fetch")`（在 unit 層、測 HTTP 邊界本身）。是否算違反 T6 要由維護者定（Q5）。
- **T4 的檢查方式在「待建置」之外沒有定義「同構」怎麼證明**（T4 §檢查方式）：只說「可由共用組裝函式在結構上保證」，但沒有一個測試或規則守住「不另建 `FastAPI(`」。記為 Q6。
- 沒有發現 ADR 與規則文件之間的矛盾：ADR-007 D1、ADR-003 都沒有談替身邊界；全文搜尋 `docs/development/adr/` 的 `mock`、`替身`、`harness` 只有 ADR-003（第 173、245 行）與 ADR-006（第 164、175 行）命中，內容都與本題相容。**ADR 沒有「替身邊界」的決議**，規則只存在於 T4、T6。
