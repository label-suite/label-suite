### 人工驗收步驟（留作紀錄）

以下指令都在 repo 根執行。正式層密碼一律當場產生、只放在環境變數，不寫進任何檔案。

1. **啟動**

   - 前置：Docker Compose **v2.20.0 以上**（`docker compose version`），Node 22、pnpm 10、uv。
   - 安裝：`pnpm run bootstrap`（預期 exit 0，`git config core.hooksPath` 為 `scripts/git-hooks`）。
   - **Lite 層（SQLite，不設 `DATABASE_URL`）**：
     ```sh
     cp .env.example .env
     docker compose up --build --wait --wait-timeout 300   # 預期 exit 0
     ```
     前端與 API 的唯一入口：**http://localhost:8080**（`FRONTEND_PORT`，預設 8080）；API 走 http://localhost:8080/api/v1/ 。後端 8000 不對主機開放。
   - **正式層（PostgreSQL）**：先 `docker compose down -v` 收掉 Lite 層（兩層都用 8080），再
     ```sh
     POSTGRES_PASSWORD=$(openssl rand -hex 16) docker compose -f docker-compose.prod.yml up --build --wait --wait-timeout 300
     ```
     預期 exit 0；入口同樣是 http://localhost:8080 。之後對正式層下 `ps`、`logs`、`stop`、`down` 時要再帶任一個非空的 `POSTGRES_PASSWORD`（只是讓檔案能解析），例如 `POSTGRES_PASSWORD=x docker compose -f docker-compose.prod.yml ps`。
   - **本機開發（不用容器）**：`cp .env.example .env && pnpm run dev`；後端 http://localhost:8000 （`BACKEND_PORT`），前端開發伺服器 http://localhost:5173 。
   - **e2e**：`pnpm --filter e2e exec playwright install chromium` 後 `pnpm --filter e2e test`（自行起 http://localhost:5173 與 http://localhost:8000 ，跑完自動關閉）。
   - **本機自查**：`pnpm run check`（12 步）；`pnpm run check --with-e2e --with-semgrep`（加跑 e2e 與 Semgrep；Semgrep 需本機有 `semgrep`，沒有時可用 `docker run --rm -v "$PWD:/src" -w /src semgrep/semgrep:1.186.0 semgrep --test .semgrep/` 與 `... semgrep scan --error --config .semgrep/label-suite.yml backend/ frontend/ e2e/`）。要跑 PostgreSQL 那一輪時設 `TEST_DATABASE_URL=postgresql+asyncpg://<user>:<password>@127.0.0.1:<port>/<db>`。
