## 目標

- 讓想開任務的人自己把一個標記任務開起來，不必找工程師改程式；**建立完他就是這個任務的** :ref[專案負責人]{id="term.project-leader"}
- 讓「這個任務要標什麼」完全由 :ref[任務設定]{id="term.task-config"} 決定：換一種研究題目只要換設定，平台不用改
- 讓建立者在上傳資料集之後**當場看到自己的資料**，並指定每一欄的用途，而不是先建立任務才發現欄位不對
- 讓四個步驟各自有明確的過關條件，不讓人帶著不完整的設定往下走
- **讓標記員看不到的東西，在建立任務的時候就擋住**：平台不會替建立者猜哪一欄是答案

## 使用角色

:::tip{title="權限代號"}
R：Read（可讀取）　C：Create（可新增）　E：Edit（可編輯）　D：Delete（可刪除）　(o)：只限自己的資料　—：無權限
:::

- :ref[平台成員]{id="term.platform-member"}：C（建立任務）
- :ref[系統管理員]{id="term.system-admin"}：C（建立任務）
- :ref[專案負責人]{id="term.project-leader"}、:ref[審核員]{id="term.reviewer"}、:ref[標記員]{id="term.annotator"}：**無權限**——這一頁在任務還不存在的時候用，進來的人只有系統角色，沒有任何任務角色
- 建立任務的人**建立完才自動成為那個任務的專案負責人**（PRD §使用者角色）；他進這一頁的時候是平台成員或系統管理員
- 系統管理員可以在角色設定（[規格 06-02](../06-admin/02-role-settings.mdx)）把「新增任務」這一格收窄關掉；被關掉的人進不了這一頁，見 [§卡控機制](#卡控機制)
- 這和 PRD §權限矩陣 的「03 新增任務：平台成員 C、系統管理員 C」一致，沒有超出
- 這一頁**不管成員**：邀請標記員與審核員在[規格 03-03 任務詳情](./03-task-detail.mdx)，畫面上也明寫「完成任務建立後，再邀請標記員與審核員加入任務。」

- **建立一個任務**
  - 觸發：使用者在 [規格 03-01 任務列表](./01-task-list.mdx) 點「新增任務」
  - 前置條件：使用者已登入，而且是平台成員或系統管理員
  - 主流程：
    1. 使用者進入第一步「基本資料」
    2. 使用者填任務名稱、上傳資料集、指定每一欄的用途、選這個任務要產出什麼
    3. 系統確認五件事都成立（見 [§什麼時候才能離開第一步](#什麼時候才能離開第一步)）→ 使用者進入第二步「標記設定檔」
    4. 使用者設定每一種輸出類型要怎麼標，並在預覽上試標一次
    5. 系統確認必填都填了、設定沒有錯、也沒有未儲存的改動 → 使用者進入第三步「啟動設定」
    6. 使用者設定試標要抽幾筆、要不要把試標與正式標記的資料隔開
    7. 系統確認筆數通過檢查 → 使用者進入第四步「標記說明」，這一步**選填**
    8. 使用者點「建立任務」→ 系統建立任務、把建立者設為這個任務的專案負責人、記下試標設定
    9. 使用者前往該任務的任務詳情（[規格 03-03](./03-task-detail.mdx)）
  - 替代流程：
    - A1（第 3、5、7 步）任一步的條件沒有通過 → 「下一步」不能點；欄位下方與頁首各顯示一次說明，指出是哪個欄位與怎麼改，使用者留在原步驟
    - A2（任何一步）使用者點「上一步」→ 回到前一步，已填的內容都還在
    - A3（第 7 步）使用者在第四步什麼都不填 → 一樣可以建立任務
  - 例外流程：
    - E1（任何一步）使用者點「取消」，或要離開這一頁（點側欄、關分頁），而且已經改過東西 → 顯示「離開此頁面？」的確認；確認離開就回到任務列表且**不建立任務**，選「繼續編輯」就留在原處，流程結束
    - E2（任何一步）使用者按 F5 → 瀏覽器先問一次；確認後系統把他**還原到原本那一步**並回填所有已填資料，流程結束
  - 結果：任務建立起來，建立者是它的專案負責人，而且試標的抽樣設定已經記下；任務的狀態是 :ref[任務]{id="term.task"} 五個狀態裡的「草稿」

## 規格

### 四個步驟

<PrototypeFrame page="task-management/task-new" caption="新增任務" client:idle />

1. 使用者進入這一頁 → 頁首顯示主標題「新增任務」與副標題「依序完成四個步驟以建立標記任務」
2. 標題下方是四個步驟的進度指示：基本資料、標記設定檔、啟動設定、標記說明
3. 最下方是操作列：「取消」、「上一步」、「下一步」；**第一步看不到「上一步」**
4. 走到第四步 → 「下一步」的文字變成「建立任務」，而且**不會因為第四步沒填而不能點**（第四步選填）

- 這是一條**單行道**：每一步都要通過自己的條件才能往下，但隨時可以回上一步
- 任務要到使用者按下「建立任務」才真的建立；在那之前平台**不會寫入任何正式的任務資料**

### 任務名稱

<PrototypeFrame page="task-management/task-new" caption="新增任務" client:idle />

1. 單行文字欄位，必填，旁邊有字數計數器
2. 上限 100 字
3. 欄位的提示文字舉了一個例子（「例：新聞標題情感分類」），讓建立者知道要寫得具體
4. 任務名稱**可以和別的任務重複**

- 名稱重複不擋，因為同一批資料可能要用不同設定跑好幾次；[規格 03-01](./01-task-list.mdx) 的列表靠更新時間與輸出類型分辨

### 上傳資料集

<PrototypeFrame page="task-management/task-new" caption="新增任務" client:idle />

1. 上傳區可以點也可以拖，說明文字寫「僅支援 JSON · 最大 200 MB · UTF-8」
2. 只收 :ref[JSON 資料集]{id="term.json-dataset"}；單檔上限 200 MB；編碼 UTF-8
3. 上傳成功之後 → **上傳區不會消失**，使用者可以繼續追加檔案
4. 每個已上傳的檔案各佔一列，顯示檔名、檔案大小、一個預覽按鈕與一個移除按鈕
5. 使用者點某一列或它的預覽按鈕 → 開啟一個接近滿視窗的視窗，顯示**那個檔案第一筆紀錄的原始內容**，唯讀；長字串在寬度內自動換行，不需要左右拉；內容太長就在視窗內上下捲
6. 那個視窗可以用關閉按鈕或點視窗外面關掉
7. 使用者移除其中一個檔案 → 系統重新偵測資料列來源、重建欄位剖析與預覽

- **所有上傳的檔案合起來算同一個資料集**
- 非 JSON 的檔案 → 那一個檔案單獨被擋下並顯示錯誤，**已經通過的其他檔案不受影響**
- `.json` 檔裡是一行一筆的寫法時，系統一樣讀得出來
- 追加檔案時，新檔案必須在**目前選的資料列來源**下取得出紀錄、而且欄位集合和已上傳的**完全一致**；不一致就擋下那一個檔案並說明
- 預覽取不出那個檔案的紀錄時 → 依序退：先用那個檔案自己偵測出的最佳來源，還是取不出就顯示它的原始根節點，**保證視窗打開一定有東西可看**

### 資料列來源

<PrototypeFrame page="task-management/task-new" caption="新增任務" client:idle />

一份 JSON 不一定整份就是一個清單，紀錄可能包在某個鍵底下。所以系統要先搞清楚「哪一段才是一筆一筆的資料」。

1. 上傳成功 → 系統自動找出可以當成紀錄清單的陣列（含包在物件裡與多層的寫法），並預設選最合適的那一個
2. 找到多個候選 → 欄位預覽上方出現一個下拉可以手動換，並顯示有幾個候選；每個選項同時顯示它的位置與那裡有幾筆紀錄
3. 只有一個候選 → 那個下拉不能點
4. 完全找不到可用的紀錄清單 → 顯示錯誤並**擋下進入下一步**
5. 使用者換了資料列來源之後，如果有任何已上傳的檔案在新來源下取不出紀錄 → 顯示**指名那個檔案**的不相容提示，而且那個檔案的紀錄**不算進**合併後的總筆數
6. 換到一個所有檔案都取得出紀錄的來源 → 第 5 條的提示解除

### 欄位預覽與欄位的用途

<PrototypeFrame page="task-management/task-new" caption="新增任務" client:idle />

這是第一步的核心：建立者在這裡看到自己的資料，並逐欄指定它在這個任務裡要做什麼。

1. 上傳成功 → 上傳區下方**立刻**出現欄位預覽表格，不必點任何按鈕
2. 表格顯示**前 2 筆**資料列；欄位是目前資料列來源**所有紀錄**第一層鍵的聯集
3. 欄位標頭顯示**原始的鍵名稱**，不翻成中文，旁邊有一個型別摘要：字串、數字、布林、陣列、物件、混合，以及「這一欄全是空的」（畫面用一個破折號表示最後這一種）
4. 陣列或物件的格子顯示摘要文字，滑過去可以看原始內容
5. 提示列顯示資料總筆數
6. 每個欄位標頭下方有一個下拉，四個選項：`— 不使用 —`、`Evidence（背景）`、`Input（輸入）`、`Output（輸出）`；下拉本身沒有可見的標題，但讀螢幕的人會聽到它是這一欄的「角色」

| 用途 | 這一欄在任務裡是什麼 | 有缺值時 |
| :--- | :--- | :--- |
| `Input（輸入）` | 標記員要標的那段內容 | **擋下**，不能進下一步 |
| `Evidence（背景）` | 給標記員參考、但不是要標的那段 | **擋下**，不能進下一步 |
| `Output（輸出）` | 已經有的標記，當成預標記給標記員修改 | **不擋**，那一筆算沒有預標記 |
| `— 不使用 —` | 這個任務不用這一欄 | 不檢查 |

7. 指定用途之後，欄位下方顯示回饋：輸入或背景有缺值 → 紅色錯誤並列出有問題的那幾筆（紀錄有 `id` 就顯示它的值，沒有就顯示列號，先列前幾筆）；輸入或背景全部有值 → 綠色確認；輸出 → 藍色的預標記覆蓋率（幾筆有、共幾筆）
8. 缺值的判斷涵蓋**全部紀錄**，不只預覽的那 2 筆
9. 什麼叫缺值：沒有這個鍵、空值、空字串或只有空白、空陣列、空物件；**`0` 與 `false` 算有值**
10. 預設每一欄都是「不使用」（唯一的例外見 [§自動猜測輸入欄位](#自動猜測輸入欄位)）
11. 重新上傳或移除檔案 → 所有欄位的用途**重設**
12. 換資料列來源 → **各來源已經指定的用途各自記著**，換回來會自動還原；檢查與送出只看目前這個來源
13. 建立任務時只帶**已經指定用途**的欄位；沒有指定的不列入（來源同一條裡另有一句相反的說法，見 [§待釐清](#待釐清) Q5）

- 背景與輸出都是**選填**；兩個都不指定也可以建立任務
- 輸入欄位的數量受 [§選這個任務要產出什麼](#選這個任務要產出什麼) 的輸入類型約束
- 把一欄改回「不使用」→ 它造成的錯誤與阻擋**立刻**解除
- **這一頁不提供「預填來源欄位」的設定**：來源另有一個宣告「整合預覽的預填實體與預填三元組從哪一欄來」的設定，但精靈沒有這個介面，所以用精靈建立的任務一律沒有它；既有任務的這個設定在任務詳情載入與儲存時要原樣保留
- 預填來源的宣告**不會改變欄位的用途**，而且用途是輸出或沒有用途的欄位**一律不得預填**——這和 [§自動猜測輸入欄位](#自動猜測輸入欄位) 的警示是同一條防線

### 自動猜測輸入欄位

<PrototypeFrame page="task-management/task-new" caption="新增任務" client:idle />

欄名看起來就是「要標的那段文字」時，系統先幫建立者填好，省掉一次點擊。

1. 欄位名稱（不分大小寫）包含 `text`、`content`、`sentence`、`passage`、`document`、`body`、`context` 其中任一段 → 視為命中
2. 命中的欄位依原始出現順序被指定為輸入，**最多指定到目前輸入類型需要的數量**（單一項目 1 個、項目對 2 個；還沒選輸入類型時上限 1 個）
3. 超出上限的其餘命中欄位，以及沒命中的欄位 → 維持「不使用」
4. 這個猜測**只作用在還沒指定過用途的欄位**：不會覆寫使用者手動指定的，也不會覆寫換資料列來源時記著並還原的
5. 使用者隨時可以逐欄改掉猜測的結果，改法和手動指定完全一樣

:::warning{title="平台永遠不會自動猜測背景與輸出"}
這是一條**永久規則**，不是這一版的暫行範圍：

輸出欄位的內容會當成預標記**給標記員看得到**。如果平台靠欄名字面去決定哪一欄是輸出，等於把「要不要對標記員公開這一欄」這個判斷從建立者手上拿走。
而研究用的資料集普遍有 `gold_label`、`gold_answer`、`gold_entities` 這類保留答案的欄名——**自動猜測會直接變成** :ref[標準答案]{id="term.ground-truth"} **的洩漏途徑**，違反 `AGENTS.md` 的測試集保護。

所以背景與輸出一律由建立者自己指定。日後若要放寬，必須先提出一個**不依賴欄名字面比對**的建立者確認機制。
:::

### 清單標題

<PrototypeFrame page="task-management/task-new" caption="新增任務" client:idle />

標記員之後在標記清單上看到的每一列要顯示什麼，從這裡決定。

1. 資料列來源那一列旁有一個「清單標題」下拉（畫面上的標籤是「標記清單標題欄位（清單標題）」），預設是「自動（依資料形狀）」
2. 選項只有三種來源：「自動（依資料形狀）」、目前來源裡用途是**輸入或背景**的欄位、以及名稱叫 `id` 而用途不是輸出的欄位
3. **用途是輸出的欄位一律不會出現在選項裡**
4. 物件陣列的欄位會標成「〈欄位名〉（取第 1 則的文字）」
5. 「標記清單預覽」列出目前來源**前 3 筆**的標題（來源要求它在表格下方，**畫面目前放在表格上方**，見 [§待釐清](#待釐清) Q1）
6. 選「自動」時，每一筆的標題和標記清單上看到的完全一樣——取第一個能產生文字的輸入欄位，不截斷；還是沒有文字才退回 `id`，而 `id` 的用途是輸出時退回列號
7. 明確選了某一欄時，預覽上的標題**太長會截斷**（約 40 字並加省略號），那一筆是空的就顯示「（空白）」
8. 下拉選擇、欄位用途指定、換資料列來源之後 → 預覽**立刻**更新，不必按任何按鈕
9. 已選的欄位不再是合法選項時（改成「不使用」或輸出、或換來源之後不存在了）→ 清單標題**退回「自動」**並顯示一句說明原因的提示
10. `id` 是例外：只有改成輸出或換來源之後不存在，才算不再合法；改成「不使用」時仍然可以選
11. 第 9 條的提示會**一直顯示**，直到使用者重新選一次清單標題，或把所有資料集檔案移除為止；期間的欄位用途變更與預覽重繪都不會讓它消失

- 第 6 條的「和標記清單完全一樣」是刻意的：建立者在這裡看到的就是標記員之後會看到的，不是另一套算法

### 對話串欄位

<PrototypeFrame page="task-management/task-new" caption="新增任務" client:idle />

資料是一段對話時，標記員應該看到一則一則的發言，而不是一坨原始內容。

1. 輸入欄位在前幾筆紀錄裡是**非空的物件陣列**，而且有至少一個子欄位在所有元素裡都是字串 → 出現「對話串欄位」的確認區，開頭是一個「以對話串呈現此輸入欄位」的勾選項（來源要求它在欄位預覽下方，**畫面目前放在表格上方**，見 [§待釐清](#待釐清) Q1）
2. 確認區有四個對應：**文字欄位**（必選）、**發言者欄位**（可選）、**發言編號欄位**（可選，不選就用陣列順序從 1 起算）、**回覆對象欄位**（可選，預設留空）
3. 系統依偵測結果預填前三個，建立者可以改任何一個，也可以把那個勾選項取消掉——**取消就是取消提議**；重新勾起來會重新偵測並重新預填
4. 偵測不到 → 不提議；第二步的預覽就照原始內容呈現
5. 子欄位的名稱只決定**預填什麼**，不決定要不要提議；而且只看用途已經是輸入的欄位
6. 已確認的對應在欄位用途變更、換資料列來源或重新上傳之後變得不合法 → 系統**重新偵測**
7. 建立者取消提議之後 → 系統**不再自動預填**
8. 回覆對象欄位指的是「這則發言在回誰」，候選是所有元素裡值都是字串、數字、空值或缺漏、而且至少一個元素非空的子欄位，不含已經選為文字欄位的那一個
9. 沒有任何合格的候選 → **不顯示**回覆對象這個下拉
10. 系統**不預填回覆對象**：不看欄位名稱、不從內文的 `@某人` 猜、也不從實體推——建立者沒選就是沒有
11. 已確認的回覆對象變得不合法 → 只把它清空，**其他仍然合法的對應保留**
12. 確認之後，第二步的預覽以對話串呈現：一則一列，含發言編號、發言者（如果有）與文字

- 第 10 條和 [§自動猜測輸入欄位](#自動猜測輸入欄位) 的理由同一類：猜錯回覆關係會讓標記員看到錯的對話結構，而這件事建立者自己最清楚
- 預覽的文字來源**絕不對物件硬取字串**；沒有輸入欄位時也**不會退回任何不是輸入的欄位**
- 偵測到了但建立者還沒確認、或已經取消提議 → 第二步的預覽同樣照原始內容呈現，不以對話串呈現
- 輸入欄位是單純的字串時，文字內容和沒有對話串這件事之前**完全一樣**，不受本節影響
- 既有任務的對話串設定裡沒有「回覆對象」這一項時，視同沒有選
- 這一節只適用輸入類型是「單一項目」的時候

### 選這個任務要產出什麼

<PrototypeFrame page="task-management/task-new" caption="新增任務" client:idle />

1. 這一區有**三組**選擇：大分類（可多選）、輸入類型（單選）、:ref[輸出類型]{id="term.output-type"}
2. 大分類四個：分類、回歸、序列、生成
3. 輸入類型兩個，互斥：單一項目、項目對
4. 輸出類型依已選的大分類**連動過濾**，每個大分類底下的選擇方式由它自己決定：

   | 大分類 | 選擇方式 | 底下的輸出類型 |
   | :--- | :--- | :--- |
   | 分類 | **單選**，兩項互斥 | :ref[單一標籤]{id="term.single-label"}、:ref[多標籤]{id="term.multi-label"} |
   | 回歸 | **單選**，兩項互斥 | :ref[單維度]{id="term.single-dim"}、:ref[多維度]{id="term.multi-dim"} |
   | 序列 | **多選** | :ref[序列標註]{id="term.sequence-tagging"}、:ref[實體辨識]{id="term.entity-recognition"}、:ref[關係識別]{id="term.relation-identification"} |
   | 生成 | **多選** | :ref[自由文字]{id="term.free-text"} |

5. 大分類與輸入類型**永遠看得到**
6. 還沒選任何大分類 → 輸出類型那一區顯示灰色提示「請先選擇大分類」，不顯示任何選項
7. 只選 1 個大分類 → 直接顯示它底下的輸出類型，不加分組標題
8. 選 2 個以上 → 依大分類分組顯示並加上分類名稱的子標題
9. 取消某個大分類 → 那一組輸出類型消失，而且**已選的自動取消**
10. 分類與回歸在同一組內換選項 → 原本選的自動取消；序列可以同時留著多個（含實體辨識與關係識別一起選）
11. **跨大分類可以同時選**：一個任務可以既做分類又做序列
12. 切換語言 → 所有選項的文字即時跟著換
13. 這八種以外的舊輸出類型（平台早期用過、現在已經退役的那幾種）**不得出現在任何大分類、任何輸入類型或任一語言的選項裡**

- 八個中文名稱依來源定案並進術語表，見 [§已確認決議](#已確認決議) Q10；其餘頁面引用術語表，不各自定名
- 這一區在畫面上的標題是「任務類型」，但 D3 已經讓「任務類型」退役，見 [§待釐清](#待釐清) Q2
- 畫面上輸出類型那一組的標題寫「可多選」，但分類與回歸其實是單選，見 [§待釐清](#待釐清) Q4
- 平台**不會**從這三組推導出一個「單一的任務類型」存起來——這是刻意的，見 [§已確認決議](#已確認決議) Q11

### 什麼時候才能離開第一步

<PrototypeFrame page="task-management/task-new" caption="新增任務" client:idle />

「下一步」預設不能點，五個條件**全部**成立才能點：

1. 任務名稱非空
2. 至少選了一個輸出類型
3. 資料集檔案通過格式、大小與編碼檢查，而且至少有一個檔案
4. 輸入欄位的數量符合輸入類型：單一項目**恰好 1 個**、項目對**恰好 2 個**
5. 所有輸入欄位、以及所有已指定為背景的欄位，都**沒有缺值**

- 條件沒過時的訊息在欄位下方顯示一次、頁首也顯示一次，兩邊都要指出**欄位名稱**與**怎麼改**
- 同時有多個欄位缺值時，頁首先顯示第一個不完整的欄位
- 找不到可用的資料列來源也會擋下（見 [§資料列來源](#資料列來源)）

### 標記設定與標記預覽的版面

<PrototypeFrame page="task-management/task-new" caption="新增任務" client:idle />

第二步是這一頁的核心：建立者在這裡決定「每一種輸出類型要怎麼標」，並在旁邊的預覽上**真的標一次**看看。

1. 第二步這張卡的標題是「標記設定檔」
2. 卡裡分成兩塊：**標記設定**在一邊、**標記預覽**在另一邊，兩塊的小標字樣與層級一致、上緣對齊
3. 螢幕夠寬時 → 設定在左、預覽在右
4. 螢幕較窄時 → 設定在上、預覽在下，設定裡的每個面板照樣操作得到
5. 兩塊下方是一張**設定檔工具卡**：範本與上傳在上、分隔線、然後是可編輯的設定內容與「儲存」
6. 這個版面是**所有輸出類型與所有組合共用的**，不會因為選了哪一種而換成另一套版面

- 平台之後新增一種輸出類型時，它會**自動沿用同一套版面**，不必為它另做一頁
- 設定與預覽永遠成對出現：改了設定，旁邊的預覽立刻跟著變

### 每一種輸出類型的設定欄位

<PrototypeFrame page="task-management/task-new" caption="新增任務" client:idle />

1. 不論選了一種還是多種，**每一種輸出類型各佔一個可展開收合的面板**，面板標題是序號加上它的名稱
2. 選超過兩種時 → 只有第一個面板預設展開，其餘預設收合
3. 面板標題可以用鍵盤聚焦與開合
4. 面板裡的設定欄位**由平台的輸出類型清單決定**，不是寫死在這一頁
5. 每一種輸出類型的設定欄位如下：

| 輸出類型 | 設定欄位 | 必填 |
| :--- | :--- | :--- |
| :ref[序列標註]{id="term.sequence-tagging"} | 標籤類型（可新增刪除的清單，每項有顏色與名稱；**不得為空、也不得有空白的項目**） | 是 |
| | 選取吸附（字元／詞） | 是 |
| :ref[實體辨識]{id="term.entity-recognition"} | 實體類型（同上的清單，同樣不得為空或有空白項目） | 是 |
| | 選取吸附（字元／詞） | 是 |
| | 允許重疊標記 | 否 |
| :ref[關係識別]{id="term.relation-identification"} | 語意類型標籤（按 Enter 新增的標籤列，提示文字舉了 `causes`、`bodyLocation` 為例） | **否** |
| :ref[單一標籤]{id="term.single-label"} | 標籤選項（同上的清單，同樣不得為空或有空白項目） | 是 |
| :ref[多標籤]{id="term.multi-label"} | 標籤選項（階層式的樹，見 [§階層標籤的編輯與選取](#階層標籤的編輯與選取)） | 是 |
| | 最多可選數量（0 代表不限） | 否 |
| :ref[單維度]{id="term.single-dim"} | 維度名稱、最小值、最大值、間距（**最小值要小於最大值、間距要大於 0**） | 是 |
| :ref[多維度]{id="term.multi-dim"} | 維度列表（**至少一個維度**，每個維度一張卡；同樣要最小值小於最大值、間距大於 0） | 是 |
| :ref[自由文字]{id="term.free-text"} | 輸入區說明（預設「請閱讀以下內容」，**去掉空白後不得為空、最多 100 字**） | 是 |
| | 作答區說明（預設「請輸入回答」，**同樣不得為空、最多 100 字**） | 是 |
| | 最大字數 | 否 |
| **每一種都有** | 允許無法判定 (Bypass)（預設開啟） | 否 |

6. 清單型欄位的「新增」按鈕文字**依語境改字**：單一標籤是「新增標籤」、實體辨識是「新增實體類型」、序列標註是「新增標籤類型」
7. 「允許無法判定 (Bypass)」是**每一種輸出類型都有的共通欄位**，由平台統一附加，不在個別型別裡各寫一次
8. 自由文字**不得再有「顯示參考答案給標記者」這個設定**（含它的舊名）：設定面板不顯示它、設定內容也不存它
9. 讀進一份還帶著那個舊設定的設定檔 → **把它移除**，並依目前語言補上兩段說明的預設值；補完之後不能卡在「畫面看起來有值、實際上沒有所以過不了」的狀態

- 單維度與多維度**用同一種維度卡片**：同樣的欄位標籤、同樣的三欄排列。單維度固定一張卡、沒有新增與刪除；多維度可以有多張並能新增刪除，而且卡片清單上方**不再重複顯示「維度設定」這個標題**
- 多維度的維度是**通用的**：名稱與範圍由建立者自訂，不限於某一組特定維度
- **序列標註沒有「允許重疊標記」這個設定，而且永遠不重疊**：這是這一種型別的固有性質，不是可以調的欄位。設定面板不顯示它、設定內容不存它，而且**在設定內容區貼一份帶著它的設定會被判定為錯誤並擋下**，平台不會默默把它改成「不允許」
- 「選取吸附」**只影響圈選的落點，不影響存下來的位置**：選「字元」就是拖到哪裡算哪裡，選「詞」就是放開滑鼠時把頭尾各自對齊到最近的詞界。兩種設定存出來的資料結構完全相同，**切換它不會讓任何既有標記失效、錯位或被清掉**
- 有些瀏覽器判斷不出詞界：選了「詞」但環境做不到時 → **退回「不吸附」的行為**，而且**不因此改寫任務的設定值**（建立者看到的設定還是「詞」）

### 標記預覽的共通規則

<PrototypeFrame page="task-management/task-new" caption="新增任務" client:idle />

1. 每一種輸出類型在預覽裡有**自己的互動區塊**，建立者可以真的點、圈、拖、打字
2. 已經上傳資料集 → 預覽顯示**資料集的實際內容**；還沒上傳 → 顯示預設的範例文字
3. 預覽的文字取自用途是**輸入**的欄位
4. 在某一種輸出類型的預覽上操作 → **只刷新那一塊**，不會動到輸入文字，也不會動到其他輸出類型的預覽
5. 設定欄位一改 → 預覽立刻跟著更新
6. 幾種輸出類型**自己就會把輸入內容完整呈現**（序列標註、實體辨識、關係識別、自由文字）；只要選了其中任何一種，預覽就**不再另外顯示一塊通用的輸入文字**
7. 都沒有選到那幾種時 → 通用的輸入文字區塊顯示在所有輸出類型預覽的**上方**
8. 通用輸入文字的呈現依輸入類型：單一項目顯示一個「原始文本」標題加一塊文字；項目對在配對區塊上方顯示一次「原始文本」，底下兩塊文字各有自己的小標（小標的字見 [§項目對名稱](#項目對名稱)）
9. 預覽**預設不為「背景」欄位顯示獨立區塊**；只有自由文字例外——它會在最上面顯示「背景參考 (Evidence)」與那一欄的實際內容
10. 沒有指定背景欄位時 → **不顯示空的背景區塊**

- 第 6、7 條是**依輸出類型自己的宣告推導**的，不是看任務叫什麼名字；複合的任務一樣照這個規則走
- 多種獨立的輸出類型之間用分隔線隔開，而且**有固定的先後**：自己呈現輸入的那幾種排前面，自由文字排最後
- 實體辨識與關係識別合併時，那一塊有一個「整合預覽」的標題
- 指定了多個背景欄位時，每一塊各帶自己的欄位名小標
- 多維度一個維度都沒有時，預覽顯示提示而不是空白

### 八種輸出類型的預覽互動

<PrototypeFrame page="task-management/task-new" caption="新增任務" client:idle />

| 輸出類型 | 建立者在預覽上可以做什麼 |
| :--- | :--- |
| 序列標註 | 在**未切分的原始文本**上拖曳圈出一段，然後點一個標籤類型完成標記；下方是已標記的清單（含類型、文字、位置與刪除）。圈到和既有標記相交的位置 → 當場拒絕並回饋 |
| 實體辨識 | 圈文字建立實體、一排實體類型按鈕、實體清單（含位置與刪除）。**兩種順序都支援**：先選類型再圈文字，或先圈文字再選類型 |
| 關係識別 | 依序操作「第一個對象 → 關係 → 第二個對象 → **退回** → 新增」的建構器（退回讓建立者取消上一步，不必整個重來），下方是三元組清單。單獨使用時，既有實體只是**唯讀的高亮**，不能建立或刪除實體 |
| 單一標籤 | 文字加一排標籤，**只能選一個**，點了會切換 |
| 多標籤 | 文字加一個**可搜尋的階層選擇器**，見 [§階層標籤的編輯與選取](#階層標籤的編輯與選取) |
| 單維度 | 文字加一個維度名稱與一條可拖的滑桿；當前值即時跟著滑塊顯示在它正上方，左邊顯示最小值，右邊有一個可以直接打數字的欄位 |
| 多維度 | 每個維度各一條獨立的滑桿，每條用不同顏色；其餘和單維度一樣。**顏色只是輔助**，維度名稱、當前數值與範圍都還是讀得到的 |
| 自由文字 | 選填的「背景參考 (Evidence)」、輸入區說明、輸入的實際內容、作答區說明，然後是一個可編輯的作答框（含字數計數器） |

1. 實體辨識的「先圈後選」那一條：還沒選類型就圈起來的範圍 → **持續反白等著**，不顯示任何催促的提示；建立者點了類型才完成新增，而且那個類型**保持作用中**，方便連續標
2. 新圈的範圍會**取代**上一個還沒分類的範圍
3. 關係識別在單獨使用時，建立者選到不是既有實體的文字 → 提示他改選已經高亮的實體
4. 關係識別的三個元素都存並顯示「文字加上它在原文的位置」
5. 關係識別的「類型」選單**只在語意類型標籤不是空的時候才出現**；空的時候三元組列不顯示類型徽章也沒有選單
6. 滑桿與右邊那個數字欄位**雙向同步**，兩邊都能用鍵盤操作；數字欄位可以直接打範圍內的小數，**不會被間距吸附**，只有超出最小值或最大值才校正到邊界
7. 自由文字的作答框與兩段說明：主要標題用建立者設定的說明，**不用資料欄位的原始名稱**
8. 自由文字有指定輸出欄位 → 作答框以那一欄的值預填；沒有指定 → 作答框是空的，而且上方**不顯示「回答」這個字**
9. 自由文字的輸入內容卡**只取用用途是輸入的欄位**；取不到時**不回退去顯示其他欄位**（否則背景或輸出的資料會因為回退而外流）
10. 自由文字和實體辨識一起選時 → 它的專屬預覽**不重複顯示輸入內容卡**，但輸入區說明的標題照樣顯示
11. 兩段說明去掉空白之後是空的 → 預覽顯示**實際的空值**，不是拿預設值去補
12. 自由文字勾了無法判定 → **只清空停用作答區**，輸入區說明與輸入內容**仍然讀得到**

- 關係識別**可以單獨使用**；它和實體辨識一起選時才有整合預覽，見下一節
- 單獨使用時，預覽**不再顯示一層重複的「關係識別預覽」內層標題**
- 序列標註的預覽**不顯示「序列標註」這個卡片標題**，直接從「原始文本」開始；自由文字同樣不顯示它的卡片標題

### 實體辨識與關係識別的整合預覽

<PrototypeFrame page="task-management/task-new" caption="新增任務" client:idle />

這兩種輸出類型有一個**單向的來源關係**：關係識別可以單獨用，但和實體辨識一起選時，實體辨識圈出來的實體就是關係可以連的對象。

1. 兩種**同時被選** → 預覽合併成一個整合的介面：共用同一段文字、可以先建立或修改實體、再建立關係；實體清單與三元組清單合併呈現
2. 整合模式下，同一個反白的範圍**兩邊都能消費**：點實體類型就是建立實體，點關係的步驟就是建立關係草稿
3. 整合模式會在關係識別的設定面板標題下方顯示一個**相依提示**
4. 整合模式下，關係識別的設定會自動記下「實體從實體辨識來」
5. 只選關係識別 → **不顯示實體辨識的面板，也沒有相依提示**，而且設定裡不會有那個「實體從哪裡來」的記錄
6. 選了關係識別**不會自動把實體辨識也加進來**；只有建立者自己兩個都選才啟用整合模式
7. 取消實體辨識 → 關係識別**留著**，切回單獨模式並把那筆記錄移除，**已經建好的三元組不會被連帶取消**
8. 整合模式也要能從**完全沒有預標記的空白狀態**開始標

- 複合的任務一律**當成多個單一輸出類型的組合**：除了上面明訂的協作，每一種輸出類型在整合預覽裡還是保有自己的設定、互動、無法判定與驗收，不會因為合併呈現就被省略

### 階層標籤的編輯與選取

<PrototypeFrame page="task-management/task-new" caption="新增任務" client:idle />

多標籤的標籤選項不是一層的清單，而是一棵**可以有上下層的樹**。

**編輯那棵樹**

1. 建立者可以新增根節點、子節點與同層節點，編輯每個節點的識別碼與顯示名稱，調整同層順序，展開收合，以及刪除整個分支
2. 每個節點的識別碼**在整棵樹裡唯一而且穩定**，改顯示名稱不會改它
3. 顯示名稱**可以跨分支重複**
4. 一個節點加了第一個子節點之後 → 它變成分支，但**仍然可以被選**；原本已經選的保留；分支不能設顏色，所以原本的顏色會被移除
5. 每個結構操作都有**可以聚焦、名稱具體的按鈕**，不是只能靠拖拉
6. 那棵樹可以用鍵盤走：上下移動、向右展開或進入第一個子節點、向左收合或回到上一層、跳到第一個與最後一個節點
7. 刪除**含有子節點**的分支 → 先用頁面上的確認視窗攔下來，內容要寫出會一併刪掉幾個子節點、而且不可復原；可以取消
8. 沒有子節點的節點刪除**不需要確認**
9. 刪掉的分支裡有預覽已經選的節點 → 那些選取一併移除，焦點移到前一個看得到的節點或它的上一層
10. 新增、刪除與驗證結果都會**播報給讀螢幕的人**
11. 那棵樹有三個上限：**最多 8 層**（根算第 1 層）、**最多 500 個節點**、**識別碼與顯示名稱各最多 100 字**
12. 超過任一個上限，或有空值、識別碼重複、子節點無效時 → **三個入口（手動編輯、設定內容、從資料集帶入）用同一套規則一起擋下**，並保留最後一份有效的設定，不會只建出一半的樹

**在預覽上選**

13. 選擇器**可以搜尋**，比對的是節點名稱與它的上層名稱
14. 清單**攤平顯示所有層級**，用縮排表達階層，沒有展開收合
15. 每個節點都有自己獨立的勾選框，**選上層不會連動下層**
16. 選項**不顯示完整路徑**，但完整路徑保留在它的可存取名稱裡，讓不同分支下的同名節點分得開
17. 選了一個節點之後 → **選擇器保持開啟**，焦點留在剛操作的那個勾選框，並播報選了什麼與已選幾個
18. 要關閉選擇器 → 按 Esc、點關閉、點觸發按鈕，或點選擇器外面；用 Esc 或關閉按鈕關掉時焦點回到觸發按鈕
19. 已選的標籤只顯示**被選節點的名稱**，不顯示整條路徑；但移除按鈕的可存取名稱可以保留完整路徑
20. 搜尋列與標題**固定在選擇器頂端**，不隨清單捲動
21. 「最多可選數量」依**已選節點的條數**計算；到達上限時其餘未選的節點變成不可選，但**已經選的還是可以取消**
22. 那個數量填 0 代表不限；填的數字比可選的節點總數還大 → 顯示一個不擋流程的提示並**視同不限**

- 兩個不同分支下有同名的節點時，它們靠完整路徑**各自獨立**，不會因為顯示的字一樣就互相覆蓋

### 無法判定（Bypass）

<PrototypeFrame page="task-management/task-new" caption="新增任務" client:idle />

標記員遇到真的判斷不出來的資料時，需要一個誠實的出口，而不是被迫亂選一個。

1. 每一種輸出類型的設定裡都有一個「允許無法判定 (Bypass)」的開關，**預設開啟**
2. 開著 → 那一種輸出類型的預覽區塊**底部**顯示一個獨立的「無法判定 (Bypass)」勾選項
3. 關掉 → 那個勾選項不顯示，而且**既有的勾選狀態一併清除**、預覽重新初始化
4. 勾了之後 → 那一種輸出類型預覽的其他控制項**清空並停用**（看得出來不能操作），但**不影響輸入文字，也不影響其他輸出類型**；那個勾選項本身還是點得到
5. 取消勾選 → 那一塊恢復可操作，並且**像第一次載入一樣重新初始化**（包含從資料集帶入的預標記會重新套用）
6. 重新上傳或移除資料集檔案 → 所有輸出類型的勾選狀態一併重設
7. 實體辨識與關係識別的整合預覽裡，兩者**各有一個帶名稱前綴的勾選項**（例如「實體辨識：無法判定 (Bypass)」）
8. 在整合預覽裡勾**實體辨識**的那一個 → 因為關係要靠實體，**整區（含關係建構器）一起清空停用**
9. 勾**關係識別**的那一個 → 只清空停用關係建構器與三元組清單，**實體的標記不受影響**

- 這一節定的是「標記員之後在標記工作區會有什麼可用的行為」；那個介面長什麼樣由[規格 04-02 標記工作區](../04-annotation/02-annotation-workspace.mdx)定

### 從資料集帶入預設值

<PrototypeFrame page="task-management/task-new" caption="新增任務" client:idle />

建立者在第一步指定了用途是**輸出**的欄位時，那些值就是**已經有的標記**，第二步會用它們把設定與預覽先填好。

1. 有輸出欄位 → 各輸出類型的預覽**以那一欄的實際值初始化**：單一標籤預選對應的標籤、維度的滑桿設到實際數值、序列標註與實體辨識依位置落位、關係識別帶入實際的三元組、自由文字預填實際答案
2. 單一標籤的**標籤選項**也從資料裡出現過的值自動建出來
3. 多標籤的自動帶入**看資料的形狀**：一層的字串清單 → 建一層標籤；巢狀的路徑清單 → 依所有紀錄第一次出現的順序合併共同前綴，建出一棵合併的樹，並且**只用第一筆資料初始化預覽的選取**
4. 以下情況**算資料錯誤**，一律擋下自動帶入並**指出是哪一列的哪一欄**，不猜也不截斷路徑：同一欄混用兩種形狀、路徑裡有不是字串的段、同一個識別碼出現在不同上層之下、路徑沒有從根開始，以及路徑對不上既有的任何一條完整路徑
5. 輸出欄位的第一筆是一個物件 → **多維度的維度列表自動從它的鍵建出來**，每個維度的範圍依實際資料推斷（例如值都在 0 到 1 之間就用 0 到 1 與小數間距，有負值就對稱擴展，值很大就把上限放大），不是一律套同一組預設範圍
6. 預標記的三元組帶有語意類型時 → 關係識別的**語意類型標籤自動從資料裡出現過的類型帶入**（依出現順序去重），讓設定與選單反映實際資料，而不是寫死的預設值
7. 三元組裡認不出語意類型時 → 語意類型標籤**維持空的**，三元組列不顯示類型徽章與選單
8. 自動帶入**只做一次**，帶過之後不重複執行
9. 沒有輸出欄位 → 各輸出類型維持自己的預設值，自由文字的作答框是空的
10. 有多個輸出欄位 → 依每一欄的資料形狀**對應到形狀相符的輸出類型**各自初始化

:::warning{title="輸出欄位是建立者明確指定的預標記，不是繞過測試集保護的後門"}
輸出欄位的內容會**給標記員看得到並可以修改**，所以它只能是建立者自己指定的、要公開給標記員的預標記。
它**不得被用來把隱藏的** :ref[標準答案]{id="term.ground-truth"} **下發給標記員**——這和 [§自動猜測輸入欄位](#自動猜測輸入欄位) 的警示是同一條防線，也是 `AGENTS.md` 的測試集保護在第二步的落地。
:::

### 項目對名稱

<PrototypeFrame page="task-management/task-new" caption="新增任務" client:idle />

輸入類型是「項目對」時，兩段文字在畫面上要各有一個名字，標記員才知道哪一段是什麼。

1. 輸入類型是項目對 → 設定那一邊的面板清單**上方**多一張「項目對名稱」設定卡，**不能收合**，外框和輸出類型的面板一樣
2. 卡裡有兩個單行欄位：「項目一名稱」與「項目二名稱」
3. 預設值是第一步兩個輸入欄位的**原始欄位名稱**，依輸入欄位的順序帶入
4. 沒有可用的輸入欄位 → 退回「句子 A」與「句子 B」
5. 建立者改任一個 → 預覽配對區塊對應的小標**即時跟著變**
6. 把某一個清空（去掉空白之後是空的）→ 那一側的小標**退回預設值**，另一側不受影響
7. 換資料集、重新上傳，或改了欄位用途 → 兩個欄位**重新以新的輸入欄位名稱初始化**，先前編輯的值捨棄
8. 輸入類型是單一項目 → **不顯示這張卡**

- 這張卡只影響第二步的設定與預覽顯示的名字，**不改變欄位的用途，也不改變資料本身**

### 設定檔工具：範本、上傳與設定內容

<PrototypeFrame page="task-management/task-new" caption="新增任務" client:idle />

兩塊主工作區下方那張工具卡，給的是「不想一個一個點」的另一條路。

1. 工具卡是**一個外框**，依序是：範本與上傳那一列、分隔線、格式切換、可編輯的設定內容、「儲存」；範本與設定內容**不各自再做一個外框**
2. 「從範本開始或者上傳設定檔」那一列：範本按鈕依已選的輸出類型提供預設模板，點了就載入（**畫面目前只為「實體辨識＋關係識別」這一個組合產生範本按鈕**，見 [§待釐清](#待釐清) Q8）
3. 「上傳設定檔（YAML / JSON）」：讀進來之後**載到設定內容區，要建立者自己按儲存才套用**
4. 設定內容可以用兩種格式呈現並切換
5. 設定欄位與設定內容**共用同一份設定**：改設定欄位 → 設定內容即時跟著變
6. 在設定內容區手改之後點「儲存」→ 設定欄位同步更新；**設定無效時顯示錯誤**，而且錯誤要指得出位置、建立者打的內容要留著
7. 切換語言時，**設定內容區沒有未儲存的改動、而且目前用的還是預設的標籤文字** → 標籤跟著換語言；**有未儲存的改動就不自動覆寫**，保留建立者手改的內容

- 第 3 條與第 6 條都是刻意的：平台**不會自動儲存、也不會自動覆寫**建立者在設定內容區打的東西
- 建立者回到第一步改了選的輸出類型 → **被取消那幾種的設定移除，仍然選著的保留**，不會整份重來
- 設定內容區**有未儲存的改動時不能切換格式**，避免改動在切換時消失
- 以兩種格式各存一次再回填 → 階層標籤的結構、順序、識別碼、名稱、葉節點顏色與「最多可選數量」**完全相同**，不會在來回之間失真

### 什麼時候才能離開第二步

<PrototypeFrame page="task-management/task-new" caption="新增任務" client:idle />

「下一步」預設不能點，三個條件**全部**成立才能點：

1. 所有已選輸出類型的**必填設定欄位都通過**
2. 設定內容**沒有格式或結構的錯誤**
3. 設定內容區**沒有未儲存的改動**

- 第 3 條不會自動幫建立者儲存，也不會自動丟掉他的改動——它只是擋著並提示先儲存
- 關係識別的「語意類型標籤」是**選填**，空的時候不會擋住前進
- 任務建立送出前，所有輸出類型的設定都要再通過一次驗證；有任何一項沒過就不會真的建立任務

### 啟動設定

<PrototypeFrame page="task-management/task-new" caption="新增任務" client:idle />

第三步只做兩件事：**把這個任務的** :ref[試標]{id="term.dry-run"} **要抽幾筆先定下來**，以及要不要把試標與正式標記的資料隔開。

1. 這一步的開頭就提示「完成任務建立後，再邀請標記員與審核員加入任務。」——**第三步不管成員**
2. 「抽樣設定」裡有一個「每回合抽樣筆數」的數字欄位，旁邊有一個「?」按鈕，滑過去或用鍵盤聚焦時顯示它的範圍
3. 抽樣的方式**固定是「抽幾筆」**，畫面上沒有百分比那種模式，也沒有抽樣分佈的進度條
4. 建立者在第一步選好輸出類型之後 → 這個欄位**自動預填一個建議的筆數**，依大分類的試標比例換算：

   | 大分類 | 試標比例 |
   | :--- | :--- |
   | 分類 | 12% |
   | 回歸 | 15% |
   | 序列 | 15% |
   | 生成 | 18% |

5. 選了多個大分類 → **取比例最高的那一個**（例如同時選了分類與生成，用 18%）
6. 畫面上**不暴露百分比**：建立者看到與填的都是筆數
7. 筆數要**至少 1 筆、而且小於資料集的總筆數**
8. 下方是「資料隔離」的開關，**預設開啟**，說明寫「預設啟用，避免試標與正式標記資料混用」
9. 「下一步」預設不能點，**筆數通過檢查才能點**

- 第 3 條的「沒有進度條」是刻意的：任務詳情的抽樣設定用的是固定筆數，兩邊要一致，不要在這裡給一個百分比的印象
- 第三步只做**第一次**的初始化；之後要調整，以及邀請成員，都在[規格 03-03 任務詳情](./03-task-detail.mdx)
- 建立者在這一步設的筆數與資料隔離，建立成功後**在任務詳情看到的是同一份**

### 標記說明

<PrototypeFrame page="task-management/task-new" caption="新增任務" client:idle />

第四步**整步選填**：開頭就寫「此步驟為選填。不上傳說明，仍可完成任務建立。」

1. 這一步分成兩組**互相獨立**的說明：「提供給標記員」與「提供給審核員」
2. 每一組都有一個可以直接打字的說明欄位（「標記說明內容」與「審核說明內容」）與一個**自己的**附件清單
3. 兩組都可以**只打字、只上傳檔案，或兩者都用**；也可以兩組都空著
4. 附件支援**多檔**，可以逐檔移除；兩組的清單彼此獨立
5. 附件可以是 PDF、圖片或 Markdown；圖片限 PNG、JPG、JPEG、WebP
6. 超出這些格式的檔案 → **擋下並提示**
7. 最下面是「開始標記前強制顯示」的開關，**預設關閉**，說明寫「啟用後，標記員進入作業前必須先閱讀說明」
8. 走到第四步時，操作列的「下一步」文字變成「建立任務」，而且**不會因為沒填而不能點**（送出中會進入等待狀態，見 [§規格 › 建立任務](#建立任務)）

- 第 3 條是刻意的：**不強制兩個角色都填**。有些任務只需要給標記員說明，有些只需要給審核員
- 開關打開之後，標記員**第一次進入這個任務的標記介面**時會看到說明視窗；他確認讀過之後，**重新整理或再次進入都不會再跳**。那個視窗長什麼樣、怎麼預覽附件的圖片，由[規格 04-02 標記工作區](../04-annotation/02-annotation-workspace.mdx)定

### 建立任務

<PrototypeFrame page="task-management/task-new" caption="新增任務" client:idle />

1. 建立者點「建立任務」→ 系統建立任務，並在**同一個動作裡**完成四件事：把建立者設為這個任務的 :ref[專案負責人]{id="term.project-leader"}、保存第二步的設定、保存第三步的啟動設定、**保存第四步兩個角色的說明內容與附件**（沒填就是空的）
2. 成功 → 前往該任務的任務詳情（[規格 03-03](./03-task-detail.mdx)）；暫存的精靈內容清掉
3. **任何一步失敗 → 整件事回到原狀**：不會留下一個「有任務卻沒有負責人」、「有任務卻沒有設定」或「有任務卻沒有說明」的半套結果
4. 送出中 → 「建立任務」進入等待狀態並**不能重複點**
5. 網路中斷之後重送同一次建立 → **不會建出第二個任務**，拿到的是原本那一個；這個保證有時間界線，來源定為 **24 小時**
6. 同一次建立換了內容再送 → **回報衝突**，不建立新任務，也不把原本那一個當成這次的結果
7. **重送時權限要重新看一次**：建立者的建立任務權限在這之間被收回 → 即使是同一次重送也擋下，不回傳任務
8. 建立出來的任務狀態是 :ref[任務]{id="term.task"} 五個狀態裡的**草稿**

- 第二步的設定在建立時**存成一個不會被改動的版本**；之後在任務詳情改設定會**新增一個版本**，不覆蓋舊的，所以任何時候都查得到當初是怎麼設的
- 第 5、6 條合起來的意思是：重送**內容一樣**才給原本那一個，**內容不一樣**就當成另一回事擋下來——否則使用者會以為自己改過的設定生效了，其實沒有

### 深色模式與動畫

<PrototypeFrame page="task-management/task-new" caption="新增任務" client:idle />

1. 整頁支援深色模式：表單、卡片、預覽區與步驟指示器在深色下都看得清楚
2. 使用者在系統設定裡要求減少動畫 → 這一頁的過場動畫**降到最低**

### 離開這一頁與重新整理

<PrototypeFrame page="task-management/task-new" caption="新增任務" client:idle />

1. 使用者點「取消」，或要離開這一頁（點側欄、關分頁），而且**已經改過東西** → 顯示確認視窗，標題「離開此頁面？」，內容「你有尚未儲存的變更，離開將會遺失所有已填寫的內容。」，兩個選擇是「繼續編輯」與「離開」
2. 選「離開」→ 回到 [規格 03-01 任務列表](./01-task-list.mdx)，**不建立任務**
3. 選「繼續編輯」→ 留在原處，什麼都不變
4. 使用者按 F5 → 瀏覽器先問一次；確認後系統**還原到原本那一步**並回填所有已填資料（任務名稱、三組選擇、資料集檔案列表與欄位預覽、**已選的清單標題**、**已確認的對話串對應**、第二步的設定與預覽、啟動設定、標記說明）
5. 使用者**從別的地方進來**這一頁（點「新增任務」、點側欄、用瀏覽器上一頁／下一頁）→ 一律從空白的第一步開始，**不還原**
6. 任務建立成功之後 → 暫存的內容清掉

- 第 4 條與第 5 條的差別是刻意的：重新整理是「我還在填」，從外面進來是「我要開一個新的」
- 完全沒有改過任何東西時，點「取消」或離開**不會**跳確認

| 欄位 | 型別 | 必填 | 規則 | 使用者看到 |

| 任務名稱 | 文字 | 是 | 不得為空；上限 100 字；可以和其他任務重複 | 第一步的任務名稱欄與字數計數器 |
| 資料集檔案 | 檔案（多個） | 是 | 只收 JSON；單檔上限 200 MB；UTF-8；所有檔案算同一個資料集；欄位集合必須一致 | 上傳區與下方的檔案列表 |
| 資料列來源 | 單選 | 是 | 系統偵測，可手動換；取不出紀錄就擋下 | 欄位預覽上方的下拉與候選數提示 |
| 欄位的用途 | 每欄一個：不使用、背景、輸入、輸出 | 是 | 預設不使用；只有輸入會被自動猜測；輸入數量受輸入類型約束；只帶已指定的欄位 | 每個欄位標頭下方的下拉與下方回饋；還沒指定用途的欄位，那一欄的格子會淡化 |
| 清單標題 | 單選：自動或某一欄 | 是 | 預設自動；選項不含用途是輸出的欄位；失效時退回自動 | 清單標題下拉與「標記清單預覽」 |
| 對話串欄位 | 四個對應，或無 | 否 | 只在輸入是物件陣列時提議；回覆對象不預填；取消提議後不再自動提議 | 「以對話串呈現此輸入欄位」的勾選項與四個下拉 |
| 大分類 | 多選：分類、回歸、序列、生成 | 是 | 至少要讓使用者選得出一個輸出類型 | 第一步的大分類那一組 |
| 輸入類型 | 單選：單一項目、項目對 | 是 | 決定輸入欄位要幾個 | 第一步的輸入類型那一組 |
| 輸出類型 | 多選：8 種 | 是 | 至少一個；分類與回歸同組單選，序列與生成多選；跨大分類可同時選 | 第一步的輸出類型那一組 |
| 每一種輸出類型的設定 | 依型別而定，見 [§每一種輸出類型的設定欄位](#每一種輸出類型的設定欄位) | 是 | 必填欄位全部通過才能離開第二步 | 第二步設定那一邊的手風琴面板 |
| 允許無法判定 (Bypass) | 是／否，每一種輸出類型各一個 | 否 | 預設開啟；關掉時那一種的預覽不顯示勾選項並清除既有狀態 | 每個面板裡的開關、預覽區塊底部的勾選項 |
| 項目對名稱 | 兩個文字 | 否 | 只在輸入類型是項目對時存在；預設是兩個輸入欄位的原始名稱；清空就退回預設 | 第二步的「項目對名稱」設定卡與預覽的兩個小標 |
| 每回合抽樣筆數 | 整數 | 是 | 至少 1 筆、小於資料集總筆數；選好輸出類型後自動預填建議值 | 第三步的「每回合抽樣筆數」 |
| 資料隔離 | 是／否 | 是 | 預設開啟 | 第三步的「資料隔離」開關 |
| 標記說明內容 | 文字 | 否 | 可以只填這個、不上傳檔案 | 第四步「提供給標記員」的說明欄位 |
| 標記員附件 | 檔案（多個） | 否 | PDF、圖片（PNG／JPG／JPEG／WebP）或 Markdown；可逐檔移除 | 第四步「提供給標記員」的檔案清單 |
| 審核說明內容 | 文字 | 否 | 與標記員那一組完全獨立 | 第四步「提供給審核員」的說明欄位 |
| 審核員附件 | 檔案（多個） | 否 | 同標記員附件的格式；清單彼此獨立 | 第四步「提供給審核員」的檔案清單 |
| 開始標記前強制顯示 | 是／否 | 是 | **預設關閉**；開啟後標記員第一次進入該任務會看到說明視窗 | 第四步最下方的開關 |

- 這一頁**不顯示也不設定**任務狀態；建立出來的任務一律是「草稿」

## 卡控機制

| 條件 | 結果 |
| :--- | :--- |
| 不是平台成員也不是系統管理員 | 進不了這一頁，被帶回他進得去的入口並顯示無權限提示；也不能建立任務 |
| 「新增任務」這一格被系統管理員在角色設定裡關掉 | 同上，被關掉的人一樣進不來 |
| 任務名稱為空 | 「下一步」不能點 |
| 沒有選任何輸出類型 | 「下一步」不能點 |
| 沒有上傳任何資料集檔案 | 「下一步」不能點 |
| 上傳的檔案不是 JSON | 那一個檔案被擋下並顯示錯誤，其他檔案不受影響 |
| 上傳的檔案超過 200 MB | 同上 |
| 追加的檔案在目前資料列來源取不出紀錄，或欄位集合不一致 | 擋下那一個檔案並顯示不相容提示 |
| 完全偵測不到可用的紀錄清單 | 顯示錯誤並擋下進入下一步 |
| 輸入類型是單一項目但輸入欄位不是恰好 1 個 | 擋下進入下一步並說明要怎麼改 |
| 輸入類型是項目對但輸入欄位不是恰好 2 個 | 同上 |
| 任一輸入或背景欄位有缺值 | 擋下進入下一步，欄位下方與頁首各顯示一次，指出用途、欄位名稱與缺值筆數 |
| 輸出欄位有缺值 | **不擋**，那一筆視為沒有預標記 |
| 欄位名稱像是答案（例如含 `gold`） | 平台**不會**因此把它指定為輸出；背景與輸出一律不自動猜測 |
| 清單標題的選項 | 一律不含用途是輸出的欄位 |
| 已選的清單標題欄位失效 | 退回「自動」並顯示說明原因的提示 |
| 建立者取消對話串提議 | 之後不再自動預填 |
| 已經改過東西又要離開或取消 | 先顯示「離開此頁面？」確認；選「離開」才走，而且不建立任務 |
| 任一已選輸出類型的必填設定欄位沒過 | 第二步的「下一步」不能點 |
| 設定內容有格式或結構錯誤 | 第二步的「下一步」不能點 |
| 設定內容區有未儲存的改動 | 第二步的「下一步」不能點並提示先儲存；**平台不自動儲存、也不自動覆寫** |
| 關係識別的語意類型標籤是空的 | **不擋**，它是選填；三元組列不顯示類型徽章與選單 |
| 階層標籤超過深度、節點數或名稱長度上限，或有空值、識別碼重複、子節點無效、沒有根節點，或分支被設了顏色 | 三個入口（手動編輯、設定內容、從資料集帶入）用同一套規則一起擋下，並保留最後一份有效設定，不建出一半的樹 |
| 多標籤的輸出欄位同一欄混用兩種形狀、有不是字串的段、同一識別碼出現在不同上層之下、路徑沒有從根開始，或對不上任何一條完整路徑 | 擋下自動帶入並指出是哪一列的哪一欄，不猜也不截斷 |
| 預標記已經選了的標籤數量**超過「最多可選數量」** | 擋下進入下一步並指出是哪一列的哪一欄；**不會默默把超出的裁掉** |
| 單維度或多維度的最小值不小於最大值，或間距不大於 0 | 擋下進入下一步並顯示要怎麼改 |
| 多維度一個維度都沒有 | 擋下進入下一步 |
| 標籤類型、實體類型或標籤選項是空的，或有空白的項目 | 擋下進入下一步 |
| 自由文字的輸入區說明或作答區說明去掉空白後是空的，或超過 100 字 | 擋下進入下一步，**建立者打的內容留著**並顯示可定位的錯誤 |
| 設定內容裡帶著序列標註的「允許重疊標記」 | 判定為錯誤並擋下，**不默默改寫成「不允許」** |
| 設定內容裡的項目對名稱不是剛好兩個文字，或輸入類型不是項目對 | 顯示錯誤且**不套用** |
| 預標記的位置超出原文長度，或起點不小於終點 | **那一筆**被拒絕並列在預覽的錯誤清單裡，其餘正常載入，**不擋**前進 |
| 刪除含子節點的階層標籤分支 | 先用頁面上的確認視窗攔下，寫出會一併刪幾個子節點與不可復原 |
| 「最多可選數量」到達上限 | 其餘未選的節點變成不可選，**已選的仍可取消** |
| 「最多可選數量」填得比可選節點總數還大 | 顯示不擋流程的提示，視同不限 |
| 關係識別單獨使用時選到不是既有實體的文字 | 提示改選已高亮的實體，不建立實體 |
| 圈選的範圍和既有的序列標註相交 | 當場拒絕並回饋 |
| 圈選的範圍和既有標記**相鄰但不相交**（頭接著上一段的尾） | **允許**，正常新增 |
| 圈選的範圍完全落在既有標記之內 | 一樣拒絕，而且要給出**看得出來的**回饋 |
| 圈選處於被拒絕的狀態時點了標籤類型 | **不清掉**那個暫存的選取 |
| 選了關係識別 | **不會自動把實體辨識加進來** |
| 取消實體辨識 | 關係識別留著並切回單獨模式，已建的三元組不被連帶取消 |
| 勾了某一種輸出類型的「無法判定」 | 那一塊的其他控制項清空並停用，不影響輸入文字與其他輸出類型 |
| 在整合預覽勾了實體辨識的「無法判定」 | 整區（含關係建構器）一起清空停用 |
| 每回合抽樣筆數是 0、負數，或不小於資料集總筆數 | 第三步的「下一步」不能點並顯示要怎麼改 |
| 第四步兩組說明都空著 | **不擋**，整步選填 |
| 只填了其中一組說明 | **不擋**，不強制兩個角色都填 |
| 附件不是 PDF、圖片或 Markdown | 擋下那一個檔案並提示 |
| 圖片不是 PNG、JPG、JPEG 或 WebP | 同上 |
| 建立送出中又點「建立任務」 | 按鈕在等待狀態、點不下去，不會重複送出 |
| 建立過程中任何一步失敗 | 整件事回到原狀，不留下只有一半的任務 |
| 網路中斷後重送同一次建立、內容相同 | 回傳原本那一個任務，不建立第二個 |
| 重送同一次建立但內容不同 | 回報衝突，不建立新任務，也不把原本那一個當成這次的結果 |
| 建立者的建立任務權限在送出之後被收回 | **即使是同一次重送也擋下**，不回傳任務——權限每一次請求都重新看一次，不是只在進頁面時看 |
| 重送距第一次超過 24 小時 | 不再保證回傳原本那一個任務 |
| 從別的地方進入這一頁 | 一律從空白的第一步開始，不還原上次的內容 |

## 邊界情況（Edge Case）

| 情況 | 使用者看到什麼 |
| :--- | :--- |
| 沒有建立任務權限的人直接打開這一頁 | 被帶回他進得去的入口並顯示無權限提示，不是一個空白的精靈 |
| 上傳了檔案又全部移除 | 「下一步」回到不能點；欄位預覽與清單標題預覽一起消失 |
| JSON 整份就是一個陣列 | 正常偵測成資料列來源，下拉不能點（只有一個候選） |
| 紀錄包在物件的某個鍵底下 | 一樣偵測得到，並顯示有幾個候選 |
| `.json` 裡是一行一筆的寫法 | 一樣讀得出紀錄 |
| 不同紀錄的欄位不完全一樣 | 表格的欄位是**所有紀錄**第一層鍵的聯集，缺那個鍵的紀錄算缺值 |
| 某一欄的值有時是字串有時是數字 | 型別摘要顯示「混合」 |
| 某一欄的值是 `0` 或 `false` | **算有值**，不會被當成缺值擋下 |
| 某一欄全部是空陣列 | 算缺值；指定為輸入或背景就會擋下 |
| 欄名同時含 `text` 與 `content` 等多個線索 | 依原始出現順序指定，最多到輸入類型需要的數量 |
| 還沒選輸入類型就上傳資料集 | 自動猜測最多指定 1 個輸入欄位 |
| 資料集有 `gold_label` 這種欄位 | 它維持「不使用」；要當預標記必須由建立者自己選 |
| 清單標題選了 `id`，之後把 `id` 改成「不使用」 | 清單標題**保持**原來的選擇，不退回自動 |
| 清單標題選了 `id`，之後把 `id` 改成輸出 | 退回「自動」並顯示提示 |
| 對話串的回覆對象在資料裡是空值 | 那一則是根發言；下游不縮排也不標示回應關係 |
| 已確認對話串後換掉資料集 | 系統重新偵測；不再合法的對應被清掉，仍合法的保留 |
| 取消了對話串提議，之後又換資料集 | 仍然不自動預填 |
| 先選了分類的某一項，再選回歸 | 兩個大分類都在，但分類與回歸各自只留一個選項 |
| 同時選了實體辨識與關係識別 | 兩個都留著；它們在第二步合併成整合預覽（階段二撰寫） |
| 取消「序列」這個大分類 | 它底下已選的輸出類型一起消失 |
| 什麼都沒填就點「取消」 | 直接回到任務列表，不跳確認 |
| 填了一半按 F5 | 瀏覽器問一次，確認後回到原本那一步並回填 |
| 填了一半從側欄跳走 | 跳確認；選「離開」就回不去了，已填的內容不保留 |
| 第二步選了三種以上輸出類型 | 只有第一個面板預設展開，其餘收合 |
| 還沒上傳資料集就進第二步 | 預覽顯示預設的範例文字，不是空白 |
| 切換「選取吸附」 | 既有的標記**不失效、不錯位、不被清掉**，位置也不變；之後的圈選才改用新的落點規則 |
| 兩個不同分支下有同名的標籤節點 | 各自獨立；選了一個不會把另一個也選上 |
| 一個標籤節點加了第一個子節點 | 它變成分支，仍然可以被選，原本的顏色移除，已選的保留 |
| 刪掉的分支裡有預覽已選的節點 | 那些選取一併移除，焦點移到前一個看得到的節點或它的上一層 |
| 只選關係識別，資料集沒有既有實體 | 關係建構器沒有可連的對象，而單獨模式沒有建立實體的入口；來源沒有交代這時候要顯示什麼，見 [§待釐清](#待釐清) Q7 |
| 多維度的輸出欄位第一筆是一個物件 | 維度列表自動從它的鍵建出來，範圍依實際資料推斷 |
| 預標記的三元組認不出語意類型 | 語意類型標籤維持空的，三元組列不顯示類型徽章與選單 |
| 自動帶入之後建立者又手改了設定 | 不會再自動帶入一次覆蓋掉他的修改 |
| 項目對任務沒有可用的輸入欄位 | 兩個名稱退回「句子 A」與「句子 B」 |
| 切換語言但設定內容區有未儲存的改動 | 標籤**不自動換語言**，保留建立者手改的內容 |
| 第三步的筆數剛好等於資料集總筆數 | 被擋下——試標要抽的是一部分，不是全部 |
| 資料集只有 1 筆 | 筆數要至少 1 筆又要小於總筆數，兩個條件湊不出合法值；來源沒有交代這時候怎麼辦，見 [§待釐清](#待釐清) Q9（**題未決，所以還沒有對應的 Scenario**）|
| 選了多個大分類 | 預填的筆數取比例最高的那一個大分類 |
| 第四步只上傳檔案、說明欄位空著 | 可以建立 |
| 第四步只填說明、沒有附件 | 可以建立 |
| 建立成功之後按瀏覽器上一頁回到這一頁 | 從空白的第一步開始，暫存已經清掉 |
| 使用者在深色模式下走完四步 | 每一步的表單、卡片、預覽與步驟指示器都看得清楚 |
| 使用者在系統設定裡要求減少動畫 | 這一頁的過場動畫降到最低 |

### Q1. 清單標題與對話串確認區在畫面上在表格上方，來源要求在下方——以哪一邊為準？

- [ ] 以來源為準，畫面把兩個區塊移到表格下方
- [ ] 以畫面為準，本頁的敘述跟著改
- [ ] 其他（請說明）

> 建議：第一個。來源的 `FR-002c-9` 明寫「表格下方 MUST 顯示『標記清單預覽』」、`FR-002c-10` 明寫要在**欄位預覽下方**提議並顯示確認區，`AC-1.10` 也是「欄位預覽下方出現對話串確認區」。
> 但畫面把這兩個區塊都掛在資料列來源那一條上，而那一條排在欄位預覽表格**之前**，所以使用者看到的順序是：資料列來源 → 清單標題 → 對話串確認 → 欄位預覽表格。

> 選第一個要改 `design/prototype/`（本 skill 不改）。
> 需要決定的人：維護者

### Q4. 輸入類型是不是必填？來源自己有兩種說法

- [ ] 是必填：沒選輸入類型就不能離開第一步
- [ ] 不是必填：沒選的時候就不檢查輸入欄位的數量（目前畫面的行為）
- [ ] 其他（請說明）

> 建議：第一個。來源在三個地方說法不一致：
>
> | 來源位置 | 說的是 |
> | :--- | :--- |
> | 使用者故事 1 的介面定義「必要欄位」 | 把輸入類型**列為必要欄位** |
> | 同一節的「`下一步` 啟用條件」 | 五個條件裡**沒有**「已選輸入類型」，只有「輸入欄位數量符合輸入類型」 |
> | `FR-002c-2` | 寫的是「**當**輸入類型為單一項目時…」，帶條件 |
>
> 畫面站在第二種：沒選輸入類型時整段數量檢查跳過，所以使用者可以一個輸入欄位都不指定就進第二步。
> 這有實際後果：第二步的預覽要靠輸入欄位取文字，沒有輸入欄位的任務到了第二步會沒有東西可預覽。
> 本頁的 [§什麼時候才能離開第一步](#什麼時候才能離開第一步) 照來源的五個條件寫，所以**目前等於走了第二種**，但這是來源的矛盾、不是本頁的判斷。
> 需要決定的人：維護者

### Q5. 背景與輸出都留空時，是「只帶已指定用途的欄位」還是「所有欄位照常納入設定」？

> 第二句看起來是舊版本留下來的——在欄位用途這套機制出現之前，欄位是「全部納入」的；加上用途之後，第一句才是現行的規則，而且畫面也是只帶已指定的。

### Q7. 只選關係識別、而資料集沒有既有實體時，建立者看到什麼？

> 這在實務上會發生：一個只想做關係標記的人，資料集裡本來不一定有實體欄位。
> 需要決定的人：維護者

### Q8. 範本按鈕只有一個組合有，其餘輸出類型都沒有——以哪一邊為準？

- [ ] 以來源為準，每一種已選的輸出類型都要有範本可點
- [ ] 以畫面為準，範本只提供給特定的組合，本頁的規則跟著改
- [ ] 其他（請說明）

> 建議：第一個。來源的介面定義寫「範本按鈕：**依已選 output types** 提供預設模板，點擊即載入」。
> 但畫面只在**同時選了實體辨識與關係識別**這一個組合時才產生範本按鈕，其他任何選擇都直接跳過——所以一個只選自由文字的建立者，那一列上**沒有任何範本可點**。
> 範本的用處正是「不想一個一個點」；只有一個組合有，等於這條路對多數人不存在。
> 選第一個要改 `design/prototype/`（本 skill 不改）。
> 需要決定的人：維護者

### Q9. 資料集只有一筆時，第三步的抽樣筆數要填什麼？

- [ ] 給資料集一個最少筆數的下限，低於它就在第一步擋下來
- [ ] 第三步在這種情況允許筆數等於總筆數
- [ ] 其他（請說明）

> 建議：第一個。來源要求抽樣筆數**至少 1 筆、而且小於資料集總筆數**——這兩個條件在資料集只有 1 筆時**湊不出任何合法值**，建立者會卡在第三步，而且畫面只會告訴他範圍是什麼，不會告訴他問題其實在資料集。
> 來源從頭到尾沒有定資料集的最少筆數，也沒有交代這種情況。
> 選第一個的話，問題在第一步就被指出來（「這個資料集太小，至少要 N 筆」），比讓他走到第三步才卡住清楚得多。
> 試標的意義是「先抽一部分確認大家理解一致」，所以資料集小到不能抽一部分時，本來就不適合進這個流程。
> 需要決定的人：維護者

- [ ] 所有欄位都可以選

> 理由：來源的 `FR-002c-9` 明寫選項的推導規則，並禁止列出用途是輸出的欄位，並定了失效時退回自動、提示要持續顯示到何時、以及 `id` 的例外。
> 排除輸出欄位的理由和 Q9 一樣：清單標題是標記員在標記清單上看得到的字，拿預標記當標題等於把答案放到標題上（#75）。

### Q17. 重新整理要還原，從別處進來要清空？（已定案，沿用舊來源）

- [x] 是；F5 還原到原本那一步並回填，從外部導航進來一律從空白的第一步開始
- [ ] 兩種情況都還原

> 理由：`FR-007a` 定的是離頁確認（含取消建立、側欄跳頁、重新整理、關閉分頁都要先問）；**還原的規則在來源的行為規則與原型互動規格**，兩處各寫一次並明確區分「重新整理」與「新進入」。（來源自己的流程圖說明把 `FR-007a` 標成「離頁確認與精靈狀態還原」，但該條本文只有離頁確認。）

## Q&A

### Q. 為什麼不直接讓使用者選一個「任務類型」就好？

因為真實的研究題目常常要同時產出好幾種結果。同一批病歷可能既要標出實體、又要標出實體之間的關係；同一批評論可能既要分類、又要給分數。如果平台只認一個固定的任務類型，每出現一種新組合就要加一個新類型、加一段新程式；改成「選一到多種輸出類型」之後，新組合不必動平台。

### Q. 為什麼欄位的用途要建立者自己指定，不讓平台看欄名就好？

輸入欄位可以猜，因為猜錯了建立者馬上看得出來，而且改一下就好。但輸出欄位的內容會當成預標記**給標記員看**——如果平台看到一欄叫 `gold_answer` 就自動把它變成輸出，那批資料的答案就直接送到標記員眼前了。這不是方便與不方便的問題，是會不會把答案洩出去的問題，所以背景與輸出一律要建立者自己決定。

### Q. 為什麼 `0` 要算有值？

因為很多題目的答案本來就是 `0`。情緒分數 0 分、是否轉診 `false`、計數 0 次——這些都是真正的資料，不是「沒填」。如果把它們當成缺值，一個評分類的資料集會整批過不了第一步，而建立者會完全不知道為什麼。

### Q. 為什麼第二步要讓建立者在預覽上真的標一次？

因為設定看起來合理、標起來卻很難用，是標記任務最常見的失敗。標籤名稱到了畫面上太長、維度的範圍和實際資料差很遠、實體類型分得太細——這些在設定欄位上看不出來，在預覽上標兩筆就會發現。讓建立者自己先標一次，比讓十個標記員標完才回報便宜得多。

### Q. 為什麼「選取吸附」不影響存下來的位置？

因為吸附是「幫你對齊」的輔助，不是資料的一部分。如果換一個吸附方式會讓既有的標記失效或錯位，建立者就不敢在設定好之後再去調它——而他本來就應該可以隨時調。所以兩種設定存出來的東西完全一樣，差別只在拖曳放開的那一刻落在哪裡。

### Q. 為什麼重新整理要還原，從任務列表進來卻要清空？

因為這兩件事使用者的意思不一樣。按 F5 的人是「畫面怪怪的，我重新載一下」，他手上那個任務還沒填完；從任務列表點「新增任務」的人是「我要開一個新的任務」，這時候跳出上一次填到一半的內容只會讓他困惑——他會不確定眼前這些東西是不是自己剛剛填的。
