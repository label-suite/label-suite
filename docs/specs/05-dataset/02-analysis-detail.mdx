## 目標

| 目標 | 誰受益 |
| :--- | :--- |
| 讓:ref[專案負責人]{id="term.project-leader"}與:ref[審核員]{id="term.reviewer"}在**同一個任務上下文**底下對照看統計與品質，不必在兩個頁面之間來回帶著任務代號 | 兩種角色——分開成兩頁的話，每次切換都要重新確認「我現在看的是哪個任務」 |
| 讓從儀表板的「:ref[IAA]{id="term.iaa"} 待確認」提醒點進來的人**直接落在品質監控**，不必再自己切一次 | 被提醒叫來做品質決定的專案負責人 |
| 讓網址**一個連結就說完「哪個任務、哪個分頁」**，重新整理與分享都還在原處 | 需要互相對照同一個畫面的人 |
| 讓**切換分頁不打斷閱讀**：各自的捲動位置分開記 | 在長表格裡逐列比對的審核員 |
| 讓**複合任務的每一種輸出類型都看得到自己的統計**，而不是只看到第一種 | 同時產出多種標記的任務——它們最容易在「一個任務一種類型」的假設下被壓成一種 |
| 讓**沒有門檻的輸出類型不要被誤判成未通過**：算得出數值但還沒校準的，與永久沒有自動指標的，是兩件不同的事 | 做品質決定的專案負責人——把兩者混在一起，一個永遠無法達標的型別會把整個任務永久鎖在未通過 |
| 讓**「樣本難標」與「這個人標得有問題」分開**：前者是樣本層的旗標，後者才是標記員的風險 | 被錯誤標成高風險的標記員——高分歧樣本拉高他的風險等級是把資料的難度算到人頭上 |
| 讓**序列標註的標記匯得出訓練用的序列格式**，而且同一份標記用不同方案重匯都是同一個結果 | 下游研究流程——標記方案改成匯出時才選之後，沒有這個契約的話這個輸出類型等於不能用於訓練 |
| 讓這一頁**只讀、碰不到任何答案內容** | 整個標記品質管線——分析頁若能讀到標準答案，測試集保護就破了 |

## 使用角色

:::tip{title="權限代號"}
R：Read（可讀取）　C：Create（可新增）　E：Edit（可編輯）　D：Delete（可刪除）　(o)：只限自己的資料
:::

| 角色 | 這一頁能做什麼 | PRD §權限矩陣的上限 |
| :--- | :--- | :--- |
| :ref[專案負責人]{id="term.project-leader"} | R | 「05 資料集分析」給專案負責人 `R` |
| :ref[審核員]{id="term.reviewer"} | R | 同一列給審核員 `R` |
| :ref[標記員]{id="term.annotator"} | **進不來** | 同一列給標記員 `—` |

- 這一頁**完全唯讀**，沒有任何新增、編輯或刪除；畫面上唯一會改變資料的入口在[規格 03-03 任務詳情](../03-task-management/03-task-detail.mdx)，由階段四的建議行動導過去
- 能不能進來，**只看使用者在那一個任務的:ref[任務角色]{id="term.task-role"}**：任務角色是專案負責人或審核員才進得來
- 進來之後，**兩個分頁各有一道自己的任務層級權限**：統計總覽的資料讀取要「**看任務統計**」、品質監控的資料讀取要「**看品質分析**」。這兩個名字由[規格 05-01](./01-analysis-list.mdx#使用角色)定名，這一頁沿用
- 這一頁不是作業頁，所以兩道權限都取使用者在**那一個任務**各個**生效**成員身分的允許聯集；**受邀但還沒生效的成員身分視同不存在**
- 這兩項權限是 PRD §權限矩陣「05 資料集分析」那一格的**細化、不放寬**（依 `spec-migration.md` 的 D10）；種子設定只開給專案負責人與審核員，與上一條的任務角色條件一致，所以上線初期**兩道條件的結果相同**
- :ref[系統管理員]{id="term.system-admin"}沒有任務角色時進不來，和[規格 05-01](./01-analysis-list.mdx#使用角色)、[規格 03-03](../03-task-management/03-task-detail.mdx) 一樣

### 進入某個任務的分析詳情

- 觸發：使用者從[規格 05-01 分析列表](./01-analysis-list.mdx#點任務列進入分析詳情)點任務列，或從儀表板的「IAA 待確認」提醒點進來
- 前置條件：使用者已登入
- 主流程：
  1. 系統驗**任務代號**與**成員資格** → 兩者都過才繼續
  2. 系統載入**任務上下文**：任務代號、任務名稱、任務的輸出類型清單 → 上下文就位
  3. 系統依**網址上的分頁參數**決定落在哪個分頁 → 統計總覽或品質監控
  4. 系統渲染**共用外殼**：頁首、麵包屑、分頁列 → 兩個分頁共用這一層
  5. 系統顯示該分頁的內容 → 依該分頁自己的狀態顯示載入中、空、就緒或錯誤
- 替代流程：
  - A1（第 3 步）沒帶分頁參數，或參數不是兩個合法值之一 → 落在**統計總覽**，回到第 4 步
- 例外流程：
  - E1（第 1 步）任務代號不存在，或使用者在那個任務沒有專案負責人或審核員的成員資格 → **導回分析列表**並顯示提示，流程結束（見 [§卡控機制](#卡控機制)）
  - E2（第 2 步）任務的輸出類型取不到、是空的、缺少、或含認不得的鍵 → 兩個分頁都顯示**可重試的錯誤**，外殼與分頁列仍在，流程結束（見 [§卡控機制](#卡控機制)）
- 結果：使用者停在某一個任務的某一個分頁上，網址同時說明了這兩件事

### 在同一頁換分頁

- 觸發：使用者點分頁列上的另一個分頁
- 前置條件：任務上下文已就位
- 主流程：
  1. 使用者點另一個分頁 → 系統先記住**目前分頁的捲動位置**
  2. 系統換掉顯示中的分頁與**選取狀態** → 只換內容，不離開這一頁
  3. 系統更新**網址上的分頁參數** → 連結可直接分享到這個分頁
  4. 系統**還原目標分頁上次的捲動位置** → 回到上次停下的地方
- 替代流程：
  - A1（第 4 步）目標分頁沒有上次的位置 → 從**頂端**開始，流程結束
- 結果：任務上下文沒有重建，網址指向新的分頁

## 規格

### 這一頁讀得到什麼、不得改什麼

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

這一頁是**一個任務的分析結果**，給專案負責人與審核員看。

1. 這一頁讀得到的，只有**聚合後的統計與品質指標**：筆數、比例、分布、一致性數值、排名、偏離次數
2. 這一頁**讀不到也不得顯示**任何一筆標記的**答案內容**，也不得顯示:ref[標準答案]{id="term.ground-truth"}；一致性最低樣本清單（階段四）只顯示樣本識別、分歧度數值與**文本摘要**，不顯示任何標記員填的答案
3. 這一頁**沒有任何編輯**：指標區與分析區全部唯讀
4. 這一頁**不是**[規格 03-03 任務詳情](../03-task-management/03-task-detail.mdx)。匯出對話框、匯出入口與匯出紀錄表都在那一頁；這一頁只定義**匯出時怎麼從標記推導出序列**（階段五）
5. 兩個分頁的內容分屬四個階段：統計總覽的逐型內容在階段二，品質監控的 IAA 報告在階段三，標記員與樣本層分析在階段四

### 兩個合法入口

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

這一頁只有兩個入口，而且**各自決定落在哪一個分頁**。

1. 從[規格 05-01 分析列表](./01-analysis-list.mdx#點任務列進入分析詳情)點任務列 → 進入**那個任務**的分析詳情，落在**統計總覽**
2. 從儀表板的「IAA 待確認」提醒點進來 → 進入那個任務的分析詳情，**直接落在品質監控**
3. 第 2 條是深層連結，它**必須把任務上下文一併載入**，不得只是切到分頁卻沒有資料
4. 品質監控除了第 2 條，也可以**從統計總覽切過去**
5. 這一頁的網址要同時說明**哪一個任務**與**哪一個分頁**：任務代號是網址的一部分，分頁由下面的分頁參數決定

### 進來先驗兩件事：任務代號與成員資格

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

不管從哪個入口進來，系統都先驗任務代號與成員資格，**過不了就不渲染任何內容**。

1. 任務代號**不存在** → 導回[分析列表](./01-analysis-list.mdx)並顯示提示
2. 使用者在那個任務**沒有專案負責人或審核員的成員資格** → 同樣導回分析列表並顯示提示
3. 上面兩種情況是**同一個觸發**，使用者看到的是**同一句提示**：`找不到指定的任務，或您沒有該任務的存取權限。`（英文：`The requested task could not be found, or you do not have access to it.`）
4. 第 3 條刻意不分辨「任務不存在」與「沒有權限」——分辨了就等於告訴外人這個任務存在
5. 提示由**分析列表那一頁顯示**（錯誤樣式的浮動提示），但**提示要不要出現是這一頁決定的**；這一頁導回去時要讓那一頁知道這是一次被擋下的進入
6. 任務角色**缺少或認不得**時一律視為第 2 條，**失敗即關閉**；不得退回成任何預設角色
7. 驗不過時**不得**悄悄換成某個預設任務再顯示出來

### 兩個分頁各有一道自己的權限

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

上一項過了只代表**進得來**；兩個分頁的**資料讀取**另外各有一道任務層級的權限。

1. 統計總覽的資料讀取要「**看任務統計**」；品質監控的資料讀取要「**看品質分析**」
2. 這兩道都**疊在**「任務角色是專案負責人或審核員」**之上**，不取代它
3. 權限取使用者在**那一個任務**各個**生效**成員身分的**允許聯集**
4. **受邀但還沒生效**的成員身分**視同不存在**，而且在**兩道判定裡都視同不存在**
5. 第 4 條的兩道判定**結果不同，不得混為一條**：

| 哪一道判定 | 什麼情況 | 結果 |
| :--- | :--- | :--- |
| 能不能**進來** | 去掉未生效的身分之後，**一個生效身分都不剩** | **進不來**，導回分析列表（見[§進來先驗兩件事](#進來先驗兩件事任務代號與成員資格)） |
| 某個分頁的**資料讀取** | 還有生效身分，但這些身分的允許聯集**不含那個分頁的權限** | 只**拒絕那一個分頁的資料讀取**，另一個分頁照常可讀 |

6. 匯出檔的下載另有一道「**匯出資料**」權限，種子設定只開給專案負責人；但匯出入口不在這一頁，在[規格 03-03](../03-task-management/03-task-detail.mdx)
7. 「看任務統計」與「看品質分析」兩項是 PRD §權限矩陣「**05 資料集分析**」那一格的**細化、不放寬**；「匯出資料」對應的是**另一格**——「**03 匯出標記結果**」（專案負責人 `C`），由[規格 03-03](../03-task-management/03-task-detail.mdx)承接，不在這一頁的那一格之內

### 頁首與麵包屑

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

頁首固定寫**頁面的用途**，任務名稱寫在麵包屑的第二段。

1. 頁首大標固定是 `任務詳情`（英文 `Task detail`），**不得用任務名稱取代**
2. 頁首副標固定是 `檢視統計總覽與品質監控`（英文 `Review statistics and quality monitoring`）
3. 麵包屑固定是 `資料集分析 › 〈任務名稱〉`（第一段英文 `Dataset Analysis`），第一段連回[分析列表](./01-analysis-list.mdx)
4. 麵包屑**放在頁首標題區塊的下方**，**不得放在大標前面**——放前面會把整個頁首往下推，與其他頁的標題基準線不齊
5. 語系切換時，麵包屑第二段要顯示**當前語系的任務名稱**
6. 第 1 條與第 2 條都隨語系切換

### 分頁列與網址上的分頁參數

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

分頁列只有兩個入口，切換是**頁內切換**。

1. 分頁列有兩個：`統計總覽`（英文 `Statistics`）、`品質監控`（英文 `Quality Monitor`）；同一時刻恰好一個是**選取**狀態
   - 英文的 `Statistics` 刻意**不是**「統計總覽」的直譯，**不得**自行補成 `Statistics Overview`
2. 切換是**頁內切換**，**不得**導向分析列表、也不得整頁重新載入
3. 網址上的分頁參數**只允許兩個值**，分別對應**統計總覽**與**品質監控**
4. **沒帶**分頁參數時一律落在**統計總覽**
5. 分頁參數不是那兩個值之一時，**回退成統計總覽**
6. 切換分頁時要**更新**網址上的分頁參數，讓連結可以直接分享到某一個分頁、重新整理後也還在同一個分頁
7. 分頁參數**只決定選取哪個分頁**，**不得**用來覆寫任務代號或任務的輸出類型

### 任務上下文載入一次，切換分頁不重建

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

兩個分頁共用同一份任務上下文，這是這一頁做成雙分頁而不是兩頁的全部理由。

1. 任務上下文至少包含：**任務代號**、**任務名稱**、**任務的輸出類型清單**（每一筆是一個:ref[輸出類型]{id="term.output-type"}與它的設定）、使用者在這個任務的成員角色
2. 任務的輸出類型**由任務資料決定**，**不得**由網址決定
3. 切換分頁**不得重建**任務上下文
4. 外殼（頁首、麵包屑、分頁列）為兩個分頁**共用**，不隨分頁切換重新產生
5. 複合任務的輸出類型要**保留原本的順序**：階段二與階段三的逐型區塊依這個順序並列

### 兩個分頁各有一組自己的狀態

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

兩個分頁的狀態**數量不同**，而且各自**互斥**：同一時刻恰好成立一種。

1. 統計總覽有**四種**：

| 狀態 | 什麼時候 |
| :--- | :--- |
| 載入中 | 資料還沒到位 |
| 空 | **還沒有任何已提交的標記** |
| 就緒 | 有統計可看 |
| 錯誤 | 載入失敗 |

2. 品質監控有**六種**：

| 狀態 | 什麼時候 |
| :--- | :--- |
| 載入中 | 資料還沒到位 |
| 試標進行中 | :ref[試標]{id="term.dry-run"}還沒跑完 |
| 報告待產生 | 試標跑完、報告還沒排到 |
| 報告產生中 | 報告正在算 |
| 就緒 | 有報告可看 |
| 錯誤 | 載入失敗 |

3. 品質監控的**試標進行中、報告待產生、報告產生中三種都歸在空狀態集合**——它們的共同原因是「試標還沒完成」，所以都不是「就緒」
4. 但第 3 條的三種**各有自己的標題與說明**，**不得共用一組文案**：使用者要能從畫面上看出現在等的是「標記員還沒標完」、「排到了還沒開始算」還是「正在算」。三組文案寫在階段三
5. 第 3 條的三種狀態**不得**與「載入中」混用：前者是**還沒有東西可算**，後者是**算好了還沒到畫面上**
6. 四種與六種狀態**不得互相代用**，也不得只用一個布林值表示
7. 「載入中」是來源明文要求的狀態，但**目前的畫面兩個分頁都沒有實作它**。與[規格 05-01 §四種互斥的頁面狀態](./01-analysis-list.mdx#四種互斥的頁面狀態)第 4 點同一類：**來源有明文就照寫**，畫面補不補由[規格 04-01 §待釐清](../04-annotation/01-annotation-list.mdx#待釐清) Q8 一併決定
8. 空狀態與錯誤狀態下，**外殼與分頁列都還在**，使用者仍可切到另一個分頁

### 載入失敗只換掉內容區

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

某個分頁的內容載入失敗時，壞掉的是**內容**，不是整頁。

1. 錯誤狀態顯示在**該分頁的內容區**：標題 `資料載入失敗`、說明 `無法載入此面板的內容，請稍後再試。`，另有 `重新載入`
2. 頁首、麵包屑、分頁列**不受影響**；另一個分頁**不受影響**
3. `重新載入` 是**重試**，不是回到列表
4. 任務的輸出類型**取不到、是空的、缺少、或含認不得的鍵**時，**兩個分頁都**落到這個錯誤狀態
5. 第 4 條**不得**用猜的補上：不得挑一個預設輸出類型、不得猜一個組合、不得只渲染認得的那幾個

### 兩個分頁的捲動位置分開記

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

在長表格裡比對到一半切去另一個分頁，切回來要**還在原處**。

1. 兩個分頁**各自記住自己的捲動位置**，互相獨立
2. 切換分頁時**不得重設**捲動位置
3. 目標分頁還沒有記錄過位置時，從**頂端**開始

### 語系切換不重新載入

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

1. 語系切換要**即時**更新全頁文案，**不得**觸發整頁重新載入
2. 要跟著換的至少包含：頁首大標與副標、麵包屑兩段、兩個分頁的名稱、空狀態與錯誤狀態的文案
3. 統計總覽要跟著換的還有**圖表標題、軸標籤、圖例與說明文字**（逐型內容見階段二）
4. 品質監控要跟著換的還有**指標名稱、圖例與說明文字**（見階段三、四）
5. 第 1 條的「不重新載入」帶來兩個後果：目前所在的**分頁不變**、**捲動位置不變**

### 不同螢幕寬度的呈現

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

1. 在 **375、768、1440** 三種寬度下，進入任一分頁、切換分頁與閱讀指標**都要能完成**，關鍵內容不得被截斷
2. 手機版（寬度 **767 以下**）欄位空間不足時：**允許橫向捲動**
3. 第 2 條至少要涵蓋這些比較寬的內容：**維度間的散布圖**、**多標籤共現矩陣**、**IAA 報告表格**、**標記一致性偏離分析表格**、**標記員分析表格**
4. 橫向捲動**不得造成整頁水平捲動**

### 這一頁的外殼碰不到的東西

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

1. 外殼**不決定**任何一個分頁的內容要顯示什麼指標——那是輸出類型與分頁各自的規則
2. 外殼**不改**任務設定、不改成員身分、不改標記
3. 外殼**不產生** IAA 報告，也不決定報告何時算完
4. 匯出的對話框、入口與紀錄表**不在這一頁**

### 共用五指標

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

不管任務的輸出類型是什麼組合，統計總覽最上面**固定**是同一組五個指標。

1. 區塊標題是 `共用指標`，五個指標與它們的說明文字是：

| 指標 | 說明文字 | 這個數字在算什麼 |
| :--- | :--- | :--- |
| `句子數量` | `分析母體` | 這個任務納入分析的句子總數 |
| `Token 數量` | `空格分詞` | 以空白切出來的詞數 |
| `完成率` | `〈已完成〉 / 〈全部〉 已完成` | 已完成的數量與全部的數量 |
| `已提交樣本` | `至少 1 位已提交` | 至少有一位標記員提交過的樣本數 |
| `平均標記時間` | `每句平均用時` | 每個句子的平均作答時間 |

2. 這一組**恰好五項**：**不得增加、也不得減少**
3. **完成率只能叫「完成率」**，**不得**用別的名字表示它
4. 不論任務的輸出類型是哪一種組合，這五項**都要看得到**（空狀態下要不要照常顯示，另見[§待釐清](#待釐清) Q6）
5. 來源把第一項寫成 `Sentence 數量`，但**畫面寫「句子數量」**；中文以畫面為準
6. 完成率**由誰算出來**，來源沒有交代，見[§待釐清](#待釐清) Q9

### 逐型區塊依任務的輸出類型長出來

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

共用指標下方是**逐型**的統計區塊，有幾種輸出類型就有幾個區塊。

1. 區塊由任務的**輸出類型清單**決定，**八種都要能渲染**
2. 一種輸出類型**一張子區塊卡片**
3. 複合任務（兩種以上）依輸出類型清單的**原本順序**逐型**並列**
4. **不得**只顯示第一種輸出類型，**不得**用某個固定的優先序覆蓋原本的順序，**不得**把多種壓成一種
5. 任務的**輸入類型**是「項目對」時，欄位的顯示名稱**沿用任務設定裡那一對的名稱**，**不得**為統計總覽另建一套分支（見[規格 03-02](../03-task-management/02-task-new.mdx)）
6. 本頁的用詞是「輸出類型」，與術語表一致——這個名詞原本有兩種寫法，維護者 2026-11-06 裁定一律用**輸出類型**（[#131](https://github.com/label-suite/label-suite/issues/131) 已一次改完）

### 單一標籤的統計

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

1. 一個區塊：`標籤分佈`，副標 `各標籤在提交標記中的次數與比例（每筆樣本僅能選擇一個標籤）`
2. 每一個標籤一列，一列就是一條**橫向長條**，條子旁同時有**比例**與**次數**
3. 區塊下方的註腳是 `單標籤任務：每筆標記恰包含 1 個標籤，比例合計 100%`

### 多標籤的統計

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

1. 兩個區塊：`標籤分佈`、`多標籤共現矩陣`
2. `標籤分佈` 與單一標籤一樣是**每個標籤一條橫向長條、條旁有比例與次數**，但兩邊的副標與註腳不同：
   - 副標是 `各標籤在提交標記中的次數與比例（共 〈筆數〉 筆標記，多標籤任務）`
   - 註腳改成顯示**平均每筆標記包含幾個標籤**
3. `多標籤共現矩陣` 是一張方陣，列與欄都是標籤，格子裡是**兩個標籤同時出現的次數**；副標是 `兩個標籤同時出現的次數。對角線為各標籤單獨出現的樣本數。`
4. 矩陣的註腳是 `顏色深度反映共現頻率高低；白色格子代表極少共現。`
5. 第 3 條那句副標講的**對角線**，與畫面上對角線的數字對不上，見[§待釐清](#待釐清) Q7

### 多標籤的「標籤」是整條階層路徑

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

任務的標籤設定可以是階層的。這一組規則決定階層底下「一個標籤」算什麼。

1. **一個標籤 ＝ 一整條路徑**（從最上層到被選到的那個節點），畫面上**依序用 `›` 把各層的名稱接起來**，例如 `A › B`
2. **同名但路徑不同**的節點是**不同的類別**
3. **不得**隱含計入祖先：提交 `A › B` **不會**讓 `A` 的次數增加
4. 路徑可以停在中間一層，也可以停在最末一層；所以 `A` 與 `A › B` 是**兩個獨立的類別**，只有標記員**另外提交了 `A` 本身**時 `A` 才被計一次
5. `標籤分佈` 的列、以及共現矩陣的**列與欄**，都以**整條路徑**為單位
6. 標記員在**同一筆樣本**同時提交 `A` 與 `A › B` 時，兩者之間是**一般的共現**，**不得**因為有階層關係而特別處理、合併或略過
7. 比例的**母體定義不變**，改變的只有「一個類別怎麼認」
8. 扁平的標籤設定與舊資料視為**長度 1 的路徑**，算出來的結果**要與扁平標籤原本的算法相同**
9. **不得**提供「依最上層（或任何一層祖先）彙總」的呈現——那不在這一頁的範圍
10. 計數**由資料裡的路徑驅動**，**不得**寫死層數、節點名稱，也不得依任務類型分支

### 單維度的統計

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

1. 一個區塊：`評分分佈直方圖`，副標寫**量表範圍與有效標記筆數**（畫面的示例是 `標記員在 1–5 評分量表上的分佈情形（共 396 筆有效標記）`）
2. 直方圖**一個刻度一根柱**，最高的那一根標出數值（**畫面才有的**，來源沒有提到）
3. 圖下方是統計摘要，五項：`Mean`、`SD`、`Median`、`Min`、`Max`
4. 來源只要求**平均值、標準差、中位數**三項，畫面另有**最小值與最大值**；**兩邊都要有**，五項都寫入

### 多維度的統計

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

1. 依**維度的數量**顯示**逐維度**的分佈直方圖，維度的名稱由**任務設定**決定（畫面的示例任務是兩個維度：`Valence`、`Arousal`）
2. **每一個維度各有自己的統計摘要**，項目與單維度相同（`Mean`、`SD`、`Median`、`Min`、`Max`）
3. 另外顯示**維度之間**的分佈：
   - **兩個維度** → 散布圖
   - **三個維度以上** → 逐對散布，或平行座標
4. 散布圖上**用紅點標出被標成高分歧旗標的樣本**，圖例三項：`主要標記群`、`高分歧旗標`、`低頻分佈`
5. 第 4 條**來源沒有提到**——高分歧旗標是品質監控那一邊的概念（見階段四），但畫面把它疊在統計總覽的散布圖上，所以**依畫面寫入、不得漏掉**；那個旗標的判定規則不在這一節

### 實體辨識的統計

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

1. 三個區塊：`實體類型分佈`、`每句平均實體數`、`Entity Span 長度分佈`
2. 統計的單位是**實體片段**
3. `實體類型分佈` 依**任務設定的實體類型清單**聚合，**不得**混進任何不是實體的資料
4. `每句平均實體數` 以句子裡標到的實體片段數算平均；主數字的標籤是 `平均實體數 / 句`，另有四個摘要：`總句子數`、`總實體標記數`、`無實體句子比例`、`單句最多實體數`（**這四項是畫面才有的**，來源沒有提到）
5. 來源另外**允許**附帶 `0`、`1`、`2`、`3+` 的分佈桶
6. `Entity Span 長度分佈` **以 :ref[Token]{id="term.token"} 長度為主、字元長度為輔**，軸標籤是 `Span 長度（token 數）`
7. 第 6 條**至少要有 `1`、`2`、`3`、`4+` 四個分桶**——這是來源的**最低要求**（「至少輸出」）
8. 畫面給得比第 7 條更細：`1`、`2`、`3`、`4`、`5`、`6+`（長度 6 以上併成一桶）。**比最低要求更細不算違反**；要不要以畫面的六桶為準，見[§待釐清](#待釐清) Q8
9. 第 6 條的單位與序列標註**刻意相反**（序列標註以字元分桶），**不得**為了一致而把兩邊統一

### 關係識別的統計

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

1. 兩個區塊：`關係類型分佈`、`Triple 統計摘要`
2. `關係類型分佈` 是每一種關係類型的**三元組標記次數**
3. `Triple 統計摘要` 是三元組層級的聚合，六項：`Triple 總數`、`唯一 Triple 數`、`平均 / 句`、`≥ 5 次標記 Triple`、`平均標記員數 / Triple`、`單句最多 Triple`
4. 來源只說「關係類型分佈與 Triple 數量統計」，第 3 條的**六項全是畫面才有的**，不得漏掉
5. 其中 `≥ 5 次標記 Triple` 就是品質監控那一邊所說的「可比較單位」在這個輸出類型上的樣子（見階段四）
6. 同一個任務**同時含實體辨識**時，**實體類型分佈只出現在實體辨識的區塊**，**不得**在這個區塊重複呈現

### 序列標註的統計

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

1. 三個區塊：`標籤類型分佈`、`每句平均標記片段數`、`標記片段長度分佈`
2. 統計母體是**已提交的標記片段**
3. `標籤類型分佈` 直接依片段的標籤聚合：
   - **不得**出現 `B-`、`I-`、`E-`、`S-` 任一前綴，也**不得**出現 `O`
   - 一段 `n` 個字的標記**算 1 筆**，**不得**算成 `n` 筆
   - 畫面的註腳就是這一條：`一段連續字元的標記片段計為 1 筆，不因字元數放大計算`
   - 來源在這一點附了一句「與標記工作區那一份規格的口徑一致」，指的是**審核端的標籤次數統計**（同一個 `n` 字的標記計為 1，不得因方案前綴拆成多筆）；而[規格 04-02](../04-annotation/02-annotation-workspace.mdx#審核卡上刻意完全不渲染的六樣東西)記的是**審核卡上根本不渲染標記分布統計盒**，所以那一頁沒有對應的規則可以指——**這一條的依據是本頁來源自己**
4. `每句平均標記片段數` 直接以樣本內的**片段筆數**算平均——**片段本身就是片段**，「把連續同類型的標記還原成片段」這一步**不得保留**；主數字的標籤是 `平均標記片段數／句`，另有 `總句子數`、`總標記片段數`（**這兩項是畫面才有的**，來源沒有提到）
5. `標記片段長度分佈` **以字元長度計算**（結束位置減起始位置），至少四桶：`1 字元`、`2 字元`、`3 字元`、`4+ 字元`，**不得**以 token 長度分桶
6. 具體的例子：某樣本有一筆 3 個字的 `ORG` 與一筆 2 個字的 `TITLE` → 標籤類型分佈是 `ORG` 1 筆、`TITLE` 1 筆；**該樣本的片段數是 2，不是 5**
7. 第 3 到 5 條是來源的**破壞性改版**：原本的母體是「依任務的切詞設定切出的 token 序列」、再依任務的標記方案解析出標籤類型；那兩個設定欄位已經在任務設定那一份規格被移除，**母體與解析步驟都沒有對象**，任何路徑都不得保留

### 品質監控要先有試標才有東西看

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

:ref[IAA]{id="term.iaa"} 報告是:ref[試標]{id="term.dry-run"}的產物，試標沒跑完就沒有報告。

1. 試標還沒完成時，品質監控顯示空狀態：標題 `IAA 報告將在 Dry Run 完成後產生`、說明 `請先完成 Dry Run，系統將自動計算 IAA 並產生品質報告。`，以及次要按鈕 `前往任務詳情`
2. 第 1 條那個按鈕導向**那個任務的**[任務詳情](../03-task-management/03-task-detail.mdx)
3. 空狀態的三個子狀態（試標進行中、報告待產生、報告產生中）**各有自己的標題與說明**：

| 子狀態 | 標題 | 說明 |
| :--- | :--- | :--- |
| 試標進行中 | `Dry Run 進行中` | `Dry Run 仍在執行中，等待所有標記員完成提交。` |
| 報告待產生 | `報告待產生` | `Dry Run 已完成，IAA 報告已排入計算佇列。` |
| 報告產生中 | `報告產生中` | `IAA 正在計算中，請稍候。這可能需要幾分鐘。` |

4. 第 1 條的那一組是**沒有子狀態資訊時的預設文案**；有子狀態就用第 3 條那一組取代
5. 空狀態下，只要**分母大於 0** 就要顯示一個待完成徽章：`—/〈分母〉 待完成 Dry Run`
6. 第 5 條的分母**只靠任務的輸出類型就算得出來**（哪些型別計入分母見[§任務層級的達標徽章](#任務層級的達標徽章)），不需要任何試標資料
7. 第 5 條**不得**顯示成 `0/〈分母〉`——`0` 表示「算過了，零個達標」，而這時候還沒算
8. **分母是 0 時不顯示待完成徽章**：那種任務的摘要狀態直接是**不適用**（見[§任務層級的達標徽章](#任務層級的達標徽章)第 9 條），而來源明文禁止 `y = 0` 的任務顯示任何通過、未通過或**待完成**的判定
9. 目前的畫面**沒有**落實第 8 條：它不分分母是不是 0 都會把待完成徽章填上，所以只有自由文字的任務會看到 `—/0 待完成 Dry Run`

### 逐型 IAA 報告的版面

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

一種輸出類型一份 IAA 報告，依任務的輸出類型清單**原本的順序**並列。

1. 區塊標題是 `IAA 報告`
2. 每一份報告至少有四樣東西：**主指標的名稱**、**指標數值**、**與門檻的比較結果**、**計算方法說明**

### 達標顏色只給真的有門檻的型別

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

1. 有門檻的型別：指標數值要有**明確的視覺**標示達標（綠）與未達標（紅）
2. **兩類型別不套綠紅**，改用中性樣式：
   - **永久沒有自動指標**的（現在只有自由文字）
   - **算得出數值、但還沒有門檻**的（現在只有序列標註）
3. 第 2 條那兩類的**文案不得互相沿用**——這是來源明文的禁止，理由見[§自由文字：永久沒有自動指標](#自由文字永久沒有自動指標)第 4 條
4. 自由文字那一類**不得**顯示空白，也**不得**顯示 `0`

### 自由文字：永久沒有自動指標

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

1. 自由文字**不計算自動 IAA**
2. 它的子區塊顯示一張狀態卡：導言 `不適用—由審核員評估`，說明 `自由文字回覆無標準答案，不納入自動 IAA 計算與整體達標比例分母；品質由 Reviewer 於審核流程中逐筆評估。`
3. **不得**顯示空白、**不得**顯示 `0`、**不得**套達標綠或未達標紅
4. 這一類的語意是「**永久沒有自動指標，由審核員評估**」。它與序列標註那一類**在分母上的效果相同，但語意完全不同**，所以**文案不得共用**；把「不適用—由審核員評估」用在序列標註上是**錯誤陳述**
5. 自由文字**排除於達標分母**（見[§任務層級的達標徽章](#任務層級的達標徽章)）
6. 自由文字**仍然有一個品質指標**：標記員被修改率（見階段四）——那是它唯一可能擁有的品質訊號

### 序列標註：算得出來，但還沒有門檻

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

序列標註的主指標**算得出來**，只是平台還沒有足夠的實證資料可以訂門檻。

1. 顯示主指標的**點估計值**，並支援跨標記員與跨樣本的**排序**
2. **不得**顯示任何門檻值、**不得**顯示達標或未達標的文案、**不得**套綠或紅
3. 用**中性**樣式標示 `u-α 待實證校準：目前僅顯示點估計值與排序，尚未訂定達標門檻。`
4. **不得**顯示「不適用—由審核員評估」——那是自由文字的語意，用在這裡是錯誤陳述
5. **不得**為它定任何門檻常數、預設值或建議值；實作**不得**用任何寫死的數字回退。門檻要等取得第一批試標的實測分布後，另開變更依實證校準
6. 這一類**不阻擋**任何流程，也**不得**讓任務層級的摘要落到「未通過」
7. **其餘規則照常適用**：小樣本警示、樣本或標記員不足時的「無法計算」、一致性最低樣本清單、標記員品質排名、邊界分歧分析——**沒校準的是「門檻」，不是「指標」**
8. 畫面上**不存在** `Token-level Alpha` 這個字樣、**不存在**任何門檻數值，也**不存在**「把所有標記員都標成 `O` 的位置遮掉」這類遮罩說明
9. 第 8 條那個舊指標與它的 0.75 門檻**已正式廢止**，那兩個識別名稱**不得**在規格、原型或測試中重新使用
10. 第 8 條的遮罩**沒有對象可遮**：片段模型底下沒有逐格的位置陣列、沒有 `O` 標籤；而且 u-α 本來就以連續體長度加權處理未標記的區段，**不得**用任何片段版本的等價遮罩規則取代

### 多標籤的逐標籤 Alpha 以整條路徑為標籤

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

[§多標籤的「標籤」是整條階層路徑](#多標籤的標籤是整條階層路徑)定的是統計那一面；品質監控這一面同一套規則。

1. 逐標籤 Alpha 的「標籤」是**完整路徑**，巨集平均的對象是**各條完整路徑**
2. **正例出現次數不足 5 次**的稀有標籤**排除於巨集平均**
3. 第 2 條的「正例出現次數」**以完整路徑計**，**不得**把子孫路徑的次數併進祖先路徑
4. 被排除的稀有標籤要**列出排除清單**，清單上寫的是**完整路徑**
5. 階層與扁平的門檻**同一個值**，不因為改成完整路徑而變

### 樣本或標記員不足時顯示「無法計算」

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

1. 任一輸出類型的**有效樣本數少於 2**、或**有效標記員數少於 2** 時，那個型別的主指標**在數學上沒有定義**
2. 這時候顯示**明確的「無法計算」狀態**並**說明原因**
3. **不得**退回顯示 `0.00`，也不得退回任何其他數值
4. **不得**因此阻擋使用者進入正式標記
5. 第 1 到 4 條對一般的 Alpha 與序列標註的單位化 α **同等適用**

### 小樣本估計警示

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

1. 某個輸出類型的**完成標記員數少於 5** 時，在那個指標旁顯示一個**中性**的 `小樣本估計` 警示徽章
2. 這個徽章**不阻擋**達標判定
3. **點估計值照常顯示**，不因為小樣本而隱藏
4. 序列標註也照常顯示這個徽章

### 任務層級的達標徽章

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

逐型報告上方有一個任務層級的徽章，區塊標題是 `IAA 綜合結果`。

1. 徽章的格式是 `〈達標數〉/〈分母〉 達標 · 〈排除數〉 型排除`；**排除數是 0 時整個後綴省略**
2. **分母**是任務的輸出類型裡**既不是「永久沒有自動指標」、也不是「還沒有門檻」**的**相異**型別數
3. **分子**是其中主指標達標的型別數
4. **兩類排除型別都不進分子也不進分母**。未校準的型別沒有門檻可比，把它算進分母會讓一個永遠無法達標的型別**把整體永久鎖在未通過**
5. 第 1 條的**排除數涵蓋兩類**，算的是它們在這個任務的輸出類型裡命中的**相異型別總數**
6. 達標的判定是：**分子等於分母，而且分母大於 0**。這是**全部達標**，不是多數決
7. 分母是 1 時**仍然用分數的形式**呈現（`1/1 達標`），不另外分岔成別的版面
8. 「無法計算」（樣本或標記員不足）**不計入分子**——沒有數值就不算達標；但它**仍然計入分母**，因為它不屬於那兩類排除型別。所以單一型別的任務無法計算時，徽章是 `0/1 達標`
9. **分母是 0** 時（任務的輸出類型全都落在那兩類裡），摘要狀態是**不適用**，徽章顯示 `不適用`；**不得**顯示 `0/0`、**不得留空白**，也**不得**顯示任何通過、未通過或待完成的判定
10. 這個徽章是**顧問性的**，不阻擋任何流程
11. **卡片狀態與徽章必須取自同一次計算的結果**，不得各算一次
12. 具體的例子：

| 任務的輸出類型 | 試標與達標情形 | 徽章 |
| :--- | :--- | :--- |
| 單一標籤、序列標註、自由文字 | 試標已完成，單一標籤達標 | `1/1 達標 · 2 型排除` |
| 序列標註、自由文字 | 任何情形 | `不適用` |
| 只有自由文字 | 任何情形 | `不適用` |
| 單一標籤 | 有效標記員只有 1 位 | `0/1 達標` |
| 單一標籤、多標籤 | 還沒有試標資料 | `—/2 待完成 Dry Run` |

13. 畫面的字典裡還留著 `整體通過`、`整體未達標`、`部分通過` 三個字串，但**沒有任何地方引用它們**——徽章的文字只有第 1、9 條與待完成那三種。**不得**把那三個字串當成第三種徽章狀態寫進規格

### IAA 狀態是列表頁的唯一來源

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

1. 品質監控同時要輸出一個:ref[IAA 狀態]{id="term.iaa-status"}，供[規格 05-01 的 IAA 狀態徽章](./01-analysis-list.mdx#iaa-狀態徽章)使用；那一頁的徽章**只能**以這個狀態為來源
2. 五個狀態沿用[規格 05-01 §已確認決議](./01-analysis-list.mdx#已確認決議)定的名字：**通過**、**計算中**、**未通過**、**尚未開始**、**不適用**
3. 這個狀態**必須依[§任務層級的達標徽章](#任務層級的達標徽章)第 6 條的判定、由逐型結果推導**
4. **不得**用任何單一輸出類型的結果直接代表整體

### IAA 閘門的語意：顧問性，不阻擋

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

這一節是整個平台對 IAA 閘門語意的**唯一權威來源**。其他模組呈現 IAA 閘門行為時以這一節為準，**不得**另行定義或推導出不同的語意。

1. **IAA 是顧問性指標**。「等待 IAA 確認」的語意是「**軟性警告 ＋ 需要人工確認**」，**不是**硬性閘門
2. 指標沒達到門檻時，系統**必須顯示明顯的警示**，但**不得阻擋**使用者進入正式標記
3. 第 2 條只適用**真的登錄了門檻**的型別。沒有門檻的型別**不得**顯示任何「未達門檻」的警示，也**不得**因此被當成未通過
4. 第 3 條**不是放寬**阻擋語意——沒有門檻的型別一樣不阻擋流程
5. **「還在算」不屬於第 2 條**。最新一輪試標的 IAA 還在計算中或計算失敗時，根本還沒有任何 IAA 結果，那不是「沒達到門檻」；這時候能不能進入正式標記，由[規格 03-03](../03-task-management/03-task-detail.mdx)的 IAA 計算狀態處理
6. 第 5 條不改變第 2 條對**已有結果**的不阻擋語意；[§樣本或標記員不足時顯示「無法計算」](#樣本或標記員不足時顯示無法計算)屬於**已經得到結果**，一樣不阻擋
7. **算 IAA 的輸入只有標記員自己的原始作答**
8. **審核員不是一位標記者**。他的審核修正值**不得**併進 IAA 的計算
9. IAA **逐回合計算**，**不得**跨回合累積
10. 被明確**排除的標記作業**不計入 IAA
11. **已停用成員**的既有標記**仍然計入** IAA
12. 標記員在某個輸出類型上**跳過**時，那一筆在那個輸出類型上**視為缺值**，不計入分母；**不得**當成一個「空白答案」拿去和其他標記員的實際答案比對

### 品質指標就緒訊號

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

這一頁要對外提供一個布林訊號，讓[規格 03-03](../03-task-management/03-task-detail.mdx)判斷任務能不能結案。

1. 訊號的意思只有一件事：**IAA 的計算有沒有結束**
2. 它由該任務**最新一輪**試標的 IAA 計算狀態推導：**已完成** → 就緒；**待計算**與**計算失敗** → 未就緒
3. 「無法計算」已經算是**計算完成**，所以**就緒**；**不得**因為某個輸出類型無法計算就判為未就緒
4. **缺少試標紀錄**、或紀錄裡**沒有這個計算狀態**時，**視為就緒**，**不得**阻擋
5. 這個訊號**不描述 IAA 有沒有達到門檻**。達標與否不影響它
6. 標記員被修改率（階段四）**由審核差異即時推導、沒有非同步的計算狀態**，**不得**當成這個訊號的輸入
7. 這個訊號的**唯一消費者**是[規格 03-03](../03-task-management/03-task-detail.mdx)的結案前置條件；**不得**用它阻擋試標完成，也不得用它阻擋開始正式標記

### 共用品質監控區的三個區塊與順序

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

逐型的 IAA 報告之外，品質監控還有三個區塊。

1. 三個區塊在就緒狀態下**固定依序**呈現：**異常偵測** → **標記員風險評估** → **標記一致性偏離分析**
2. 第 1 條的順序是硬規則，**不得**調換
3. 來源**在三個地方都明寫這是「一份」**：介面定義把它列為「**共用**品質監控功能區」、行為規則說「**共用**品質監控區塊…固定依序呈現」、驗收標準說偏離分析是「quality tab 中」的「**獨立區塊**，固定顯示在標記員風險評估區塊**下方**」。來源說「逐型並列」的只有 **IAA 報告**那一項
4. 但**目前的畫面是在每一種輸出類型的區塊裡各出現一次**（七份；自由文字那一份完全沒有這三個區塊），而且每一份的內容是那一型特有的——**畫面與來源不符**，見[§待釐清](#待釐清) Q18
5. 標記員被修改率**不屬於**這三個區塊，它是**任務層級的一張表**，位置在逐型迴圈之外（見[§標記員被修改率](#標記員被修改率)）——這一項是來源**唯一**明文寫「置於逐輸出類型迴圈之外」的區塊

### 異常偵測

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

1. 區塊標題是 `異常偵測`，副標 `自動標記標記速度異常與離群標記值`
2. 區塊**至少涵蓋兩類**：**標記速度異常**（過快與過慢）與**離群的標記值**
3. 第 2 條兩類各有自己的小標：`標記速度異常`、`高分歧樣本`
4. 速度異常的每一筆寫**是誰、哪一種異常**，以及**支撐的數字**（平均速度、比較基準、該標記員的提交筆數）
5. 離群標記值的每一筆寫**哪一個樣本、是誰**，以及**他的值與群體平均的對照**
6. 兩類各自有空狀態：`無速度異常`、`無高分歧樣本旗標`；關係識別那一型的離群空狀態是另一句 `暫無 high_divergence 樣本`——**這一句把內部的英文鍵名漏到使用者看得到的文案裡**
7. 來源的用詞是「離群標記值」，畫面的小標是「高分歧樣本」而副標寫「離群標記值」——**同一件事兩個說法，兩邊都照畫面寫出來**

### 標記員風險評估：三個等級與一個「資料不足」

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

1. 區塊標題是 `標記員風險評估`，副標 `風險等級與異常原因獨立於 high_divergence 樣本旗標顯示`
   - 七個逐型面板的 HTML 裡各寫了一句不同的副標文字，但那個位置的文字**由共用字典統一覆寫**，所以畫面上永遠是上面這一句；面板裡的那幾句**是死字串、不會出現**
2. 風險等級**恰好三個值**：`正常`、`觀察`、`高風險`
3. 升級規則是**或**的關係——**任一條成立就升級**：

| 等級 | 任一條成立即升級 |
| :--- | :--- |
| `觀察` | 個別 IAA **低於**群體 IAA 減 **0.05**；**或** 平均速度**低於**群體平均的 **0.6 倍** |
| `高風險` | 個別 IAA **低於該型別的 IAA 門檻**；**或** 離群率**高於 30%**；**或** 平均速度**低於**群體平均的 **0.4 倍** |

4. 第 3 條的數字是**預設值**，**專案負責人可以在任務設定裡覆寫**
5. 標記員**已完成樣本數低於 10** 時，**略過**風險等級的計算，並顯示 `資料不足，暫不評估`
   - 來源的條文與驗收標準**兩處都明寫這一整句**
   - 畫面把它**拆成兩格**：風險等級那一欄顯示 `資料不足`，異常原因那一欄顯示 `〈已完成數〉 / 10，暫不評估`（示例 `8 / 10，暫不評估`）
6. 第 5 條**不得**顯示成預設的 `正常`
7. 風險等級的值域**恰好是第 2 條那三個**，來源明寫**不得**用第四個值表示資料不足
8. 第 5 條那種標記員：風險等級是**空的**，另有一個「資料不足」的旗標為真；其餘標記員的「資料不足」為假、風險等級是三值之一
9. 兩欄**不得**出現互相矛盾的組合（例如資料不足為真卻又給了一個等級）
10. **畫面目前不是這樣做的**：它在**風險等級那一欄**直接顯示第四個值 `資料不足`（標記上是 `insufficient`），沒有「空等級 ＋ 另一個旗標欄」這種結構。這是**畫面與來源第 7、8 條不符**，見[§待釐清](#待釐清) Q22
11. 風險表的每一列至少有：標記員、平均速度、該型別的指標值、風險等級、異常原因、樣本數、建議行動
12. 表上另有一列**群體平均**供對照（格式如 `群體平均 — Alpha: 0.85 ／ 平均速度: 31.3s／句`）
13. 這一頁的[規格 03-03](../03-task-management/03-task-detail.mdx)有一個「品質旗標」欄，畫面上是**另外三個中文名**；兩者是不是同一個訊號、名字取哪一組，見[§待釐清](#待釐清) Q19

### 風險的異常原因只限標記員層級

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

1. `觀察` 與 `高風險` 的標記員要標示**一個或多個**異常原因
2. 原因**只有三種**，而且**都是標記員層級**的：

| 原因 | 判定 |
| :--- | :--- |
| `系統性偏差` | 個別平均與群體平均的差距**絕對值超過 1 個標準差**，而且**有方向性**（系統性偏高或偏低） |
| `標記過快` | 個別平均速度**低於**群體平均的 **0.6 倍** |
| `標記過慢` | 個別平均速度**高於**群體平均的 **2.0 倍** |

3. 沒有異常原因時顯示 `無異常原因`
4. **不得**用樣本層級的屬性當標記員的異常原因（例如「資料模糊」）——那是樣本的性質，不是這個人的
5. 多維度任務的原因**逐維度分開標示**（畫面的示例如 `V 系統性偏高`、`A 標記過慢`），**不得**合併成單一原因

### 高分歧樣本是樣本層的旗標，不是標記員的風險

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

1. 高分歧樣本以**樣本層級的旗標**獨立顯示，**與標記員風險評估區塊分開呈現**
2. 判定：同一個樣本裡，**任一標記員**的標記值距群體**中位數超過 2 個標準差**，而且**其他標記員之間一致性高**（兩兩比較的組內相關係數高於 **0.75**）
3. 每一筆至少有樣本識別、分歧分數、不一致的標記員清單
4. **高分歧樣本不得拉高相關標記員的風險等級**
5. 第 4 條的理由：一個樣本本身難標，不代表標它的人有問題

### 多維度的風險等級取最高的那一個維度

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

1. 多維度任務的標記員風險等級**取各維度之中較高的那一級**
2. 第 1 條是把原本兩個維度的平均作法**泛化到任意維度數**
3. 各維度的**異常原因分開標示**，**不得**合併顯示

### 建議行動只有專案負責人能執行

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

1. 風險表最後一欄是建議行動，兩個按鈕：`審核標記`、`調整參與狀態`
2. **只有:ref[專案負責人]{id="term.project-leader"}能觸發**這兩個行動
3. :ref[審核員]{id="term.reviewer"}**只能看**風險等級與原因，**不得**觸發行動；他看到的是 `僅 Project Leader 可執行`
   - **關係識別那一型的畫面少了這一句**：它的風險表有四個行動按鈕，卻沒有任何一個 `僅 Project Leader 可執行` 的說明，其餘六型都有。按鈕不可按但沒有說明，審核員會以為是壞掉了
4. 兩個按鈕都是**導頁**，不在這一頁改任何東西：

| 按鈕 | 去哪裡 |
| :--- | :--- |
| `審核標記` | 那個任務的[標記清單](../04-annotation/01-annotation-list.mdx)，而且**預先帶上審核員視角與試標回合** |
| `調整參與狀態` | 那個任務的[任務詳情](../03-task-management/03-task-detail.mdx)的**成員管理**分頁 |

5. 第 4 條第一列預先帶試標回合，是因為品質分析**本來就以試標完成為前提**
6. 這兩個行動是這一頁唯一會把人帶到「能改東西的地方」的出口；這一頁本身仍然**完全唯讀**

### 標記一致性偏離分析

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

這是一個**獨立區塊**，顯示每位標記員在可比較單位裡偏離群體的次數與比例。

1. 區塊標題是 `標記一致性偏離分析`，副標 `顯示每位標記員在可比較單位中的離群值筆數與比例，作為觀測訊號，不直接覆寫風險等級。`

### 標記員被修改率

<PrototypeFrame page="dataset/dataset-analysis-detail" caption="分析詳情" client:idle />

這是**自由文字唯一可能擁有的品質指標**，所以它的範圍與前兩個區塊不同。

1. 區塊標題是 `標記員被修改率`，副標 `依標記員彙總 Reviewer 實際變更答案的比例；分母為至少一位 Reviewer 已提交決定的審核單位（不含待審）`
2. 這是**任務層級的一張表**：一列一位標記員，一欄一種輸出類型，另有一欄 `總計`；每一格的格式是 `〈分子〉 / 〈分母〉 (〈百分比〉%)`，百分比四捨五入到整數
3. 這張表**放在逐型迴圈之外**，**不得**逐型另建子區塊。理由：分母以審核單位計，本質上是逐標記員一個數字；逐型拆開會變成每個型別各自一張資訊密度極低的小表
4. **八種輸出類型全納，含自由文字**
5. 第 4 條與[§逐型標記員品質排名](#逐型標記員品質排名)的七種**刻意不同**：排名依賴多數決或合併聚合等跨標記員比對，自由文字做不到；而被修改率的分子分母都來自**逐一審核單位的差異比對**，自由文字可以比照其餘七種計算
6. 被修改率與標記員品質排名是**互補但不同**的觀測面向：前者是與審核員決策的差異比率（八型全納），後者是與多數決或合併聚合參考值的一致率排名（七型）。兩者是**分屬不同區塊的獨立資料**，**不得**互相覆寫，也**不得**合併顯示成單一分數
7. **分子**：該標記員名下的審核單位中，**經審核員實際更動過答案**的數量；判定依據是**逐輸出類型的差異比對結果**（「是否相同」為否的那些）
8. **分子不得用審核單位的狀態值計數**。那個狀態的語意是「有改動**而且**已審人數還沒到法定人數」；達到法定人數的改動單位會落到別的狀態，用狀態值計數會**系統性漏計所有已達法定人數的改動**
9. **分母**：該標記員名下**至少有一位審核員已提交決策**的審核單位數，也就是**排除還沒審的**
10. 第 9 條的理由：**沒審不等於沒改**。把沒審的算進分母，審核覆蓋率低的任務會被**系統性低估**被修改率
11. 標記員自己沒提交的，**不成立審核單位**，自然不在分子也不在分母
12. **排除規則一**：標記員在某個輸出類型上**跳過**時，那一筆不計入該次差異比對的分子與分母
13. **排除規則二**：被明確**排除的標記作業**不計入分子與分母
14. 第 12、13 條目前**原型都沒有落實**，而且各有一個**資料層的缺口**：跳過的旗標沒有被帶進比對用的答案形狀，所以比對函式分不出「跳過」與「空白未作答」；排除清單只存在任務詳情頁的區域記憶體、沒有持久化，標記工作區對它零知悉。來源把這兩件事**明文列為獨立的實作項**
15. **不得**用「退回／通過」的決策來定義被修改率。原型送出審核時只寫進自由文字的歷程摘要、沒有結構化的決策欄位；而且「退回但沒改答案」與「退回並改了答案」是來源**明文承認的兩種獨立組合**
16. 第 15 條的意思是：日後若要一個「被退回率」指標，得先有結構化的決策儲存，那是**另一項變更**，不在這一條的範圍
17. 完成樣本數**少於 5** 的標記員顯示小樣本估計警示，**不得**從清單中剔除
18. 指標的定義**與回合類型無關**，試標與正式標記都適用。正式標記每一筆樣本只指派一位標記員，標記員之間沒有重疊、算不出 IAA，**被修改率是正式標記底下唯一可能的逐標記員品質訊號**
19. **但這一版只落地試標那一塊**：品質監控整個分頁目前綁在試標上，正式標記的呈現位置**待後續變更定案**

### 從標記推導序列的規則

這一節**沒有畫面**：匯出的對話框、入口與紀錄表都在[規格 03-03 任務詳情](../03-task-management/03-task-detail.mdx)，這一頁只定義**怎麼從標記推導出序列**。這個推導的契約是**跨模組的唯一權威來源**：[規格 03-02 新增任務](../03-task-management/02-task-new.mdx)與[規格 04-02 標記工作區](../04-annotation/02-annotation-workspace.mdx)的來源都明文把它指名給這一頁，其他模組**不得**另行定義或推導出不同的語意。

1. 這個推導**只適用:ref[序列標註]{id="term.sequence-tagging"}**
2. 第 1 條之所以成立，前提是**片段互不相交**——任務設定那一份規格把序列標註的「允許重疊」鎖成**不允許**，所以扁平序列與片段集合之間是**一對一**的，壓成序列不會掉資訊
3. :ref[實體辨識]{id="term.entity-recognition"}**允許重疊與巢狀**，沒有第 2 條的性質，**不得**套用這個推導
4. 推導是 `標記片段 ＋ 原始文本` 的**純函式**：同樣的輸入在任何時間、任何執行環境重複匯出，**必須產生逐字元相同的序列**
5. **不得**把時間戳、隨機性、瀏覽器語系或本機設定當成推導的輸入
6. **標記方案屬於匯出，不屬於任務**：
   - 三個方案是 `BIO`、`BIOES`、`IOB2`，預設 `BIO`
   - 方案是**匯出當下的輸出格式選項**，**不得**寫回任務設定、**不得**影響任何既有標記
   - **同一份標記結果必須能用不同方案重複匯出**，而且不需要重新標記
7. **字元級是預設**（兩個單位是 `character` 與 `word`，預設 `character`）：
   - 每一個**字元**就是一個位置，片段的半開區間 `[起點, 終點)` 直接對應位置索引
   - **起點**那一格給 `B-〈標籤〉`
   - **起點之後到終點之前**的每一格給 `I-〈標籤〉`
   - **沒有被任何片段覆蓋**的位置給 `O`
   - 這條路徑**不需要任何切詞引擎**，也**不可能產生對齊誤差**
8. **方案之間的差別只在表示層**：
   - `BIOES`：**單一位置**的片段給 `S-〈標籤〉`；多位置片段的**最後一格**給 `E-〈標籤〉`
   - `IOB2` 與 `BIO` 的**標記集合相同**，差別只在歷史命名，**必須產生相同的序列**
   - 三個方案**都從同一組片段推導**，**不得**各自維護一條獨立的轉換路徑
9. **空集合**：某個樣本一個片段都沒有時，**必須輸出與文本等長的全 `O` 序列**；**不得**省略那個樣本，也**不得**輸出空陣列
10. 具體的例子（文本 `台積電董事長出席`，一筆 `起點 0、終點 3、標籤 ORG` 的片段）：

| 方案 | 推導出的序列 |
| :--- | :--- |
| `BIO`（預設） | `B-ORG`、`I-ORG`、`I-ORG`、`O`、`O`、`O`、`O`、`O` |
| `BIOES` | `B-ORG`、`I-ORG`、`E-ORG`、`O`、`O`、`O`、`O`、`O` |
| `IOB2` | 與 `BIO` 相同 |

11. 第 10 條的序列**長度等於文本的字元數**
12. 字元級匯出的檔案裡**記下**用的是哪一個方案與哪一個單位，而且**不含**任何切詞引擎的資訊

### 詞級匯出要帶切詞資訊並回報擴張

詞級是**進階選項**。選了它之後多出四組規則：可重現性、對齊採擴張、擴張必須被看見、不回寫。

1. **可重現性**：匯出檔必須寫入**切詞引擎**與**引擎版本**兩項資訊
2. 缺少第 1 條任一項時，**必須擋下這一次匯出並說明原因**——同一份標記在不同切詞引擎或不同版本下會得到不同的序列，少了這兩項的資料集**無法重現**
3. **對齊採擴張**：片段的邊界落在一個詞的內部時，**必須擴張到涵蓋整個詞**
4. 第 3 條**不得**截斷那個片段、**不得**丟棄那一筆標記，也**不得**以「無法對齊」為由略過那個樣本
5. 擴張模式**只有「擴張」這一種**，沒有其他選項
6. **擴張必須被看見**：匯出完成後顯示 `〈筆數〉 段標記因對齊被擴張` 的摘要；**筆數是 0 時不顯示這個摘要**
7. 第 6 條的摘要**必須可以展開**，逐筆列出**原始的標記文字**、**擴張後的文字**，以及**起訖位置的差值**
8. **不回寫**：擴張**只發生在匯出的產物裡**，**不得**修改任何已儲存的標記片段——標記員實際圈選的位置才是權威值
9. **字元級不適用**：單位是字元時，**不得**寫入切詞引擎資訊，也**不得**顯示擴張摘要（字元級不可能發生擴張）
10. 具體的例子（文本 `台積電董事長出席`，一筆涵蓋 `董事` 的 `起點 3、終點 5、標籤 TITLE` 片段，而所選的切詞引擎把 `董事長` 切成一個詞）：
    - 那一筆被**擴張成涵蓋 `董事長`**，沒有被截斷也沒有被丟棄
    - 匯出檔帶著切詞引擎與版本
    - 摘要顯示 `1 段標記因對齊被擴張`，展開後列出原始文字 `董事`、擴張後文字 `董事長` 與位置差值
    - **已儲存的片段仍然是 `起點 3、終點 5、標籤 TITLE`**，沒有被回寫
11. 第 6、7 條以及第 2 條的「說明原因」**屬於畫面呈現**，落地位置在[規格 03-03](../03-task-management/03-task-detail.mdx)；這一頁只定義**應該被回報的資料**，以及推導與中介資料的純函式行為**可以被獨立驗證**

## 卡控機制

- 任務代號不存在 → 導回分析列表，顯示 `找不到指定的任務，或您沒有該任務的存取權限。`
- 使用者在那個任務沒有專案負責人或審核員的成員資格 → 同上，與前一條是同一個觸發、同一句提示
- 使用者在那個任務的任務角色缺少或認不得 → 視同沒有成員資格，**失敗即關閉**，導回分析列表
- 使用者在那個任務**唯一的**成員身分是「受邀但還沒生效」 → 視同不存在，等於沒有生效身分，依前一條處理
- 使用者還有其他生效身分，但聯集後不含某個分頁的權限 → 只**拒絕那一個分頁的資料讀取**，**不得**整頁擋掉
- 標記員身分進入這一頁 → 進不來，依第二條處理
- 驗證不過 → **不得**退回成任何預設任務再渲染內容
- 「看任務統計」不成立 → **拒絕統計總覽的資料讀取**；不得改成顯示空統計
- 「看品質分析」不成立 → **拒絕品質監控的資料讀取**；不得改成顯示空報告
- 任一分頁的權限不成立 → 只拒絕那一個分頁，**不得**整頁擋掉
- 網址上的分頁參數不是那兩個合法值之一 → **回退成統計總覽**
- 沒帶分頁參數 → 落在統計總覽
- 網址試圖指定任務的輸出類型 → **忽略**，輸出類型只由任務資料決定
- 任務的輸出類型取不到、是空的、缺少、或含認不得的鍵 → 兩個分頁都顯示**可重試的錯誤狀態**；**不得**猜一個預設輸出類型、不得猜組合、不得只渲染認得的那幾個
- 切換分頁 → **不得**導向分析列表、不得重新載入整頁、不得重建任務上下文
- 切換分頁 → **不得**重設任一分頁的捲動位置
- 語系切換 → **不得**整頁重新載入、不得改變目前所在的分頁
- 任一分頁的內容載入失敗 → 只換掉**該分頁的內容區**，頁首、麵包屑、分頁列與另一個分頁不受影響
- 共用指標不是恰好五項（多一項或少一項） → 違規；**不得**增減
- 完成率用別的名字表示 → 違規；它只能叫「完成率」
- 任務有兩種以上輸出類型 → 依**原本順序**逐型並列；**不得**只顯示第一種、不得用固定優先序覆蓋順序、不得壓成一種
- 任務的輸入類型是「項目對」 → 欄位顯示名稱**沿用任務設定裡那一對的名稱**；**不得**為統計總覽另建分支
- 序列標註的標籤類型分佈 → **不得**出現 `B-`／`I-`／`E-`／`S-` 前綴或 `O`
- 序列標註的一段 `n` 字標記 → **算 1 筆**；算成 `n` 筆即違規
- 序列標註的片段長度分佈 → **以字元長度分桶**；以 token 長度分桶即違規
- 序列標註 → **不得**保留「依切詞設定切出 token 序列」的母體，也不得保留「把連續同類型標記還原成片段」的步驟
- 實體辨識的 `Entity Span 長度分佈` → **以 :ref[Token]{id="term.token"} 長度為主**，至少 `1`／`2`／`3`／`4+` 四桶；不得改成與序列標註的字元分桶一致
- 任務同時含實體辨識與關係識別 → 實體類型分佈**只出現在實體辨識的區塊**
- 多標籤提交 `A › B` → **不得**讓 `A` 的次數增加
- 多標籤的 `A` 與 `A › B` → 視為**兩個獨立類別**；同名但路徑不同的節點**不得**合併
- 多標籤同一筆樣本同時提交 `A` 與 `A › B` → 共現矩陣當**一般共現**處理，不得因階層關係特別處理、合併或略過
- 多標籤的計數 → **由資料裡的路徑驅動**；寫死層數、節點名稱或依任務類型分支即違規
- 多標籤 → **不得**提供依最上層或任何祖先層彙總的呈現
- 自由文字 → **不得**提供標籤類或分數類的圖表
- 還沒有任何已提交的標記 → 統計總覽顯示空狀態，標題 `尚無標記資料`，含 `前往任務詳情` 次要按鈕
- 試標還沒完成 → 品質監控顯示空狀態，含 `前往任務詳情` 次要按鈕
- 空狀態且分母大於 0 → 顯示 `—/〈分母〉 待完成 Dry Run`；**不得**顯示 `0/〈分母〉`
- 空狀態且分母是 0 → **不顯示待完成徽章**，摘要狀態直接是不適用
- 任一型別的 IAA 報告 → 必須同時有主指標名稱、數值、與門檻的比較結果、計算方法說明
- 輔助／顯示用指標 → **預設收合**；主指標**不得**收合
- 有門檻的型別 → 達標綠、未達標紅
- 自由文字 → 中性樣式並顯示 `不適用—由審核員評估`；**不得**空白、不得顯示 `0`、不得套綠紅
- 序列標註 → 中性樣式並顯示 `u-α 待實證校準…`；**不得**顯示門檻、不得顯示達標或未達標文案、不得套綠紅
- 序列標註 → **不得**顯示 `不適用—由審核員評估`（那是自由文字的語意）
- 序列標註 → **不得**定任何門檻常數、預設值或建議值；實作**不得**用寫死的數字回退
- 畫面任何位置 → **不得**出現 `Token-level Alpha` 字樣、不得出現已廢止的那個門檻、不得出現任何「遮掉全員都標成 `O` 的位置」這類遮罩說明
- 實體辨識的部分重疊 F1 → **只能切換顯示**；當成第二道達標判定即違規
- 關係識別的 0.80 → **顯示帶**；當成第二道判定即違規
- 單維度的達標判定 → 取**建議階**；多維度的達標判定 → 取**嚴格階**；取錯即違規
- 多標籤 → 正例出現次數少於 5 的標籤**排除於巨集平均**，並**列出排除清單**（寫完整路徑）
- 多標籤 → **不得**把子孫路徑的正例出現次數併進祖先路徑
- 有效樣本數少於 2，或有效標記員數少於 2 → 顯示「無法計算」與原因；**不得**顯示 `0.00` 或任何回退數值；**不得**阻擋進入正式標記
- 完成標記員數少於 5 → 中性 `小樣本估計` 徽章；**不得**阻擋達標判定；點估計照常顯示
- 兩類排除型別（永久沒有自動指標、還沒有門檻） → **不進分子也不進分母**
- 分母是 0 → 摘要狀態是**不適用**；**不得**顯示 `0/0`、不得顯示通過或未通過
- 「無法計算」的型別 → **不計入分子**，但**仍計入分母**
- 分母是 1 → **仍用分數形式**呈現，不另外分岔版面
- 排除數是 0 → **省略**「· 〈排除數〉 型排除」後綴
- 卡片狀態與徽章 → 必須**取自同一次計算的結果**
- IAA 沒達門檻 → 顯示明顯警示；**不得阻擋**使用者進入正式標記
- 沒有門檻的型別 → **不得**顯示任何「未達門檻」警示，**不得**被計入未通過
- 審核員的審核修正值 → **不得**併進 IAA 的計算
- IAA → **逐回合**計算，不得跨回合累積
- 被明確排除的標記作業 → **不計入** IAA
- 已停用成員的既有標記 → **仍然計入** IAA
- 標記員在某個輸出類型上跳過 → 那一筆在那個輸出類型上**視為缺值**、不計入分母；**不得**當成空白答案拿去比對
- 列表頁的 IAA 狀態 → **只能**以這一頁輸出的狀態為來源；**不得**由單一輸出類型的結果直接代表整體
- 就緒訊號：最新一輪試標的 IAA 計算狀態是待計算或計算失敗 → **未就緒**
- 就緒訊號：計算狀態是已完成（**含**因樣本不足而「無法計算」） → **就緒**
- 就緒訊號：缺少試標紀錄或缺少計算狀態 → **視為就緒**，不得阻擋
- 就緒訊號 → **不得**描述 IAA 有沒有達標、不得把被修改率當輸入、不得用來阻擋試標完成或開始正式標記
- 三個共用區塊 → 固定依序：異常偵測 → 標記員風險評估 → 標記一致性偏離分析；調換即違規
- 風險等級的值域 → **恰好三個值**；用第四個值表示資料不足即違規
- 標記員已完成樣本數低於 10 → **略過**風險等級計算，顯示 `資料不足，暫不評估`（畫面拆成兩格：等級欄 `資料不足`、原因欄 `〈已完成數〉 / 10，暫不評估`）；**不得**顯示預設的 `正常`
- 略過評估的標記員 → 風險等級**空的**、資料不足旗標為真；兩欄**不得**互相矛盾
- 觀察或高風險的標記員 → 標示一個或多個異常原因；原因**只限標記員層級**三種
- 異常原因 → **不得**用樣本層級的屬性（例如「資料模糊」）
- 多維度任務的異常原因 → **逐維度分開標示**，不得合併
- 多維度任務的風險等級 → 取**各維度中較高**的那一級
- 高分歧樣本 → 以樣本層級旗標**獨立顯示**，與風險評估區塊分開；**不得**拉高相關標記員的風險等級
- 建議行動 → **只有專案負責人能觸發**；審核員只能看，看到 `僅 Project Leader 可執行`
- `審核標記` → 導向那個任務的標記清單，**預先帶上審核員視角與試標回合**
- `調整參與狀態` → 導向那個任務的任務詳情的**成員管理**分頁
- 偏離分析 → **至少五個獨立欄位**（可比較單位數、1.5 倍標準差的筆數與比例、2 倍標準差的筆數與比例）
- 偏離分析第一欄的欄名 → **依輸出類型**用對應的資料單位名稱；一律硬寫成三元組即違規
- 偏離分析 → **不得**直接覆寫風險等級；**不得**用單一高分歧樣本取代整體偏離比例
- 偏離分析與品質排名 → **不得**互相覆寫，也不得合併成單一分數
- 一致性最低樣本清單 → **七種**輸出類型各一份；**自由文字沒有**
- 一致性最低樣本清單 → 依分歧度**由高到低**排序，每份**預設最多 20 筆**
- 一致性最低樣本清單 → **不得**直接觸發或修改審核單位狀態機或爭議池的仲裁結果；**不得**依賴任何審核流程的仲裁結果
- 序列標註的逐樣本分歧度 → 用**成對比較片段 F1（嚴格）**；用它的主指標即違規（主指標是語料層級的，單一樣本上估計不穩定）
- 序列標註 → 舊的逐格分歧率與舊的多數決一致率**兩個名稱都不得保留、不得重新使用**
- 標記員品質排名 → **七種**輸出類型各一份；自由文字不參與
- 標記員品質排名 → 單維度與多維度**由低到高**排序（平均絕對偏差越低排越前），其餘由高到低
- 標記員品質排名的參考值 → 是**多位標記員聚合後的參考集合**，**不是**標準答案
- 完成樣本數少於 5 的標記員 → 顯示小樣本估計警示，**不得**從排名或清單中剔除
- 標記員品質排名 → 對**還沒有門檻**的輸出類型**照常提供**
- 邊界分歧分析 → **只有**實體辨識與序列標註有；其餘六種**不得**顯示任何內容
- 被修改率 → **八種輸出類型全納，含自由文字**
- 被修改率的表 → **任務層級一張**，放在逐型迴圈之外；逐型另建子區塊即違規
- 被修改率的分子 → 以**逐輸出類型的差異比對結果**判定；**不得**用審核單位的狀態值計數（會系統性漏計已達法定人數的改動）
- 被修改率的分母 → **排除還沒審的**審核單位；把沒審的算進去即違規（沒審不等於沒改）
- 被修改率 → **不得**用「退回／通過」的決策定義
- 被修改率 → 標記員跳過的輸出類型、以及被明確排除的標記作業，都**不計入**分子與分母
- 被修改率與標記員品質排名 → **不得**互相覆寫，也不得合併顯示成單一分數
- 序列推導 → **只適用序列標註**；套用到實體辨識即違規（它允許重疊與巢狀，壓成序列會掉資訊）
- 序列推導 → 必須是 `標記片段 ＋ 原始文本` 的**純函式**；引入時間戳、隨機性、瀏覽器語系或本機設定即違規
- 標記方案 → **不得**寫回任務設定、**不得**影響既有標記
- `IOB2` 與 `BIO` → **必須產生相同的序列**
- 三個方案 → **都從同一組片段推導**；各自維護一條轉換路徑即違規
- 某個樣本一個片段都沒有 → **輸出與文本等長的全 `O` 序列**；省略樣本或輸出空陣列即違規
- 字元級匯出 → **不得**呼叫任何切詞引擎、**不得**寫入切詞資訊、**不得**顯示擴張摘要
- 詞級匯出缺切詞引擎或版本 → **擋下這一次匯出並說明原因**，不得產生任何匯出檔
- 片段邊界落在詞的內部 → **擴張到涵蓋整個詞**；截斷、丟棄或略過那個樣本都違規
- 擴張 → **只發生在匯出的產物裡**；回寫已儲存的標記片段即違規
- 擴張筆數大於 0 → **必須顯示摘要且可展開**；筆數是 0 → **不得**顯示摘要
- 這一頁的任何位置 → **不得**顯示任何一筆標記的答案內容或標準答案

## 邊界情況（Edge Case）

- **進入**
  - 直接貼網址、帶著品質監控的分頁參數進來 → 落在品質監控，而且任務上下文**一併載入**，不是空的分頁
  - 從儀表板的提醒進來，但該任務的試標還沒完成 → 落在品質監控的**空狀態**，外殼與分頁列都在
  - 網址只有任務代號、沒有分頁參數 → 落在統計總覽
  - 網址帶著這一頁不認得的其他查詢條件 → 來源沒有定義要保留還是移除，見[§待釐清](#待釐清) Q4
- **兩個分頁之間**
  - 在統計總覽捲到底再切到品質監控，再切回來 → **回到原來的位置**，不是頂端
  - 第一次切到品質監控 → 從**頂端**開始
  - 在品質監控時重新整理 → **還在品質監控**
  - 在品質監控時切語系 → 還在品質監控，捲動位置不變
  - 兩個分頁同時都空（還沒有標記、也還沒有試標） → 兩個分頁各自顯示**自己的空狀態**，文案不得互換
- **權限**
  - 使用者在同一個任務有兩個生效的成員身分 → 權限取**聯集**
  - 兩個生效身分裡只有一個帶「看品質分析」 → 品質監控**讀得到**
  - 唯一的成員身分是「受邀但還沒生效」 → **進不來**
  - 進來之後成員資格被移除、或任務被封存 → 來源沒有定義已載入的畫面要怎麼處理，見[§待釐清](#待釐清) Q5
- **載入與錯誤**
  - 任務上下文載入失敗 → 兩個分頁都顯示可重試的錯誤
  - 任務的輸出類型是空陣列 → 可重試的錯誤，**不是**空狀態——空狀態的意思是「還沒有人提交」，不是「這個任務沒有輸出類型」
  - 任務的輸出類型含一個認不得的鍵、其餘認得 → 整個分頁都落到錯誤，**不得**只渲染認得的那幾個
  - 某一個分頁的內容載入失敗 → 另一個分頁照常可用
- **統計總覽的逐型內容**
  - 任務只有一種輸出類型 → 一張子區塊卡片
  - 任務有八種輸出類型 → 八張卡片，依原本順序並列
  - 任務同時含實體辨識與關係識別 → 實體類型分佈只出現一次（在實體辨識那一張卡）
  - 多維度任務只有**一個**維度 → 來源只定義了兩維與三維以上，見[§待釐清](#待釐清) Q11
  - 多維度任務有三個以上維度 → 維度之間的分佈改用逐對散布或平行座標，不是單一散布圖
  - 序列標註的某個樣本一個片段都沒有 → 該樣本對片段數的貢獻是 0，不是被略過
  - 多標籤的階層設定裡有同名但不同路徑的節點 → 分成兩個類別，兩列
  - 多標籤的資料是扁平的 → 視為長度 1 的路徑，結果與扁平標籤原本的算法相同
  - 自由文字的回覆全是空白 → `空白回覆比例` 是 100%，平均字數是 0，**不得**改成空狀態
- **品質監控的達標合成**
  - 任務只有自由文字 → **不適用**
  - 任務只有序列標註 → **不適用**（分母是 0）
  - 任務只有序列標註與自由文字 → **不適用**，而且**不得**顯示 `0/0`
  - 單一型別的任務且那一型無法計算 → `0/1 達標`
  - 複合任務裡一型無法計算、其餘都達標 → 那一型**不進分子、仍進分母**，所以不會顯示成全部達標
  - 還沒有任何試標資料 → `—/〈分母〉 待完成 Dry Run`
  - 試標跑完、報告還在算 → 空狀態的「報告產生中」，不是錯誤也不是載入中
  - 完成標記員剛好 5 位 → **不顯示**小樣本徽章（門檻是「少於 5」）
  - 完成標記員 4 位 → 顯示小樣本徽章，點估計照常
  - 多標籤的**每一個標籤**正例出現次數都少於 5 → 巨集平均一個對象都不剩，見[§待釐清](#待釐清) Q16
  - 最新一輪試標的 IAA **計算失敗** → 就緒訊號是未就緒，但品質監控要落到哪一個狀態，見[§待釐清](#待釐清) Q17
  - 多維度任務的其中一個維度無法計算 → 巨集平均的對象少一個；來源沒有定義整體要怎麼處理，與上一條同一題，見[§待釐清](#待釐清) Q16
- **標記員與樣本層分析**
  - 某標記員已完成 8 筆（低於 10） → 等級欄顯示 `資料不足`、原因欄顯示 `8 / 10，暫不評估`，沒有給他任何風險等級
  - 某標記員已完成剛好 10 筆 → 照常評估風險等級
  - 某標記員同時命中觀察與高風險的條件 → 取**高風險**（任一條成立即升級）
  - 某標記員只命中速度那一條 → 一樣升級（三條是或的關係）
  - 多維度任務的某標記員在一個維度是觀察、另一個是高風險 → 風險等級是**高風險**，兩個維度的原因**分開列**
  - 某個樣本被標成高分歧 → 它出現在樣本層的旗標裡，標它的標記員**風險等級不因此上升**
  - 任務裡完全沒有速度異常、也沒有高分歧樣本 → 異常偵測兩類各顯示自己的空狀態（`無速度異常`、`無高分歧樣本旗標`）
  - 審核員進入品質監控 → 看得到風險等級與原因，但建議行動不可觸發
  - 某型別的一致性最低樣本超過 20 筆 → 依上限只收 20 筆進清單，清單區域放不下時以捲動查看
  - 任務只有自由文字 → **沒有**一致性最低樣本清單、**沒有**品質排名、**沒有**邊界分歧分析，但**有**被修改率
  - 任務含實體辨識與關係識別 → 邊界分歧分析只出現在實體辨識那一份
  - 某標記員名下的審核單位**全都還沒審** → 分母是 0，被修改率算不出來；畫面目前顯示 `0 / 0 (0%)`，而來源沒有定義這一格該顯示什麼，見[§待釐清](#待釐清) Q21
  - 某標記員被審核員退回但答案沒被改 → **不計入**被修改率的分子（分子看的是答案有沒有被更動）
- **匯出推導**
  - 某個樣本一個片段都沒有 → 全 `O` 且長度等於文本字元數，不是空陣列也不是略過
  - 同一份標記用三種方案各匯一次 → `BIO` 與 `IOB2` 的序列**完全相同**，`BIOES` 只差在單一位置給 `S-` 與末位給 `E-`
  - 單一位置的片段用 `BIOES` → 那一格是 `S-〈標籤〉`，不是 `B-〈標籤〉`
  - 同一份標記在不同時間、不同瀏覽器各匯一次 → 兩次**逐字元相同**
  - 選詞級但引擎沒有版本 → **擋下**，沒有產生任何檔案；改回字元級後正常完成
  - 詞級但所有片段的邊界都剛好落在詞界上 → 擴張筆數是 0，**不顯示**摘要
  - 某個輸出類型是實體辨識 → **那一型不套用**這個推導；同一個任務裡的序列標註**照常推導**
- **螢幕寬度**
  - 手機版進入品質監控 → 比較寬的表格**橫向捲動**，不造成整頁水平捲動
  - 手機版進入統計總覽 → **散布圖與共現矩陣**橫向捲動
  - 768 寬度 → 關鍵內容不得被截斷

- [ ] 改來源的規則：允許風險等級欄直接顯示第四個值 `資料不足`，只要底層的等級值域仍然是三個
- [ ] 其他（請說明）

> 建議：第二個。畫面上在同一欄顯示 `資料不足` 對使用者最直接——他要知道的是「這個人現在有沒有風險等級」；而來源真正要守的是**底層等級的值域不要長出第四個值**，那一點與畫面上顯示什麼並不衝突。
> 需要決定的人：產品負責人
> 依據狀態：來源的條文明寫風險等級的值域「恰為三值，**不得以第四個值表示資料不足**」，而且要求那種標記員的等級**為空**、另有一個資料不足旗標為真。但**畫面是在風險等級那一欄直接寫第四個值** `資料不足`（標記上是 `insufficient`），沒有空等級、也沒有獨立的旗標欄。**兩邊方向相反**，而且來源那一句是對**資料值域**說的、畫面那一格是**呈現**，兩者是不是真的衝突也需要維護者判定。

- [x] **兩個集合**，目前的成員是：永久沒有自動指標的只有**自由文字**；算得出數值但還沒有門檻的只有**序列標註**

> **連帶的結論**：[規格 05-01](./01-analysis-list.mdx#iaa-狀態徽章) 的徽章顯示「不適用」的條件，是任務的輸出類型**全都落在這兩個集合裡**——不只是「只有自由文字」。只有序列標註、或只有序列標註與自由文字，一樣是「不適用」。

## Q&A

### Q. 為什麼統計與品質要做成一頁兩個分頁，而不是兩頁？

因為兩邊問的是**同一個任務**的兩個問題：「標了多少、分布長什麼樣」與「標得一致不一致」。做成兩頁的話，每次切換都要重新帶任務代號、重新確認成員資格、重新建立上下文，而使用者實際的動作是在兩組數字之間來回對照。做成一頁兩個分頁，任務上下文只建立一次，捲動位置各自記住，網址一個連結就說完「哪個任務、哪個分頁」。

### Q. 為什麼統計總覽是四種狀態，品質監控卻是六種？

因為品質監控多出三種「還沒有東西可算」的情況：試標還在跑、試標跑完但報告還沒排到、報告正在算。統計總覽只要有人提交就算得出來，所以它的「空」只有一種原因。這三種都歸在空狀態集合、都**不是**「載入中」——載入中的意思是算好了還沒到畫面上；但它們**各有自己的標題與說明**，因為把它們壓成一組文案，就沒辦法回答「現在到底在等什麼」。

### Q. 為什麼任務代號不存在與沒有權限要顯示同一句話？

分辨了就等於告訴外人「這個任務存在，只是你看不到」。這一頁的使用者是專案負責人與審核員，任務之間本來就有:ref[資料隔離]{id="term.data-isolation"}；把兩種情況合成一句 `找不到指定的任務，或您沒有該任務的存取權限。`，外人就無法用網址逐個試出哪些任務代號是真的。

### Q. 為什麼共用指標要寫死「恰好五項、完成率不得改名」，這不是多管閒事嗎？

因為同一個任務的完成率會在三個地方出現：[規格 05-01](./01-analysis-list.mdx#任務列表的欄位) 的列表、[規格 04-01](../04-annotation/01-annotation-list.mdx) 的任務資訊卡，還有這一頁的共用指標。只要承載它的那一組欄位可以多一項、少一項，或者完成率在某一處被叫成「進度」，三個地方就會各自長出自己的算法，而使用者看到的是同一個任務的三個不同數字。寫死「恰好五項、名字不得改」是為了讓這三處指向同一個數字——至於**那個數字由誰算出來**，來源沒有交代，是[§待釐清](#待釐清) Q9。

### Q. 為什麼序列標註用字元分桶，實體辨識卻用 token 分桶？兩個不是都在量「一段標記有多長」嗎？

因為兩種輸出類型的**儲存單位不同**，而不是量法不同。序列標註的標記在任務設定那一份規格改版後是用**字元位置**存的（起始與結束），所以「長度」天生就是字元數；實體辨識的長度一直以 token 為主、字元為輔。來源明文把兩邊分開寫，所以**不得**為了「看起來一致」而統一——統一的代價是其中一邊要先把答案投影到另一個座標系，而序列標註那個座標系（token 網格）已經不存在了。

### Q. 多標籤的 `A` 與 `A › B` 為什麼算兩個類別，不是一個？

因為標記員**可以只選到中間一層就停下**。如果把 `A › B` 併進 `A`，那麼「只選了 `A`」與「選到 `A › B`」這兩件不同的事就分不出來，而它們在標記品質上的意思完全不同：前者是標記員認為只到這一層，後者是他判斷得更細。同理，提交 `A › B` 不會讓 `A` 的次數增加——否則 `A` 的次數會同時包含「真的選了 `A`」與「選了它底下任何一個子孫」，比例的分母就說不清了。

### Q. 「永久沒有自動指標」與「還沒有門檻」在分母上效果一樣，為什麼一定要分成兩種說法？

因為它們對讀的人交代的是兩件不同的事。自由文字**永遠**不會有自動指標——它沒有可比對的選項，品質只能由審核員逐筆看；所以「不適用—由審核員評估」是一句**終局**的話。序列標註的指標**算得出來**，只是平台還沒有足夠的實測資料可以訂門檻；對它說「不適用—由審核員評估」會讓人以為這一型永遠不會有數字，而畫面上明明有一個點估計值。反過來，對自由文字說「待實證校準」會讓人等一個永遠不會來的門檻。兩者在 `〈達標數〉/〈分母〉` 上都不計分母，但**文案共用就是錯誤陳述**。

### Q. 為什麼沒有門檻的型別連分母都不能進？不是應該算進去、顯示成未達標嗎？

因為它沒有門檻可以比。把它算進分母，分子永遠少它一個，而達標的判定是「分子等於分母」——結果是**一個永遠無法達標的型別把整個任務永久鎖在未通過**。任務的其他型別全部達標也沒有用。所以它既不進分子也不進分母，而是在徽章後面以「· 〈排除數〉 型排除」交代清楚被排除了幾種。

### Q. 「無法計算」為什麼要計入分母，而排除型別不計？

因為它們「沒有數值」的原因不同。排除型別是**結構上**沒有數值：自由文字永遠不會有，序列標註現在沒有門檻可比——這是任務設定決定的，與這次試標跑得好不好無關。「無法計算」是**這一次**資料不夠：有效樣本少於 2 或有效標記員少於 2，換一次試標、多幾位標記員就算得出來。所以它仍然是「本來應該算得出來的型別」，要留在分母裡，只是這次沒有達標——單一型別的任務無法計算時徽章是 `0/1 達標`，這個 `0` 誠實地說明「這一型目前沒有達標」，而不是把它藏起來。

### Q. 高分歧樣本為什麼不能拉高標記員的風險等級？他確實標得跟別人不一樣啊

因為那兩件事問的是不同的問題。高分歧樣本說的是「**這一筆資料讓大家標不一樣**」——可能是題目本身有歧義、可能是說明沒寫清楚；風險等級說的是「**這個人的標記行為有問題**」。把前者算到後者頭上，結果是負責標難題的人風險等級最高，而真正要看的訊號（他在一般樣本上也偏離、或他標得異常快）反而被稀釋。所以來源要求兩者**分開呈現**，而且明文寫「高分歧樣本不應拉高對應標記員的風險等級」。

### Q. 被修改率為什麼不能直接數「狀態是已修改」的審核單位？

因為那個狀態的語意不只是「有改動」，它是「**有改動，而且已審人數還沒到法定人數**」。一旦達到法定人數，同一個改動過的單位就會離開那個狀態、落到爭議或已定稿；如果用狀態值去數，所有**已經達到法定人數的改動**都會被漏掉——而那些正是最確定「真的被改了」的單位。所以分子要看的是**逐輸出類型的差異比對結果**（答案到底一不一樣），不是狀態欄的值。

### Q. 為什麼被修改率的分母要排除還沒審的單位？

因為**沒審不等於沒改**。把還沒審的算進分母，等於預設「沒人看過的都算沒被改」，於是審核覆蓋率越低的任務，被修改率看起來越漂亮——而那正好是最該被檢視的任務。排除之後，這個比率的意思變成「**在已經審過的範圍內，有多少比例被改了**」，覆蓋率高低不會污染它。

### Q. 標記方案為什麼是匯出時才選，不存在任務設定裡？

因為方案是**輸出格式**，不是標記行為。序列標註的標記在任務設定那一份規格改版後是以**字元位置**儲存的（起點、終點、標籤），而 `BIO`、`BIOES`、`IOB2` 只是把同一組片段攤平成序列的三種寫法——片段集合與扁平序列之間是一對一的，所以同一份標記可以用任何一種方案重匯，不需要重新標記。反過來，如果方案存在任務設定裡，換一種寫法就得改任務、甚至重標一次，而標記內容其實完全沒變。

### Q. 為什麼字元級是預設，詞級反而要多那麼多規則？

因為字元級**不需要切詞**：每個字元就是一個位置，片段的起訖直接對應位置索引，不可能有對齊誤差，也不需要記下任何引擎資訊。詞級一旦引入切詞引擎，同一份標記在不同引擎或不同版本下會切出不同的序列——所以必須把引擎與版本寫進檔案，少了任何一項就擋下匯出，否則那份資料集沒辦法重現。而且詞界與標記邊界不一定對齊，所以還要定「擴張」這一種處理方式、並把擴張了幾筆誠實地回報出來。

### Q. 兩個分頁各一道權限，那沒有「看品質分析」的人進來會看到什麼？

他進得來，統計總覽照常可讀，切到品質監控時**那一個分頁的資料讀取被拒絕**。擋的是分頁的資料，不是整頁——因為能不能進這一頁是任務角色決定的，而兩道分頁權限是那一格之內的細化。上線初期種子設定把兩道權限都開給專案負責人與審核員，所以實際上不會有人只拿到一半。
