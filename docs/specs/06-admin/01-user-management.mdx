# 06-01 使用者管理

:badge[已定案]{variant="success"} :badge[系統管理]{variant="neutral"}

> 來源：舊規格 `specs/admin/006-user-management/spec.md` v1.4.0（`label-suite` repo，2026-10-12），以及 2026-10-29 的決議（#17）；本次依 Issue #32 改寫為新的章節結構
> 參考畫面：`design/prototype/pages/admin/user-management.html`
> 相關規格：[規格 06-02 角色設定](./02-role-settings.mdx)

## 目標

- 提供全平台帳號的集中管理，讓 :ref[系統管理員]{id="term.system-admin"} 在同一頁查詢、新增、編輯、停用與啟用帳號，並指派 :ref[系統角色]{id="term.system-role"}
- 以 :ref[設定密碼信]{id="term.password-setup-email"} 讓新成員自己設定密碼，系統管理員不經手任何人的密碼
- 每次帳號異動都留下 :ref[異動紀錄]{id="term.audit-log"}，讓系統管理員事後查得到誰在什麼時間改了什麼
- 保護 :ref[Seeder 管理員]{id="term.seeder-admin"} 與最後一位啟用中的系統管理員，讓平台不會失去管理者
- 降級、停用與修改 Email 立即生效，讓失去資格的人無法繼續使用原本的登入狀態

## 使用角色

:::tip{title="權限代號"}
R：Read（可讀取）　C：Create（可新增）　E：Edit（可編輯）　D：Delete（可刪除）　(o)：只限自己的資料
:::

- :ref[系統管理員]{id="term.system-admin"}：R/C/E
  - R 需要角色設定中的「進入使用者管理頁」權限；C、E（新增、編輯、停用、啟用、變更系統角色、重發設定密碼信）另需要「新增／編輯／停用使用者、指派系統角色」權限
  - 這兩項權限只能在系統管理員之內收窄，不能開放給平台成員；設定方式見[規格 06-02 角色設定](./02-role-settings.mdx)
  - 帳號不能刪除，只能停用，所以沒有 D
- :ref[平台成員]{id="term.platform-member"}：無權限
- 未登入的訪客：無權限
- 受邀的使用者（剛被新增、尚未設定密碼）：無權限；只會收到設定密碼信，在信中的連結設定自己的密碼
- :ref[任務角色]{id="term.task-role"}不在本頁指派，任何人都不能在這頁指派任務角色

- **邀請新帳號**
  - 觸發：有新成員要加入平台，系統管理員替對方建立帳號
  - 前置條件：系統管理員已登入，且具備新增帳號的權限，停在使用者管理分頁
  - 主流程：
    1. 系統管理員點擊「新增使用者」 → 系統顯示新增表單
    2. 系統管理員填寫姓名、Email、系統角色並點擊「儲存」 → 系統寄出設定密碼信，建立帳號，顯示「使用者已建立」與「設定密碼信已寄出」
    3. 受邀的使用者在 24 小時內開啟信中的連結並設定密碼 → 系統完成設定，對方之後可以用 Email 與密碼登入
  - 替代流程：
    - A1（第 3 步）連結已過期或遺失 → 系統管理員在該帳號那一列點擊「重發設定密碼信」，系統寄出新連結、舊連結作廢，回到第 3 步（見 [§規格](#規格) 重發設定密碼信）
  - 例外流程：
    - E1（第 2 步）設定密碼信寄不出去 → 不建立帳號，表單保留已填內容，回到第 2 步（見 [§卡控機制](#卡控機制)）
    - E2（第 2 步）Email 已被其他帳號使用 → 不儲存，表單保留已填內容，回到第 2 步（見 [§卡控機制](#卡控機制)）
    - E3（第 3 步）連結已用過或已作廢 → 無法設定密碼，流程結束，需要時走 A1（見 [§卡控機制](#卡控機制)）
  - 結果：列表多一個啟用中的帳號；受邀的使用者設定密碼後可以登入；異動紀錄多一筆「新增」

- **停用帳號**
  - 觸發：成員離開平台，或帳號有外流風險，系統管理員要讓它立即無法使用
  - 前置條件：系統管理員已登入，且具備管理帳號的權限；目標帳號為啟用中
  - 主流程：
    1. 系統管理員在目標帳號那一列點擊「停用」 → 系統顯示確認視窗「確定要停用 \{姓名\} 的帳號嗎？」，並說明停用後對方會立即無法登入
    2. 系統管理員點擊「停用」 → 系統把帳號標示為停用並留在列表，對方目前的登入狀態立即失效，顯示「帳號已停用」
  - 替代流程：
    - A1（第 2 步）系統管理員點擊「取消」 → 關閉確認視窗，帳號維持啟用，流程結束
    - A2（第 2 步）停用的是自己 → 確認後自己立即登出並回到登入頁，不回到列表，流程結束
  - 例外流程：
    - E1（第 1 步）目標是 Seeder 管理員 → 停用操作不可用，流程結束（見 [§卡控機制](#卡控機制)）
    - E2（第 2 步）停用後平台會沒有啟用中的系統管理員 → 系統擋下，帳號維持啟用，流程結束（見 [§卡控機制](#卡控機制)）
  - 結果：帳號為停用，無法登入；之後重新啟用時，停用前的登入狀態不會恢復；異動紀錄多一筆「停用」

- **變更系統角色**
  - 觸發：成員的職責改變，要升為系統管理員或降為平台成員
  - 前置條件：系統管理員已登入，且具備管理帳號的權限
  - 主流程：
    1. 系統管理員在目標帳號那一列點擊「編輯」 → 系統顯示「編輯使用者」表單
    2. 系統管理員改選系統角色並點擊「儲存」 → 系統儲存，顯示「帳號資訊已更新」
    3. 對方下一次操作 → 依新的系統角色判斷能做什麼；被降為平台成員的人無法再進入使用者管理頁
  - 例外流程：
    - E1（第 2 步）把 Seeder 管理員或最後一位啟用中的系統管理員降為平台成員 → 系統擋下，角色不變，表單保留，回到第 2 步（見 [§卡控機制](#卡控機制)）
  - 結果：帳號的系統角色已更新並立即生效；異動紀錄多一筆「角色變更」

## 規格

- **存取與分頁切換**

  <PrototypeFrame page="admin/user-management" caption="使用者管理" client:idle />

  系統管理員從側欄進入「系統管理」，在「使用者管理」與「角色設定」兩個分頁之間切換。
  1. 進入「系統管理」 → 預設停在「使用者管理」分頁，顯示全平台帳號列表
  2. 點擊「角色設定」分頁 → 進入[規格 06-02 角色設定](./02-role-settings.mdx)
  3. 未登入的訪客開啟本頁 → 導向登入頁
  4. 平台成員開啟本頁 → 導向儀表板，看不到任何帳號資料
  - 每次開啟或操作，都依帳號「當下」的系統角色與權限判斷；被降級或停用的人，即使仍在登入中，下一次操作就被擋下
  - 只有「進入使用者管理頁」權限、沒有管理權限的系統管理員，可以查看列表與異動紀錄，但新增、編輯、停用、啟用與重發都會被擋下
  - 手機寬度下仍能完成搜尋、篩選、新增、編輯、停用與啟用；版面以 prototype 為準

- **帳號列表**

  <PrototypeFrame page="admin/user-management" caption="使用者管理" client:idle />

  系統管理員在列表查看全平台帳號，不論對方有沒有參與任何任務；以關鍵字、系統角色、帳號狀態找出目標帳號。
  1. 在搜尋框輸入關鍵字（提示文字「搜尋姓名或 Email…」） → 列表只顯示姓名或 Email 含有關鍵字的帳號，部分符合、不分大小寫
  2. 在角色篩選選擇系統角色（預設「全部角色」） → 只顯示該系統角色的帳號
  3. 在狀態篩選選擇「啟用」或「停用」（預設「全部狀態」） → 只顯示該狀態的帳號
  4. 沒有符合的帳號 → 顯示「找不到符合條件的使用者」與「請嘗試清除篩選條件或使用不同的關鍵字」，並提供「清除篩選」
  5. 點擊「清除篩選」 → 清空關鍵字與兩個篩選，回到完整列表
  6. 換頁或切換每頁筆數 → 保留目前的關鍵字與篩選條件
  - 每列顯示姓名、Email、系統角色、狀態、建立時間與操作；欄位規則見 [§資料欄位](#資料欄位)
  - 預設依建立時間由新到舊排序，剛新增的帳號在最前面
  - 每頁預設 20 筆，可以切換為 50 或 100 筆；列表下方顯示總筆數與目前頁數（例：「共 24 筆 · 第 1 / 2 頁」）
  - 停用的帳號留在列表中，狀態標示為「停用」
  - 列表與表單都沒有任務角色；新增表單提示「任務角色（標記員、審核員等）在任務詳情頁個別指派」

- **新增帳號**

  <PrototypeFrame page="admin/user-management" caption="使用者管理" client:idle />

  系統管理員點擊「新增使用者」替新成員建立帳號，系統寄出設定密碼信讓對方自己設定密碼。
  1. 點擊「新增使用者」 → 顯示「新增使用者」表單，欄位為姓名、Email、系統角色；Email 下方提示「建立帳號後將寄送設定密碼信至此信箱」
  2. 填寫後點擊「儲存」 → 寄出設定密碼信，建立帳號，表單關閉，列表出現新帳號，顯示「使用者已建立」與「設定密碼信已寄出」
  3. 點擊「取消」 → 不建立帳號，已填的內容捨棄
  4. 受邀的使用者在 24 小時內開啟連結並設定密碼 → 設定完成，之後可以登入；設定密碼的頁面屬於帳號模組
  - 表單沒有帳號狀態欄；新增的帳號一律為啟用
  - 新帳號在設定密碼前為「尚未設定密碼」，無法用密碼登入
  - 設定密碼連結從寄出起 24 小時內有效，只能成功使用一次；過期、已用過或已作廢的連結一律顯示「連結無法使用」，不透露是哪一種原因

- **編輯帳號**

  <PrototypeFrame page="admin/user-management" caption="使用者管理" client:idle />

  系統管理員在帳號那一列點擊「編輯」，修改姓名、Email 或系統角色。
  1. 點擊「編輯」 → 顯示「編輯使用者」表單，帶入目前的姓名、Email、系統角色
  2. 修改後點擊「儲存」 → 表單關閉，列表顯示新的內容，顯示「帳號資訊已更新」
  3. 點擊「取消」 → 不儲存，帳號維持原狀
  - 修改 Email 後，對方目前的登入狀態立即失效，需要用新的 Email 重新登入
  - 系統角色的變更在對方下一次操作起生效
  - 表單沒有帳號狀態欄；停用與啟用只能從列表操作，讓停用一律經過確認與保護規則

- **停用與啟用**

  <PrototypeFrame page="admin/user-management" caption="使用者管理" client:idle />

  系統管理員從列表停用帳號，讓對方立即無法登入；之後可以重新啟用。
  1. 在啟用中的帳號那一列點擊「停用」 → 顯示確認視窗「確定要停用 \{姓名\} 的帳號嗎？」，說明停用後對方會立即無法登入，所有登入中的狀態一併失效
  2. 點擊「停用」 → 帳號標示為停用，對方目前的登入狀態立即失效，顯示「帳號已停用」
  3. 點擊「取消」 → 關閉確認視窗，帳號維持啟用
  4. 在停用中的帳號那一列點擊「啟用」 → 帳號標示為啟用，對方可以重新登入，顯示「帳號已重新啟用」
  - 重新啟用不會恢復停用前的登入狀態，對方要重新登入
  - 停用的是目前登入的自己時，確認後立即登出並回到登入頁，不回到列表
  - Seeder 管理員那一列的「停用」不可用，並說明原因

- **重發設定密碼信**

  <PrototypeFrame page="admin/user-management" caption="使用者管理" client:idle />

  受邀的使用者沒收到信或連結過期時，系統管理員在該帳號那一列重發設定密碼信。
  1. 在尚未設定密碼的帳號那一列點擊「重發設定密碼信」 → 寄出新的連結，原本的連結作廢，顯示「設定密碼信已寄出」
  - 只有尚未設定密碼的帳號會出現「重發設定密碼信」；已設定密碼的帳號沒有這個操作
  - 新連結同樣從寄出起 24 小時內有效、只能成功使用一次

- **異動紀錄**

  <PrototypeFrame page="admin/user-management" caption="使用者管理" client:idle />

  系統管理員在帳號那一列點擊「查看異動紀錄」，在側邊面板查看這個帳號的所有異動。
  1. 點擊「查看異動紀錄」 → 開啟「異動紀錄」面板，只列出這個帳號的紀錄
  2. 帳號沒有任何紀錄 → 面板顯示「尚無異動紀錄」
  3. 點擊「關閉」 → 關閉面板，回到列表
  - 每筆紀錄包含時間、操作類型、操作者與變更前後的差異；由新到舊排列；時間依瀏覽者裝置的時區顯示
  - 操作類型有六種：新增、編輯、停用、啟用、角色變更、重發設定密碼信；重發只在寄信成功時留下紀錄
  - 紀錄不會出現密碼、設定密碼連結或其他登入用的資料
  - 「查看異動紀錄」入口有說明用途的名稱，讓螢幕閱讀器使用者也能辨識
  - 查看紀錄同樣需要「進入使用者管理頁」權限

### 資料欄位

| :--- | :--- | :--- | :--- | :--- |

| Email | 文字 | 是 | 須為有效的 Email 格式；不分大小寫、比對前先統一寫法，不可與其他帳號重複；最多 254 字 | 不顯示（無權限） |
| 系統角色 | 選項 | 是 | 單選：平台成員、系統管理員；新增時沒有預設值 | 不顯示（無權限） |
| 帳號狀態 | 選項 | — | 啟用、停用兩種；新增的帳號為啟用；只能從列表的「停用」「啟用」變更，不出現在表單 | 不顯示（無權限） |

## 卡控機制

- 未登入的訪客開啟本頁 → 導向登入頁
- 平台成員開啟本頁或以任何方式讀取帳號資料 → 擋下，導向儀表板，看不到任何帳號資料
- 系統管理員沒有「進入使用者管理頁」權限 → 擋下，看不到任何帳號資料
- 系統管理員只有「進入使用者管理頁」權限，送出新增、編輯、停用、啟用或重發 → 擋下，帳號不變
- 系統管理員被降為平台成員或被停用後，以原本的登入狀態繼續操作 → 下一次操作就被擋下，不必等登入狀態到期
- 姓名、Email 或系統角色未填，姓名超過 100 字、Email 超過 254 字，或 Email 格式無效 → 無法儲存，顯示「請填寫姓名與有效 Email」，表單保留已填內容
- 系統角色不是平台成員或系統管理員 → 系統擋下，帳號不會被建立或修改
- Email 已被其他帳號使用（大小寫不同也算同一個） → 無法儲存，顯示「Email 已存在」，表單不關閉
- 新增時設定密碼信寄不出去 → 不建立帳號，顯示「設定密碼信寄送失敗」，表單保留已填內容
- 重發時設定密碼信寄不出去 → 顯示「設定密碼信寄送失敗」，原本的連結仍然有效，不留下異動紀錄
- 設定密碼連結超過 24 小時、已成功使用過，或已因重發而作廢 → 顯示「連結無法使用」，無法設定密碼
- 停用、降級、刪除 Seeder 管理員，或取消其 Seeder 管理員身分 → 系統擋下，不論是從頁面或其他途徑；頁面上 Seeder 管理員的「停用」不可用
- 停用或降級後，平台會沒有任何啟用中的系統管理員 → 系統擋下，帳號維持原狀
- 停用的是目前登入的自己 → 須在確認視窗再次確認；仍受 Seeder 管理員與「至少保留一位啟用中的系統管理員」的限制
- 帳號異動的異動紀錄沒有留下 → 該次異動一併失敗，帳號維持原狀，不會出現有異動卻沒有紀錄的情況
- Seeder 管理員只能由平台部署者在部署時執行初始化建立，頁面上沒有建立的入口：
  - 初始化一律建立全新帳號，不會把既有帳號升為 Seeder 管理員；指定既有帳號時明確失敗
  - 對同一個身分重複執行初始化 → 不產生變化，不會出現第二位 Seeder 管理員
  - 初始化沒有預設密碼，由部署者自行提供；初始化不會停在只完成一半的狀態

## 邊界情況（Edge Case）

- **存取與分頁切換**
  - 系統管理員在頁面上停留時被另一位系統管理員降為平台成員 → 下一次操作被擋下並導向儀表板
  - 以手機寬度開啟 → 仍能完成搜尋、篩選、新增、編輯、停用與啟用
- **帳號列表**
  - 篩選後沒有任何帳號 → 顯示空狀態與「清除篩選」，不顯示錯誤
  - 篩選後結果超過一頁 → 換頁時保留關鍵字與篩選條件
- **新增帳號**
  - 新增時郵件服務暫時無法寄信 → 不建立帳號，表單保留，系統管理員可以稍後再按一次「儲存」
  - 受邀的使用者在 24 小時後才開啟連結 → 顯示「連結無法使用」，需請系統管理員重發
  - 同一條連結被開啟兩次 → 第一次設定成功，第二次顯示「連結無法使用」
- **新增與編輯的欄位長度**
  - 姓名剛好 100 字、Email 剛好 254 字 → 可以儲存
- **編輯帳號**
  - 修改正在登入中的帳號的 Email → 對方下一次操作被擋下，需要重新登入
- **停用與啟用**
  - 平台只剩兩位啟用中的系統管理員，兩人同時停用對方 → 只有一個成功，平台仍保有一位啟用中的系統管理員
  - 停用正在登入中的帳號 → 對方下一次操作被擋下，且無法再登入
  - 停用後再重新啟用 → 對方可以登入，但停用前的登入狀態不會恢復
- **重發設定密碼信**
  - 重發後開啟舊的連結 → 顯示「連結無法使用」
- **異動紀錄**
  - 帳號沒有任何異動 → 面板顯示「尚無異動紀錄」，不顯示錯誤
  - 兩位系統管理員的裝置在不同時區 → 同一筆紀錄的時間各自依自己裝置的時區顯示

- [ ] 姓名 1–50 字，Email 最多 254 字
- [x] 姓名 1–100 字，Email 最多 254 字

> 理由：Email 254 字是信箱格式本身的上限；姓名 100 字可容納中英文全名，又不會撐壞列表。舊規格沒有寫長度，搬移時提出（#32）。

## Q&A

### Q. 為什麼帳號不能刪除，只能停用？

停用的帳號仍保留它的異動紀錄與參與過的任務紀錄，日後查得到是誰做的；需要時也能重新啟用。

### Q. 為什麼重新啟用後要重新登入？

停用期間，原本的登入狀態可能已經外流；重新啟用不恢復它們，外流的登入狀態就無法再被使用。

### Q. 為什麼連結失效時不說明是過期還是被作廢？

只顯示「連結無法使用」，拿到連結的人就無法從訊息推測帳號的狀態；受邀的使用者只要請系統管理員重發即可。
