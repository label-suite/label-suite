# Tasks

依相依順序排列：語系、外觀偏好與共用元件就位 → 側欄規則與狀態 → 外殼組合、路由與暫時落點 → 端對端旅程 → 整合檢查。行為以 `specs/` 為準，做法以 `design.md` 與 `ui-design.md` 為準，前後端交接以 `api-contract.md` 為準（本次無 API 變更）。測試與實作在同一個 task（TDD，architecture §測試分層）；JavaScript 一律以 `pnpm` 執行，不用 `npm install`。

本次沒有後端、資料庫或 `[@dba]` 工作（sd §設計結論、§資料模型異動），也沒有 `[@technical-writer]` 工作：規格書回寫（clarification Q3、Q4、Q6）與設計系統的兩份元件規格、畫面清冊、G-66（Q9、Q13）已在規劃階段提交（commit `081721f`、`378fcb0f`），常駐文件 `frontend-routes.mdx` 依 `rules.tasks` 由實作角色在 3.6 校正。

**為什麼群組 1 很大**：`scripts/check-changed.sh` 在每一次動到 `frontend/**/*.ts{,x}` 的提交都對整棵樹跑 `node scripts/check-component-reuse.mjs`，而它在本分支目前因四個「程式實作」路徑不存在而失敗（design §Context）。所以第一個前端提交就必須讓三個元件搬好、`components/app-shell/app-shell.tsx` 存在，群組 1 因此包含語系、外觀偏好、三個元件搬移、對話框原語與外殼的畫面層。

每個群組提交前跑（`openspec/config.yaml` operations.apply）：`pnpm --filter frontend lint`、`pnpm --filter frontend typecheck`、`pnpm --filter frontend test`、`pnpm --filter frontend build`、`node scripts/check-component-reuse.mjs`；動到 `docs/` 時另跑 `pnpm check:specs`；NoteCraft 站台建置以 CI 的 `docs-site` job 為準，不在 worktree 跑 `notecraftapp build`（會把 worktree 路徑寫進全機共用的 `~/.notecraft/` 快取）。

契約漂移檢查指令（在 repo 根目錄執行）：
