# Tasks

依相依順序排列：拒絕回應的分類 → 共用畫面 → 元件展示頁的一節與常駐文件校正 → 展示頁上的 e2e → 整合檢查。行為以 `specs/` 為準，做法以 `design.md` 與 `ui-design.md` 為準，前後端交接以 `api-contract.md` 為準（本次無 API 變更）。測試與實作在同一個 task（TDD，architecture §測試分層）；測試層只用 unit、integration、e2e 三個詞。JavaScript 一律以 `pnpm` 執行，不用 `npm install`。

本次沒有後端、資料庫或 `[@dba]` 工作（`system-design.md` §設計結論、§資料模型異動），也沒有 `[@technical-writer]` 工作：`design/system/design-gaps.md` 的 G-67、G-68（clarification Q7、Q8）與 `docs/diagrams/architecture/frontend-routes.mdx`（clarification P2、Q2、Q8）已在規劃階段提交，常駐文件依 `rules.tasks` 由實作角色在 3.3 校正。

每個群組提交前跑（`openspec/config.yaml` operations.apply）：`pnpm --filter frontend lint`、`pnpm --filter frontend typecheck`、`pnpm --filter frontend test`、`pnpm --filter frontend build`、`node scripts/check-component-reuse.mjs`（pre-commit 在每次動到 `.ts`／`.tsx` 的提交都會跑它，`FAIL` 就停下回報，不加允許清單）；動到 `docs/` 時另跑 `pnpm check:specs`；動到 `e2e/` 時另跑 `pnpm --filter e2e test:static`。NoteCraft 站台建置以 CI 的 `docs-site` job 為準，不在 worktree 跑 `notecraftapp build`（會把 worktree 路徑寫進全機共用的快取）。

契約漂移檢查指令（在 repo 根目錄執行）：

- 後端：`cd backend && uv run python -m app.scripts.export_openapi && git diff --exit-code -- openapi.json ../docs/diagrams/architecture/api.openapi.json && test -z "$(git status --porcelain -- openapi.json ../docs/diagrams/architecture/api.openapi.json)"`
- 前端：`pnpm --filter frontend api:generate && git diff --exit-code -- frontend/src/api/generated && test -z "$(git status --porcelain -- frontend/src/api/generated)"`
