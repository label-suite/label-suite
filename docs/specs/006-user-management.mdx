# 006 使用者管理

本規格搬自舊 spec `specs/admin/006-user-management/spec.md` v1.4.0（`label-suite` repo，commit `76d6221d`，2026-10-12），沿用其 FR、SC、AC 編號；對照見文末附錄。

## 目標

:ref[系統管理員]{id="term.系統管理員"} 在單一頁面查詢全平台帳號，新增、編輯、停用與重新啟用帳號，並指派:ref[系統角色]{id="term.系統角色"}，讓平台帳號的生命週期集中由一處管理。每次帳號異動都留下:ref[異動紀錄]{id="term.異動紀錄"}，以利事後稽核；:ref[Seeder 管理員]{id="term.Seeder管理員"} 與最後一位啟用中的系統管理員受到保護，讓平台不會失去管理者。

- **SC-001**：系統管理員可以進入使用者管理頁，並看到全平台的帳號列表。
- **SC-002**：套用搜尋與篩選後，列表結果應在同一頁更新。
- **SC-003**：新增、編輯、停用、啟用帳號後，列表應反映最新狀態。
- **SC-005**：在手機、平板與桌面寬度下，系統管理員都可以完成搜尋、篩選、新增、編輯與停用，以利在任何裝置處理帳號問題。
- **SC-007**：Seeder 管理員與最後一位啟用中的系統管理員不會被停用或降級。
- **SC-008**：系統管理員停用自己後，其所有登入狀態失效並回到登入頁；重新啟用不會讓舊的登入狀態恢復。
- **SC-009**：每次帳號異動都可以查到異動紀錄。
- **SC-010**：設定密碼信寄送失敗時，列表不會出現該帳號，並顯示可理解的錯誤。
- **SC-011**：開啟某帳號的異動紀錄時，只看到該帳號的紀錄。
- **SC-012**：異動紀錄與帳號異動同時寫入，不會出現有異動卻沒有紀錄的情況；其他帳號的事件與敏感內容不會出現在查詢結果。
- **SC-013**：設定密碼連結在 24 小時內只能成功使用一次；重發、作廢或過期的連結都無法設定密碼。
- **SC-014**：Seeder 管理員的初始化指令重複執行不會產生第二位 Seeder 管理員，也不會讓既有帳號升權。
- **SC-015**：只有通過權限設定的系統管理員可以讀取或修改帳號；權限變更後的下一個請求立即依新設定判斷。

## 使用權限

只有目前仍為系統管理員的帳號可以進入本頁。讀取與異動另受 007 角色設定的權限項控制；權限項只能在系統管理員之內收窄，不能授權給:ref[平台成員]{id="term.平台成員"}。

| 動作 | 系統管理員 | 平台成員 | 未登入 |
| --- | --- | --- | --- |
| 查看帳號列表與異動紀錄（`admin.user_management.view`） | ✓ | ✗ | ✗ |
| 新增、編輯、停用、啟用帳號，變更系統角色（`admin.user_management.manage`） | ✓ | ✗ | ✗ |
| 指派:ref[任務角色]{id="term.任務角色"} | ✗ | ✗ | ✗ |

任務角色在任務詳情頁指派，不在本頁處理。

## 操作流程

1. 系統管理員從側欄進入「系統管理」，預設停在「使用者管理」分頁。
2. 系統確認目前帳號仍為系統管理員且具備查看權限，再載入帳號列表；不符時依 FR-011 導向其他頁面。
3. 系統管理員以關鍵字、系統角色或帳號狀態篩選，或換頁找到目標帳號。
4. 系統管理員執行下列其中一項：
   1. 新增帳號：填寫姓名、Email、系統角色；系統寄出:ref[設定密碼信]{id="term.設定密碼信"}，寄送成功才建立帳號。
   2. 編輯帳號：修改姓名、Email 或系統角色。
   3. 停用帳號：確認後停用，並撤銷該帳號所有登入狀態；停用的是自己時，確認後直接登出並回到登入頁。
   4. 啟用帳號：恢復停用帳號的登入資格。
   5. 查看異動紀錄：開啟該帳號的異動紀錄面板。
   6. 重發設定密碼信：帳號尚未設定密碼時，重新寄出設定密碼信。
5. 異動成功後，列表更新，並寫入一筆異動紀錄。
6. 點擊「角色設定」分頁時，進入 007 角色設定頁。

## 資料模型

### 使用者帳號

| 欄位 | 型別 | 約束 | 說明 |
| --- | --- | --- | --- |
| `id` | 識別碼 | 主鍵 | |
| `name` | 文字 | 必填 | 姓名 |
| `email` | 文字 | 必填；正規化後唯一 | 依 020 的 NFC 與 casefold 規則比對，讓大小寫不同的同一信箱不能重複註冊 |
| `role` | 列舉 | `user`、`super_admin` | 系統角色 |
| `is_active` | 布林 | 必填 | 帳號狀態：`true` 為啟用，`false` 為停用 |
| `is_seeder` | 布林 | 必填；不得被清除 | 標記 Seeder 管理員 |
| `hashed_password` | 文字 | 可為空 | 尚未設定密碼的受邀帳號為空值，不得以空字串代替 |
| `credential_version` | 整數 | 必填 | 改 Email 時遞增，讓舊的登入憑證失效 |
| `created_at` | 時間 | 必填 | 列表預設排序依據 |

帳號狀態只在啟用與停用之間轉換，兩個方向都可以；轉換受 FR-008c、FR-008d 限制。

### 設定密碼連結

| 欄位 | 型別 | 約束 | 說明 |
| --- | --- | --- | --- |
| `user_id` | 識別碼 | 必填 | 受邀帳號 |
| `issued_at` | 時間 | 必填 | 核發時間 |
| `expires_at` | 時間 | 核發後 24 小時 | 有效期限 |
| `used_at` | 時間 | 可為空 | 成功設定密碼的時間 |
| `revoked_at` | 時間 | 可為空 | 因重發而作廢的時間，與 `used_at` 分開記錄 |

### 異動紀錄

異動紀錄是 ADR-032 共用稽核事件 `audit_events` 的讀取投影，本模組不另建資料表。

| 欄位 | 說明 |
| --- | --- |
| `actor_user_id` | 操作者 |
| `target_type`、`target_id` | 固定為 `user` 與目標帳號 ID，以利只查詢單一帳號 |
| `action` | 操作類型：新增、編輯、停用、啟用、角色變更、重發設定密碼信 |
| `payload_summary` | 變更前後的差異，只含允許清單內的欄位 |
| `occurred_at` | 發生時間 |

## 規格

### 系統管理 › 使用者管理

<PrototypeFrame page="admin/user-management" caption="使用者管理" client:idle />

#### 存取與導覽

- **FR-001**：系統須提供使用者管理頁，讓系統管理員集中管理全平台帳號。
- **FR-002**：**僅限**目前仍為系統管理員、且具備 `admin.user_management.view` 的帳號可以進入本頁；新增、編輯、停用、啟用與系統角色變更另須具備 `admin.user_management.manage`，以利 007 在系統管理員之內細分權限。「目前」指每個請求當下資料庫中的角色；帳號被降級為平台成員後，下一個讀取或異動請求須被拒絕，即使其登入憑證仍在有效期內，讓降級立即生效。
- **FR-010**：頁面應提供「使用者管理」與「角色設定」兩個分頁，預設停在「使用者管理」；點擊「角色設定」應進入 007 角色設定頁，讓兩項系統管理功能互相切換。
- **FR-011**：沒有權限的請求須被拒絕，且不得回傳任何帳號資料；未登入者應導向登入頁，平台成員應導向儀表板，讓使用者回到可用的頁面。
- **FR-012**：在 767px 以下的寬度，系統管理員仍應能完成查詢與帳號管理，以利在手機上處理帳號問題。

#### 帳號列表

- **FR-003**：列表須涵蓋全平台帳號，不受任務成員關係限制，並呈現姓名、Email、系統角色、帳號狀態與建立時間，讓系統管理員一眼判斷帳號狀況。
- **FR-004**：系統須支援以關鍵字搜尋帳號，以利快速找到目標；沒有符合的帳號時應顯示空狀態與清除篩選的入口，讓系統管理員知道查詢已完成並能回到完整列表。
- **FR-004a**：關鍵字須同時比對姓名與 Email，採部分符合且不分大小寫，讓系統管理員只記得片段也能找到帳號。
- **FR-005**：系統須支援依系統角色篩選，以利檢視所有系統管理員。
- **FR-005a**：列表應分頁，每頁預設 20 筆，可以切換為 50 或 100 筆；換頁時應保留目前的搜尋與篩選條件，以利逐頁檢查同一批結果。
- **FR-005b**：列表預設應依建立時間由新到舊排序，讓剛新增的帳號出現在最前面。
- **FR-005c**：系統須支援依帳號狀態篩選，選項為全部、啟用與停用，以利找出停用中的帳號。
- **FR-009**：本頁**只能**管理系統角色，不得指派任務角色，以利維持系統角色與任務角色的邊界。

#### 新增與編輯帳號

- **FR-006**：系統須支援新增帳號，欄位包含姓名、Email 與系統角色，讓新成員加入平台。
- **FR-006a**：新增帳號時須寄送設定密碼信至該帳號 Email；受邀帳號在設定密碼前的密碼欄須為空值，以利區分「尚未設定」與「已設定」。
- **FR-006b**：設定密碼信寄送失敗時，系統不得建立該帳號，且須顯示寄信失敗的錯誤，讓系統管理員稍後重試時不會留下無法登入的帳號。
- **FR-006c**：設定密碼連結自核發起 24 小時內有效，且只能成功使用一次；重發同一帳號的連結時，須先作廢原連結。過期或作廢的連結應一律回覆「連結無法使用」，不得顯示設定成功，以利避免洩漏連結狀態。作廢時間與使用時間須分開記錄，以利稽核。
- **FR-006d**：尚未設定密碼的帳號，列表該列須提供「重發設定密碼信」操作；已設定密碼的帳號不得出現此操作。重發依 FR-006c 作廢原連結並核發新連結；作廢、核發與寄信須在同一作業完成，寄送失敗時整個重發回滾，原連結維持有效，並須顯示寄信失敗的錯誤。以利受邀者連結過期後重新取得連結，又不會因寄信失敗而失去手上可用的連結。
- **FR-007**：系統須支援編輯帳號的姓名、Email 與系統角色。Email 須依 020 FR-009 的正規化規則判斷唯一；修改 Email 成功時，須在同一交易遞增 `credential_version` 並撤銷該帳號所有登入狀態，讓舊憑證在下一個請求失效。
- **FR-007a**：新增與編輯表單都不得提供帳號狀態欄；新增的帳號一律為啟用，帳號狀態只能經由停用與啟用操作變更，以利停用一律套用 FR-008 系列的確認、撤銷與保護規則。

#### 停用與啟用帳號

- **FR-008**：系統須支援停用帳號，停用的帳號應保留在列表中並標示停用，以利日後重新啟用。
- **FR-008a**：停用成功後，系統須立即撤銷該帳號所有未撤銷的登入狀態，且每個請求都須重新讀取帳號狀態，讓已發出的憑證在下一個請求即被拒絕。安全撤銷不得記為使用者自行登出，以利區分兩者。
- **FR-008b**：系統須支援重新啟用停用中的帳號，啟用後可以再次登入；啟用不得恢復停用前已撤銷的登入狀態，讓停用期間外流的憑證無法復活。
- **FR-008c**：系統須拒絕停用或降級 Seeder 管理員，以利平台永遠保有一位初始管理者。
- **FR-008d**：系統須拒絕任何會讓平台沒有啟用中系統管理員的停用或降級，讓平台不會失去管理者。

停用的是目前登入的自己時，見卡控機制「停用自己」。

#### 異動紀錄

- **FR-013**：新增、編輯、停用、啟用、系統角色變更與成功的重發設定密碼信都須寫入異動紀錄，且須與帳號異動在同一交易完成，讓每筆異動都有對應紀錄。紀錄的差異摘要不得包含密碼、憑證或原始請求內容，以利紀錄可以安全地給系統管理員閱讀。
- **FR-013a**：列表每一列應提供開啟該帳號異動紀錄的入口，且須具備說明用途的無障礙名稱，讓螢幕閱讀器使用者也能辨識。
- **FR-013b**：開啟入口後，應只顯示該帳號的異動紀錄，每筆包含時間、操作類型、操作者與變更前後的差異；查詢同樣須通過 FR-002 的查看權限，以利紀錄不外流。
- **FR-013c**：帳號沒有任何異動紀錄時，應顯示空狀態而非錯誤，讓系統管理員知道查詢已完成。

## 卡控機制

### Email 唯一

- **前端**：新增或編輯時 Email 已被使用，應顯示「Email 已存在」，且不關閉表單，讓系統管理員直接修正。
- **後端**：依 020 FR-009 正規化後比對唯一；重複時拒絕新增或修改，以利同一信箱只對應一個帳號。
- **例外**：無

### 必填欄位

- **前端**：姓名、Email、系統角色未填時不送出，並提示缺少的欄位。
- **後端**：缺少必填欄位或系統角色不是 `user`、`super_admin` 時拒絕請求，讓繞過頁面的請求也無法寫入不完整的帳號。
- **例外**：無

### Seeder 管理員保護

- **前端**：Seeder 管理員的停用操作不可用，並說明原因。
- **後端**：拒絕停用、降級 Seeder 管理員，拒絕刪除 Seeder 管理員或清除其 seeder 標記；SQLite 與 PostgreSQL 都須在資料庫層阻擋，讓繞過 API 的直接寫入也無法移除保護。
- **例外**：無

### Seeder 管理員初始化

- **前端**：無，初始化只能由指令執行，沒有頁面入口。
- **後端**：第一位 Seeder 管理員**只能**由明確執行的初始化指令建立，且須建立全新帳號，不得提升既有帳號；一般管理 API 與資料庫遷移不得自動建立。指令不得內建預設密碼，憑證須從安全的外部輸入取得。同一身分重複執行應不產生變化；指定既有非 Seeder 帳號或另一身分時須明確失敗。建立帳號、設定憑證、角色、啟用狀態與 seeder 標記須在同一交易完成，讓初始化不會停在半完成狀態。
- **例外**：無

### 至少保留一位啟用中的系統管理員

- **前端**：無，由後端判斷。
- **後端**：停用或降級後若平台沒有啟用中的系統管理員，須拒絕並回覆保護規則錯誤。檢查與更新須在同一個原子操作完成，不得先查數量再更新，以利併發請求也無法同時移除最後兩位系統管理員。
- **例外**：無

### 停用自己

- **前端**：目標是目前登入的帳號時，須二次確認，以利避免誤操作；成功後應導向登入頁，不回到列表。
- **後端**：仍須通過 Seeder 管理員保護與至少保留一位啟用中系統管理員的檢查；成功後立即撤銷目前的登入狀態，讓停用自己與停用他人有相同效果。
- **例外**：無

### 設定密碼信寄送失敗

- **前端**：新增時顯示寄信失敗的錯誤，保留表單內容讓系統管理員稍後重試；重發時同樣顯示寄信失敗的錯誤。
- **後端**：新增時寄信失敗，整個新增作業回滾，不留下帳號；重發時寄信失敗，整個重發作業回滾，原連結維持有效，也不寫入異動紀錄。
- **例外**：無

### 權限與降級

- **前端**：沒有權限時不顯示管理內容，並依 FR-011 導頁。
- **後端**：每個請求依資料庫中當下的角色與 007 權限設定判斷，不信任登入憑證內的角色；拒絕時回覆 403 且不含任何帳號資料。
- **例外**：無

## 驗收標準

### 1. 帳號生命週期與降級

| ID | Given | When | Then |
| --- | --- | --- | --- |
| AC-1.1 | 系統管理員已新增帳號，設定密碼連結已核發 | 超過 24 小時後開啟連結，或重發後開啟舊連結 | 回覆「連結無法使用」，無法設定密碼；作廢時間不記為使用時間 |
| AC-1.2 | 尚無 Seeder 管理員 | 以同一身分執行初始化指令兩次，再以既有非 Seeder 帳號執行一次 | 只建立一位新的 Seeder 管理員；第三次明確失敗，既有帳號的登入狀態沒有升權 |
| AC-1.3 | 系統管理員 A 的登入憑證仍有效，另一位系統管理員已把 A 降為平台成員 | A 以同一憑證送出讀取或任一異動請求 | 回覆 403 且不含帳號資料，不需等待憑證到期 |
| AC-1.4 | 平台只剩兩位啟用中的系統管理員 | 兩位同時停用對方 | 只有一個請求成功，平台仍保有一位啟用中的系統管理員 |

### 2. 存取與導覽

## 決策紀錄

### 2026-10-29

- 搬移舊 spec v1.4.0，沿用 FR、SC、AC 編號（#17）。
- 版面、按鈕順序、手機版異動紀錄的呈現方式與語言切換屬於畫面，交給 prototype，不寫入規格（#17）。
- Seeder 管理員初始化與併發保護不屬於任何頁面，移入卡控機制（#17）。
- 006-Q1：新增 FR-005c，列表可依帳號狀態篩選（全部、啟用、停用），換頁時與其他條件一併保留（#17）。
- 006-Q2：新增與編輯表單移除帳號狀態欄，停用與啟用只能經由列表操作，見 FR-007a（#17）。
- 006-Q3：隨 006-Q2 不再適用，新增的帳號一律為啟用（#17）。
- 006-Q4：重發設定密碼信放在列表該列的操作，只對尚未設定密碼的帳號出現，見 FR-006d；prototype 補上寄信失敗的錯誤畫面（#17）。
- 重發寄信失敗時整個重發回滾，原連結維持有效，見 FR-006d；重發成功寫入異動紀錄，見 FR-013 與 AC-6.7（#17）。
