## Logic Flow

資料集分析只有兩個畫面——挑任務的[分析列表](./01-analysis-list.mdx#業務流程)、看統計與品質的[分析詳情](./02-analysis-detail.mdx#業務流程)——而它們之間只有一道閘：任務代號與成員資格。不管從列表點任務列、從儀表板的「IAA 待確認」提醒點進來，還是直接貼一個網址，都走[規格 05-02 §進來先驗兩件事](./02-analysis-detail.mdx#進來先驗兩件事任務代號與成員資格)那同一道（那一節開頭就寫「不管從哪個入口進來」）；過得了就落在分析詳情，過不了就一律退回分析列表。分析詳情自己完全唯讀，所以它每一條出口都是離開這一頁：麵包屑第一段與瀏覽器的「上一頁」回分析列表，兩個分頁的空狀態與風險表的兩顆建議行動按鈕把人送到別的模組。依[規格 05-02 §建議行動只有專案負責人能執行](./02-analysis-detail.mdx#建議行動只有專案負責人能執行)，專案負責人點「審核標記」會進到那個任務的標記清單；[規格 04-01 §使用角色](../04-annotation/01-annotation-list.mdx#使用角色)說法相反，所以圖上照 05-02 的原文畫，本節不裁定，見下方的缺口二。[規格 05-01 §模組入口](./01-analysis-list.mdx#模組入口)第 3 條另寫「儀表板的徽章深連結是合法的次入口」，而儀表板那一側沒有對應的條文，那一條不畫，見下方的缺口一。

本模組的第三份規格[05-03 資料匯入與版本](./03-ingestion-lineage.mdx#業務流程)**沒有畫面**，也沒有定任何頁面之間的移動：它自己明寫「沒有新增任何頁面」，建立者的入口在[規格 03-02](../03-task-management/02-task-new.mdx#業務流程)第一步、出口在[規格 03-03](../03-task-management/03-task-detail.mdx#業務流程)的試標發布，兩者都是別的模組畫面裡的步驟，不是進出這個模組某一頁的移動，所以它不貢獻任何節點與連線。

這一節只畫頁面之間怎麼走，以及決定往哪一頁走的判斷；同一頁裡的操作細節看各規格的業務流程。連線依方向分三類判：離開本模組一律畫，進入與返回只在本模組自己的規格定了那個入口、或定了「回來之後這一頁顯示什麼」時才畫，模組內兩頁之間的移動本來就要畫。每一條連線都對回規格的條文，規格裡找不到出處的連線不畫，理由逐條寫在最後那個缺口摺疊區塊；三類判準逐條盤點的結果，列在它前面那個摺疊區塊。唯一沒有規格出處的是起訖連線（S 接上的那一條），它只標出流程從哪裡開始。這個模組沒有 E 結束節點：分析列表與分析詳情是唯讀的瀏覽畫面，使用者看完可以回分析列表，或離開去任務詳情、標記清單，沒有一個必然的終點。本節**不做完整性宣稱**。

### 節點

同一個節點出現在不同分段時用同一個編號。

- 起訖
  - S 開始：使用者直接貼一個網址進分析詳情（含舊連結或無效的任務代號）；網址帶著合法的分頁參數時落在該分頁，沒帶時落在統計總覽，見[規格 05-02 §邊界情況（Edge Case）](./02-analysis-detail.mdx#邊界情況edge-case)的「進入」第 1、3 條
- 頁面（矩形）
  - P1 [05-01 分析列表](./01-analysis-list.mdx#業務流程)
  - P2 [05-02 分析詳情](./02-analysis-detail.mdx#業務流程)（統計總覽與品質監控是同一頁的兩個分頁，切換是頁內切換，見[§分頁列與網址上的分頁參數](./02-analysis-detail.mdx#分頁列與網址上的分頁參數)第 2 條）
- 判斷（菱形）
  - D1 在目前任務是專案負責人或審核員嗎？（側欄導覽項的卡控）
  - D2 任務代號與成員資格都過得了嗎？
- 其他流程或外部系統（雙邊框）
  - X1 [07-01 側欄導覽](../07-shared/01-sidebar.mdx#業務流程)的「資料集分析」
  - X2 [03-01 任務列表](../03-task-management/01-task-list.mdx#業務流程)
  - X3 [02-01 儀表板](../02-dashboard/01-dashboard.mdx#業務流程)上的提醒；事件名與消費端見[規格 07-04 §事件清單](../07-shared/04-notification-events.mdx#事件清單)的「IAA 待確認」（第 8 列）
  - X4 [03-03 任務詳情](../03-task-management/03-task-detail.mdx#業務流程)
  - X5 [04-01 標記清單](../04-annotation/01-annotation-list.mdx#業務流程)

### 分段一：進到分析列表

1. X1 側欄點「資料集分析」→ D1（系統先確認任務角色；07-01 §進入模組的條件 第 2 條；05-01 §業務流程「進到分析列表」主流程第 1 步、§模組入口 第 3 條前半「主要入口是側欄的「資料集分析」」）
2. D1 否 → X2 任務列表（擋下進入，回到任務列表並顯示說明；07-01 §進入模組的條件 第 3 條、§卡控機制「使用者在目前任務不是專案負責人也不是審核員」那一列、§驗收標準「沒有任務角色時點擊資料集分析」、§已確認決議 Q9）
3. D1 是 → P1 分析列表（進入資料集分析列表，看到他在成員資格內的任務；07-01 §進入模組的條件 第 2 條；05-01 §業務流程「進到分析列表」主流程第 2、4 步與結果、§驗收標準「側欄進來是分析列表」）

### 分段二：從列表進分析詳情

1. P1 點任一任務列 → D2（整列都可點，不只任務名稱；05-01 §點任務列進入分析詳情 第 1、2 條、§業務流程「從列表挑一個任務」主流程第 3 步、§驗收標準「點列進統計總覽」「整列可點」；05-02 §兩個合法入口 第 1 條）
2. S → D2（起訖連線，無規格條文；05-01 §點任務列進入分析詳情 第 3 條把「用舊連結或無效的任務代號直接進詳情」交給 05-02 處理；05-02 §邊界情況（Edge Case）「進入」第 1 條）
3. D2 否 → P1 分析列表（任務代號不存在、沒有專案負責人或審核員的成員資格、任務角色缺少或認不得、或任務已經封存，一律導回分析列表，由那一頁顯示「找不到指定的任務，或你沒有該任務的存取權限。」；05-02 §進來先驗兩件事：任務代號與成員資格 第 1～7 條、§業務流程「進入某個任務的分析詳情」E1、§卡控機制 前四條、§驗收標準「任務代號不存在時導回列表」「首次打開已封存任務被擋」；05-01 §點任務列進入分析詳情 第 3 條）
4. D2 是 → P2 分析詳情，落在統計總覽（沒帶分頁參數、或參數不是兩個合法值之一時一律落在統計總覽；05-01 §點任務列進入分析詳情 第 1 條；05-02 §兩個合法入口 第 1 條、§分頁列與網址上的分頁參數 第 4、5 條、§業務流程「進入某個任務的分析詳情」A1、§驗收標準「從分析列表進來落在統計總覽」）

### 分段三：儀表板的提醒進品質監控

1. X3 點儀表板的「IAA 待確認」提醒 → D2（這是深層連結，必須把任務上下文一併載入，不得只是切到分頁卻沒有資料；05-02 §兩個合法入口 第 2、3 條、§業務流程「進入某個任務的分析詳情」觸發；07-04 §事件清單 第 8 列）
2. D2 否 → P1 分析列表（同一道卡控不分入口：「不管從哪個入口進來，系統都先驗任務代號與成員資格，過不了就不渲染任何內容」；05-02 §進來先驗兩件事：任務代號與成員資格 開頭與第 1～3 條）
3. D2 是 → P2 分析詳情，直接落在品質監控（05-02 §兩個合法入口 第 2 條、§驗收標準「從儀表板提醒進來落在品質監控」；該任務的試標還沒完成時落在品質監控的空狀態、外殼與分頁列都在，見 §邊界情況（Edge Case）「進入」第 2 條）

### 分段四：從分析詳情離開

1. P2 點麵包屑第一段 → P1 分析列表（麵包屑固定是「資料集分析 › 〈任務名稱〉」，第一段連回分析列表；05-02 §頁首與麵包屑 第 3 條）
2. P2 按瀏覽器的「上一頁」→ P1 分析列表（切換分頁不留歷程，所以上一頁是離開這一頁、回到進來之前的地方；05-02 §分頁列與網址上的分頁參數 第 8 條、§已確認決議 Q1、§驗收標準「上一頁離開這一頁」；回到列表時那五個查詢條件都還原，見 05-01 §查詢條件保留在網址 第 1、3 條、§邊界情況（Edge Case）「從分析詳情返回這一頁」；05-01 §驗收標準「從詳情返回還原條件」的 Then 寫的是「四個條件都還在」，與第 3 條不一致，本節不裁定，規格的落差見 #576）
3. P2 成員資格被移除或任務被封存，下一次讀取 → P1 分析列表（不等使用者自己離開，已載入的內容不再顯示；05-02 §業務流程「停在頁面上之後資格失效」主流程第 2、3 步、§卡控機制「載入後成員資格被移除或任務被封存」那一條、§已確認決議 Q5、§驗收標準「資格失效在下一次讀取時擋住」）
4. P2 兩個分頁的空狀態各有一顆「前往任務詳情」→ X4 任務詳情（統計總覽在還沒有任何已提交的標記時、品質監控在試標還沒完成時；05-02 §統計總覽的空狀態 第 2、3 條、§品質監控要先有試標才有東西看 第 1、2 條、§卡控機制 那兩條、§驗收標準「空狀態的按鈕導向任務詳情」「試標沒完成時品質監控是空狀態」）
5. P2 專案負責人在風險表點「審核標記」→ X5 標記清單（預先帶上審核員視角與試標回合；05-02 §建議行動只有專案負責人能執行 第 1、2、4 條、§卡控機制「審核標記」那一條、§驗收標準「審核標記導向標記清單」。規格 04-01 §使用角色 說專案負責人進不了標記清單，說法相反，見缺口二）
6. P2 專案負責人在風險表點「調整參與狀態」→ X4 任務詳情的成員管理分頁（05-02 §建議行動只有專案負責人能執行 第 1、2、4 條、§卡控機制「調整參與狀態」那一條、§驗收標準「調整參與狀態導向成員管理」；03-03 §成員管理）

<summary>三類判準逐條盤點：哪些畫了、哪些沒畫</summary>

- **頁內切換**：統計總覽與品質監控之間的切換（[規格 05-02 §分頁列與網址上的分頁參數](./02-analysis-detail.mdx#分頁列與網址上的分頁參數)第 2 條明寫「不得導向分析列表、也不得整頁重新載入」），不跨頁。
- **停在原頁的狀態**：兩頁各自的狀態（05-01 的四種互斥狀態加第五種「篩選後沒有結果」、05-02 兩個分頁的四種與六種）都停在原頁，[規格 05-01 §卡控機制](./01-analysis-list.mdx#卡控機制)還明寫「使用者只有標記員的成員資格 → 顯示空狀態，**不導回其他頁面**」。

- **離開**：分段一第 2 條的落點規則在[規格 07-01 §進入模組的條件](../07-shared/01-sidebar.mdx#進入模組的條件)，分段四第 4～6 條的規則寫在 05-02、落點卻在模組 03 與 04，四條都畫。
