# 07-02 工作頁籤

:badge[草稿]{variant="warning"} :badge[共用介面]{variant="neutral"}

> 來源：舊 repo `specs/shared/019-workspace-tabs/spec.md`（112 條，釘在 `singyichen/label-suite@faf83356`，見 `docs/specs/legacy/07-02-workspace-tabs.ids` 的首行）
> 參考畫面：無獨立頁面。頁籤列掛在側欄殼層上，出現在每一個登入後頁面裡，畫面以 `design/prototype/pages/shared/sidebar.js` 與 `sidebar.css` 為準（同 [規格 07-01 §待釐清](./01-sidebar.mdx#待釐清) Q5）
> 相關規格：[規格 07-01 側欄導覽](./01-sidebar.mdx)、規格 03-03 任務詳情（未撰寫）、規格 04-02 標記工作區（未撰寫）

## 目標

- 提供一列 :ref[工作頁籤]{id="term.workspace-tabs"}，讓所有登入後的使用者同時保留多個頁面的檢視狀態並快速切換，不必靠瀏覽器分頁或重新操作一次篩選與子分頁
- 讓 :ref[專案負責人]{id="term.project-leader"} 把同一個 :ref[任務]{id="term.task"} 的 :ref[試標]{id="term.dry-run"} 與 :ref[正式標記]{id="term.official-run"} 各開一個頁籤來回比對，判斷正式標記的 :ref[爭議]{id="term.dispute"} 是不是在試標時就已經分歧——這是標記品質管控的工作流程，不只是操作便利
- 用未儲存保護，讓 :ref[標記員]{id="term.annotator"} 與 :ref[審核員]{id="term.reviewer"} 不會因為頁籤被自動淘汰而遺失還沒送出的作答或審核決定

## 使用角色

:::tip{title="權限代號"}
R：Read（可讀取）　C：Create（可新增）　E：Edit（可編輯）　D：Delete（可刪除）　(o)：只限自己的資料　—：無權限
:::

頁籤是使用者自己的工作狀態，不是業務資料；每個人只看得到也只改得到自己的頁籤。

PRD §權限矩陣目前給「07 共用介面」的上限是 R；下列的 E (o) 只作用在使用者自己的頁籤狀態，不碰任何業務資料。
依 [規格 07-01 §已確認決議](./01-sidebar.mdx#已確認決議) Q1，PRD 會放寬到 `R／E (o)`，改動由 Issue #85 處理。

- :ref[平台成員]{id="term.platform-member"}：R／E (o)
- :ref[系統管理員]{id="term.system-admin"}：R／E (o)；系統管理的頁面同樣可以開成頁籤
- :ref[Seeder 管理員]{id="term.seeder-admin"}：R／E (o)；與系統管理員相同
- 未登入的訪客：無權限；頁籤列只出現在登入後的頁面
:ref[任務角色]{id="term.task-role"} 不影響能不能用頁籤，只影響頁籤裡那一頁進不進得去（見 [規格 07-01 §進入模組的條件](./01-sidebar.mdx#進入模組的條件)）。

- **開啟頁籤**
  - 觸發：使用者點側欄、清單、通知或儀表板上會換頁的項目
  - 前置條件：使用者已登入，頁籤列已顯示
  - 主流程：
    1. 使用者點項目 → 系統依同一性規則判斷這一頁是不是已經開著
    2. 沒開著 → 系統確認頁籤數量還沒到上限 → 在作用中頁籤的右邊插入新頁籤
    3. 系統掛載該頁並由網址還原它的檢視狀態
  - 替代流程：
    - A1（第 1 步）這一頁已經開著 → 切到那個頁籤，不新開，回到第 3 步
    - A2（第 2 步）已達上限但有可以淘汰的頁籤 → 淘汰最久沒用且沒有未儲存變更的那一個、把它推進最近關閉的清單，再插入新頁籤，回到第 3 步
  - 例外流程：
    - E1（第 2 步）已達上限且每一個頁籤都有未儲存變更 → 擋下開啟並顯示說明，流程結束（見 [§卡控機制](#卡控機制)）
    - E2（第 1 步）使用者按住 `Ctrl` 或 `⌘`、或用滑鼠中鍵點擊 → 交給瀏覽器開新的瀏覽器分頁，不建立工作頁籤，流程結束
  - 結果：目標頁面在一個頁籤裡顯示，檢視狀態與網址一致；被擋下時沒有任何頁籤被動到

- **切換頁籤**
  - 觸發：使用者點另一個頁籤，或按 `Alt` 加數字
  - 前置條件：至少有兩個頁籤
  - 主流程：
    1. 使用者選另一個頁籤 → 系統記住目前頁籤的捲動位置
    2. 系統卸載目前的頁面、掛載目標頁籤的頁面
    3. 系統由網址還原子分頁、篩選與階段，再還原該頁籤的捲動位置
  - 替代流程：
    - A1（第 3 步）目標頁籤先前已經載入過 → 不顯示整頁載入中，直接呈現內容
  - 例外流程：
    - E1（第 3 步）該頁指向的資料在閒置期間失去權限或已不存在 → 該頁籤顯示無權限或找不到的畫面，不自動關閉，流程結束（見 [§規格 › 權限或資料失效](#權限或資料失效)）
  - 結果：畫面回到離開那個頁籤之前的樣子，包含子分頁、篩選、階段與捲動位置

- **關閉與重開頁籤**
  - 觸發：使用者關閉某個頁籤
  - 前置條件：至少有一個頁籤
  - 主流程：
    1. 系統確認該頁籤有沒有未儲存變更 → 沒有
    2. 系統關閉該頁籤，並把它推進最近關閉的清單
    3. 關的是作用中頁籤時 → 焦點依 [規格 07-01 §工作頁籤的位置](./01-sidebar.mdx#工作頁籤的位置) 移動
  - 替代流程：
    - A1（第 3 步）使用者點「重開剛關閉的」或按 `Alt+Shift+T` → 取出最近關閉的一筆重新開啟，回到「開啟頁籤」的第 1 步
  - 例外流程：
    - E1（第 1 步）該頁籤有未儲存變更 → 沿用該頁原有的確認對話；使用者取消就不關閉，流程結束（見 [§規格 › 未儲存保護](#未儲存保護)）
  - 結果：頁籤關閉且可以重開；有未儲存變更時使用者一定先被問過

## 規格

### 頁籤列的位置

所有登入後、有側欄的頁面都有頁籤列，系統管理的頁面也一樣。

1. 使用者進入任何登入後的頁面 → 主要內容區的上方顯示頁籤列，至少包含目前這一頁的頁籤
2. 使用者在較窄的螢幕 → 不顯示頁籤列，改在頂部顯示總覽選單的按鈕，上面寫目前開了幾頁
3. 任何時候，頁籤列與頂部的總覽按鈕恰有一個看得到

### 開啟頁籤與去重

系統用「同一性規則」判斷使用者點的那一頁是不是已經開著；已經開著就切過去，沒開著才新開。

1. 使用者點側欄、清單、通知或儀表板上會換頁的項目 → 系統依下表判斷
2. 已經開著 → 切到那個頁籤，不新開第二個
3. 沒開著 → 在目前作用中頁籤的**右邊**插入新頁籤
4. 使用者在某一頁裡切換子分頁或篩選，而切換後的狀態剛好和另一個已開的頁籤相同 → 切到那個頁籤，原本的頁籤維持原狀並顯示說明；不合併、不產生重複
5. 使用者按住 `Ctrl` 或 `⌘`、或用滑鼠中鍵點擊 → 交給瀏覽器開新的瀏覽器分頁，不建立工作頁籤

**同一性規則**（唯一來源，新增頁面種類要回來改這張表）：

| 頁面種類 | 兩個頁籤算同一個的條件 |
| :--- | :--- |
| 標記工作區 | 同一個任務、同一種模式（標記或審核）。同一個任務的標記與審核算不同頁籤 |
| 新增任務 | 永遠只能開一個 |
| 任務詳情 | 完整的檢視狀態都相同（任務、子分頁、各項篩選與階段）。所以同一個任務可以開多個頁籤，這是試標與正式標記比對的基礎 |
| 其餘所有頁面 | 完整的檢視狀態都相同 |

- 任務詳情的「完整檢視狀態」包含哪些項目由規格 03-03 任務詳情定義（未撰寫），本頁不重複列舉
- 專案負責人開啟標記工作區時頁籤要算哪一種模式，見 [§待釐清](#待釐清) Q1

### 頁籤的標題

頁籤的標題要讓使用者一眼分辨「這是哪一種頁面」和「對象是誰」，所以分成種類小標籤與對象名稱兩部分。

1. 使用者開了多個頁籤 → 每個頁籤顯示它的種類小標籤加對象名稱
2. 儀表板、個人設定、任務列表、新增任務、標記清單、資料集分析列表、使用者管理、角色設定 → 沒有小標籤，只顯示頁面名稱
3. 標記工作區 → 小標籤是「標記」或「審核」，後面接任務名稱
4. 任務詳情 → 沒有階段時小標籤是「詳情」，試標是「試標 R`{n}`」（`n` 是試標的回合數），正式標記是「正式」，後面都接任務名稱
5. 資料集分析詳情 → 小標籤是「分析」，後面接任務名稱
6. 任務名稱查不到時 → 依序退回頁籤上記的名稱、再退回任務的編號，不顯示空白
7. 名稱太長 → 以省略號截斷，完整文字仍可從滑鼠停留的提示與總覽選單看到

- 英文介面的小標籤依序是 `Annotate`、`Review`、`Detail`、`Dry Run RN`、`Official`、`Analysis`；名稱取英文名，英文名缺漏時退回中文名
- 小標籤的顏色依語意區分（試標用警示色、正式用主色、審核用資訊色、其餘用中性色），具體色票以 prototype 為準
- 「R`{n}`」的 `n` 只用在試標的回合編號（第一輪是「試標 R1」）；正式標記不編號
- 總覽選單與小螢幕的選單顯示的是「小標籤加空格加名稱」的純文字，不另外畫小標籤

### 切換頁籤與狀態還原

頁籤只記一個網址；切回去的時候重新掛載那一頁，再由網址把畫面還原回來。

1. 使用者切到另一個頁籤 → 系統先記住目前頁籤的捲動位置
2. 系統掛載目標頁籤的頁面 → 由網址還原子分頁、篩選、頁碼與階段，再還原該頁籤的捲動位置
3. 目標頁籤先前已經載入過 → 不顯示整頁載入中
4. 使用者重新整理瀏覽器 → 頁籤清單與目前停在哪一個都還原回來
5. 使用者另開一個瀏覽器分頁進入平台 → 那個分頁的頁籤列從空白開始，不帶入別的分頁開過的頁籤
6. 使用者登出 → 頁籤清單、捲動位置與最近關閉的清單都清空；下一位登入的人從空白開始
7. 使用者按瀏覽器的上一頁 → 只回到同一個頁籤裡的上一個檢視狀態，不會跳到別的頁籤，也不會增減頁籤

- 頁籤不保留頁面本身的執行狀態，只保留網址與捲動位置；還原得回來的前提是那一頁把檢視狀態寫進網址
- 某一頁還沒把某項檢視狀態寫進網址時，那一項切回來就還原不了；那是該頁自己要補的，見 [§邊界情況（Edge Case）](#邊界情況edge-case)

### 數量上限與淘汰

頁籤最多 8 個；開到第 9 個時系統自己讓位，但絕不動到有未儲存變更的頁籤。

1. 使用者開到第 9 個頁籤 → 系統先淘汰最久沒用且沒有未儲存變更的那一個，再開新的
2. 被淘汰的頁籤 → 推進最近關閉的清單，可以重開
3. 已經有 8 個頁籤而且每一個都有未儲存變更 → 擋下開啟並顯示說明，不淘汰任何一個

- 上限是 8 個頁籤；最近關閉的清單最多記 10 筆，超過就丟掉最舊的
- 「最久沒用」看的是最後一次成為作用中頁籤的時間
- 這兩個數字是否為業務決定，見 [§待釐清](#待釐清) Q4

### 未儲存保護

還沒送出的作答或審核決定不會因為頁籤被自動淘汰而消失。

1. 標記員在標記工作區有還沒送出的作答 → 該頁籤視為有未儲存變更
2. 審核員在標記工作區有還沒送出的審核決定 → 同樣視為有未儲存變更
3. 使用者在新增任務填了一半 → 該頁籤視為有未儲存變更
4. 有未儲存變更的頁籤 → 不會被自動淘汰
5. 使用者主動關閉有未儲存變更的頁籤 → 沿用該頁原本就有的確認對話，不另外做第二套

- 目前只有標記工作區與新增任務會回報未儲存狀態，其餘頁面一律視為沒有；還有哪些頁面要回報見 [§待釐清](#待釐清) Q2

### 關閉與重開

使用者關掉頁籤之後還救得回來；焦點的落點由側欄那一頁定義，本節只講關閉與重開本身。

1. 使用者關閉任何頁籤 → 焦點怎麼移動依 [規格 07-01 §工作頁籤的位置](./01-sidebar.mdx#工作頁籤的位置)；那一節是這條規則的唯一正典，本頁不重寫也不另外驗收
2. 手動關閉、全部關閉、被自動淘汰的頁籤 → 都推進最近關閉的清單
4. 使用者點「重開剛關閉的」或按 `Alt+Shift+T` → 取出最近關閉的一筆重新開啟，順序是後關的先重開
5. 要重開的那一筆，依同一性規則發現已經有頁籤開著 → 切到那個頁籤，不新開，並把該筆從清單移除
6. 最近關閉的清單是空的 → 「重開剛關閉的」不能點

### 全部關閉

使用者一次收掉整個工作區，但有未儲存變更的頁籤一個都不會被關掉。

1. 使用者點「全部關閉」→ 關掉所有沒有未儲存變更的頁籤，有未儲存變更的留下
2. 有頁籤被跳過 → 顯示說明，寫出被跳過的數量
3. 作用中頁籤被關掉、但還有被跳過的頁籤 → 焦點落在其中一個被跳過的頁籤
4. 關完之後沒有任何頁籤 → 頁籤列顯示空狀態
5. 被關掉的頁籤 → 都推進最近關閉的清單，可以依關閉的反序一個一個重開

- 全部關閉本身不彈確認對話，只跳過並說明；使用者一個一個關的時候仍然會看到該頁原本的確認對話

### 頁籤總覽選單

開了多個頁籤之後，使用者從總覽選單找特定的頁籤、重開剛關閉的、或一次清空。

1. 使用者點總覽按鈕 → 展開選單，按鈕與選單上都看得到目前開了幾頁，清單的項目數等於頁籤數
2. 作用中的頁籤在清單裡有看得出來的標示
3. 清單每一列只有一行：頁面種類的圖示、標題、關閉按鈕
4. 選單最下面是「重開剛關閉的」與「全部關閉」
5. 使用者在篩選框輸入文字 → 只留下標題或頁面種類名稱命中的那幾列，不分大小寫，不比對網址上的參數
6. 使用者點清單裡某一列 → 切到那個頁籤並關閉選單，行為和點頁籤列上的頁籤一樣
7. 使用者在桌機橫向捲動頁籤列 → 總覽按鈕留在頁籤列最右端，不跟著移動

### 快捷鍵

桌機使用者不離開鍵盤就能切換、關閉與重開頁籤；在打字的時候這些按鍵一律讓位。

1. 使用者按 `Alt` 加 1 到 8 → 切到那個位置的頁籤；那個位置沒有頁籤就不動作
2. 使用者按 `Alt+W` → 關閉作用中的頁籤
3. 使用者按 `Alt+Shift+T` → 重開剛關閉的頁籤
4. 焦點在輸入框、文字區或可編輯的區域 → 這三個快捷鍵都不攔截，使用者照常打字
5. 使用者的鍵盤配置會讓 `Alt` 改變輸入的字元（例如 macOS 的 `Option`＋數字會打出特殊符號）→ 焦點不在可輸入的地方時，`Alt` 加數字仍然切到那個位置的頁籤

- 這三個快捷鍵都列在快捷鍵總覽的「頁籤」那一組，總覽本身的呈現見 [規格 07-01 §快捷鍵總覽](./01-sidebar.mdx#快捷鍵總覽)；總覽上顯示的按鍵組合以本節為準
- `Alt+Shift+T` 不會攔截瀏覽器自己的重開分頁快捷鍵，兩者是不同的按鍵組合

### 小螢幕的呈現

螢幕窄到放不下一排頁籤時，改用頂部的總覽選單，使用者仍然切換得到每一個頁籤。

1. 使用者在較窄的螢幕 → 不顯示頁籤列，頂部的總覽按鈕寫著目前開了幾頁
2. 使用者展開選單並點某一列 → 切到那個頁籤並關閉選單
3. 開滿 8 個頁籤並展開選單 → 畫面與選單都不需要左右滑動

### 權限或資料失效

權限或資料在頁籤閒置的時候變了，只在使用者切回去的時候才檢查。

1. 使用者切回某個頁籤，而它指向的東西已經沒有權限 → 該頁籤顯示無權限的畫面，不自動關閉
2. 使用者切回某個頁籤，而它指向的任務已經被刪掉 → 該頁籤顯示找不到的畫面，不自動關閉
3. 兩種情況都由使用者自己關閉那個頁籤
4. 系統不主動推播權限變更；狀態只在下一次切回時重新檢查

- 無權限與找不到這兩個畫面的內容由哪一份規格定義，見 [§待釐清](#待釐清) Q5

### 鍵盤操作

只用鍵盤或只讀文字的使用者，走得到頁籤列與總覽選單的每一個控制項，而且知道自己停在哪裡。

1. 焦點在某個頁籤上 → 使用者按左右方向鍵把焦點移到相鄰的頁籤，不會順便切換；按 Enter 或空白鍵才切換
2. 每個頁籤的關閉按鈕都有看得懂的名稱，內容是該頁籤的純文字標題
3. 使用者展開總覽選單 → 焦點直接進到篩選框
4. 焦點在選單清單裡 → 上下方向鍵移動反白但不切換，Enter 才切換並關閉選單，`Esc` 關閉選單並把焦點還給總覽按鈕
5. 使用者用只讀文字的方式使用平台 → 讀得出頁籤列是一組頁籤，而且哪一個是作用中的

### 不支援的事

寫出來是為了讓讀者不用去猜：

1. 不跨瀏覽器分頁、不跨裝置同步
2. 不分割畫面、不並排顯示；同一時間只顯示一個頁籤的內容
3. 不提供同一頁裡的「試標與正式標記對照模式」；比對的做法就是各開一個頁籤來回切換
4. 不主動推播權限變更
5. 表格原有的翻頁行為不受頁籤影響

### 資料欄位

頁籤是使用者自己的工作狀態，不含任何業務資料。

| 欄位 | 型別 | 必填 | 規則 | 使用者看到 |
| :--- | :--- | :--- | :--- | :--- |
| 頁籤的網址 | 文字 | 是 | 平台內的網址，是頁籤唯一持久保留的狀態 | 不直接顯示；決定切回去看到什麼 |
| 頁面種類 | 單選 | 是 | 決定小標籤與同一性規則 | 小標籤 |
| 對象名稱 | 文字 | 否 | 任務名稱；查不到時退回頁籤上記的名稱，再退回任務編號 | 頁籤標題的名稱部分 |
| 最後使用時間 | 時間 | 是 | 最後一次成為作用中頁籤的時間；達上限時用來挑淘汰對象 | 不直接顯示 |
| 有未儲存變更 | 是／否 | 是 | 只有標記工作區與新增任務會回報，其餘固定為否 | 關閉時是否出現確認對話 |
| 捲動位置 | 數值 | 否 | 不寫進網址；只在同一個瀏覽器分頁內記住 | 切回去時畫面停在原來的位置 |
| 最近關閉的清單 | 清單 | 否 | 後關的排前面，最多 10 筆，超過丟最舊的；登出清空 | 「重開剛關閉的」能不能點、重開哪一個 |

## 卡控機制

| 條件 | 結果 |
| :--- | :--- |
| 要開的那一頁依同一性規則已經開著 | 切到既有頁籤，不新開第二個 |
| 已有 8 個頁籤且每一個都有未儲存變更 | 擋下開啟並顯示說明，不淘汰任何頁籤 |
| 頁籤有未儲存變更 | 不會被自動淘汰 |
| 使用者主動關閉有未儲存變更的頁籤 | 沿用該頁原有的確認對話，不另做第二套 |
| 「全部關閉」遇到有未儲存變更的頁籤 | 跳過它並在說明裡寫出被跳過的數量 |
| 最近關閉的清單是空的 | 「重開剛關閉的」不能點 |
| 要重開的那一筆已經有頁籤開著 | 切到那個頁籤，不新開，並把該筆移除 |
| 使用者按住 `Ctrl`／`⌘` 或用滑鼠中鍵點擊 | 交給瀏覽器開新分頁，不建立工作頁籤 |
| 焦點在輸入框、文字區或可編輯區域 | 頁籤的三個快捷鍵都不攔截 |
| 切回頁籤時已經沒有權限或資料已不存在 | 顯示無權限或找不到的畫面，不自動關閉 |

## 邊界情況（Edge Case）

| 情況 | 使用者看到什麼 |
| :--- | :--- |
| 瀏覽器不讓平台在分頁內記東西（例如隱私模式的限制） | 頁籤列退回只有目前這一頁，不出現錯誤畫面也不中斷載入 |
| 同一個瀏覽器分頁裡開了不同模組的頁籤 | 互不影響，各自依自己的同一性規則判斷 |
| 淘汰判定的那一瞬間，候選頁籤剛好開始有未儲存變更 | 以觸發開啟的那一刻判斷一次，不持續監看；這是已知的簡化 |
| 某一頁還沒把某項檢視狀態寫進網址 | 切回那個頁籤時該項狀態還原不回來；這是該頁自己要補的，不是頁籤的問題 |
| 多個頁籤同時顯示無權限或找不到的畫面 | 互不影響，各自由使用者獨立關閉 |
| 任務名稱很長 | 頁籤上以省略號截斷，完整文字仍可從滑鼠停留的提示與總覽選單看到 |
| 任務名稱在目前語言沒有對應文字 | 退回另一種語言的名稱，再退回任務編號，不顯示空白 |
| 使用者只用鍵盤操作頁籤列 | 方向鍵移得到每一個頁籤，看得出目前焦點在哪，Enter 才切換 |

## 驗收標準

| Scenario | Given | When | Then |
| :--- | :--- | :--- | :--- |
| 每一頁都看得到頁籤列 | 使用者在任一登入後頁面，含系統管理的頁面 | 頁面載入完成 | 主要內容區上方顯示頁籤列，至少有目前這一頁的頁籤 |
| 頁籤列與總覽按鈕只有一個 | 使用者在任一登入後頁面 | 查看畫面 | 頁籤列與頂部總覽按鈕恰有一個看得到 |
| 同一頁再點一次切到既有頁籤 | 某一頁已經開著 | 再點一次會導向那一頁的項目 | 切到既有頁籤，沒有新開第二個 |
| 新頁籤插在作用中頁籤右邊 | 頁籤數還沒到上限 | 點一個還沒開過的項目 | 新頁籤插在作用中頁籤的右邊 |
| 按住 Ctrl 點擊交給瀏覽器 | 任一會換頁的項目 | 按住 `Ctrl` 或 `⌘`、或用滑鼠中鍵點擊 | 瀏覽器開新分頁，沒有建立工作頁籤 |

| 新增任務只能開一個 | 新增任務的頁籤已經開著 | 再從任何入口開啟新增任務 | 切到既有頁籤，沒有新開第二個 |
| 同一任務不同階段各一個頁籤 | 某任務試標階段的任務詳情頁籤已經開著 | 開啟同一任務正式標記階段的任務詳情 | 新開一個獨立頁籤，兩個並存 |

| 有未儲存變更的頁籤不被淘汰 | 某頁籤有未儲存變更且最久沒用 | 開新頁籤觸發淘汰判定 | 該頁籤保留，系統改淘汰別的或擋下 |
| 審核還沒送出也算未儲存 | 審核員在標記工作區有還沒送出的審核決定 | 檢查該頁籤的未儲存狀態 | 視為有未儲存變更，與標記的作答同等對待 |
| 關閉有未儲存變更的頁籤 | 某頁籤有未儲存變更 | 使用者點它的關閉按鈕 | 出現該頁原有的確認對話，取消就不關閉 |
| 切回頁籤還原子分頁與捲動 | 頁籤 A 停在某子分頁、已篩選、已翻頁、已捲動 | 切到頁籤 B 再切回 A | 子分頁、篩選、頁碼與捲動位置都和離開前一致 |
| 已載入過的頁籤不顯示載入中 | 頁籤 A 先前已經載入過 | 切回頁籤 A | 不出現整頁載入中的畫面 |
| 重新整理後頁籤還在 | 已開多個頁籤 | 重新整理瀏覽器 | 頁籤清單與目前停在哪一個都還原回來 |
| 另開瀏覽器分頁從空白開始 | 已開多個頁籤 | 在新的瀏覽器分頁進入平台 | 那個分頁的頁籤列是空白的，沒有帶入別的分頁的頁籤 |
| 登出後下一位從空白開始 | 使用者開過多個頁籤後登出 | 下一位使用者登入 | 頁籤列空白，看不到前一位開過的任務名稱；「重開剛關閉的」不能點 |
| 上一頁只在同一個頁籤內移動 | 使用者在某頁籤內切換過子分頁 | 按瀏覽器的上一頁 | 回到同一個頁籤裡的上一個檢視狀態，沒有跳到別的頁籤，頁籤數不變 |
| 切回時沒有權限 | 某頁籤指向的東西在閒置期間被收回權限 | 切回那個頁籤 | 顯示無權限的畫面，頁籤沒有自動關閉 |
| 切回時資料已不存在 | 某頁籤指向的任務在閒置期間被刪掉 | 切回那個頁籤 | 顯示找不到的畫面，頁籤沒有自動關閉 |
| 不主動推播權限變更 | 某頁籤正顯示無權限的畫面 | 在背景恢復該使用者的權限 | 該頁籤沒有自動更新也沒有自動關閉，要等使用者下次切回才重新檢查 |
| 重開剛關閉的頁籤 | 使用者剛關閉一個頁籤 | 點「重開剛關閉的」 | 那個頁籤重新開啟，和關閉前是同一頁 |
| 重開依後關的先出 | 使用者依序關閉頁籤 A、再關 B | 連續點「重開剛關閉的」兩次 | 第一次重開 B，第二次重開 A |
| 最近關閉的清單滿了丟最舊 | 已累積 10 筆關閉紀錄 | 再關閉第 11 個頁籤 | 最舊的一筆被丟掉，其餘 10 筆保留 |
| 重開撞到已開的頁籤 | 要重開的那一筆已經有頁籤開著 | 點「重開剛關閉的」 | 切到那個頁籤，沒有新開，該筆從清單移除 |
| 清單空時不能重開 | 最近關閉的清單是空的 | 展開總覽選單 | 「重開剛關閉的」是停用的，點不下去 |
| 全部關閉跳過未儲存的 | 已開五個頁籤，其中兩個有未儲存變更 | 點「全部關閉」 | 三個沒有未儲存變更的被關閉，兩個保留，說明寫出被跳過兩個 |
| 全部關閉後焦點落在被跳過的 | 承上，作用中頁籤是被關閉的三個之一 | 全部關閉執行完成 | 焦點落在其中一個被保留的頁籤 |
| 全部關閉後可以逐一重開 | 全部關閉關掉了三個頁籤 | 連續點「重開剛關閉的」三次 | 三個頁籤依關閉的反序一個一個重開 |
| 總覽選單顯示頁籤數 | 已開 N 個頁籤 | 展開總覽選單 | 按鈕與選單都看得到 N，清單項目數等於 N，作用中的那一列有標示 |
| 總覽選單的篩選 | 選單已展開，有一個頁籤標題含某字串 | 在篩選框輸入那個字串的小寫 | 只留下標題或頁面種類名稱命中的那幾列，其餘隱藏 |
| 總覽選單不比對網址參數 | 選單已展開 | 在篩選框輸入只出現在網址參數裡的文字 | 沒有任何一列被留下 |
| 點總覽選單的項目切換頁籤 | 選單已展開，清單裡有非作用中的頁籤 | 點那一列 | 切到那個頁籤並關閉選單 |
| 總覽按鈕不隨頁籤列捲動 | 桌機，頁籤多到頁籤列可以橫向捲動 | 橫向捲動頁籤列 | 總覽按鈕留在頁籤列最右端，位置不變 |
| Alt 加數字切換頁籤 | 已開 N 個頁籤 | 按 `Alt` 加 1 到 8 其中一個數字 | 切到那個位置的頁籤；那個位置沒有頁籤就不動作 |
| 修飾鍵改變字元時仍能切換 | 使用者的鍵盤配置會讓 `Alt` 加數字打出特殊符號，焦點不在可輸入的地方 | 按 `Alt` 加 1 | 切到第一個頁籤，沒有打出特殊符號 |
| 按 Alt+Shift+T 重開 | 最近關閉的清單非空，焦點不在可輸入的地方 | 按 `Alt+Shift+T` | 與點「重開剛關閉的」結果相同 |
| Alt+W 關閉作用中頁籤 | 任一頁籤是作用中的 | 按 `Alt+W` | 關閉它並依焦點規則移到下一個頁籤 |
| 輸入框內不攔截數字鍵 | 焦點在輸入框、文字區或可編輯區域 | 按 `Alt` 加數字 | 照常輸入字元，沒有切換頁籤 |
| 輸入框內不攔截關閉鍵 | 焦點在輸入框、文字區或可編輯區域 | 按 `Alt+W` | 照常輸入字元，沒有關閉頁籤 |
| 輸入框內不攔截重開鍵 | 焦點在輸入框、文字區或可編輯區域 | 按 `Alt+Shift+T` | 照常輸入字元，沒有重開頁籤 |
| 試標與正式標記各一個頁籤比對 | 某任務試標已達門檻並開始正式標記 | 分別開啟試標與正式標記的任務詳情頁籤並來回切換 | 兩個頁籤各自保留獨立的篩選與捲動狀態，不互相覆蓋 |

## Q&A

### Q. 為什麼同一個任務的標記與審核要算兩個頁籤，但同一個任務的任務詳情可以開很多個？

兩者問的問題不一樣。標記與審核是兩種工作，同一個人在同一個任務裡最多各做一次，所以各一個頁籤就夠；再多開只會讓他自己搞不清楚哪個是哪個。任務詳情是「看同一個任務的不同切面」，而比對試標與正式標記正需要兩個切面並存——那是這個功能存在的主要理由。

### Q. 為什麼未儲存的頁籤不能被自動淘汰，但使用者自己關就可以？

自動淘汰是系統為了讓新頁籤有位子而做的決定，使用者沒有參與，所以不能讓他在毫無察覺的情況下損失還沒送出的作答。使用者自己按關閉是他的決定，只要先問過他就行——所以那裡沿用該頁原本的確認對話。

### Q. 為什麼「全部關閉」不彈確認對話，只跳過有未儲存變更的？

因為它已經不會造成損失。有未儲存變更的頁籤一個都不會被關掉，使用者還會看到跳過了幾個。再加一層確認，只是讓一個安全的操作變得囉嗦。

### Q. 為什麼另開一個瀏覽器分頁不會帶入原本的頁籤？

工作頁籤記的是「這個瀏覽器分頁裡的工作狀態」。如果兩個瀏覽器分頁共用同一份頁籤清單，它們會互相搶「目前停在哪一個頁籤」，使用者在 A 分頁切換會讓 B 分頁跳掉。各自獨立比較符合使用者開新分頁的本意。
