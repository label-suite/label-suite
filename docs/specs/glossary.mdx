# 術語表

規格書中的業務名詞都定義在這裡，規格內用 `:ref[名詞]{id="term.xxx"}` 引用。

- `id` 用 `term.<英文 kebab-case>`，全站唯一；改名時只改 label，不改 `id`
- 只寫業務定義，不寫系統怎麼存
- 依筆畫或模組分組皆可，新增時接在同組最後

## 角色

:::define{id="term.system-role" label="系統角色"}
<strong>系統角色</strong>：決定使用者在整個平台可以做什麼的角色，每個帳號恰有一個：平台成員或系統管理員。和任務角色無關。
:::

:::define{id="term.task-role" label="任務角色"}
<strong>任務角色</strong>：決定使用者在單一任務內可以做什麼的角色，例如審核員、標記員；在任務內指派，和系統角色無關。
:::

:::define{id="term.platform-member" label="平台成員"}
<strong>平台成員</strong>：系統角色為「平台成員」的使用者，可以參與被指派的任務，不能管理平台帳號與角色權限。
:::

:::define{id="term.system-admin" label="系統管理員"}
<strong>系統管理員</strong>：系統角色為「系統管理員」的使用者，可以管理平台帳號與角色權限。
:::

:::define{id="term.seeder-admin" label="Seeder 管理員"}
<strong>Seeder 管理員</strong>：平台部署時由部署者建立的第一位系統管理員；不能被停用、降級或移除，讓平台永遠保有一位管理者。
:::

:::define{id="term.annotator" label="標記員"}
<strong>標記員</strong>：任務角色之一，負責在任務中產出標記結果的使用者。
:::

:::define{id="term.project-leader" label="專案負責人"}
<strong>專案負責人</strong>：任務角色之一；建立任務的人自動取得。負責設定任務、指派成員、推進試標與正式標記、確認一致性結果與匯出標記結果。
:::

:::define{id="term.reviewer" label="審核員"}
<strong>審核員</strong>：任務角色之一，負責審核標記員的標記結果並處理爭議。
:::

:::define{id="term.arbiter" label="仲裁者"}
<strong>仲裁者</strong>：在任務中被指定負責仲裁的審核員；不是獨立的角色，權限和審核員相同，只多了對爭議做最終決定的責任。
:::

## 帳號

:::define{id="term.audit-log" label="異動紀錄"}
<strong>異動紀錄</strong>：帳號被新增、編輯、停用、啟用、變更系統角色或重發設定密碼信時留下的紀錄，包含操作者、時間、操作類型與變更前後的差異。
:::

:::define{id="term.login-state" label="登入狀態"}
<strong>登入狀態</strong>：使用者在某一台裝置上「現在是登入著的」這件事；每次登入開始一段，同一個人在兩台裝置上登入就是兩段互不相干的登入狀態。一段登入狀態會因為使用者自己登出、安全事件撤銷或時間到了而結束。
:::

:::define{id="term.password-setup-email" label="設定密碼信"}
<strong>設定密碼信</strong>：新增帳號或重發時寄到該帳號 Email 的信，內含 24 小時內有效、只能使用一次的設定密碼連結，讓新使用者自己設定密碼。
:::

## 任務

:::define{id="term.archived-task" label="封存"}
<strong>封存</strong>：任務被刪除後的狀態；任務不再出現在任務列表與任何入口，但資料留著，供查核與日後復原。平台上沒有把任務真正清掉的操作。
:::

:::define{id="term.task" label="任務"}
<strong>任務</strong>：一次標記工作的單位，包含資料集、任務設定與成員；依序經過草稿、試標中、等待 IAA 確認、正式標記中、已完成五個狀態。
:::

:::define{id="term.output-type" label="輸出類型"}
<strong>輸出類型</strong>：一個任務要產出哪一種標記結果；平台目前支援八種，由建立任務的人從中選一到多種組合出這個任務要標的東西。八種的中文名稱由規格 03-02 定名（見該頁 §已確認決議 Q10，依據是來源自己三處已拍板的條文）；<mark>規格 03-01 Q4 與 07-01 Q6 都已於 2026-11-08 定案，不再等它折回。</mark><sup>[#249](https://github.com/label-suite/label-suite/issues/249)</sup>任務不對應單一固定的「任務類型」。
:::

### 八種輸出類型

:::define{id="term.single-label" label="單一標籤"}
<strong>單一標籤</strong>：輸出類型之一；標記員從一組標籤裡**只選一個**。例如判斷一句話的情緒是正面、負面還是中立。
:::

:::define{id="term.multi-label" label="多標籤"}
<strong>多標籤</strong>：輸出類型之一；標記員從一組標籤裡**選任意多個**，標籤本身可以有上下層的分類關係，每一層都能單獨勾選。
:::

:::define{id="term.single-dim" label="單維度"}
<strong>單維度</strong>：輸出類型之一；標記員在**一個**尺度上給一個數值，例如情緒強度 1 到 5 分。
:::

:::define{id="term.multi-dim" label="多維度"}
<strong>多維度</strong>：輸出類型之一；標記員在**多個**尺度上各給一個數值，例如同時評正負向與激動程度。
:::

:::define{id="term.sequence-tagging" label="序列標註"}
<strong>序列標註</strong>：輸出類型之一；標記員把一段文字切成一個個單位，逐個標上類別。
:::

:::define{id="term.entity-recognition" label="實體辨識"}
<strong>實體辨識</strong>：輸出類型之一；標記員在文字裡圈出一段範圍，並指定它是哪一種實體，例如人名、藥名。
:::

:::define{id="term.relation-identification" label="關係識別"}
<strong>關係識別</strong>：輸出類型之一；標記員指出兩個對象之間是什麼關係。可以單獨使用；和實體辨識一起選時，圈出來的實體就是它可以連的對象。
:::

:::define{id="term.free-text" label="自由文字"}
<strong>自由文字</strong>：輸出類型之一；標記員自己寫一段文字作答，例如摘要或回答問題。
:::


:::define{id="term.json-dataset" label="JSON 資料集"}
<strong>JSON 資料集</strong>：建立任務時上傳的資料檔，一筆紀錄一個項目；平台只收這一種格式。同一個任務可以上傳多個檔案，它們合起來算同一個資料集。
:::

:::define{id="term.task-config" label="任務設定"}
<strong>任務設定</strong>：決定一個任務的輸入形式、要產出哪些標記與資料欄位用途的設定；換一種研究任務只要換任務設定，不必修改平台。
:::

:::define{id="term.data-isolation" label="資料隔離"}
<strong>資料隔離</strong>：讓試標與正式標記的資料與結果不混用的設定；預設開啟，關掉要先確認不可逆風險，而且這個動作會留下紀錄。關掉只放寬跨階段的結果不混用保證，不放寬「同一份資料不會被兩個回合重複用到」——後者不論開關與否都成立。
:::

:::define{id="term.guideline-version" label="指引版本"}
<strong>指引版本</strong>：標記說明與審核說明這幾份內容的版本號，內容真的改過並存成功就往上加一；每個回合在建立時釘住當時的版本，事後改說明不會動到已經開始的回合。
:::

:::define{id="term.history" label="歷程"}
<strong>歷程</strong>：一筆資料從被標記到定案之間，每一個人做過什麼的時序紀錄——誰在什麼時候寫入什麼、附了什麼理由、花了多少時間。給使用者看的畫面上這個頁籤叫「操作紀錄」（規格 04-02 §已確認決議 Q2，維護者裁定 2026-11-09），但規格與本表一律用「歷程」這個概念名稱，因為來源通篇用「歷程事件」「歷程可追溯」描述它。誰看得到哪一層由規格 04-02 §歷程的分層遮蔽 定義。
:::

:::define{id="term.dataset-version" label="資料集版本"}
<strong>資料集版本</strong>：一次匯入所產生的、**完整**的資料快照。版本有兩個狀態：**草稿**（還能更正來源與欄位分類）與**已定版**（內容從此不可改，任務只能綁這一種）。要修訂內容只能建立下一個版本，既有版本的項目不會因此改變；父版本只用來記錄血緣。「已定版」由規格 05-03 §已確認決議 Q10 定名（維護者裁定 2026-11-06），刻意不用:ref[封存]{id="term.archived-task"}——那個詞指任務的退場，和版本的「生效且不可改」幾乎相反。
:::

:::define{id="term.dry-run" label="試標"}
<strong>試標</strong>：正式標記前的小規模標記，用來確認標記員對規則的理解是否一致；只產出一致性指標，不產出最終答案。
:::

:::define{id="term.official-run" label="正式標記"}
<strong>正式標記</strong>：試標確認後的正式標記回合；審核定稿的結果就是任務最終的標記成果。
:::

:::define{id="term.token" label="Token"}
<strong>Token</strong>：把一段文字以**空白**切開之後的一個詞。它是兩個地方的計數單位：資料集分析的共用指標 `Token 數量`，以及:ref[實體辨識]{id="term.entity-recognition"}的片段長度分佈。:ref[序列標註]{id="term.sequence-tagging"}的片段長度**不以它為單位**，而是以字元計。
:::

:::define{id="term.iaa" label="IAA"}
<strong>IAA</strong>：標記者間一致性（Inter-Annotator Agreement），衡量多位標記員對同一筆資料的標記有多一致；結果只供專案負責人參考，不會自動決定任務能否進入正式標記。
:::

:::define{id="term.iaa-status" label="IAA 狀態"}
<strong>IAA 狀態</strong>：資料集分析把 :ref[IAA]{id="term.iaa"} 的計算結果收斂成的五種摘要狀態——<strong>通過</strong>、<strong>計算中</strong>、<strong>未通過</strong>、<strong>尚未開始</strong>、<strong>不適用</strong>；<strong>列表只顯示這個狀態、不顯示原始數值</strong>，而分析詳情除了這個狀態，另外顯示**有登錄門檻的那些輸出類型**的指標數值與門檻——自由文字顯示「不適用」狀態卡、沒有數值，序列標註只顯示點估計值、沒有門檻（見規格 05-02）。「不適用」用在任務的輸出類型全都不計入 IAA 達標分母的時候（哪些型別不計入，見規格 05-02 的「已確認決議」）。
:::

:::define{id="term.annotator-risk-level" label="風險等級"}
<strong>風險等級</strong>：一位標記員在某一種:ref[輸出類型]{id="term.output-type"}上的標記品質評級，值域<strong>恰好三個</strong>——<strong>正常</strong>、<strong>觀察</strong>、<strong>高風險</strong>；判定規則（三條或邏輯的升級條件與各自的倍數門檻）由規格 05-02 擁有。已完成樣本數不足時<strong>不給等級</strong>，另有一個「資料不足」旗標為真，而畫面那一欄改顯示「資料不足」——所以<strong>顯示標籤有四個、值域仍是三個</strong>。規格 03-03 成員進度表的「品質旗標」是<strong>同一個訊號</strong>，沿用這一組名字、不另立一組（規格 05-02 §已確認決議 Q19，維護者裁定 2026-11-06）；「資料不足」怎麼呈現見同章 Q22（維護者裁定 2026-11-07）。
:::

:::define{id="term.sample-anomaly-status" label="樣本異常狀態"}
<strong>樣本異常狀態</strong>：<strong>單一筆資料</strong>在逐:ref[輸出類型]{id="term.output-type"}區塊裡的異常偵測結果，值域恰好三個——<strong>正常</strong>、<strong>注意</strong>、<strong>異常</strong>。它和:ref[風險等級]{id="term.annotator-risk-level"}是<strong>兩個不同的訊號</strong>：這一個講「這一筆樣本標得怎樣」，那一個講「這位標記員整體標得怎樣」，所以兩組名字刻意不統一（維護者裁定 2026-11-08，見規格 05-02 §已確認決議 Q23）。兩組的英文中間值都是 <code>Watch</code>，那是巧合。
:::

:::define{id="term.ground-truth" label="標準答案"}
<strong>標準答案</strong>：測試集資料的正確答案，用來評估標記品質；標記員能接觸到的任何地方都看不到。
:::

:::define{id="term.dispute" label="爭議"}
<strong>爭議</strong>：審核時無法直接定稿的標記結果，例如標記員之間的答案衝突；由仲裁者做最終決定。
:::

## 權限

:::define{id="term.permission-matrix" label="權限矩陣"}
<strong>權限矩陣</strong>：把平台的每一個功能權限，對每一個角色給出「開」或「關」的那張對照表。它分成**系統角色**與**任務角色**兩層，兩層不互相推導；:ref[系統管理員]{id="term.system-admin"}在規格 06-02 檢視與調整它，但**只能在 PRD §權限矩陣 的上限內收窄、不能放寬**。矩陣格**不單獨賦予任何存取權**——它只是授權判斷的必要條件之一，操作還要過資源條件。
:::

### 平台層的權限（對系統角色給值）

:::define{id="term.perm-profile-view" label="檢視個人設定頁"}
<strong>檢視個人設定頁</strong>：看自己的個人設定頁。對應 PRD §權限矩陣「01 帳號」的 <code>R</code>。
:::

:::define{id="term.perm-profile-edit" label="編輯個人資料與密碼"}
<strong>編輯個人資料與密碼</strong>：改自己的個人資料與密碼。對應「01 帳號」的 <code>E</code>。
:::

:::define{id="term.perm-dashboard-view" label="檢視儀表板"}
<strong>檢視儀表板</strong>：進入儀表板。對應「02 儀表板」；兩種系統角色的這一格**固定開啟**。
:::

:::define{id="term.perm-task-list-view" label="檢視任務列表"}
<strong>檢視任務列表</strong>：進入任務列表。對應「03 任務列表」。
:::

:::define{id="term.perm-task-create" label="建立新任務"}
<strong>建立新任務</strong>：建立一個新任務。對應「03 新增任務」的 <code>C</code>。
:::

:::define{id="term.perm-user-management-view" label="進入使用者管理頁"}
<strong>進入使用者管理頁</strong>：進入使用者管理頁並查看帳號列表與異動紀錄。對應「06 使用者管理」的 <code>R</code>；平台成員這一格**固定關閉**。
:::

:::define{id="term.perm-user-management-manage" label="新增／編輯／停用使用者、指派系統角色"}
<strong>新增／編輯／停用使用者、指派系統角色</strong>：在使用者管理頁做寫入動作。對應「06 使用者管理」的 <code>C</code> 與 <code>E</code>；平台成員這一格**固定關閉**。
:::

:::define{id="term.perm-role-settings-view" label="進入角色權限設定頁"}
<strong>進入角色權限設定頁</strong>：進入角色設定頁並檢視:ref[權限矩陣]{id="term.permission-matrix"}。對應「06 角色設定」的 <code>R</code>；平台成員這一格**固定關閉**。
:::

:::define{id="term.perm-role-settings-manage" label="編輯並儲存角色權限矩陣"}
<strong>編輯並儲存角色權限矩陣</strong>：改並存:ref[權限矩陣]{id="term.permission-matrix"}。對應「06 角色設定」的 <code>E</code>；平台成員這一格**固定關閉**。
:::

:::define{id="term.perm-platform-overview-view" label="檢視全平台統計"}
<strong>檢視全平台統計</strong>：看跨任務的全平台統計。**已登錄、待啟用**；能力由 PRD §權限矩陣「02 儀表板」系統管理員的 <code>R</code>（不帶「只限自己」）涵蓋，但來源把它歸在系統管理模組而 PRD 的系統管理沒有對應列——**落位對應儀表板那一格、不新增 PRD 的列**（規格 06-02 §已確認決議 Q3，維護者裁定 2026-11-09）。
:::

### 任務層的權限（對任務角色給值）

:::define{id="term.perm-task-detail-view" label="檢視任務詳情"}
<strong>檢視任務詳情</strong>：看一個任務的詳情。對應「03 任務詳情」的 <code>R</code>。
:::

:::define{id="term.perm-task-detail-edit" label="編輯任務設定"}
<strong>編輯任務設定</strong>：改任務詳情裡允許修改的內容；仍受任務狀態與欄位規則限制。對應「03 任務詳情」的 <code>E</code>。
:::

:::define{id="term.perm-task-members-manage" label="管理任務成員與任務角色"}
<strong>管理任務成員與任務角色</strong>：加減任務成員、指派任務角色，含審核與仲裁的名冊。對應「03 任務詳情」的 <code>E</code>。
:::

:::define{id="term.perm-task-lifecycle-manage" label="推進任務生命週期"}
<strong>推進任務生命週期</strong>：發布、退回草稿、結案、重試 :ref[IAA]{id="term.iaa"}、停用:ref[資料隔離]{id="term.data-isolation"}。**已登錄、待啟用**；對應「03 任務詳情」的 <code>E</code>。
:::

:::define{id="term.perm-task-delete" label="刪除草稿任務"}
<strong>刪除草稿任務</strong>：把一個還是草稿的任務移到:ref[封存]{id="term.archived-task"}。**已登錄、待啟用**；PRD §權限矩陣 整個 03 模組**沒有任何一格有 <code>D</code>**，這個落差見規格 03-01 與 06-02。
:::

:::define{id="term.perm-annotate" label="以標記員身分標記"}
<strong>以標記員身分標記</strong>：在標記工作區產出標記。對應「04 標記清單與標記工作區（產出標記）」。
:::

:::define{id="term.perm-review" label="以審核員身分審核"}
<strong>以審核員身分審核</strong>：在標記工作區審核標記結果。對應「04 標記清單與標記工作區（審核與仲裁）」的審核員 <code>R/E</code>。
:::

:::define{id="term.perm-exception-resolve" label="處置最終例外"}
<strong>處置最終例外</strong>：在最終例外池做四種收尾處置。**已登錄、待啟用**；PRD 給專案負責人那一格的上限只有 <code>R</code>，而這是寫入動作，落差見規格 04-02 與 06-02。
:::

:::define{id="term.perm-dispute-adjudicate" label="裁定爭議"}
<strong>裁定爭議</strong>：仲裁名冊為空時由:ref[專案負責人]{id="term.project-leader"}對:ref[爭議]{id="term.dispute"}做最終決定。**已登錄、待啟用**；上限落差同「處置最終例外」。
:::

:::define{id="term.perm-dataset-stats-view" label="看任務統計"}
<strong>看任務統計</strong>：看一個任務的標記統計。對應「05 資料集分析」。
:::

:::define{id="term.perm-dataset-quality-view" label="看品質分析"}
<strong>看品質分析</strong>：看一個任務的品質監控（含 :ref[IAA]{id="term.iaa"}）。對應「05 資料集分析」。
:::

:::define{id="term.perm-dataset-export" label="匯出資料"}
<strong>匯出資料</strong>：下載或匯出標記結果。對應「03 匯出標記結果」的 <code>C</code>；來源把它歸在資料集模組，**鍵留在資料集那一段、在說明裡註明對應那一格**（規格 06-02 §已確認決議 Q1，維護者裁定 2026-11-09）。
:::

:::define{id="term.perm-dataset-ingestion-view" label="看資料匯入與版本"}
<strong>看資料匯入與版本</strong>：看得到一個任務的資料是從哪一次匯入來的、綁的是哪一個資料集版本。這個權限鍵**舊規格沒有**，是依 PRD §權限矩陣「05 資料匯入與版本」那一列補上的（規格 06-02 §已確認決議 Q2，維護者裁定 2026-11-09）：PRD 給專案負責人與審核員都看得到。
:::

:::define{id="term.perm-dataset-ingestion-create" label="匯入資料並建立版本"}
<strong>匯入資料並建立版本</strong>：把一批資料匯進來並產生一個新的資料集版本。和:ref[看資料匯入與版本]{id="term.perm-dataset-ingestion-view"}拆成兩個鍵，是因為 PRD 在同一列給了專案負責人 `R/C`、審核員只有 `R`——一個鍵表達不出「審核員看得到但不能匯入」（規格 06-02 §已確認決議 Q2，維護者裁定 2026-11-09）。
:::

## 共用介面

:::define{id="term.appearance-mode" label="外觀模式"}
<strong>外觀模式</strong>：使用者對介面明暗的偏好，有淺色、深色與跟隨系統三種；「跟隨系統」**跟著使用者作業系統的設定變化**（維護者 2026-11-09 裁定，見[規格 01-04 §已確認決議](./01-account/04-profile.mdx#已確認決議) Q7 與[規格 07-01 §已確認決議](./07-shared/01-sidebar.mdx#已確認決議) Q14；Q14 取代 Q10 的「固定呈現淺色」）。
:::

:::define{id="term.notification" label="通知"}
<strong>通知</strong>：平台上與使用者有關的事情發生時留下的訊息；使用者在側欄看得到未讀的數量，點開可以看清單並一次全部標為已讀。
:::

:::define{id="term.workspace-tabs" label="工作頁籤"}
<strong>工作頁籤</strong>：讓使用者在多個已開啟的工作區之間切換的頁籤列，掛在各頁共用的側欄上。
:::
