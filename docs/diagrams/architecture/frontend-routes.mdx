# 前端路由與骨架

這份記 `main` 上的 `frontend/` 現在長怎樣：每條路由用哪個頁面元件、對到哪一份規格與哪個 Logic Flow 節點，加上前端骨架；**只寫已合併的程式有的東西**。
要照著做的規則在 [技術架構的前端](../../development/architecture.mdx#前端)，為什麼這樣決定在 [ADR-005](../../development/adr/005-frontend-architecture.mdx)；畫面長相以 `design/prototype/pages/` 為準，頁面怎麼被進入與離開以各模組 `index.mdx` 的 Logic Flow 為準。
本文與程式不一致時，是本文錯了：以程式為準，並回頭改本文。

各節的收合區塊是實作或規劃時才要查的細節，預設收起。

## 誰改、什麼時候改

規劃時先改本文，change 的 `ui-design.md` 只寫本文的路徑與異動摘要，不重抄本文的內容。

| 時機 | 誰 | 做什麼 |
| :--- | :--- | :--- |
| 規劃（寫 `ui-design.md`） | `ui-ux` | 新頁面加進 [§路由](#路由) 與 [§頁面與功能元件](#頁面與功能元件)；動到骨架時改 [§前端骨架](#前端骨架)。`ui-design.md` 的「常駐文件異動」節寫出本文路徑與異動摘要 |
| 規劃審閱 | `design-reviewer` | 核對本文與這次的 `ui-design.md` 一致 |
| 實作後 | `frontend-developer` | 實作出來的路由、頁面元件、規格編號或 Logic Flow 節點和設計不同時，依程式校正本文；動到前端骨架的改 [§前端骨架](#前端骨架) |
| 程式審查 | `code-reviewer` | 再核對一次本文與實作一致；不一致時列為審查意見 |

change 的 `ui-design.md` 仍然寫這次頁面的元件樹、資料來源、畫面狀態與 design token；本文留下的是合併之後全系統的路由與頁面。

## 頁面與功能元件

頁面組合功能元件與 `components/ui/` 的原語；目前送請求的只有功能元件，經生成的 hook。頁面只能經功能的 `index.ts` 使用它。

| 頁面 | 功能元件 | 生成的 hook（operationId） | 文案的 namespace |
| :--- | :--- | :--- | :--- |
| `DevHealthPage` | `HealthStatusPanel`（`features/system-health/`） | `useGetHealth`（`getHealth`） | `systemHealth` |
| `DevGalleryPage` | 無；直接列出 `components/ui/` 的原語 | 無，不送任何請求 | `devGallery` |
| `LoginPage` | `LoginView`（`features/auth/`）：`AuthLayout`（頁首與 `LanguageToggle`）、`AuthCard`、`FormErrorBanner`、`GoogleSignIn`、`LoginForm`（含 `PasswordInput`）；送出與 Google 開始由 `useLoginController` 處理 | `useGetAuthOptions`（`getAuthOptions`）；請求函式 `createSession`、`getGoogleAuthorization`；登入成功後重查 `getCurrentSession` | `auth` |
| `GoogleCallbackPage` | `GoogleCallbackHandler`（`features/auth/`） | 請求函式 `createGoogleSession`；成功後重查 `getCurrentSession` | 無畫面文案 |
| `DashboardPlaceholderPage` | `AuthLayout`、`SignedInCard`（含角色 `Badge` 與 `LogoutButton`）（`features/auth/`） | `getCurrentSession`（與守門共用同一份快取）、`useDeleteCurrentSession`（`deleteCurrentSession`） | `auth` |

:::note{title="健康檢查頁的四種狀態" collapsible}
- `HealthStatusPanel` 用 `toHealthViewState` 把查詢結果轉成四種狀態之一：載入中、正常、後端錯誤（任何錯誤外層）、連不上
- 後端回的 `message`、`code`、`traceId` 與錯誤種類原樣顯示，不再翻譯
- 兩頁都在進入時設定 `document.title`
:::

:::note{title="登入相關頁面的行為" collapsible}
- 登入頁：登入頁設定回來前、或取不到時，Google 按鈕、「或」分隔線與「前往註冊」都不畫，也不顯示橫幅；`googleEnabled` 為假時不畫 Google 按鈕與分隔線，`selfRegistrationEnabled` 為假時不畫「前往註冊」整列
- 錯誤橫幅的文字依 `LoginNotice` 取 `auth` 語言檔的 `login.error.*`，不顯示後端的 `message`；五種：`invalidCredentials`、`googleRejected`、`sessionExpired`、`sessionInvalid`、`unavailable`
- 登入頁開啟時顯示的那一句：導覽狀態帶來的（Google 回調的 E2、沒有回應）優先，其次是守門查詢帶的；讀一次就清掉，同一次造訪重開登入頁不再出現
- Google 回調：網址有 `error`、或缺 `code`、`state` 時不呼叫後端，安靜回登入頁；`ACCOUNT_GOOGLE_FLOW_INVALID` 安靜回登入頁（E1），`ACCOUNT_GOOGLE_REJECTED` 帶 Google 那一句（E2），其他失敗帶「沒有回應」那一句；同一組 `code`、`state` 只送一次，回調網址一律以取代的方式離開歷史紀錄
- 登出：`LogoutButton` 送出期間不再接受按鍵；不論結果都清掉其他查詢快取、把登入狀態記成未登入，由守門帶回登入頁
- 登入頁與落點在進入時設定 `document.title`
:::

## 前端骨架

一條請求由頁面走到後端只有一條路：功能元件 → Orval 生成的 hook → `apiFetch` → `fetch`。分層與允許的 import 由 `frontend/eslint.config.js` 檢查，規則本體見 `docs/development/rules/frontend-agent-rules.mdx` 的 F1。

### 目錄

```text
frontend/
├─ orval.config.ts          唯一的 Orval 設定：讀 ../backend/openapi.json
├─ vite.config.ts           開發伺服器固定 5173 port，不設 proxy
├─ build/extract-tokens.ts  Vite 外掛：從 tokens.css 取出 CSS 變數
└─ src/
   ├─ main.tsx              啟動：檢查 API 設定、決定語言、render
   ├─ app/                  router、providers、QueryClient
   ├─ pages/<page>/         頁面：組合功能元件與原語
   ├─ features/<feature>/   功能元件與它的狀態轉換
   ├─ components/ui/        shadcn/ui 原語，匯出 variant 陣列
   ├─ api/                  mutator.ts（唯一出口）、session-refresh.ts、ApiError、外層判定、config
   │  └─ generated/         Orval 產物，禁止手改
   ├─ lib/                  i18n、date（day.js 唯一入口）、abort、utils
   ├─ styles/               theme.css：shadcn 變數對到 tokens.css 的變數名
   └─ test/                 Vitest setup、MSW server、外層 fixture
```

| 目錄 | 放什麼 | 判斷方式 |
| :--- | :--- | :--- |
| `pages/` | 一條路由一個資料夾 | 被 `router.tsx` 掛上去 |
| `features/` | 一個功能一個資料夾，對外只從 `index.ts` 匯出 | 會送請求，或有自己的狀態轉換 |
| `components/ui/` | 沒有業務的原語 | 換一個頁面也照樣能用 |
| `api/`、`lib/` | 全站共用的基礎建設 | 不 import `pages/`、`features/` |

### 單一 HTTP 邊界

`src/api/mutator.ts` 的 `apiFetch` 是前端唯一的 HTTP 出口，也是 Orval 的 mutator：base URL、cookie、`Accept-Language`、CSRF 標頭、逾時、取消、`401` 之後的延續，以及把每一種失敗轉成 `ApiError`，都只在這裡。理由見 `docs/development/rules/api-agent-rules.mdx` 的 A6。

| 結果 | `apiFetch` 回傳或丟出 |
| :--- | :--- |
| 成功外層 | `{ data, meta }`，`meta` 是外層的 `traceId` 與 `timestamp` |
| `204` | `undefined` |
| 錯誤外層 | `ApiError`，`kind: "http"`，帶 `status`、`code`、`message`、`traceId`；`422` 另帶 `fieldErrors` |
| 回應不是外層 | `ApiError`，`kind: "invalidResponse"`，`traceId` 取自 `X-Correlation-ID` 標頭 |
| 連不上 | `ApiError`，`kind: "network"` |
| 逾時 | `ApiError`，`kind: "timeout"` |
| 呼叫端取消 | `ApiError`，`kind: "aborted"` |

失敗一律不自動重試：`apiFetch` 只在 `401 AUTH_REQUIRED` 時延續登入狀態後重送（見 [§登入狀態與守門](#登入狀態與守門)），其他失敗不重試；`createQueryClient()` 把查詢與寫入的 `retry` 都關掉。元件與 hook 只會看到 `ApiError`，不會看到原生的 `TypeError`、`DOMException` 或 `Response`。

:::note{title="apiFetch 的細節" collapsible}
- `VITE_API_BASE_URL`：空字串代表同源相對路徑；否則必須是結尾沒有 `/` 的絕對 `http(s)` URL。`main.tsx` 啟動時先呼叫 `readApiConfig()`，不合格就不 render
- 每個請求都 `credentials: "include"`，`Accept-Language` 取目前的介面語言；有 body 時設 `Content-Type: application/json`
- `POST`、`PUT`、`PATCH`、`DELETE` 讀得到 `__Host-ls_csrf` cookie 時，把它的值放進 `X-CSRF-Token` 標頭
- `ApiFetchOptions.skipSessionRefresh` 讓請求只送一次、不延續；只有延續請求本身設它
- 預設逾時 15 秒，可用 `ApiFetchOptions.timeoutMs` 逐次覆寫；TanStack Query 傳進來的 signal 與逾時合成一個
- query 參數用 `URLSearchParams` 組，`null` 與 `undefined` 略過，陣列重複同一個 key
- 外層只驗外層本身的欄位，`data` 裡面的形狀交給生成的型別
- 非 `http` 的 `ApiError.message` 是英文診斷字串，不含回應內容或原生錯誤的訊息
- `isAuthError()` 只認錯誤外層的 `401`；`403` 不算
- 語言：`main.tsx` 呼叫 `initI18n()`，讀 `localStorage` 的 `labelsuite.lang`；值不是 `en`、讀不到或沒有時是 `zh-TW`，不看瀏覽器語言，並把 `<html lang>` 設成同一個值。登入頁頁首的 `LanguageToggle` 經 `changeInterfaceLanguage` 切換、記住並更新 `<html lang>`。啟動時預載 `common` 與 `auth` 兩個 namespace，開發用頁面的 namespace 由各自的入口註冊
:::

### 登入狀態與守門

所有守門都讀同一個「目前的登入狀態」查詢；任何請求回 `401 AUTH_REQUIRED` 時，由 `apiFetch` 先延續登入狀態再重送，頁面不必自己處理。只做授權四步的第 1、2 步，角色能看到什麼由後端決定。

| 元件 | 在哪裡 | 做什麼 |
| :--- | :--- | :--- |
| `useSessionState`、`sessionQueryOptions` | `features/auth/session-query.ts` | 以生成的 `getGetCurrentSessionQueryKey()` 為 key 查 `getCurrentSession`，`staleTime` 無限；查詢**不會失敗**：除了取消，每一種拒絕或沒有回應都轉成 `{ kind: "signedOut", notice }`，守門只看資料分支 |
| `RequireAuthRoute`、`PublicOnlyRoute`、`RootRedirect` | `features/auth/route-guards.tsx` | 查詢回來前只畫頁面底色，避免頁面閃一下再跳走；之後以取代歷史紀錄的方式導向登入頁或落點 |
| `sendWithSessionRefresh`、`refreshSession` | `src/api/session-refresh.ts` | 延續是 single-flight：同一時間只有一個 `createSessionRefresh`，其他被拒的請求共用它；整個流程延續至多 2 次、重送至多 2 次 |
| `App`、`AppProviders` | `src/app/app.tsx`、`providers.tsx` | 可選的 `queryClient`（`AppProviders` 的屬性名是 `client`）讓測試換成新的快取；沒給時用整頁共用的那一個 |

:::note{title="延續的步驟與登入頁的句子" collapsible}
- 延續：延續成功就重送一次；延續回 `409 ACCOUNT_REFRESH_CONFLICT`（另一個分頁剛延續過）時等 300 毫秒再重送一次；那次重送仍回 `401 AUTH_REQUIRED` 時再延續一次，成功就再重送一次；其他失敗原樣交給呼叫端。延續請求本身帶 `skipSessionRefresh`，不會再觸發延續
- 守門查詢失敗時登入頁顯示的句子（`noticeForSessionError`）：`ACCOUNT_SESSION_EXPIRED`、`ACCOUNT_SESSION_INVALID` 各對到一句被動登出；`AUTH_REQUIRED` 與用完的 `ACCOUNT_REFRESH_CONFLICT` 不顯示句子；連不上、逾時、回應不是外層或 `5xx` 顯示「沒有回應」那一句
- 登入成功後重查登入狀態，守門自己把頁面帶到落點，一律去落點、不帶回原本要去的頁面
- `403` 不在這裡處理，交給各頁
- Google 登入不用 `302`：授權網址由後端以 JSON 回給前端，前端整頁導覽過去；Google 回到前端的 `/account/google/callback`，再由前端把 `code`、`state` 送給後端
:::

### 生成的 hooks 與 MSW mock

`pnpm --filter frontend api:generate` 讀已提交的 `backend/openapi.json`，把 TanStack Query 的 hooks、型別與 MSW mock 產生到 `src/api/generated/`；每次產生前會先清空這個資料夾，所以裡面不能手改或手加檔案。為什麼用 Orval 見 [ADR-003 的 D6](../../development/adr/003-backend-architecture.mdx#d6-前端-client-用-orval-產生)。

| 檔案 | 內容 | 誰可以 import |
| :--- | :--- | :--- |
| `label-suite.ts` | 每個 operationId 一個請求函式與 hook，例 `getHealth`、`useGetHealth`、`getGetHealthQueryKey` | 功能元件 |
| `label-suite.schemas.ts` | API 文件裡的型別，例 `HealthDataResponse`、`ErrorResponse`、`ErrorDetail` | 任何層 |
| `label-suite.msw.ts` | 每個 operationId 一個 MSW handler，回 faker 產生的資料 | 只有測試 |
| `label-suite.faker.ts` | faker 產生的回應 | 只有測試 |

測試共用一個 MSW server（`src/test/msw-server.ts`），預設掛生成的 handler，只用來證明請求有被攔到；要固定內容的測試用 `server.use()` 疊上 `src/test/envelope-fixtures.ts` 的 fixture。沒被攔到的請求直接讓測試失敗。

:::note{title="漂移檢查與測試替身的邊界" collapsible}
- 漂移檢查的指令見 `openspec/config.yaml` 的 `operations.apply`（前端契約漂移那一條）：重新產生後 `src/api/generated/` 不能有任何差異或新檔
- `msw`、`@faker-js/faker`、`src/test/` 與生成的 `*.msw.ts`、`*.faker.ts` 只有測試檔能 import，ESLint 擋住其他地方，測試替身不會進到正式 bundle
- UI 層（`pages/`、`features/`、`components/`）不能直接用 `fetch` 或 `axios`
:::

### 元件展示頁

`/dev/gallery` 把 `src/components/ui/` 每個原語宣告的 variant、尺寸與狀態各列一次，取代 Storybook；理由見 [ADR-005 的 D3](../../development/adr/005-frontend-architecture.mdx#d3-元件庫用-shadcnui)。

| 組成 | 做什麼 |
| :--- | :--- |
| `variant-catalog.ts` | 每個原語的展示清單；有匯出 variant 陣列的原語用 `satisfies` 綁住，原語加了 variant 這裡不跟著加就型別錯誤 |
| `completeness.test.tsx` | 兩層：清單的 key 等於原語匯出的陣列；畫面上每個宣告的值各有一個 `[data-gallery-item]`，而且 `components/ui/` 的每個原語檔都有一節 |
| `ThemeToggle` | 切換 `<html data-theme>` 的淺色與深色；只存在元件狀態，離開展示頁恢復淺色 |
| `TokenMappingSection` | 列出 `styles/theme.css` 的對照；只有這一頁可以把 `theme.css` 讀成原始文字 |

目前的原語：`alert`、`badge`（含角色變體 `role`）、`button`（含送出中的 `loading`）、`card`、`empty`、`input`、`label`、`separator`、`skeleton`。新增原語時，展示頁要有它的一節，否則完整性測試失敗。

:::note{title="design token 怎麼進到元件" collapsible}
- `build/extract-tokens.ts` 在開發與建置時讀 `design/prototype/assets/tokens.css`，只取 `:root` 與 `html[data-theme="dark"]` 的 `--*` 宣告，以虛擬模組 `virtual:design-tokens.css` 提供，不寫檔
- `main.tsx` 直接 import 它、不放在 `@layer` 裡，所以 `tokens.css` 的值會蓋過 Tailwind 同名的主題變數
- `styles/theme.css` 只寫變數名，把 shadcn 的語意變數指向 `tokens.css` 的變數，沒有任何色值；理由見 [ADR-005 的 D4](../../development/adr/005-frontend-architecture.mdx#d4-design-token-寫一層對照)
:::
