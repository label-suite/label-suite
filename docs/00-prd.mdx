## 3. 使用者角色

角色分兩層：:ref[系統角色]{id="term.系統角色"} 決定平台層級的權限，:ref[任務角色]{id="term.任務角色"} 決定在單一任務內的權限。兩層互相獨立，系統角色不會讓使用者自動取得任何任務角色，以利各任務自行控管參與人員。

| 角色 | 層級 | 可以執行 |
| --- | --- | --- |
| :ref[平台成員]{id="term.平台成員"}（`user`） | 系統角色 | 登入平台，並在被指派任務角色的任務中工作 |
| :ref[系統管理員]{id="term.系統管理員"}（`super_admin`） | 系統角色 | 平台成員的所有權限，加上系統管理（帳號與角色權限） |
| 專案負責人（`project_leader`） | 任務角色 | 無：待任務管理規格補齊 |
| 審核員（`reviewer`） | 任務角色 | 無：待任務管理規格補齊 |
| :ref[標記員]{id="term.標記員"}（`annotator`） | 任務角色 | 無：待標記作業規格補齊 |

## 12. 術語表

### 系統角色

::::define{id="term.系統角色" label="系統角色"}
決定使用者在整個平台可以做什麼的角色，每個帳號恰有一個：`user` 或 `super_admin`。
::::

### 任務角色

::::define{id="term.任務角色" label="任務角色"}
決定使用者在單一任務內可以做什麼的角色：`project_leader`、`reviewer`、`annotator`。在任務內指派，與系統角色無關。
::::

### 平台成員

::::define{id="term.平台成員" label="平台成員"}
系統角色為 `user` 的使用者。
::::

### 系統管理員

::::define{id="term.系統管理員" label="系統管理員"}
系統角色為 `super_admin` 的使用者，可以管理平台帳號與角色權限。
::::

### Seeder 管理員

::::define{id="term.Seeder管理員" label="Seeder 管理員"}
由初始化指令建立的第一位系統管理員，帳號帶有 seeder 標記。
::::

### 標記員

::::define{id="term.標記員" label="標記員"}
任務角色為 `annotator`、負責產出標記結果的使用者。
::::

### 異動紀錄

::::define{id="term.異動紀錄" label="異動紀錄"}
帳號被新增、編輯、停用、啟用、變更系統角色或重發設定密碼信時留下的稽核事件，記錄操作者、目標帳號、時間、操作類型與變更前後的差異。
::::

### 設定密碼信

::::define{id="term.設定密碼信" label="設定密碼信"}
新增帳號或重發時寄給該帳號 Email 的信，內含一次性的設定密碼連結，讓新使用者設定自己的密碼。
::::
