# Proposal

本份是 change `sidebar-nav`（Issue #720，Epic #713 共用介面外殼）的提案，摘要同目錄的 `system-analysis.md`（以下稱 sa）、`system-design.md`（sd）、`ui-design.md`（ui）、`api-contract.md`，不與它們矛盾；範圍取決於待決問題的地方都寫明題號，**本份不替任何一題選邊**，題目集中在 [§待決問題](#待決問題)，由 clarification 一次問完。

## Why

登入後目前只有 #719 的暫時落點，明文「沒有側欄」（`openspec/specs/auth-guard` Requirement「暫時落點顯示目前登入者並提供登出」）；規格 07-01 要求每一個登入後頁面都有同一套側欄，讓使用者知道自己在哪、能去哪，並切換語言與外觀、查看快捷鍵、登出。依產品路線圖（`docs/product/roadmap.mdx` §排序依據 第 2 條），01-01 之後接 07-01，#721、#722、#725 與之後每一個登入後頁面都掛在這層外殼上，所以現在要先做。

## What Changes

- **新增登入後外殼與側欄**（規格 07-01）：包住所有登入後路由的外殼，畫出品牌區、五或六個導覽項、系統管理次選單、底部工具列、使用者晶片與登出、快捷鍵總覽；桌機可收合、手機改為上方品牌列加下方主導覽。畫面以 `design/prototype/pages/shared/sidebar.js`、`sidebar.css` 為準，維護者 2026-11-27 已核可（Issue #720 留言「Ready gate：畫面已核可」）
- **依系統角色顯示導覽項**：平台成員五項，系統管理員（含 Seeder 管理員）多「系統管理」；「系統管理」看不看得到只是顯示，不是授權（sd §權限檢查點）
- **依任務角色的第三個導覽項、角色標示與兩個進入條件**：判斷集中在單一個任務角色來源的接縫（sd §設計結論、ui §非畫面的模組）。目前任務、任務成員的資料與讀取都不存在，本次這個來源固定回答「任何任務都沒有任務角色、沒有目前任務」，**不新增後端讀取**（sd SD-1 的 A）；依任務角色的另外 12 條 Scenario 在本次能不能驗收、移交給誰，取決於 **sa-1、sa-2**（含 SD-1、SD-3、U11）
- **目前位置與角色標示覆寫**由每條登入後路由宣告；系統管理的頁面固定讀作「系統管理員」，本次只建入口（ui §進入、離開與返回）
- **擋下時導向落點並帶一次性說明**（第三個導覽項回儀表板、資料集分析回任務列表）；說明的位置、元件與文案取決於 **sa-9（U2）**，任務列表不存在時的落點取決於 **sa-3（U1）**
- **語言切換**：登入後的語言切換由側欄提供，沿用既有的本機偏好與預設繁中；缺翻譯時顯示繁體中文原文（07-01 §邊界情況）
- **外觀切換**：淺色與深色一鍵切換、記在本機、換頁與重新整理都維持、第一次繪製前就解析（不閃淺色）；「跟隨系統」依作業系統（07-01 Q14）、值無效時的解讀在本次就成立。三選一的完整設定屬 01-04（#727），兩邊讀同一份偏好。登入頁是否跟著深色取決於 **sa-14（U10）**
- **快捷鍵總覽**：桌機以 `?` 或入口開啟、手機沒有；本次列哪幾組、「審核」那組列哪兩個動作取決於 **sa-10（U5）**
- **側欄收合**：桌機點側欄空白處收合、記在本機、手機不啟用；收合有沒有鍵盤路徑取決於 **U6**
- **登出**：側欄的登出控制項與暫時落點的登出共用同一段送出邏輯，沿用 `deleteCurrentSession`
- **角色被改掉時側欄不立刻變**：每次換頁在背景重查登入狀態，視窗重新取得焦點不重查（ui §資料來源，回應 sd SD-4）
- **三個元件搬到共用元件區**（Issue #720 §驗收條件 第 2 項、維護者 2026-11-27 裁定、`frontend-agent-rules` F5）：`features/auth/language-toggle.tsx`、`features/auth/brand-mark.tsx`、`pages/dev-gallery/theme-toggle.tsx` 搬到 `frontend/src/components/`，登入頁與元件展示頁改用共用版本；`password-input.tsx` 不搬（Issue #720 留言「備註（來自 #747）」）。元件規格的「程式實作」欄寫在哪取決於 **sa-12（U4）**；元件展示頁的外觀切換要不要改成同一個元件取決於 **sa-11（U3）**
- **新增對話框原語**（快捷鍵總覽用），元件展示頁加一個區塊（ui §元件樹）
- **不包含**：通知（取決於 **sa-5（U8）**）、工作頁籤的位置（**sa-7**，擬移交 #725）、儀表板行動入口卡不擋（**sa-8**，擬移交 #722）、各導覽項的落點頁本身、外觀三選一的完整設定、標記清單讀取入口標記那一端（sa §範圍「這次不包含」）。收合、登出、螢幕寬度、鍵盤、錯誤與等待提示目前暫列在本次，是否成立見 **sa-6**
- **無 BREAKING 變更**：API、資料庫、`openapi.json` 都不變（`api-contract.md`）。會改變既有 Requirement 行為的只有兩項，且都取決於待決：暫時落點從「沒有側欄」改為掛進外殼（**sa-3／U1**），元件展示頁的外觀切換改為記住選擇、離開不還原（**sa-11／U3**）

## Capabilities

### New Capabilities

- `app-shell-sidebar`：登入後外殼的側欄——導覽項與可見性、目前位置、進入模組的條件與擋下、系統管理次選單、語言切換入口、外觀切換入口、快捷鍵總覽、登出、側欄收合、不同螢幕寬度的呈現與其邊界情況。來源：規格 07-01 §規格、§卡控機制、§邊界情況、§驗收標準
- `appearance-mode`：外觀模式偏好——淺色、深色、跟隨系統三種值的保存、解析、預設與無效值處理，以及第一次繪製前套用。獨立成一個 capability，是因為 01-04 個人設定（#727）會讀寫同一份偏好，不應去改側欄的 spec。來源：規格 07-01 §外觀切換、§資料欄位、Q14；規格 01-04 §偏好設定（只引用存放與三種值，三選一的畫面不在本次）

### Modified Capabilities

一定會有 delta：

- `frontend-i18n`：Requirement「介面文字只取自語言檔」的模組分組要加上側欄的 `appShell`、共用元件的文字從 `auth` 移到 `common`（ui §文案）；Requirement「介面語言預設繁體中文並記住使用者的選擇」寫的切換位置「登入頁或暫時落點的頁首」要改為含側欄；缺翻譯時以繁體中文原文為備用（07-01 §邊界情況「某個名詞缺少目前語言的文字」）
- `component-gallery`：Requirement「展示頁列出每個宣告的項目」列出的區塊要加上對話框原語（`components/ui/` 的每一個原語都要出現在展示頁）

取決於待決問題：

- `auth-guard`：Requirement「暫時落點顯示目前登入者並提供登出」寫明「沿用登入頁的頁首、沒有側欄」。**sa-3／U1** 選「暫時落點掛進外殼」時要出 delta（頁首與卡片裡的登出鈕留不留也在同一題）；選「維持沒有側欄」時不改
- `login-session`：Requirement「從這一台登出」寫「暫時落點的『登出』鈕呼叫它」。**sa-3／U1** 若拿掉暫時落點卡片裡的登出鈕，要改成側欄的登出控制項；保留則不改
- `component-gallery`（第二條）：Requirement「展示頁切換淺色與深色」明文不寫入儲存、離開展示頁還原淺色。**sa-11／U3** 選「展示頁改用同一個共用外觀切換」時要出 delta；選「展示頁保留自己的兩顆鈕」時不改
- `frontend-routing`：Requirement「每頁設定瀏覽器標題」。**sa-3／U1** 選「為不存在的落點註冊建置中暫時頁」時，那些頁要有瀏覽器標題，才要出 delta；其他選項不改

不改：`permission-authorization`、`role-permission-matrix`（側欄只讀，不改授權；與矩陣收窄的關係見 sa-13）、`design-token-mapping`（ui 在對照層新增的兩個語意變數都指向既有 token，屬既有 Requirement 的範圍）、`api-envelope`、`date-time-display`（側欄本次不顯示時間）。

## Impact

- **後端**：無。不新增、不修改端點、模組、資料表、`app/core/` 或 Alembic migration（sd §設計結論、§資料模型異動）；`backend/openapi.json` 應與 `main` 逐位元組相同（`api-contract.md`）。側欄沿用 `getCurrentSession`、`deleteCurrentSession`，`createSessionRefresh` 經既有的 `apiFetch` 延續流程間接呼叫
- **前端**：新增 `src/app/` 的外殼組合層與 `features/app-shell/`（外殼、品牌區、導覽、次選單、工具列、使用者晶片、登出鈕、快捷鍵總覽、導覽模型、收合偏好）；新增 `lib/theme.ts`（外觀偏好）、`components/ui/dialog.tsx`；`features/auth` 抽出共用的登出 hook；三個元件搬到 `components/`；路由加上外殼 layout 與每條登入後路由的導覽宣告；`lib/i18n` 新增 `appShell` 語言檔並改備用語言。詳細檔案以 ui §元件樹 為準
- **依賴**：不新增套件。對話框原語以既有的 `radix-ui` 建，圖示沿用 `lucide-react`
- **常駐文件**：`docs/diagrams/architecture/frontend-routes.mdx`（ui §常駐文件異動；§路由、§頁面與功能元件、§元件展示頁 三節等 U1、U3 裁定後回改）。`backend-modules.mdx`、`error-codes.mdx`、`endpoint-authorization.mdx`、`data-table-dictionary.mdx` 不改
- **設計系統**：`design/system/components/lang-toggle.md` 的「程式實作」、`design/system/pages/shared-app-shell.md`；是否新增品牌標誌與外觀切換的元件規格、重新產生 `screen-inventory.md` 取決於 **sa-12／U4**。不改 `design/prototype/`
- **檢查腳本**：`scripts/check-component-reuse.mjs` 是否要配合調整取決於 **sa-12／U4**
- **後續單**：#722、#730 要接住擋下說明（sa-9）；#773 讀取入口標記 `entry=nav`；#728、#729 用角色標示覆寫入口；#727 讀寫同一份外觀偏好；#725、#722、#740 是否接手移出的驗收標準見 sa-5、sa-7、sa-8；建立任務成員的單（sa 提到 #762 或 #766）是否接手依任務角色的 Scenario 見 sa-1
- **Hard Rule 5（任務設定驅動）**：側欄不依任務類型分支；prototype 點「標記作業」帶 `task_type` 的做法依 07-01 Q6 移除，只帶入口標記 `entry=nav`（ui §Prototype 對照）
- **Hard Rule 6（測試集答案不外露）**：側欄碰到的端點只回登入者自己的四個帳號欄位，沒有任務、資料集、樣本或標準答案；擋下說明是固定文案、不帶任務名或任務 ID（sd §權限檢查點、`api-contract.md` §getCurrentSession §欄位遮蔽）
- **規模**：規格 07-01 §驗收標準 69 條，本次暫列 58 條（sa §規模檢查），其中 23 條的前置條件或落點目前不存在，能不能在本次驗收取決於 sa-1、sa-3、sa-10
