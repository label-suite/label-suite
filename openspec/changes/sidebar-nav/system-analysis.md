# System Analysis

本份是 change `sidebar-nav`（Issue #720，Epic #713 共用介面外殼）的系統分析。它只寫業務面：需求依據、範圍、角色、流程串接、跨模組依賴、矛盾與待決問題。技術設計、介面契約與畫面細節分別交給 `system-design`、`api-contract`、`ui-design`。

## 需求依據

### 現況盤點（先搜尋的結果）

- 登入後只有一頁：#719 的暫時落點（儀表板將來的路徑），沿用登入頁的頁首與卡片，**沒有側欄**；其餘網址一律導回根路徑
- 已有可沿用的能力：登入狀態查詢（帶回名稱、Email、系統角色）、從這一台登出、繁中與英文切換並記在本機、系統角色每次從伺服器讀
- 已有、但不是本次要的樣子：外觀切換只存在元件展示頁，不記住選擇、離開就還原淺色；語言切換與品牌標誌放在帳號 feature 裡
- **沒有**：任務、任務成員與任務角色的任何資料或讀取能力（伺服器端只有帳號、系統管理、健康檢查三個模組；授權的任務成員讀取介面已定義但沒有模組實作）；通知的任何資料；側欄要導去的儀表板（正式版）、任務列表、任務詳情、標記清單、分析列表、使用者管理、角色設定、個人設定八頁
- 設計系統：App Shell 規格「程式實作：尚未實作」；語言切換有元件規格；**外觀切換與品牌標誌沒有自己的元件規格**；畫面清冊「元件 → 畫面」表的語言切換只列帳號頁與元件展示頁，沒有列 `shared/app-shell`
- 進行中的其他 change：無，只有本 change

## 需求矛盾

1. **暫時落點「沒有側欄」與 07-01「每一頁都有側欄」**：既有 capability `auth-guard` 的 Requirement「暫時落點顯示目前登入者並提供登出」寫「頁面沒有側欄」，來源是 #719 的維護者決議 Q5（2026-11-26，`openspec/changes/archive/2026-11-26-login-auth-guard/clarification.md` Q5）；規格 07-01 §導覽項目與可見性 第 1 條寫「使用者進入任何登入後的頁面 → 側欄依序顯示……」。暫時落點是目前唯一的登入後頁面，兩者不能同時成立。#719 的決議是在側欄不存在時做的，沒有說側欄做好之後怎麼辦。→ 待決 3
2. **元件展示頁的外觀切換「不記住、離開還原淺色」與 07-01「換頁或重新整理都維持」**：`component-gallery` Requirement「展示頁切換淺色與深色」（來源 ADR-005 D4、該 change 的 clarification Q13）與 07-01 §外觀切換 第 3 條。展示頁是開發頁，不是產品畫面，但兩者共用同一個外觀屬性；離開展示頁就還原淺色，會蓋掉使用者在側欄選的深色。→ 待決 11
3. **快捷鍵總覽「目前頁面可用的」與固定的三組清單**：07-01 §快捷鍵總覽 第 2 條寫「顯示**目前頁面可用的**快捷鍵清單」，同一節的註與 Scenario 48–50 卻要求清單裡有「標記作業」「審核」「頁籤」三組，且 Scenario 的 Given 沒有限定頁面；在儀表板上，標記與審核的快捷鍵並不可用。→ 待決 10
4. **Issue #720 本文與留言對要搬的元件**：本文驗收條件列三個（語言切換、品牌標誌、外觀切換），留言（來自 #747）只討論語言切換與外觀切換。兩者沒有互相否定，依 F5 品牌標誌同樣被登入頁與側欄兩個 feature 用到；但品牌標誌與外觀切換**都沒有自己的元件規格**，Issue 要求的「更新元件規格的程式實作欄」沒有地方可寫。→ 待決 12

其餘來源之間沒有發現矛盾：07-01、PRD §權限矩陣、資料欄位盤點、01-04 對語言與外觀的擁有者、存放位置與預設值說法一致。
