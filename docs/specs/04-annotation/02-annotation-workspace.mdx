## 目標

| 目標 | 誰受益 |
| :--- | :--- |
| 讓:ref[標記員]{id="term.annotator"}一次只面對一筆資料，題目、作答控制項與任務說明**同時在畫面上**，不必在頁面之間來回 | 標記員——減少翻頁造成的標記偏差 |
| 讓任務說明**翻筆之後還在**，而且在手機上也拿得到 | 標記員與:ref[審核員]{id="term.reviewer"}——說明一消失，標準就會各憑記憶 |
| 讓工作區**完全由任務發布時凍結的設定驅動**，不替任何任務寫死特例 | 專案負責人——改設定就能改作業方式，不必等系統改版 |
| 讓網址**一直指著畫面上的那一筆**，重新整理、加書籤、貼給別人都回到同一個地方 | 需要互相對照同一筆資料的人 |
| 讓標記員在這一頁接觸不到:ref[標準答案]{id="term.ground-truth"}，**連樣本的識別鍵都不顯示** | 整個標記品質管線——答案一旦外洩，這個任務的資料就不能用了 |

## 使用角色

| 角色 | 這一頁能做什麼 | PRD §權限矩陣的上限 |
| :--- | :--- | :--- |
| :ref[標記員]{id="term.annotator"} | R／C／E，**只限被指派給自己的資料** | 「04 標記清單與標記工作區（產出標記）」給標記員 `R/C/E (o)` |
| :ref[審核員]{id="term.reviewer"} | R／E | 「04 標記清單與標記工作區（審核與仲裁）」給審核員 `R/E` |
| :ref[專案負責人]{id="term.project-leader"} | 只處理:ref[審核員]{id="term.reviewer"}收不掉的例外（階段五），**不產出標記** | 同一列給專案負責人 `R` |

- 工作區的作用角色只有標記員與審核員兩種；專案負責人進得來的是**最終例外池的處置畫面**，它共用這一頁的外殼但不是標記畫面（麵包屑第 1 層因此有第三種字面，見[§入口麵包屑的第三層](#入口麵包屑的第三層)）
- 專案負責人在這一頁的處置動作由階段五撰寫；本階段只寫到外殼層面會看到的差別
- **這裡有一處超出 PRD 的上限，本頁不默默放寬**：PRD §權限矩陣「04 標記清單與標記工作區（審核與仲裁）」那一列給專案負責人的上限是 `R`，而最終例外池的收尾（採標記員值／採審核員值／填自訂答案／排除這筆）是**寫入動作**。PRD 另有一句「專案負責人在標記工作區只處理審核員無法收斂的例外，不產出標記」，說的是**範圍**不是權限字母。本頁依[規格 07-01](../07-shared/01-sidebar.mdx)的做法明寫這個落差，**不把那一列改成 `R/E`**；PRD 的改動由 Issue #85 處理。階段五寫處置動作時要再引一次這一條
- 這個落差與[規格 04-01 §待釐清](./01-annotation-list.mdx#待釐清) Q1 是同一個缺口的兩半：那一題問的是專案負責人進不進得了標記清單，這一條管的是他進到工作區之後做的事超不超出上限
- :ref[系統管理員]{id="term.system-admin"}沒有任務角色時進不來，和[規格 04-01](./01-annotation-list.mdx)一樣

### 進入工作區並開始作業

1. 使用者從儀表板的快速入口、[標記清單](./01-annotation-list.mdx)的某一列，或**直接貼一個深連結**進來
2. 系統解析網址帶來的任務、那一筆、角色與標記階段
3. 查任務**發布時凍結**的設定，查得到嗎？
   - 查得到 → 載入那一筆樣本、說明檔案與進度，三欄就位
   - 查不到 → 導回標記清單，**不得以任何預設的輸出類型或空白控制項呈現工作區**，流程結束
4. 這個任務要求先讀說明嗎？
   - 要求，而且目前這個:ref[指引版本]{id="term.guideline-version"}還沒被確認過 → 顯示說明彈窗，使用者按確認才開始
   - 不要求 → 直接開始（替代流程 A1）
5. 使用者在中欄作業，必要時翻到上一筆或下一筆；每次翻筆都把網址改寫成畫面上的那一筆
6. 替代流程 A1：任務沒要求先讀說明 → 跳過第 4 步的彈窗，右欄的說明仍然常駐
7. 替代流程 A2：使用者在手機上 → 說明改由底部抽屜承載，翻筆時抽屜維持原本的開合狀態
8. 例外流程 E2：網址沒帶那一筆 → 導回標記清單，流程結束
9. 例外流程 E3：網址帶的那一筆查不到 → **回退到第一筆**，並把網址改寫成實際顯示的那一筆，回到第 5 步

## 規格

本階段寫的是**外殼**：版面、挑筆、翻筆、說明與檔案、進場的說明確認、網址同步與快捷鍵。中欄裡面**實際怎麼作答**（八種輸出類型）由階段二寫，**審核卡**由階段四寫。

### 工作區的外殼：三欄與行動版

<PrototypeFrame page="annotation/annotation-workspace" caption="標記工作區" client:idle />

1. 工作區是**單筆作業頁**：一次只處理一筆，整頁**沒有頁首**，最上面只有一條[入口麵包屑](#入口麵包屑的第三層)
2. 桌機固定三欄：

| 欄 | 承載什麼 |
| :--- | :--- |
| 左欄 | [標記清單](#左欄標記清單)與目前定位 |
| 中欄 | 上方[樣本導覽與進度](#中欄上方樣本導覽與進度)、主體[題目卡與標記卡](#中欄主體題目卡與標記卡)、下方[操作列](#中欄下方操作列) |
| 右欄 | [說明與檔案、操作紀錄](#右欄說明與檔案操作紀錄)雙頁籤 |

3. 右欄在桌機**可以收合，收合後可以再展開**
4. 手機（寬度 767 以下）只留精簡的目標列與主操作區，說明與檔案改放**底部抽屜、預設收合**
5. 手機必須**主操作優先**：抽屜是輔助資訊，**不得遮蔽核心的標記區**
6. 抽屜**只承載說明與檔案**；「操作紀錄」頁籤是桌機右欄才有的（見 [§已確認決議](#已確認決議) Q6）
7. 翻到下一筆時：桌機右欄**不收起、內容不重置**；手機抽屜**維持目前的開合狀態**
8. 中欄**不得出現任務標題卡**——任務名稱的標頭與卡內的語言切換鈕都不行，標記員與審核員都一樣
9. 任務名稱**只由右欄「任務說明」的摘要呈現**，而且要優先用這個任務實際的名稱，只有在缺任務上下文時才退回輸出類型層級的預設文案
10. 語言切換由側欄提供，和其他頁面一致（見[規格 07-01](../07-shared/01-sidebar.mdx)）
11. 要驗的螢幕寬度是 375、768、1440 三種
12. 來源要求的「固定任務目標列」在畫面上只有一部分落地，**任務目標與操作指引沒有落點**，見 [§待釐清](#待釐清) Q1

#### 這一頁讀得到什麼、不得改什麼

1. 工作區讀的是任務**發布時凍結**的那一份設定：輸出類型與它們的順序、欄位各自的用途（舉證、題目輸入、作答產出）、配對任務的兩邊標題、說明檔案清單
2. 樣本來源**鎖定在發布時凍結的那一份資料快照**，工作區**不得自己重算或覆寫切分**——:ref[試標]{id="term.dry-run"}與:ref[正式標記]{id="term.official-run"}都一樣
3. 說明檔案來自**當前回合釘住的那個:ref[指引版本]{id="term.guideline-version"}**；之後把說明另存新版，**不會改到已經開始的回合**
4. 工作區**不得為個別任務寫死邏輯**：有幾個輸出類型、是哪幾種、什麼順序，一律照設定來
5. 資料敏感度：這一頁讀得到的樣本內容是**任務資料**，可能含個資，只有被指派的人進得來；:ref[標準答案]{id="term.ground-truth"}**不屬於標記員讀得到的範圍**（階段二會把這條寫成卡控）
6. 設定本身在這一頁是**唯讀**的——要改設定得回[規格 03-03 任務詳情](../03-task-management/03-task-detail.mdx)

### 入口麵包屑的第三層

<PrototypeFrame page="annotation/annotation-workspace" caption="標記工作區" client:idle />

麵包屑的前兩層與「深連結和站內點進來要長得一樣」這條總規則寫在[規格 04-01 §入口麵包屑](./01-annotation-list.mdx#入口麵包屑)；工作區**多出第 3 層**，而且第 1 層在這一頁有第三種字面。

1. 工作區的麵包屑**有三層**，第 3 層就是目前層級：

| 層級 | 顯示 | 連到哪 |
| :--- | :--- | :--- |
| 第 1 層 作業區 | 審核員「審核作業」、標記員「標記作業」、專案負責人處理例外時「例外處置」 | **儀表板** |
| 第 2 層 任務 | 「〈任務名稱〉（〈標記階段〉）」 | 標記清單，**回帶任務、角色與標記階段** |
| 第 3 層 目前單位 | 依角色不同，見第 2 條 | **不帶連結，它就是目前層級** |

2. 第 3 層依角色分流，這是**資料公平性的硬性規則**：

| 角色 | 第 3 層顯示 |
| :--- | :--- |
| 審核員 | `審核單位 {sample} · {annotator}`——那一筆的識別碼與**受審標記員的帳號** |
| 標記員 | **只顯示佇列位置** `樣本 {i} / {n}`，**不得顯示那一筆的識別碼，也不顯示自己的帳號** |
| 專案負責人（例外處置） | `例外項目 {sample} · {annotator}` |

3. 標記員那一層**不得顯示識別碼**的理由寫在來源裡：有些資料集拿**沒有被指派用途的欄位**當記錄識別鍵，把它渲染進標記員看得到的地方就等於洩漏答案線索；標記員自己的帳號對標記員而言是零資訊，也不重複顯示（見 [§已確認決議](#已確認決議) Q7）
4. 麵包屑要**跟著換筆與換語言一起重畫**，不能只在進場時畫一次
5. 第 2 層一定要**回帶身分參數**：帶著標記員身分進來的，返回清單的網址也要帶同一個身分；**沒帶身分進來的就不得補上**（否則「缺值套用預設」這件事在兩頁之間就不再是共識）
6. 身分參數要和清單的四個檢視狀態**併存**，不能只轉發一種（見 [規格 04-01 §清單檢視狀態往返工作區](./01-annotation-list.mdx#清單檢視狀態往返工作區)）
7. 麵包屑在窄螢幕**不會被隱藏**，但標記員帳號在它的尾端，需要橫向捲動才看得到——窄螢幕下審核單位的身分就由這一層承載

### 左欄：標記清單

<PrototypeFrame page="annotation/annotation-workspace" caption="標記工作區" client:idle />

1. 左欄的標題**固定是「標記清單」**，**不得附加回合標籤**——不能變成「試標回合 R2」「正式標記清單」之類的字面
2. 回合是靠[麵包屑第 2 層](#入口麵包屑的第三層)講的，位置在三欄主體之上，兩者不衝突
3. 標題旁的**筆數仍然要按當前回合的清單規模顯示**：試標顯示這一回合建立的筆數，正式標記顯示正式清單的筆數
4. 當前標記階段**還沒有已建立的清單筆數**時，筆數**回退顯示該任務資料集的筆數**
5. 審核員的筆數單位是**審核單位**而不是樣本（同一筆由 N 位標記員標記就是 N 個單位），算法見階段六
6. 每一列的組成：**序號徽章 + 文本摘要（必要時加摘要標籤）+ 完成狀態標籤**
7. 文本摘要和[標記清單](./01-annotation-list.mdx)用**同一套算法**，不另立一套：見 [規格 04-01 §文本摘要怎麼來](./01-annotation-list.mdx#文本摘要怎麼來)
8. **摘要標籤只有工作區左欄會顯示**，標記清單那一頁沿用前綴、不顯示標籤。摘要取自對話串形態時，摘要**旁邊**要加標籤：

| 條件 | 標籤 |
| :--- | :--- |
| 任務設定指定了對話串欄位，而且摘要就是取自對話串形態 | 「〈則數〉 則發言」（則數就是那一串的筆數） |
| 再加上任務設定指定了發言者子欄位，而且不重複的非空發言者數至少 1 位 | 再加「〈人數〉 位發言者」 |

9. 標籤要出現在**工作區左欄的三個地方**：標記員的每一列、審核員的分組表頭、例外處置的分組表頭
10. 標籤**不得依任務編號或欄位名稱寫死**、**不得讀用途是輸出的欄位**，也**不得從實體、關係或文字裡的 `@名字` 去猜**——和前綴同一套限制
11. 搜尋比對的字串**不含前綴也不含標籤**（搜尋本身在[標記清單](./01-annotation-list.mdx)那一頁）
12. 標記員視角的完成狀態標籤是**三態**，而且儲存草稿或提交之後要**即時更新**那一列：

| 標籤 | 什麼時候 |
| :--- | :--- |
| 已提交 | 這一筆已經提交 |
| 已儲存 | 存了草稿、還沒提交 |
| 待標記 | 還沒動過 |

13. 目前在看的那一列要**高亮**，而且必須是網址帶進來的那一筆，**不得固定落在預設的第一筆**
14. 點某一列就切到那一筆
15. 審核員視角的一列是**一個審核單位**、狀態標籤換成審核單位的三態，而且同一筆的多個單位要包在該筆的分組容器裡——這一段連同分組表頭承載什麼，由**階段五**撰寫
16. 專案負責人的例外處置清單列的是**待處置的例外項**，不是一般樣本，由**階段五**撰寫

### 中欄上方：樣本導覽與進度

<PrototypeFrame page="annotation/annotation-workspace" caption="標記工作區" client:idle />

1. 中欄頂部是導覽列：**「上一筆」按鈕 + 進度摘要（含進度條）+「下一筆」按鈕**
2. 位在**首筆或末筆**時，對應的那個按鈕**停用**
3. 進度摘要依角色分流：

| 角色 | 文字 |
| :--- | :--- |
| 標記員 | `{已提交} / {總筆數} 已提交` |
| 審核員 | `我的審核提交 {已提交} / {總筆數} 個審核單位`——分子是自己已送出審核的單位數，分母是審核單位總數 |

4. 提交之後進度要**即時更新**，不必重新整理
5. 審核員的「筆」是**審核單位**，所以導覽與分母都按審核單位算（算法見階段六）；標記員的「筆」就是樣本
6. 翻筆時右欄的說明**不收起、不重置**（見[§工作區的外殼](#工作區的外殼三欄與行動版)第 7 條）

### 中欄主體：題目卡與標記卡

<PrototypeFrame page="annotation/annotation-workspace" caption="標記工作區" client:idle />

這一段只寫**卡片怎麼切**；卡片裡面實際的作答控制項由**階段二**撰寫。

1. 題目內容與標記控制項**以獨立卡片區隔**：題目卡承載舉證內容與題目輸入，標記卡承載**依設定順序逐一排出**的各個輸出類型
2. 卡片怎麼切，**依欄位用途與輸出類型的結構決定**，**不得依任務名稱或個別輸出類型寫死分支**
3. 輸出類型自己就把原文內嵌在標記區裡時（例如要在文本上圈選的那幾種），**題目卡可以省略**
4. **卡片邊框是題目／標記區塊的唯一外框**：
   - 題目卡裡的輸入內容**直接呈現，不得再包一層內框**
   - 標記卡裡**不得殘留水平分隔線**，包含區塊分隔線與「無法判定」選項上方的虛線（那個選項在畫面上的字面是「無法判定 (Bypass)」，它本身由階段二撰寫）
   - 兩種輸出類型合併成整合標記模式時，整合預覽區塊**不得在卡片裡再包一層外框**
5. **「無法判定」選項自己的虛線外框是刻意設計，要保留**
6. 這條規則**一體適用所有輸出類型**，不得逐類型寫死

### 中欄下方：操作列

<PrototypeFrame page="annotation/annotation-workspace" caption="標記工作區" client:idle />

1. 中欄底部是操作列：**左側是自動儲存狀態指示，右側是「儲存草稿」與提交按鈕**
2. 自動儲存的三態文字與它們**什麼時候才會變**，由**階段三**撰寫——那一條的重點是「指示必須誠實」，所以放在提交與草稿那一段一起寫
3. 提交按鈕**靠右對齊是兩種角色共同的契約**：審核員視角的自動儲存指示會隱藏，但送出按鈕**不得因為左側元素消失就掉到左邊**
4. 審核員視角**不提供「儲存草稿」**（按鈕隱藏，而且沒有綁行為）
5. 這個操作列是**唯一的提交位置**：審核員的「送出審核」、仲裁的「送出仲裁」都固定在這裡、**不隨中欄內容捲動**，卡片裡**不得再放一顆送出按鈕**；它們互斥顯示的規則由階段四、五撰寫

### 右欄：說明與檔案、操作紀錄

<PrototypeFrame page="annotation/annotation-workspace" caption="標記工作區" client:idle />

1. 桌機右欄是**兩個頁籤**，標記員與審核員看到的一樣，**預設停在第一個**：

| 頁籤 | 承載什麼 |
| :--- | :--- |
| 說明與檔案 | 「任務說明」摘要 + 說明檔案清單 |
| 操作紀錄 | 目前這一筆的操作時序，標記員與審核員的事件合併後依時間排 |

2. 第二個頁籤的名稱在來源與畫面不一致（來源寫「歷程」、畫面是「操作紀錄」），見 [§待釐清](#待釐清) Q2
3. 「操作紀錄」裡面放什麼、誰看得到哪些、耗時與理由怎麼呈現，由**階段五**撰寫（清單側已寫在 [規格 04-01 §處理狀況](./01-annotation-list.mdx#處理狀況)）
4. **說明與檔案是這個模組強制常駐的資訊**，不能只在進場的彈窗裡出現一次
5. 「任務說明」的標題**帶一個提示圖示**
6. 檔案清單每一列要顯示**對應檔案類型的小圖示**，並在檔名右側顯示**動作提示文字「預覽」**
7. 圖示與動作提示**由檔案類型驅動，不得依任務別寫死**；動作提示要**跟著語言切換即時更新**
8. 說明檔案的連結失效時，**不影響標記主流程**，但要顯示一則可追蹤的錯誤訊息

### 說明檔案的三種預覽

<PrototypeFrame page="annotation/annotation-workspace" caption="標記工作區" client:idle />

1. 說明檔案至少支援三種類型的**頁面內預覽彈窗**，標記員與審核員共用同一套面板與行為：

| 類型 | 點下去會怎樣 |
| :--- | :--- |
| 圖片 | 置中彈窗顯示**大圖**；**不得只用右欄底部的小圖預覽頂替** |
| PDF | 置中彈窗**在頁面內嵌入顯示**；**不得開新分頁** |
| Markdown | 置中彈窗顯示**排版後的內容**；**不得用面板底部的純文字區塊頂替** |

2. 三種彈窗都要能關掉，而且**三條關閉路徑都要有**：關閉按鈕、點背景遮罩、按 `Esc`
3. 三種彈窗都要**管好鍵盤焦點**：開啟時焦點移進彈窗、`Tab` 侷限在彈窗內、關閉後焦點**還給觸發它的那個元素**
4. PDF 與 Markdown 彈窗的**標題顯示檔案名稱**
5. Markdown 的排版至少要支援：標題、段落、有序與無序清單、粗體、斜體、行內程式碼、連結、程式碼區塊、表格與圖片
6. 安全規則（使用者看得到的結果）：
   - 說明檔案裡夾帶的網頁標記**一律當文字顯示**，不照它排版；程式碼區塊裡的內容也只當文字
   - 連結與圖片的位址**只接受一般網址、信件位址、站內相對位置與同頁錨點**，其他一律降級成純文字
   - 連結**一律開新分頁**，避免把人帶離工作區
7. 排版後的每個標題都要**帶一個由標題文字推導出來的錨點**，而且：
   - 同一份沒改過的說明，**每次排版都要得到同一組錨點**
   - 同一份說明裡**兩個文字相同的標題，要得到互不相同的錨點**
   - 錨點**不得只靠標題的出現順序決定**
8. 第 7 條不是排版細節：**審核員在修正理由裡引用某個說明段落**時，引用就是跳到這個錨點，而**點它的人是標記員**——他在試標歷史回饋裡讀那則理由（清單側見 [規格 04-01 §試標歷史回饋](./01-annotation-list.mdx#試標歷史回饋)；審核員怎麼寫引用由階段四撰寫）。錨點的順序一變，舊的引用就會指錯地方
9. 進場的說明彈窗**用同一個排版器**，不另外維護一份

### 指引閘門：第一次進來先讀說明

<PrototypeFrame page="annotation/annotation-workspace" caption="標記工作區" client:idle />

1. 任務設定可以要求**先讀說明才開始標記**（開關在[規格 03-03 任務詳情](../03-task-management/03-task-detail.mdx)）
2. **這個開關沒開，彈窗在任何情況下都不得出現**，也不受下面的確認紀錄影響（**依建議撰寫、待維護者確認**，見 [§待釐清](#待釐清) Q4）
3. 開關開著時，進場顯示說明彈窗，使用者按確認按鈕才開始；確認後**同一台裝置對同一個任務的後續進入（含重新整理）不得再顯示**（同 Q4）
4. 彈窗的內容**和右欄「說明與檔案」同一個來源**，取其中 Markdown 類型的全文顯示；沒有 Markdown 類型時**退回顯示檔名清單**——**不得為彈窗另外維護第二份說明文字**
5. 彈窗與右欄**必須是同一個:ref[指引版本]{id="term.guideline-version"}**
6. 確認紀錄**以任務為鍵各自獨立**：確認了 A 任務**不得抑制** B 任務的彈窗；換任務就要**從頭重新判定**
7. 確認紀錄還要**比對當前回合釘住的指引版本**：
   - 已經確認過**這個版本**的不再顯示
   - 第一次遇到**另一個版本**而且開關開著時，**必須重新確認**
   - 之後把說明另存新版，**不得改寫舊回合的指引，也不得讓舊版本的確認失效**
   - 歷史回合的版本**不得從任務的當前版本、最後一個試標回合或相同的回合顯示號去猜**
8. 確認紀錄要綁在**帳號**還是**裝置**上，來源明寫留待後端接上時定義，見 [§待釐清](#待釐清) Q3
9. 來源另有**三處**未被註銷的規則說「每次進入都顯示一次」，與第 2、3 條相矛盾，而來源沒有裁決句，見 [§待釐清](#待釐清) Q4

### 網址一直指向目前這一筆

<PrototypeFrame page="annotation/annotation-workspace" caption="標記工作區" client:idle />

1. 網址必須**持續指著畫面上正在看的那一筆**：每次換筆或換受審標記員，都要把它寫回網址
2. 這樣的話，**重新整理、加書籤、把連結貼給別人，都會回到畫面上的那一筆**，而不是回到最初進來的那一筆
3. 同步的範圍：

| 參數 | 誰要同步 |
| :--- | :--- |
| 那一筆的識別碼 | **所有角色** |
| 受審標記員 | **只有審核員視角**（它是審核單位的另一半） |

4. 標記員視角翻筆時身分不會變，所以**不得在網址裡新增它原本沒有的參數**
5. 改寫要**原地取代**，**不得每翻一筆就在瀏覽器的上一頁堆一筆**——否則走過 N 筆之後要按 N 次上一頁才離得開工作區
6. 改寫必須**就地更新既有的網址參數**，**不得照已知的鍵重建一份**——重建會把這一頁不讀的參數**靜默丟掉**
7. 網址帶的那一筆**查不到而回退到第一筆**時，網址也要改寫成**實際顯示的那一筆**，讓重新整理的結果穩定不漂移

### 鍵盤快捷鍵

<PrototypeFrame page="annotation/annotation-workspace" caption="標記工作區" client:idle />

1. 側欄快捷鍵總覽（見[規格 07-01](../07-shared/01-sidebar.mdx)）在「工作區」分類列出的四個快捷鍵**必須全部真的可用**，不能只是文案：

| 快捷鍵 | 做什麼 |
| :--- | :--- |
| `Ctrl/Cmd + S` | 儲存草稿 |
| `Ctrl/Cmd + Enter` | 提交目前這一筆 |
| `Alt + ←` | 上一筆 |
| `Alt + →` | 下一筆 |

2. 每個快捷鍵都要**走它對應的那顆按鈕本身的行為**，不得另開一條繞過按鈕既有條件的路：
   - 按鈕**隱藏或停用時，快捷鍵就無作用**——首筆按 `Alt + ←` 不得回捲到末筆，審核員按 `Ctrl/Cmd + S` 不得寫入草稿
   - 理由是按鈕上已經帶著角色配置與首末筆的停用狀態，另推一次就會出現**第二份會漂移的事實來源**
3. `Ctrl/Cmd + Enter` **依角色分流**：標記員觸發「提交」、審核員觸發「送出審核」，兩者都要**照各自既有的完整性驗證走**，不得繞過
4. 這四個都是**修飾鍵組合、不產生文字**，所以**焦點在輸入框裡時照常生效**——最需要「儲存草稿」的時機正是在長文作答途中
5. 必須**攔住瀏覽器的預設行為**（`Ctrl/Cmd + S` 會開「儲存網頁」、`Alt + ←` 在瀏覽器是上一頁），而且**要在判斷按鈕可不可用之前就攔**，否則隱藏或停用的目標會漏出瀏覽器的預設動作
6. 審核卡還有不帶修飾鍵的單鍵快捷鍵，和這四個的規則不同，由**階段四**撰寫

### 進不來的時候：導回清單

<PrototypeFrame page="annotation/annotation-workspace" caption="標記工作區" client:idle />

1. 網址**查不到已發布的任務設定**時，**導回[標記清單](./01-annotation-list.mdx)**，並且**不得以任何預設的輸出類型或空白控制項呈現工作區**
2. 清單那一側對應的規則寫在 [規格 04-01 §路由上下文與回退](./01-annotation-list.mdx#路由上下文與回退)；這一條是**工作區這一側**的導回
3. 網址**沒帶那一筆**時，**不得載入作業區**，一樣導回標記清單
4. 角色與標記階段的缺值回退和清單一致（角色回退成標記員、標記階段回退成試標）
5. 任務設定讀到了、但**輸出類型是空的或缺必要內容**時：顯示任務設定錯誤並**阻擋提交**，**不得用任一輸出類型的預設控制項頂替**
6. 這一頁**沒有從本機記憶體還原上下文**這條路——上下文只從網址來
7. 導回時要**保留同一個任務的上下文**

### 作答區塊由任務設定驅動

<PrototypeFrame page="annotation/annotation-workspace" caption="標記工作區" client:idle />

1. 中欄的標記區塊**完全由任務發布時凍結的那份輸出類型清單驅動**：依**清單的順序**逐一排出各輸出類型的標記區塊
2. **不得為特定輸出類型、特定組合或任務名稱寫死專屬分支**——任何合法的輸出類型組合都要能一致運作
3. 每個輸出類型**各自獨立成一個標記區塊**；任一區塊的互動**只更新該區塊**，不影響其他輸出類型的既有作答
4. 切換或儲存某一個輸出類型，**不得清除或覆寫**其他輸出類型的既有作答
5. 有幾種輸出類型就有幾個區塊，一到多個都適用；三個以上也必須都能在**同一筆的同一個畫面**內完成
6. 審核員那一側的「每種輸出類型怎麼呈現審查結果」與「逐列的直接修正入口」由**階段四**撰寫

### 題目怎麼呈現：單筆、配對與背景參考

<PrototypeFrame page="annotation/annotation-workspace" caption="標記工作區" client:idle />

1. 單筆任務只顯示**單一「原始文本」區塊**，**不得顯示雙欄配對版面**
2. 配對任務以**雙欄**呈現兩個項目，區塊小標取任務設定的**項目對名稱**；缺值時回退顯示對應輸入欄位的原始名稱
3. 項目對名稱**只影響顯示文案**，不改變欄位的用途，也不改變資料本身
4. 「**背景參考 (Evidence)**」有兩條呈現路徑，**同一筆不得同時出現兩張**：

| 情況 | 背景參考放哪 |
| :--- | :--- |
| 這個輸出類型自己就會在它的專屬預覽裡嵌入背景參考（目前只有自由文本） | 由它自己依「背景參考 → 題目內容 → 作答框」的順序呈現 |
| 其餘七種輸出類型 | 由**通用的背景參考卡**統一呈現在**題目卡最上方**，位置早於題目內容卡與所有作答控制項 |

5. 沒有指定背景參考欄位時，**不得顯示空的背景區塊**
6. 背景參考卡**只供閱讀**：不得包含任何可編輯的輸入或選取控制項
7. 當有多個輸出類型自己就把原文內嵌在它的預覽裡時（例如序列標記、實體辨識、關係識別、自由文本），**通用的輸入文字區塊不得重複顯示**，輸入內容改由那個輸出類型的專屬或整合預覽完整呈現
8. 工作區**不得為特定輸出類型另外寫死顯示順序的例外**

### 八種輸出類型的作答控制項

<PrototypeFrame page="annotation/annotation-workspace" caption="標記工作區" client:idle />

每一種的控制項都由該輸出類型的設定動態決定。下面逐一寫規則；**畫面上的四個區塊標題目前是英文**，見 [§待釐清](#待釐清) Q9。

#### 單選標籤

1. 以**互斥的單選標籤鈕**呈現設定裡的選項
2. 記下**選了哪一個**

#### 多選階層標籤

1. 以**可搜尋的階層多選器**呈現選項，分支節點與葉節點都可以勾
2. 已選的標籤鈕**只顯示節點名稱**（不顯示整條路徑）
3. 選取之後**選擇器保持開啟**，直到使用者明確關閉
4. 選擇器展開時**必須是該區塊的最上層不透明覆蓋層**，**完整遮蓋它後方的內容（包含「無法判定」勾選項）**，**不得有任何後方元素穿透顯示在選擇器之上**
5. 被遮蓋的控制項要**先關閉選擇器才能操作**；關閉途徑有四種：關閉鈕、`Esc`、再次點觸發器、點選擇器範圍外任意處
6. 設定了選取數上限（非 0）而超過時：**阻擋新增選取並提示上限**
7. 上限提示的文字要**沿用工作區既有欄位提示的字級與顏色**，**不得用瀏覽器預設樣式**呈現
8. 記下的是**從根到被選節點的完整路徑**，不是只有節點名稱

#### 單一維度評分

1. 以**單一可拖曳滑桿**呈現，右側另有數字輸入框顯示相同的值
2. 滑桿、當前值標籤與數字輸入框**三者雙向同步**（調整後 **100 毫秒內**同步完成），而且在**任何時刻顯示同一個數值**
3. 當前值標籤**即時跟隨滑塊顯示在它正上方**
4. 當前值標籤**不得用佔位符號取代數字**——**唯一例外**是勾了「無法判定」，此時顯示未評分的佔位符號
5. 還沒作答、也沒有預填時，滑桿與當前值標籤**可以停在範圍中點當起始位置**，但那個起始值**不計為已作答、不得當成有效值提交**
6. 數字輸入框**可以直接鍵入範圍內的非級距小數，而且不得被吸附**到級距上；**超出範圍時自動校正**回範圍內
7. 預填或匯入進來的值不落在設定的範圍與級距時，顯示驗證錯誤並阻擋提交
8. 記下**那個數值**

#### 多維度評分

1. 設定裡的**每一個維度各自**有獨立的滑桿與數字輸入框
2. 調整任一維度**只更新該維度**
3. 依維度順序配**不同的輔助色**，但**同時保留文字標籤**（不能只靠顏色區分）
4. **每一個維度**的當前值標籤在任何時刻都要與該維度的滑桿、數字輸入框顯示同一個數值——**包含還沒調整過的維度**（有預填就顯示預填的實際值，沒有就顯示範圍中點的起始位置）
5. 一樣**不得用佔位符號取代數字**，唯勾了「無法判定」時**全部維度**顯示未評分佔位符號
6. 任一**未評分維度的起始值不計為已作答**，不得當成有效值提交
7. 記下**每個維度各自的數值**

#### 序列標記

1. 顯示帶「原始文本」標題的、**未經任何切分**的原始文本，當成單一的圈選面
2. 使用者**拖曳圈出一段文字，再點選標籤類型**完成標記
3. 記下**起點、終點與標籤**；起點與終點是**相對於原始文本的字元位置**，而且**終點那個字元本身不算在範圍內**
4. 已標記的範圍要以**對應標籤顏色的底線**呈現
5. 另有已標記清單，每一列含**類型徽章、文字、字元位置與刪除按鈕**
6. **範圍不得相交**：落在既有範圍上時要給**即時可見的拒絕回饋**且**不建立**那一筆
7. **相鄰但不相交**（前一筆的終點正好等於新一筆的起點）**必須被允許**
8. 吸附單位由任務設定決定：不吸附，或把起訖各自**吸附到最近的詞界**
9. **吸附只影響滑鼠放開時的落點，不影響存下來的值**——兩種設定產出的資料形狀完全相同
10. 執行環境做不到詞界判定時，**那一位標記員退回「不吸附」**，並在標記卡顯示一行提示；**不得因此改寫任務的設定值**
11. 第 10 條的提示**只能定位為操作手感說明，不得呈現為資料品質警告**
12. **吸附能力的差異不影響資料可比性**：同一個任務的不同標記員可能在能力不同的環境作業，而吸附不進入資料，所以降級那一位產出的範圍與其他人**完全相容**——系統**必須照常把他的答案納入一致性、共識與差異比對**，**不得標記為可疑、降權或排除**，也**不得事後對他的邊界做任何「對齊詞界」的修正**
13. 畫面上**不存在**把原始文本預先切成一格一格、讓人逐格點選的版面，**不存在**任何帶 `B-`／`I-`／`E-`／`S-` 前綴的標籤鈕，也**不存在**「標記方案」相關的呈現
14. 提交前要驗證每一筆範圍：**起點大於等於終點**、**起點小於 0**、**終點超出原始文本長度**都是錯誤，要**阻擋提交並顯示可定位的錯誤**
15. **沒有標任何範圍又沒宣告「無法判定」時阻擋提交**；建立任一筆之後這個阻擋就解除

#### 實體辨識

1. 顯示原始文本圈選區、**依設定動態產生的實體類型按鈕列**，以及已標記實體列表
2. 列表每一列含**類型徽章、文字、字元位置與刪除按鈕**；已標範圍以對應顏色底線呈現在原始文本上
3. **兩種順序都要支援**：先選類型再圈選，或先圈選再選類型
4. **沒有先圈選文字就點實體類型按鈕**時：顯示錯誤提示，**不得建立實體**
5. 記下**文字、類型、起點與終點**（終點那個字元本身不算在範圍內）

#### 關係識別

1. **只有關係識別、沒有實體辨識**時（純模式）：既有實體以**資料集提供的唯讀高亮**呈現，**不得顯示**實體類型選擇器、實體列表或建立／刪除實體的控制項
2. 三元組用**循序建構器**建立：在原始文本反白選取文字，依序按 `E1/Arg1` → `Relation` → `E2/Arg2` 把選取填進對應的草稿格，最後按「新增」寫入列表
3. 建構器要顯示**三個草稿狀態格與當前選取的內容**
4. `E1`／`E2` 兩步**只接受與既有實體相符的選取**（不符或沒先選取時顯示錯誤、不填入）；`Relation` 這一步**接受任意選取範圍**當關係觸發詞
5. 各步驟**依草稿進度循序啟用**：前一格沒填時後續步驟停用
6. 三格**沒全部填妥前「新增」停用**——**不存在只填一部分就能新增三元組的路徑**
7. 「退回」作用在**草稿格**上，依 `E2/Arg2` → `Relation` → `E1/Arg1` 撤回最後填入的那一格；草稿全空時停用
8. 「退回」**不移除已經入列的三元組**，純模式下**也不移除既有的唯讀實體**
9. 已入列的三元組由**每一列自己的刪除按鈕**個別移除
10. 設定的關係類型清單**非空**時，每一列另外提供類型選單，供事後指定或變更那一筆的語意類型；已指定的在該列顯示類型徽章
11. 類型是**選填**的：沒指定就是空的；清單**為空**時**不顯示類型選單，也不得輸出寫死的類型**
12. 這個循序建構器**必須和新增任務的標記預覽、任務詳情的標記設定是同一個互動控制**；工作區**不得另外提供不同型態的關係建構介面**（例如下拉選單）
13. 記下**每一筆三元組的主體、客體與選填的關係類型**
14. 主體與客體的**位置**（在原始文本上的起訖）**只能來自本來就帶位置的兩種來源**：工作區建構器的互動標記（位置來自既有實體的命中），或資料集匯入時本來就帶位置的三元組
15. **來源沒帶位置時就是「沒有」**——**不得用答案字串回原始文本做比對去回推位置**。同一個詞在文本裡出現多次時比對會選到錯的那一次，而且**不會產生任何錯誤訊號**，等於把「資料缺失」靜默換成「錯誤資料」。這一條是硬規則，**不得以「多數情況正確」為由放寬**

#### 自由文本

1. 依**這個順序**呈現：背景參考（選填）→ 輸入說明 → 題目內容卡 → 輸出說明 → 作答框 → 字數計數
2. 兩段說明文字要顯示**設定裡的文案**
3. 另有**字元計數**，形式是「目前字元數 / 上限」
4. **超過上限時阻擋繼續輸入**，而且**阻擋提交**（上限算的是**字元數**）
5. 有「用途是輸出」的欄位時，作答框要**以該欄位的值預填**；沒有時作答框是**空的**
6. 記下**那段文字**

### 實體辨識與關係識別的整合模式

<PrototypeFrame page="annotation/annotation-workspace" caption="標記工作區" client:idle />

1. 任務**同時選了實體辨識與關係識別**時，兩者以**整合模式**呈現
2. 兩者**共用同一份文本**，實體列表與三元組列表**合併顯示在同一個區塊**
3. 實體辨識保留它的**兩種建立順序**
4. 關係識別保留它的**循序建構器**，但 `E1`／`E2` 的來源改成**整合模式提供的可編輯實體**（不再是唯讀的資料集實體）
5. 兩者**仍各自輸出獨立的作答**——一份是實體辨識的、一份是關係識別的
6. 這個關聯**只在任務同時選了這兩種時成立**；工作區**不得自動加入或移除**這個關聯
7. 關係識別**可以單獨使用**，那時候就是純模式
8. 整合預覽區塊**不得在卡片裡再包一層外框**（見[§中欄主體：題目卡與標記卡](#中欄主體題目卡與標記卡)）

### 對話串資料的整合預覽

<PrototypeFrame page="annotation/annotation-workspace" caption="標記工作區" client:idle />

輸入欄位是**一筆一筆的物件陣列**時（例如對話逐則發言），整合預覽有一套專屬的呈現與記錄規則。這一段的規則**不得依任務編號或欄位名稱寫死**。

1. 任務設定了**對話串欄位**時，整合預覽**一則發言一列**
2. 每一列分**三個部分**：

| 部分 | 內容 |
| :--- | :--- |
| 頭像 | 圓形，取**發言者文字的第一個字元**；沒有發言者欄位、或該則的發言者是空的，就**不顯示頭像** |
| 標頭行 | 依序顯示**發言者**與 `#` 加**發言編號** |
| 發言文字 | **另起一行**，而且**保留換行** |

3. 頭像底色**由發言者文字決定**（同一位發言者永遠同一個顏色），**不得依發言者名稱寫死顏色**
4. **所有發言都可以標記，不得截斷**
5. 發言編號取設定指向的那個子欄位的值；**沒設定就用該則的位置編號**（從 1 起算）
6. 在對話串裡標的實體，記下**它屬於哪一則發言**，以及**在那一則發言文字裡的起訖**（同樣是終點本身不算在內）
7. 三元組除了主體與客體的起訖，還要記下**主體與客體各自屬於哪一則發言**
8. **反白跨到兩則發言要被拒絕**：顯示提示，且**不新增實體也不新增關係選取**。跨發言的關聯**要用關係識別表達**
9. 回覆縮排：任務設定了**回覆欄位**，而且該則的值**等於同一筆資料裡另一則發言的編號**時，該則**縮排**並顯示「跨發言 · 回應 #〈編號〉」標記
10. 下列情況**不縮排也不顯示標記**：沒設定回覆欄位、該則的值缺漏或為空、值找不到對應的發言、值等於**它自己**的編號
11. **不得由實體、關係或文字裡的 `@名字` 去推測回覆關係**
12. 對話串上方有**兩個顯示切換按鈕**，預設停在第一個：

| 按鈕 | 效果 |
| :--- | :--- |
| 顯示已標實體 | 發言文字上繪製實體標示與關係選取標示（預設） |
| 純文字 | **不繪製**那些標示；**已記錄的實體資料不變**，而且**反白標記仍然可以進行** |

13. 實體的定位規則：

| 情況 | 怎麼定位 |
| :--- | :--- |
| 實體已經帶著所屬發言與起訖 | **照座標定位** |
| 沒帶座標，而它的文字在整份對話的發言裡**恰好出現一次** | 定位到那個位置 |
| 沒帶座標，而文字**出現多次或找不到** | **不得猜**（**不得取第一次出現的位置**）；那個實體**不標示**，並顯示「無法定位」的提示與**數量** |

14. **重疊的實體不得默默略過**：同一則發言裡區間重疊的實體，後面那個**不標示**，但**儲存的內容不變**，而且畫面要**顯示因重疊而未標示的數量**
15. **反白歧義**：反白的位置與發言文字對不上，而且那段選取文字在該則發言裡出現多次或找不到時，**不得取第一次出現的位置**，要顯示**專屬的歧義提示**；只有在該則發言裡恰好出現一次時才以那個唯一位置記錄
16. 第 15 條的提示**不得顯示沒被替換掉的佔位符號**
17. 輸入是物件陣列但**沒有設定對話串欄位**時：整合預覽要以**可摺疊、等寬字**呈現該欄位的原始內容，**不得出現 `[object Object]`**。那個摺疊區塊的標題目前把技術名詞露給使用者看，見 [§待釐清](#待釐清) Q10
18. 對話串與原始內容的呈現**只渲染用途是輸入的欄位**；用途是**輸出或背景參考**的欄位**不得因為這條路徑外露**
19. 輸入是物件陣列時，整合預覽**不得用「用途是輸出」的欄位內容預填實體或三元組**
20. 輸入**不是**物件陣列的任務，既有的「由輸出欄位解析預填」行為**不變**
21. 預填的來源**只能從任務設定明文宣告的預填欄位讀取**，**不得依固定的欄位名稱去讀**；設定沒宣告、或對應的那一項缺漏時，那一類就**不載入**。宣告的欄位**載入前還要通過一道角色守門**，規則見[§整合預覽的宣告預填欄位有另一道守門，方向相反](#整合預覽的宣告預填欄位有另一道守門方向相反)

對話串與整合預覽的提示文字逐字如下（英文介面另有對應文案）：

| 理由欄位的說明 | `理由會隨提交寫入歷程，審核員可見` |
| 反白跨到兩則發言 | `無法跨發言標記，請在同一則發言內選取` |
| 反白的文字在該則發言出現多次 | `選取的文字在這則發言中出現多次，無法判定位置，請改選更長的片段` |
| 有實體定位不到 | `有 {n} 個標記無法定位到單一發言位置，未標示` |
| 有實體因重疊而未標示 | `有 {n} 個標記與同一發言內的其他標記重疊，未標示` |
| 回覆標記 | `跨發言 · 回應 #{n}` |
| 兩個顯示切換按鈕 | `顯示已標實體`、`純文字` |
| 沒設定對話串欄位時的摺疊區塊標題 | `原始 JSON（尚未設定對話串欄位）`（**技術名詞露給使用者**，見 [§待釐清](#待釐清) Q10） |
| 四個區塊標題 | `Entity Type`、`Entity List`、`Relation Type`、`Triple List`（**中文介面顯示英文**，見 [§待釐清](#待釐清) Q9） |
| 背景參考卡標題 | `背景參考 (Evidence)` |
| 整合預覽與原始文本的標題 | `整合預覽`、`原始文本` |

### 「無法判定」

<PrototypeFrame page="annotation/annotation-workspace" caption="標記工作區" client:idle />

1. 某個輸出類型的設定**允許**時，在**該區塊底部**提供獨立的「無法判定 (Bypass)」勾選項
2. 勾選後要**清空並停用該區塊內其他的互動控制項**，而且**只影響該區塊**，不影響其他輸出類型
3. 取消勾選後要**恢復可操作**，並依預填規則**重新初始化**
4. 每個輸出類型各自記下**是否被標為無法判定**；標了之後**其餘作答內容須為空**
5. 設定**不允許**無法判定的輸出類型：標記員做不出來時**只能依一般的驗證規則被擋下**，**不得提供「無法判定」當繞過手段**
6. 勾了無法判定**必須填理由**。沒填就送出時：**阻擋送出**、理由欄位下方出現**行內錯誤訊息**，並顯示**指名缺理由的那個輸出類型**的警告訊息
7. 被擋下時**不得產生任何提交紀錄**，既有內容**維持原狀**
8. 多個輸出類型**各自獨立判定**：兩個都勾了無法判定而只有一個填了理由時，送出被擋，而且警告**只指名留白的那一個**，已填的那個不受影響
9. 理由填好之後送得出去，而且**那段理由會連同它屬於哪個輸出類型一起寫進操作紀錄**（寫進去之後誰看得到，由階段五的歷程規則決定）
10. 整合模式下兩者**各自有獨立的「無法判定」**，但效果不對稱：

| 勾哪一個 | 效果 |
| :--- | :--- |
| 實體辨識 | **整合區塊一併清空停用**（含關係建構器）——因為關係識別依賴它的實體來源 |
| 關係識別 | **只**清空停用關係建構器與三元組列表，**實體標記不受影響** |

### 預填：兩道方向相反的守門

<PrototypeFrame page="annotation/annotation-workspace" caption="標記工作區" client:idle />

這一段是這一頁的**測試集保護**所在。

1. 初始化每一筆時，**所有輸出類型的控制項都必須是空白／未選取**——**除非**下面兩種情況之一：
   - 這一筆**已經有儲存過的作答**（存過草稿且有有效值，或已提交）
   - 這個輸出類型有**「用途是輸出」的欄位**可以預填（見第 3 條）
2. 兩種情況都不成立時，**不得預填任何合成的預設值**，**包含數值的中間點**。滑桿即使因為控制項本身需要一個視覺位置，也要**用未評分狀態區分**，而且**在使用者操作前不得被當成有效值提交**
3. 有「用途是輸出」的欄位時，用**那個欄位的實際值**初始化對應的控制項，呈現為**標記員看得見、可編修、可以直接提交**的預填：

| 輸出類型 | 怎麼預填 |
| :--- | :--- |
| 單選標籤 | 預選符合的那個標籤 |
| 多選階層標籤 | 以正規化後的路徑預選 |
| 單一維度評分 | 滑桿設在實際的分數值 |
| 多維度評分 | 各維度的滑桿設在對應維度的值 |
| 序列標記 | 以可見的預標記範圍初始化 |
| 實體辨識 | 以實際的實體列表初始化 |
| 關係識別 | 以實際的三元組初始化 |
| 自由文本 | 預填實際的答案文字 |

4. 沒有對應的「輸出」用途欄位時，那個輸出類型**維持空白／未選取**
5. **逐輸出類型的預填，來源只限被明文標記為「輸出」用途的欄位。** 沒有標任何用途的、標成「輸入」或「背景參考」的欄位，**不得作為這條路徑的預填來源**
6. **隱藏的測試集標準答案，不得透過這條路徑或任何其他路徑，下發到標記員接觸得到的任何地方**——包含畫面、預覽與任何中間狀態
7. 第 5、6 條是**不可協商**的
8. 預填**不是**標準答案：它是任務建立者明確指定要讓標記員看見的起始內容，所以可以編修、也可以直接送出

:::note{title="第 5 條只管預填這條路徑，不是「這些欄位不給標記員看」"}
來源那一句若單獨照字面讀，會連**題目內容**與**背景參考**都一起剝掉；但同一份來源另有三處明文要求把它們顯示出來——`FR-024N`（背景參考卡要呈現該欄位的**實際內容**）、`FR-107` 第 5 點（對話串**只渲染**用途是輸入的欄位，也就是說輸入欄位本來就要渲染）、`AC-2.49`（宣告的預填欄位用途是輸入或背景參考時，內容**照常載入**）。所以它限定的是**預填的來源**，而它真正要擋的是那一句自己的結尾：**隱藏的標準答案不得以任何形式下發**。
:::

#### 整合預覽的宣告預填欄位有另一道守門，方向相反

1. 整合預覽的預填實體與預填三元組，**只能從任務設定明文宣告的預填欄位讀取**，**不得依固定的欄位名稱去讀**
2. 設定沒宣告、或對應的那一項缺漏時，**那一類預填就不發生**
3. 宣告的欄位**載入之前還要查它的欄位用途**，而且這道守門**從嚴**（查不出來就不給）：

| 宣告欄位的用途 | 載不載入 |
| :--- | :--- |
| 已知、而且**不是**「輸出」（例如輸入、背景參考） | **載入** |
| 是「輸出」 | **一律不預填** |
| **沒有指派、是空的，或查不出來** | **一律不預填** |

4. 這道守門**不分輸入是字串或物件陣列、不分實體或三元組**，一律適用
5. 關係類型清單由預填三元組自動帶入時，候選**同樣只能來自通過這道守門的欄位**
6. 這一段只管**資料自帶欄位**的載入路徑；輸入不是物件陣列時「由輸出用途欄位解析預填」的既有路徑**不在這一段範圍內**（見[§對話串資料的整合預覽](#對話串資料的整合預覽)第 19、20 條）
7. 兩道守門**方向相反，但不矛盾**——它們看的是**不同的設定**：

| 哪一條路徑 | 看哪個設定 | 守門方向 |
| :--- | :--- | :--- |
| 逐輸出類型的預填 | 欄位的**用途**標記 | 來源**必須是**「輸出」用途的欄位 |
| 整合預覽的預填實體與三元組 | 任務設定裡**宣告的預填欄位** | 宣告的欄位**不得是**「輸出」用途，用途不明也不給 |

8. 之所以相反：第一條路徑的「輸出」用途是任務建立者**刻意指定要讓標記員看見**的；第二條路徑的宣告欄位可能指到標準答案，所以**查不出來就不給**

### 作答被鎖住的兩種情況

<PrototypeFrame page="annotation/annotation-workspace" caption="標記工作區" client:idle />

1. 有兩種情況會把標記員的作答**鎖住**。兩種的共同效果是：畫面渲染**鎖定提示**，而且「儲存草稿」與「提交」兩顆按鈕**都停用**——但**兩顆都仍然留在畫面上**，不是消失

| 鎖 | 什麼時候 | 標題 | 說明 | 自動儲存列 | 色調 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 已定稿 | 這一筆的審核單位已經定稿（前提是這位標記員**確實有真實的已儲存提交**） | `此標記結果已定稿` | `作答內容已鎖定，無法再修改或提交。如需異動請聯絡審核員。` | `已定稿，不再自動儲存` | **資訊色** |
| 審核中 | 審核員**第一次把審核結果送出**之後，而這一筆的審核單位**還沒定稿** | `此標記已進入審核` | `審核員已開始處理這筆作答，內容已鎖定，無法再修改或提交。` | `審核中，不再自動儲存` | **提醒色**＋鎖頭圖示 |

2. 色調**不得互換**：已定稿**必須用資訊色**，**不得用錯誤色，也不得用提醒色**——**定稿是終態，不是錯誤也不是提醒**
3. **兩個鎖同時成立時以「已定稿」為準**：正式標記的單位已定稿時，顯示定稿的文案與呈現，**不得顯示審核中的文案**
4. **鎖定提示與自動儲存列不得外洩審核狀態**：那兩處**不得出現「爭議中」「等待仲裁」「例外池」字樣**，也**不得呈現審核員的決策類型、理由或身分**。（這一條只約束這兩處；「操作紀錄」頁籤看得到什麼由階段五的歷程規則決定）
5. **定稿當下已經選定的作答必須維持可辨識**：**不得讓已選與未選的選項套用相同的視覺結果**（例如整排轉灰，導致看不出當初選了什麼）
6. **沒有解鎖入口**：這一頁**不提供任何解鎖操作**；要重新開放修改的流程目前還沒有定義
7. 兩種鎖的**適用階段不同**：

| 鎖 | 試標 | 正式標記 |
| :--- | :--- | :--- |
| 已定稿 | **不適用**——試標的後續回合不受影響 | 適用 |
| 審核中 | 適用 | 適用 |

8. **快捷鍵也不得繞過**：鎖定時按儲存或提交的快捷鍵，**都不得改變這一筆的內容或狀態**
9. 鎖定期間，這一筆的審核單位狀態**不得因為任何嘗試而翻回「爭議中」或「待審」**
10. **不得誤觸**：只由示範資料遞補、而**標記員本人還沒有任何真實已儲存提交**的審核單位，**不得顯示鎖定提示**，兩顆按鈕也**不得停用**；他的**第一次提交必須正常送出**
11. 標記員自己**促成這個單位變成已定稿的那一筆提交**，因為送出時還沒定稿，**必須正常寫入、不得被擋下**
12. **鎖只鎖這一個單位**：另一個試標回合裡同一位標記員的作答，**不得因為這個單位的審核中鎖而顯示提示或被擋下**
13. 審核員與仲裁者的寫入**不受這兩個鎖約束**（他們那一側由階段四、五撰寫）

### 作答完整性與提交阻擋

<PrototypeFrame page="annotation/annotation-workspace" caption="標記工作區" client:idle />

這一段只寫**什麼情況下送不出去**；送出之後往哪、草稿與自動儲存的規則在**階段三**。

1. 提交前，**每一個輸出類型都要已經作答，或已經勾了「無法判定」**
2. 任一個還沒完成時：**阻擋提交並提示對應的那個區塊**
3. 被擋下時，**其餘已完成區塊的作答不受影響**
4. 各輸出類型自己的驗證錯誤（評分超出範圍、字數超過上限、範圍起訖不合法、配對任務缺了一邊的內容）也各自阻擋提交，並顯示**可定位的**錯誤
5. 勾了「無法判定」但沒填理由的，依[§「無法判定」](#無法判定)第 6 到 8 條阻擋

| 說明檔案的連結 | 一律開新分頁 |

| 配對任務缺了任一邊的輸入內容 | **不得顯示空白配對區塊**；顯示資料欄位錯誤並阻擋提交 |
| 沒有指定背景參考欄位 | **不得顯示空的背景區塊** |
| 輸出類型自己已呈現背景參考 | **不得再顯示第二張**背景參考卡 |
| 多個輸出類型自己內嵌原文 | 通用輸入文字區塊**不得重複顯示** |
| 背景參考卡 | **只供閱讀**，不得有任何可編輯輸入或選取控制項 |
| 多選階層標籤的選擇器展開 | **必須是最上層不透明覆蓋層**，完整遮蓋後方內容（含「無法判定」），**不得穿透** |
| 多選階層標籤超過選取上限（非 0） | **阻擋新增選取**並提示上限；提示沿用工作區既有欄位提示的字級與顏色，不得用瀏覽器預設樣式 |
| 評分的當前值標籤 | 任何時刻都要顯示數值、與數字輸入框一致，**不得用佔位符號取代數字**——唯勾了「無法判定」例外 |
| 評分未作答、也沒有預填 | 範圍中點**只是起始位置**，不計為已作答、**不得當成有效值提交** |
| **預填或匯入**的評分值不落在設定的範圍與級距 | 顯示驗證錯誤並阻擋提交 |
| 標記員**手動鍵入**的評分值 | 只依**範圍**校正：範圍內的非級距小數**必須接受、不得吸附**；超出範圍的**自動校正**回範圍內，不是驗證錯誤 |
| 序列標記圈選範圍與既有範圍相交 | **即時可見的拒絕回饋**且**不建立**那一筆 |
| 序列標記圈選範圍與既有範圍相鄰但不相交 | **必須允許** |
| 序列標記的吸附單位 | **只影響滑鼠落點，不影響存下來的值** |
| 執行環境做不到詞界判定 | 那一位標記員退回「不吸附」並顯示一行提示；**不得改寫任務設定值**，提示**不得呈現為資料品質警告** |
| 標記員的吸附能力與他人不同 | 答案**必須照常納入**一致性、共識與差異比對；**不得標記為可疑、降權或排除**，**不得事後對齊詞界** |
| 序列標記的畫面 | **不得出現**預先切格的逐格點選版面、`B-`／`I-`／`E-`／`S-` 前綴的標籤鈕或「標記方案」呈現 |
| 序列標記的範圍起點大於等於終點、起點小於 0、終點超出文本長度 | **阻擋提交**並顯示可定位的錯誤 |
| 序列標記沒有任何範圍且沒宣告「無法判定」 | 阻擋提交；建立任一筆後解除 |
| 沒先圈選文字就點實體類型按鈕 | 顯示錯誤提示，**不得建立實體** |
| 關係識別純模式 | **不得顯示**實體類型選擇器、實體列表或建立／刪除實體的控制項 |
| 關係識別的 `E1`／`E2` 選取不符既有實體，或沒先選取 | 顯示錯誤，**該草稿格不填入** |
| 關係識別三個草稿格沒全部填妥 | 「新增」停用——**不存在只填一部分就新增三元組的路徑** |
| 關係識別草稿全空 | 「退回」停用；**不移除**已入列的三元組，純模式**也不移除**既有唯讀實體 |
| 關係類型清單為空 | **不顯示類型選單**，**不得輸出寫死的類型** |
| 關係識別的建構介面 | **必須與新增任務的標記預覽是同一個互動控制**，不得另提供下拉選單之類的替代型態 |
| 三元組的來源沒帶位置資訊 | 位置就是**沒有**；**不得用答案字串回原始文本比對回推**（硬規則，不得以「多數情況正確」放寬） |
| 自由文本超過字數上限 | **阻擋繼續輸入**並**阻擋提交** |
| 自由文本沒有「用途是輸出」的欄位 | 作答框是**空的** |
| 同時選了實體辨識與關係識別 | 以**整合模式**呈現；工作區**不得自動加入或移除**這個關聯 |
| 反白跨到兩則發言 | **拒絕**並顯示提示，不新增實體也不新增關係選取 |
| 實體沒帶座標、文字在對話裡出現多次或找不到 | **不得猜**、不得取第一次出現；該實體不標示並顯示「無法定位」提示與數量 |
| 同一則發言內實體區間重疊 | 後者**不得默默略過**；儲存內容不變，畫面顯示因重疊而未標示的數量 |
| 反白位置與發言文字對不上且該文字出現多次 | **不得取第一次出現**；顯示專屬歧義提示，而且提示**不得顯示未替換的佔位符號** |
| 回覆欄位的值缺漏、為空、找不到對應發言，或等於自己 | **不縮排也不顯示**回應標記；**不得由實體、關係或 `@名字` 推測回覆關係** |
| 輸入是物件陣列但沒設定對話串欄位 | 以可摺疊、等寬字呈現原始內容，**不得出現 `[object Object]`** |
| 對話串與原始內容的呈現 | **只渲染用途是輸入的欄位**；輸出與背景參考**不得因此外露** |
| 輸入是物件陣列 | **不得用「用途是輸出」的欄位預填**實體或三元組 |
| 整合預覽的預填來源 | **只能從任務設定明文宣告的預填欄位讀取**，不得依固定欄位名稱去讀 |
| 宣告的預填欄位用途是「輸出」 | **一律不預填** |
| 宣告的預填欄位**沒有指派用途、是空的，或查不出來** | **一律不預填**（守門從嚴）；**不分輸入是字串或物件陣列、不分實體或三元組** |
| 關係類型清單由預填三元組帶入 | 候選**只能來自通過角色守門的欄位** |
| 勾了「無法判定」 | **清空並停用該區塊**其他控制項；**只影響該區塊** |
| 取消「無法判定」 | 恢復可操作並依預填規則**重新初始化** |
| 設定不允許「無法判定」的輸出類型 | 只能依一般驗證規則阻擋提交，**不得提供「無法判定」當繞過手段** |
| 勾了「無法判定」卻沒填理由 | **阻擋送出**、行內錯誤、警告訊息**指名**缺理由的輸出類型；**不得產生提交紀錄** |
| 整合模式勾了實體辨識的「無法判定」 | 整合區塊**一併**清空停用（含關係建構器） |
| 整合模式勾了關係識別的「無法判定」 | **只**清空停用關係建構器與三元組列表，實體標記不受影響 |
| 初始化一筆、沒有儲存值也沒有預填 | 所有控制項**空白／未選取**；**不得預填任何合成預設值（含數值中間點）** |
| 欄位沒標用途、或標成「輸入」「背景參考」 | **不得作為逐輸出類型預填的來源**（它們各自的呈現規則另有定義） |
| 任何路徑 | **不得把隱藏的測試集標準答案下發到標記員接觸得到的地方**（不可協商） |
| 審核單位已定稿（標記員確有真實已儲存提交） | 渲染已定稿提示；「儲存草稿」與「提交」**停用但仍留在畫面上**；快捷鍵也不得繞過 |
| 審核員已第一次正式提交、單位還沒定稿 | 渲染審核中提示（提醒色＋鎖頭圖示）並同樣停用兩顆按鈕；**試標與正式標記都適用** |
| 只由示範資料遞補、標記員本人還沒有真實已儲存提交 | **不得顯示鎖定提示**、不得停用按鈕；第一次提交**必須正常送出** |
| 標記員促成單位定稿的那一筆提交 | **必須正常寫入**，不得被鎖定擋下 |
| 鎖定期間的任何嘗試 | 單位狀態**不得翻回「爭議中」或「待審」** |
| 已定稿的鎖定提示 | **必須用資訊色**；**不得用錯誤色，也不得用提醒色** |
| 兩個鎖同時成立 | 以**已定稿**為準，**不得顯示審核中的文案** |
| 鎖定提示與自動儲存列 | **不得出現「爭議中」「等待仲裁」「例外池」字樣**，也**不得呈現審核員的決策類型、理由或身分** |
| 鎖定生效時的作答區 | **已選定的作答必須維持可辨識**，不得讓已選與未選套用相同的視覺結果 |
| 這一頁的解鎖 | **不提供任何解鎖入口** |
| 另一個試標回合的同一位標記員 | **不得因為這個單位的審核中鎖而顯示提示或被擋下** |
| 提交前任一輸出類型未作答也未勾「無法判定」 | **阻擋提交並提示對應區塊**；其餘已完成區塊不受影響 |

## 邊界情況（Edge Case）

| 情況 | 使用者看到什麼 |
| :--- | :--- |
| 網址什麼參數都沒帶 | 導回標記清單（清單那一側會顯示「未指定任務」，見[規格 04-01](./01-annotation-list.mdx#空的與找不到)） |
| 網址帶了不存在的任務 | 導回標記清單，**不會看到半套的工作區** |
| 網址帶了不存在的那一筆 | 停在第一筆，網址同步成第一筆——重新整理不會再跳一次 |
| 任務設定的輸出類型是空的 | 任務設定錯誤的訊息，提交被擋住 |
| 這個任務只有一筆 | 「上一筆」與「下一筆」兩顆都停用 |
| 停在第一筆按 `Alt + ←` | 沒有任何反應，**不會跳到最後一筆**，也不會觸發瀏覽器的上一頁 |
| 說明檔案清單是空的 | 右欄只有「任務說明」摘要，沒有檔案列；標記主流程不受影響 |
| 說明檔案的連結失效 | 一則可追蹤的錯誤訊息，標記主流程**照樣能走** |
| 說明沒有 Markdown 類型、但任務要求先讀 | 彈窗顯示檔名清單（不是空白彈窗） |
| 說明檔案裡有兩個文字一樣的標題 | 兩個標題各自跳得到，不會互相搶 |
| 作業中途換語言 | 麵包屑、頁籤名稱與動作提示文字即時跟著換；作答內容不受影響 |
| 在手機上翻筆 | 抽屜維持原本的開合，不會自己彈開也不會自己收起 |
| 把右欄收起後翻筆 | 翻筆**不會自行改變收合狀態**；收起後要展開得自己點（來源只禁止「自動收起或清空」，沒有定義手動收起之後的保存，見 [§待釐清](#待釐清) Q8） |
| 從深連結直接進來（沒經過站內導覽） | 麵包屑三層都在，和站內點進來一模一樣 |
| 任務在試標第 2 回合 | 左欄標題還是「標記清單」，回合由麵包屑第 2 層講 |
| 回合換了指引版本 | 再次進場要重新確認一次說明 |
| 同一個人在兩個分頁開同一筆 | 以版本號檢查為準：衝突時阻擋覆寫並提示手動合併（細節見階段三） |
| 任務的輸出類型只有一種 | 就一個標記區塊；規則與多種時完全相同 |
| 任務有三種以上輸出類型 | 全部都在同一筆的同一個畫面裡完成，不分頁 |
| 多選階層標籤的選擇器正蓋著「無法判定」 | 要先關掉選擇器才點得到它；四種關閉途徑任一種都行 |
| 評分滑桿停在中點、使用者沒動過 | 提交被擋（那不算作答）；畫面也看得出是未評分狀態 |
| 圈選的範圍剛好接在前一個範圍的結尾 | 正常建立——相鄰不算相交 |
| 預標記的範圍超出原始文本長度 | 那幾筆被拒絕並列在錯誤清單，其餘正常載入 |
| 關係識別純模式、反白的文字不是既有實體 | `E1`／`E2` 那一格不填入並顯示錯誤；`Relation` 那一格照樣接受 |
| 三元組來自純字串形狀、完全不帶位置 | 位置四個值都是「沒有」；差異比對**回退為純值比對，照常呈現，不得變成空差異** |
| 對話串的某則沒有發言者 | 那一則不顯示頭像，其餘照常 |
| 對話串沒有設定發言編號欄位 | 用位置編號，從 1 起算 |
| 對話串某則的回覆值指向自己 | 不縮排、不顯示回應標記 |
| 切到「純文字」模式 | 標示不畫了，但**已記錄的實體資料不變**，而且**還是可以反白標記** |
| 同一筆裡同時有定位不到與重疊未標示的實體 | 兩種數量各自顯示，不混在一起 |
| 正式標記的單位已定稿、標記員又進來 | 看到已定稿提示；兩顆按鈕在但停用；按快捷鍵沒有反應 |
| 試標的單位已定稿、標記員又進來 | **不受定稿鎖影響**，後續回合照常 |
| 審核員剛開始處理、標記員同時還開著這一筆 | 下一次渲染就看到審核中提示並鎖住；已輸入但沒存的內容不會被寫入 |

## 驗收標準

階段一與階段二的 Scenario 都列在這裡；階段三到六會往下加。

| Scenario | Given | When | Then |
| :--- | :--- | :--- | :--- |
| 桌機三欄就位 | 標記員從清單點某一筆進來 | 查看畫面 | 左欄標記清單、中欄題目與作答、右欄說明與檔案三欄都在，整頁沒有頁首 |
| 網址帶的那一筆就是作用中的那一筆 | 網址帶了有效的那一筆 | 開啟工作區 | 左欄高亮、中欄內容與進度**都對應到那一筆**，不是預設的第一筆 |
| 任務設定查不到就不給進 | 網址帶的任務查不到已發布的設定 | 開啟工作區 | 導回標記清單，**沒有**出現任何預設控制項或空白工作區 |
| 沒帶那一筆就不給進 | 網址沒帶要處理的那一筆 | 開啟工作區 | 導回標記清單，作業區沒有載入 |
| 輸出類型是空的要擋 | 任務設定的輸出類型是空的 | 開啟工作區並嘗試提交 | 顯示任務設定錯誤，提交被擋住 |
| 標記階段缺值回退成試標 | 網址沒帶標記階段 | 開啟工作區 | 以試標呈現 |
| 左欄標題不帶回合 | 任務在試標第 2 回合 | 查看左欄標題 | 文字恰為「標記清單」，**沒有**「試標回合 R2」之類的字 |
| 筆數仍按回合顯示 | 同上，這一回合建立了 10 筆 | 查看左欄標題旁的筆數 | 顯示 10 筆 |
| 列的三態標籤 | 某一筆已提交、某一筆存過草稿、某一筆沒動過 | 查看左欄 | 三列分別顯示「已提交」「已儲存」「待標記」 |
| 存檔後標籤即時更新 | 標記員在某一筆作答中 | 按「儲存草稿」 | 左欄那一列的標籤立刻變成「已儲存」，不必重新整理 |
| 進度摘要（標記員） | 任務共 10 筆、已提交 3 筆 | 查看中欄上方 | 顯示「3 / 10 已提交」與對應的進度條 |
| 進度摘要（審核員） | 審核員已送出 2 個單位、共 15 個單位 | 查看中欄上方 | 顯示「我的審核提交 2 / 15 個審核單位」 |
| 首末筆按鈕停用 | 目前停在第一筆 | 查看導覽列 | 「上一筆」停用，「下一筆」可用 |
| 麵包屑有三層 | 審核員在某個審核單位 | 查看麵包屑 | 三層：「審核作業」、「〈任務名稱〉（正式標記）」、目前單位；只有第 3 層是目前層級 |
| 第 3 層（審核員） | 同上 | 查看第 3 層文字 | **同時**有那一筆的識別碼與受審標記員的帳號 |
| 第 3 層（標記員） | 標記員在第 2 筆、共 10 筆 | 查看第 3 層文字 | 顯示「樣本 2 / 10」，**不含**那一筆的識別碼，**也不含**自己的帳號 |
| 第 1 層（專案負責人） | 專案負責人在處理最終例外 | 查看麵包屑第 1 層 | 文字是「例外處置」，不是「標記作業」 |
| 麵包屑跟著換筆重畫 | 審核員從第一個單位切到第三個單位 | 查看麵包屑第 3 層 | 變成第三個單位，不是進來時的那一個 |
| 返回網址帶回身分 | 帶著某個標記員身分進來 | 取麵包屑第 2 層的連結 | 連結帶著同一個身分參數 |
| 沒帶身分就不補 | 網址沒帶任何身分參數 | 取麵包屑第 2 層的連結 | 連結裡**沒有**任何身分參數 |

| 宣告欄位沒有用途也不預填 | 宣告了一個預填欄位，但它在用途設定裡沒有對應的鍵（或值是空字串） | 開啟整合預覽（輸入是字串或物件陣列都一樣） | 沒有任何預填實體 |
| 宣告欄位用途是背景參考就載入 | 宣告的預填欄位用途是「背景參考」，資料另有一個未宣告、名叫 `entities` 的欄位 | 開啟整合預覽 | 預填的只有**宣告那個欄位**的實體，而且畫面文字不含 `entities` 欄位的內容 |
| 關係類型候選也受守門 | 預填三元組來自一個沒通過守門的欄位 | 查看關係類型選單的候選 | 候選不含那個欄位帶來的類型 |

| 整合模式勾關係的無法判定 | 同上 | 勾關係識別的「無法判定」 | 只有關係建構器與三元組列表清空停用，實體標記還在 |
| 沒有預填就全部空白 | 某任務沒有任何「用途是輸出」的欄位，這一筆也沒作答過 | 開啟工作區 | 所有控制項都是空白／未選取，沒有任何預設選取值 |
| 有預填就以實際值初始化 | 某任務的單選標籤有「用途是輸出」的欄位 | 開啟工作區 | 那個標籤被預選為欄位的實際值，而且可以改、可以直接提交 |
| 非輸出用途的欄位被剝除 | 某任務有一個沒標用途的欄位，裡面是答案 | 以標記員身分開啟工作區 | 那個欄位的內容在畫面上任何地方都看不到 |

| 試標不受定稿鎖 | 試標的某單位已定稿 | 標記員在後續回合開啟 | 沒有定稿鎖，照常作業 |

| 鎖定提示不外洩審核狀態 | 某單位處於審核中鎖，而它其實已經有爭議項 | 查看鎖定提示與自動儲存列 | 兩處都**沒有**「爭議中」「等待仲裁」「例外池」字樣，也沒有審核員的決策、理由或身分 |
| 定稿後看得出當初選了什麼 | 某單位已定稿，標記員當初選了第二個標籤 | 開啟那一筆 | 第二個標籤仍然看得出是被選的，不是整排一樣灰 |
| 沒有解鎖入口 | 某單位已定稿 | 找解鎖的操作 | 沒有 |

| 任一區塊沒完成就擋 | 任務有三種輸出類型，只完成兩種 | 按「提交」 | 被擋下並提示沒完成的那一個區塊，已完成的兩個不受影響 |

## 待釐清

階段一開了 5 題（Q1 到 Q4 與 Q8），階段二再開 2 題（Q9、Q10）。題號**只增不減**，之後的階段從 Q11 接下去；一題在待釐清與已確認決議之間搬動時**保留原本的題號**。

### Q1. 來源要求的「固定任務目標列」，任務目標與操作指引要放哪？

- **來源怎麼寫的**：桌機介面必須提供三欄工作區與**固定任務目標列**，該列的必要元素是任務目標、操作指引、已標記數量、總量、當前階段、微型進度視覺
- **畫面上實際有什麼**：最上面只有一條麵包屑；已標記數量、總量與進度條在**中欄上方的導覽列**，當前階段在**麵包屑第 2 層**。**任務目標與操作指引沒有任何落點**——右欄「任務說明」的摘要位置放的是**任務名稱**，而且來源的行為規則還明文禁止中欄渲染任務標題卡
- **我的建議**：把「任務目標」與「操作指引」收進右欄「說明與檔案」的任務說明區，不要在頂部另立一列。工作區的垂直空間是標記效率的主要瓶頸，而這兩段內容在整個作業期間都不變，常駐在右欄比固定在頂部划算；且麵包屑已經承擔了「我在哪個任務、哪個階段」
- **影響**：[§工作區的外殼](#工作區的外殼三欄與行動版)第 12 條、[§右欄：說明與檔案、操作紀錄](#右欄說明與檔案操作紀錄)第 5 條
- **誰決定**：維護者（這是畫面與來源不一致，依 `spec-migration.md` 列入待釐清）

### Q2. 右欄第二個頁籤叫「歷程」還是「操作紀錄」？

- **來源怎麼寫的**：右欄是「說明與檔案」／**「歷程」**雙頁籤，而且來源通篇用「歷程事件」「歷程可追溯」描述這個概念
- **畫面上實際是什麼**：頁籤的字面是**「操作紀錄」**
- **我的建議**：頁籤字面用畫面的「操作紀錄」（對使用者更直白），但**概念名稱**在規格與術語表裡統一用「歷程」，因為責任鏈那一段（階段五）通篇要講「歷程事件」。兩者如果都要統一，建議統一成「操作紀錄」並同步改掉來源的概念名稱
- **影響**：[§右欄：說明與檔案、操作紀錄](#右欄說明與檔案操作紀錄)第 1、2 條；階段五的歷程章節；未來可能要加的術語表條目
- **誰決定**：維護者

### Q3. 「已經讀過說明」這件事要記在帳號上還是裝置上？

- **來源怎麼寫的**：確認紀錄必須**以任務為鍵**獨立記錄，但**「確認紀錄的儲存實體（使用者帳號綁定或裝置綁定）留待後端接上時定義」**——來源自己把這一題留著，只鎖定「逐任務可獨立追蹤」這個契約
- **差別在哪**：綁帳號的話，換一台電腦不必重讀；綁裝置的話，同一個人換瀏覽器就要再讀一次，而共用電腦的兩個人會互相抑制彼此的彈窗
- **我的建議**：綁**帳號**。這個閘門的目的是「確定這個人讀過說明」，那是人的屬性不是機器的屬性；共用電腦的情境下綁裝置會讓第二個人直接跳過說明，正好違背設定這個開關的目的
- **影響**：[§指引閘門](#指引閘門第一次進來先讀說明)第 3、6、8 條
- **誰決定**：維護者

### Q4. 說明彈窗到底是每次進入都顯示，還是每個任務確認一次？來源有五處規則、分成兩派、沒有裁決句

- **互相矛盾的五處**（全部都**沒有被劃掉**，前兩列是一派、後三列是另一派）：

| 來源位置 | 說的是 |
| :--- | :--- |
| `FR-066` 第 1 點（v4.16.0） | 任務沒開「先讀說明」時，彈窗**在任何情況下都不得渲染** |
| `FR-066` 第 3 點（v4.16.0） | 確認過之後的後續進入（含重新整理）**不得重複顯示** |
| `FR-021` | 原型頁**每次進入都必須顯示一次**說明彈窗 |
| 規格常數 `GUIDELINE_MODAL_BEHAVIOR` | 值就是「每次進入顯示一次」 |
| 使用者故事 2 的行為規則（未編號散文） | 「原型入場時**固定顯示**說明 modal 一次」 |

- **為什麼不能自己結案**：`FR-066` 第 1 點的「於任何情況下」看起來像裁決句，但它後面緊接的限定詞是「**不受第 2、3 點之確認狀態影響**」——指名的是 `FR-066` 自己的第 2、3 點，處理的是這一條內部的優先順序（閘門開關壓過確認紀錄），**沒有觸及 `FR-021`**。而且 v4.16.0 的變更紀錄自述第 1 到 3 點只是「既有原型行為之正式化…**不改變任何既有版面呈現**」，這句話正好否認它推翻了既有規則
- **我的建議**：照 `FR-066`——它版本最新，而且任務設定那一側（`force_guideline` 開關）已經定義了觸發行為，沒有開關卻強制每個人每次進來都讀一次說明，與那個開關的存在意義衝突
- **影響**：[§指引閘門](#指引閘門第一次進來先讀說明)第 2、3、9 條與[§卡控機制](#卡控機制)裡的四條閘門規則；若改採「每次都顯示」，`FR-066` 的整套確認紀錄（含逐任務、逐指引版本）就沒有消費端
- **誰決定**：維護者

### Q8. 使用者**手動**把右欄收起之後再翻筆，要維持收起還是回到展開？

- **來源怎麼寫的**：只有三處沾到，而且三處講的都是**不得自動收起**，沒有一處定義手動收起之後的狀態保存——`FR-019`「面板必須於翻筆後持續可見，不可自動收起或清空」、`AC-5.1`「右欄說明不收起且內容不重置」、`SC-005`「翻筆後內容維持，Desktop 可收合／展開」
- **為什麼需要決定**：`FR-019` 的「持續可見」和「維持使用者收起的狀態」字面上互相拉扯——照字面讀，手動收起後翻筆應該要自己展開回來，但那會讓收合鈕在翻筆流程裡形同無效
- **我的建議**：**維持使用者收起的狀態**。收合鈕的用途就是把中欄的空間讓出來，如果翻一筆就彈回來，這顆鈕在實際作業中沒有價值；`FR-019` 的本意是禁止系統自己收起，不是禁止使用者收起
- **影響**：[§工作區的外殼](#工作區的外殼三欄與行動版)第 3、7 條、[§邊界情況](#邊界情況edge-case)那一列
- **誰決定**：維護者

### Q9. 中文介面裡有四個區塊標題是英文，要不要改成中文？

- **畫面上實際是什麼**：實體辨識與關係識別的四個區塊標題，在**中文介面**顯示的是英文——`Entity Type`、`Entity List`、`Relation Type`、`Triple List`。這四個字面由共用的設定引擎提供，所以[新增任務](../03-task-management/02-task-new.mdx)的標記預覽、任務詳情的標記設定與這一頁**會一起變**
- **來源怎麼寫的**：來源只給英文識別名（`Entity Type` 按鈕列、已標記實體列表、triple 清單），**沒有指定中文字面**
- **我的建議**：改成中文（例如「實體類型」「已標記實體」「關係類型」「已建立的三元組」）。整個介面其餘部分都是中文，四個英文標題會讓標記員在作業中斷一下；而且這四個詞沒有「必須保留原文」的理由（不像 `IAA` 或 `Bypass` 是被當成術語在用）
- **影響**：[§八種輸出類型的作答控制項](#八種輸出類型的作答控制項)的實體辨識與關係識別兩段、[§畫面上的字面](#畫面上的字面)；改了會同時動到 03-02 與 03-03 兩頁描述的同一組字面
- **誰決定**：維護者（這是畫面文案，不是規則）

### Q10. 摺疊區塊的標題把技術名詞露給使用者，要不要改？

- **畫面上實際是什麼**：輸入是物件陣列、但任務還沒設定對話串欄位時，整合預覽會出現一個摺疊區塊，標題逐字是 `原始 JSON（尚未設定對話串欄位）`
- **為什麼是問題**：那是技術名詞。（這個詞在這一份規格裡只以「引用畫面字面」的形式出現，不是規格自己的用語。）標記員是這個畫面的使用者，而他不需要知道資料的儲存格式叫什麼；這個專案的規格撰寫規則本身也要求用使用者語言
- **我的建議**：改成不帶技術名詞的說法，例如「原始資料（尚未設定對話串欄位）」。這個區塊的用途是「讓人看到這筆資料長什麼樣」，換掉名詞不影響它的功能
- **影響**：[§對話串資料的整合預覽](#對話串資料的整合預覽)第 17 條、[§畫面上的字面](#畫面上的字面)
- **誰決定**：維護者（同 Q9，這是畫面文案）

## 已確認決議

### Q5. 左欄標題可不可以帶回合標籤？（已定案，沿用舊來源）

- **結論**：**不行**。標題固定「標記清單」，回合由[麵包屑第 2 層](#入口麵包屑的第三層)承載；但**筆數仍然要按當前回合的清單規模顯示**
- **依據**：來源使用者故事 1 的行為規則明文禁止在左欄標題附加回合標籤，並同時要求筆數照回合顯示；`FR-080` 第 5 點又特別聲明麵包屑不改變這條約束，兩者位置不同、不衝突
- **為什麼**：同一個畫面上把「這是哪個回合」講兩次，是資訊重複；而回合放在三欄主體之上，讀者第一眼就看得到
- **影響**：[§左欄：標記清單](#左欄標記清單)第 1 到 4 條

### Q6. 手機版有沒有「操作紀錄」？（已定案，沿用舊來源）

- **結論**：**沒有**。手機的底部抽屜只承載「說明與檔案」，操作紀錄是桌機右欄才有的
- **依據**：來源的規格常數明寫「Mobile 底部抽屜僅承載『說明與檔案』，不含歷程頁籤」，使用者故事 2 的介面定義也寫「`歷程` 頁籤為 Desktop 右欄功能」
- **為什麼**：手機要主操作優先，抽屜不得遮蔽核心標記區；操作紀錄是回顧用的資訊，不是作答必需
- **影響**：[§工作區的外殼](#工作區的外殼三欄與行動版)第 6 條

### Q7. 標記員看不看得到那一筆的識別碼？（已定案，沿用舊來源，來源標為不可協商）

- **結論**：**看不到**。麵包屑第 3 層對標記員**只顯示佇列位置**，不顯示那一筆的識別碼，也不顯示標記員自己的帳號
- **依據**：來源 `FR-080` 第 3 點標為 **NON-NEGOTIABLE**，理由是有些資料集用**沒有被指派用途的欄位**當記錄識別鍵，把它渲染進標記員看得到的地方就會違反來源的兩條資料公平性條文（標記員可見之處不得出現答案；用途是輸出的欄位不得被當成可讀內容）
- **為什麼**：識別碼本身可能就是答案線索；而標記員自己的帳號對標記員是零資訊
- **影響**：[§入口麵包屑的第三層](#入口麵包屑的第三層)第 2、3 條、[§卡控機制](#卡控機制)

## Q&A

### Q. 為什麼左欄標題不准帶回合標籤，這不是多此一舉嗎？

因為工作區是一個會停留很久的畫面，而「我在哪個回合」這件事只需要一個地方講。來源把它放在三欄主體**之上**的麵包屑，而不是左欄標題裡，理由是視線進入畫面時第一個落點在上方；標題如果也講一次，讀者就得確認兩處是不是同一件事。真正不能省的是**筆數**——它會因回合而不同，所以標題固定、筆數照回合變。

### Q. 為什麼標記員的麵包屑連那一筆的識別碼都不給看？

因為識別碼不一定只是流水號。來源點出有些資料集拿**沒有被指派用途的欄位**當記錄的識別鍵，那個欄位可能本身就帶著答案線索；一旦渲染進標記員看得到的地方，測試集保護就破了。這條在來源被標成不可協商，而且它換來的成本很低——標記員需要知道的是「我做到第幾筆、還剩幾筆」，那個識別碼對他本來就是零資訊。

### Q. 為什麼翻筆要把網址改寫成「原地取代」，不是正常地新增一筆瀏覽紀錄？

因為工作區的「下一筆」是作業動作，不是導覽動作。一個 5 筆樣本 × 3 位標記員的任務有 15 個審核單位，若每翻一筆都堆一筆瀏覽紀錄，審核員看完全部之後要按 15 次上一頁才離得開這一頁。原地取代同時保住了另一件事：重新整理、加書籤、把連結貼給別人，拿到的都是**畫面上的那一筆**，而不是最初進來的那一筆。

### Q. 為什麼說明彈窗的內容一定要和右欄同一份？

因為這個閘門的目的是「確定這個人讀過這一版說明」。如果彈窗另有一份文字，使用者確認的就不是他後續會對照的那一份，閘門只剩下儀式。同一個理由延伸到版本：彈窗與右欄必須是同一個指引版本，而換了版本就要重新確認——否則「已讀」這個紀錄會指向一份已經不適用的說明。
