# PRD 視覺化寫法

PRD 有三張固定的互動圖，各自從一份骨架複製：**【骨架】一字不改，只換【資料】**，不同專案的 PRD 看起來是同一套。
樣式另依 `docs/development/notecraft-visualize.md`，生成與寫回 MDX 的流程依 `content-visualize` skill。

| 圖         | 放在哪             | 元件 id                                           | 骨架                                                     | 不寫的情況       |
| :--------- | :----------------- | :------------------------------------------------ | :------------------------------------------------------- | :--------------- |
| Site Map   | §Site Map 最前面   | `prd-site-map`                                    | [site-map-skeleton.tsx](site-map-skeleton.tsx)           | 無，一律要有     |
| 跨模組流程 | §跨模組流程 最前面 | `prd-<主題>-flow`（例：`prd-cross-module-flow`）  | [module-flow-skeleton.tsx](module-flow-skeleton.tsx)     | 該節寫「不適用」 |
| 共用狀態機 | §共用狀態機 最前面 | `prd-<實體>-state`（例：`prd-opportunity-state`） | [state-machine-skeleton.tsx](state-machine-skeleton.tsx) | 該節寫「不適用」 |

步驟：

1. 整份複製到 `.notecraft/components/<元件 id>.tsx`
2. 只改【資料】區段與 default export 的名稱；骨架少了需要的圖形或機制時，先問使用者，同意後改骨架參考檔再複製
3. 標記 prompt 寫「核心洞察／互動／圖形／資料」，資料和章節正文**逐項一致**（正文是唯一來源，圖只是呈現）
4. `pnpm exec notecraftapp build docs` 通過後（只改元件、沒改 MDX 時，快取不會察覺，要加 `--rebuild`），在瀏覽器實際操作每個互動，確認沒有重疊、裁切與 console 錯誤

生成元件不能互相 import，所以用複製，不抽共用元件。

## 共通規則

- 模組色固定：依模組編號取下表的顏色（`label-suite-design` 的 token），三張圖用同一組；不屬於任何模組的頁面（登入）用 slate-500 `#64748B`（`--color-ink-muted`）。
  黃色（yellow-*，`--color-warning`）與紅色（red-*，`--color-error`）不當模組色，黃色只標例外、替代與待確認

  | 模組  | 01                     | 02                      | 03                   | 04                                       | 05                       | 06 以後                                |
  | :---- | :--------------------- | :---------------------- | :------------------- | :--------------------------------------- | :----------------------- | :------------------------------------- |
  | token | `--color-primary` `#6366F1` | `--color-cta` `#047857` | `--color-info` `#1D4ED8` | `--color-file-markdown` `#8B5CF6` | `--color-secondary` `#818CF8` | 從 01 重新循環，靠色條旁的模組編號區分 |

- 互動只做規定的那幾個，不加更多
- 面板、走查卡片固定佔位，切換時不跳版；第一次 render（含 SSR）直接呈現終態，之後切換才播放進場（骨架已處理）
- 圖寬由資料決定，外層可以橫向捲動，頁面不捲動

## Site Map

左側是一次看一個模組的縱向主幹樹，右側是詳情面板：上方切換模組，模組節點在最上面，主幹往下串起子模組，子模組左右交錯掛在主幹兩側，頁面在子模組下方垂直排列，左右支線互為鏡像。

| 【資料】 | 寫法 |
| :--- | :--- |
| 角色 icon 的 import | 檔頭標【資料】的那一行，改成 `ROLES` 用到的 lucide-react icon |
| `ROLES` | §使用者角色 的角色；`icon` 選一個 lucide-react icon 代表角色（例：負責人 `Crown`、人資 `UserCog`、薪酬 `Calculator`、財務 `Landmark`、主管 `Users`、員工 `User`、管理員 `ShieldCheck`、檢視者 `Eye`），角色之間 icon 不重複；**角色不用顏色區分**，顏色只用來表示權限等級 |
| `MODULES` | 模組地圖的模組；第一個放「登入」「入口」這類不屬於模組的頁面（灰）；顏色只用在主幹與模組標記，不用在框的邊條 |
| `GROUPS` | 子模組分組（`id`、`module`、`code`、`label`）；模組底下沒有分組時留空陣列，主幹改串模組的入口頁 |
| `PAGES` | §Site Map 條列的每個頁面；`parent` 是上層**頁面**，直接掛在模組或子模組底下的頁面寫 `null`；有子模組時寫 `group`；`code` 選填，寫需求來源的原編號（詳情面板顯示、搜尋會比對）；`specState`：`written` 已撰寫、`reserved` 預留未撰寫、`part` 屬於上層頁面的規格、`none` 不寫規格 |
| `access` | 每個角色一筆：`op` 可操作、`read` 唯讀、`pending` 有存取但操作權待確認（對應正文的待確認 callout）；`note` 寫權限代號與遮蔽說明；沒有權限就不寫這個角色 |
| `DEFAULT_SELECTED` | 預設選取的頁面，也決定預設顯示的模組（通常是第一個模組的入口頁） |

- 主幹上的站：有 `GROUPS` 時是子模組（不可選取），沒有時是模組的入口頁（可選取），子頁依 `parent` 掛在站底下，每深一層往外縮排
- 頁面框兩行：第一行是名稱與規格編號，第二行是角色 icon（順序固定）；權限等級用 icon 的外框表示：實心藍＝可操作、灰框＝唯讀、黃色虛線＝待確認、不顯示＝無權限
- 樹寬固定約 400px，好讓右側放得下詳情面板；名稱過長時以刪節號截斷，滑過顯示全名，詳情面板顯示完整名稱
- 詳情面板在樹的右側並跟著捲動停留（sticky），圖例收在面板底部；容器寬度放不下時（樹寬＋240px），面板移到樹下方
- 互動：模組切換（膠囊按鈕，角色篩選時改顯示可進入頁數，0 頁的模組變淡）、角色篩選（按鈕帶角色 icon；壓暗到 0.28，不隱藏）、點頁面看右側詳情面板；頁面超過 20 個（`SEARCH_PAGE_LIMIT`）時另有頁面搜尋（名稱／規格編號／原編號，Enter 選第一筆）
- 一張圖涵蓋全部模組，不依模組拆成多個元件；不用模組卡片，也不用單邊色條的框

檢查（生成後逐項確認）：

- [ ] `PAGES` 和 §Site Map 條列一一對應：頁面、階層、規格編號、預留／已撰寫狀態都相同
- [ ] 每個頁面的 `access` 和 §權限矩陣、遮蔽說明一致；沒有權限的角色不寫，不寫成唯讀；權限矩陣標待確認的格子用 `pending`，不猜成 `op` 或 `read`
- [ ] 模組地圖裡每個頁面（含預留）都出現在圖上，反之亦然；有子模組時，`GROUPS` 和 §Site Map 條列的子模組一一對應
- [ ] 每個角色篩選都至少壓暗一個頁面，或確實所有頁面都進得去（兩個角色篩選結果完全相同時，回頭確認權限矩陣是否漏寫差異；權限待確認造成的相同，在回報中註明）
- [ ] 點過每個模組按鈕，主幹與頁面都正確切換，左右兩側的頁面與支線沒有重疊或裁切，右側面板沒有被擠到樹下方（內容寬度正常時）
- [ ] 點每個頁面，詳情面板的位置、入口、權限、規格都有內容；有搜尋時，名稱、規格編號、原編號各試一筆，都會切到對應模組並選取該頁

## 跨模組流程

和規格書的流程圖（`spec-writing` 的 flow-skeleton）不同：**泳道是模組**，不是角色。

| 【資料】                     | 寫法                                                                                                                                                       |
| :--------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `TITLE`、`TRIGGER`、`RESULT` | §跨模組流程 的粗體標題、起點、終點                                                                                                                         |
| `LANES`                      | 流程經過的模組，由上而下依流程先後；同一欄需要上下兩個節點的模組 `rows: 2`                                                                                 |
| `NODES`                      | `event` 模組內發生的事件、`decision` 判斷（問句）、`start` 起點；`state` 寫商機這類共用實體的狀態變化（畫在框內最後一行）；`end`、`exception` 同規格流程圖 |
| `EDGES`                      | 跨泳道的連線加 `handoff`（交接編號，和正文「交接 1、2…」一致）；`exit`／`enter`／`via` 調整路線                                                            |
| `STEPS`                      | 走查：起點、每個交接、每個例外與替代、結果；`handoff` 寫「模組 A → 模組 B：交接的資料」；`spec` 寫細節所在的規格（未撰寫要註明）                           |

- 每段流程最多約 11 個節點、8 欄；超過時拆成兩段流程，各自一張圖
- 判斷的兩個出口不要從同一側離開：「是」往右，「否」往下（或往上）
- 例外、替代、回頭線都用黃色虛線；回頭線走泳道下緣（`via: laneBottom(n) - 8`）

檢查（生成後逐項確認）：

- [ ] 每個交接編號都對得到正文「交接」的同一步，數量相同
- [ ] 每個例外、替代路徑都對得到正文的「替代」或模組依賴、卡控說明
- [ ] 走查依序涵蓋：起點、每個交接、每個例外與替代各至少一步、結果
- [ ] 每個節點與連線至少出現在一步走查的 `highlight`，點任何節點都有反應
- [ ] `state` 的狀態變化和 §共用狀態機 的轉移一致（同一個觸發、同一個推進模組）
- [ ] 判斷的每個出口都有下文：走到結束節點，或接回主流程
- [ ] 連線沒有穿過節點、標籤沒有壓到節點或其他標籤

## 共用狀態機

| 【資料】        | 寫法                                                                                                                             |
| :-------------- | :------------------------------------------------------------------------------------------------------------------------------- |
| `MODULES`       | 會推進這個實體狀態的模組                                                                                                         |
| `STATES`        | 起點（`start`）、各狀態與座標；結束狀態 `final: true`；`desc` 一句話說明這個狀態的意思                                           |
| `TRANSITIONS`   | §共用狀態機 表格的每一列；`label` 是圖上的短標籤，`trigger` 是完整觸發條件；兩個狀態之間有兩條轉移時，用 `bend` 讓其中一條彎出去 |
| `pending`       | 待確認的轉移（黃色虛線、標「待確認」），對應正文的待確認 callout                                                                 |
| `DEFAULT_STATE` | 預設選取的狀態                                                                                                                   |

- 版面：主線由左而右排在上排，結束狀態放最右或下排；狀態之間至少留 240 的距離，標籤才不會壓到狀態框
- 互動：依模組篩選轉移、點狀態看進入與離開的轉移

檢查（生成後逐項確認）：

- [ ] `TRANSITIONS` 和 §共用狀態機 表格一一對應：從、到、觸發、推進的模組都相同
- [ ] 每個 `pending` 轉移都對得到正文的待確認 callout，反之亦然
- [ ] 每個非結束狀態都至少有一條離開的轉移；結束狀態沒有離開的轉移
- [ ] 每個模組篩選都至少亮起一條轉移
- [ ] 點每個狀態，面板的進入與離開都列得出來；標籤沒有壓到狀態框或其他標籤
