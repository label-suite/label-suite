# UI Design

本份是 change `denied-and-not-found`（Issue #721）的前端設計：規格 07-03 的兩種整頁畫面（找不到、無權限）的元件樹、資料來源、畫面狀態、design token、文案鍵與無障礙。脈絡基準是同目錄的 `system-analysis.md`（以下稱 sa，待決題號寫成 sa-N）；後端側見 `system-design.md`（以下稱 sd）。本份自己的待決問題寫成 U-N，見 [§待決問題](#待決問題)。

sa-1～sa-5 還沒決議，本份**不替它們選邊**：不受它們影響的部分（共用畫面本身）直接寫定；受影響的部分（路由、通用找不到頁、拒絕回應怎麼轉成畫面）依選項分支寫出，clarification 決議後由 ui-ux 依決議收斂成一條。

## 頁面與路由

### 不受 sa-N 影響的部分

這兩種畫面**不是頁面**，是「某一頁在擋下使用者時取代內容區的狀態」（規格 07-03 頁首、§業務流程）。所以本單的核心交付是一個**共用畫面元件** `BlockedScreen`，由會定址到「那一筆」的頁面在自己的路由裡畫它；本單不替任何既有路由加這種狀態，因為目前 `main` 上沒有任何一頁定址到「那一筆」（sa §跨模組依賴）。

| 誰會畫它     | 路由                                     | 種類與去處（由那一頁的規格定）     | 07-shared Logic Flow          | 接手 |
| :----------- | :--------------------------------------- | :--------------------------------- | :---------------------------- | :--- |
| 任務詳情     | `/task-management/task-detail?task_id=…` | 找不到、無權限；回任務列表         | 模組 03 分段四；07-shared X11 | #763 |
| 標記清單     | `/annotation/annotation-list?task_id=…`  | 找不到（帶與沒帶識別碼）；回儀表板 | 模組 04；07-shared X11        | #773 |
| 工作頁籤切回 | 頁籤裡的那一頁                           | 找不到、無權限；頁籤不自動關閉     | 07-shared 分段四 `D7 否 → P3` | #725 |
| 通知點進去   | 07-04 未指定（07-shared 缺口一）         | —                                  | —                             | #740 |

**角色**：三種登入後的系統角色（平台成員、系統管理員、Seeder 管理員）看到同一套結構，沒有任何角色多出或少了控制項（規格 07-03 §使用角色、Scenario「權限：每一種角色都看得到同一套結構」）。不需要任何任務成員身分；任務角色只影響那一頁決定顯示**哪一種**。未登入的訪客到不了這兩種畫面：守門先帶回登入頁（`auth-guard`「未登入的訪客被帶回登入頁」）。

**進入、離開與返回**（07-shared 分段五）：

- **進入**：由那一頁在判定「拒絕」或「找不到」後畫出來（P3）；本份不定何時（規格 07-03 §不在本頁範圍 第 4 條）
- **離開**：畫面上唯一的返回連結 → 那一頁指定的去處（`P3 → D9 → X11`）。它是連結，Ctrl／⌘ 或中鍵點擊交給瀏覽器開新分頁；側欄照常可用
- **返回之後**：去處那一頁自己再判一次（`D9 否 → P3`）；本單的去處都是儀表板，對每個登入者都放行，不會觸發（Scenario 9、10 移交，sa §範圍）
- **瀏覽器上一頁**：照路由歷史回上一頁，畫面不攔

## 元件樹

### 共用畫面 `BlockedScreen`

依 `docs/development/rules/frontend-agent-rules.mdx` F5：用到這個畫面的 prototype 產品畫面是 `task-management/task-detail` 與 `annotation/annotation-list`，分屬兩個 feature，所以是**共用元件，放 `frontend/src/components/`**。設計系統沒有它的元件規格（`state-panel.md` §用到它的畫面 已註明這兩個面板「是各自的實作」，不是 State Panel），所以下表寫「設計系統無」；要不要補登記見 U2。檔名最後一個字是 `screen`，`design/system/components/` 沒有同字尾的規格，`scripts/check-component-reuse.mjs` 不會把它認成重造；它也不在 `features/`、`pages/`，不在掃描範圍。

```text
BlockedScreen                 設計系統無：新建，放 frontend/src/components/blocked-screen.tsx
├─ 容器（取代內容區的一塊）    card.md：沿用 frontend/src/components/ui/card.tsx（U1 推薦；若 U1 選 Empty State 面板，改為沿用 frontend/src/components/ui/empty.tsx 並解決它固定的 Inbox 圖示）
│  ├─ 標題                    設計系統無：原生標題元素，層級由呼叫端指定（預設一級）
│  ├─ 說明                    設計系統無：原生段落；內含識別碼時插入下一列
│  │  └─ BlockedIdentifier    設計系統無：新建，同檔匯出（frontend/src/components/blocked-screen.tsx）
│  └─ 返回連結                button.md：沿用 frontend/src/components/ui/button.tsx（variant default、size sm，以 asChild 包 React Router 的 Link）
```

元件的輸入（語意描述，不是程式碼）：

| 輸入           | 必填             | 說明                                                                                                                                                                          |
| :------------- | :--------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 種類           | 必填             | 找不到或無權限二選一；畫在容器的 `data-kind` 上，讓測試分得出兩種畫面（Scenario「反向：兩種畫面不得互換」）。兩種**外觀相同**（prototype 兩個面板同一組 class），差別只在字面 |
| 標題           | 必填             | 一句話說出狀況，不帶識別碼（07-03 §畫面的組成 第 2 條）；字面由呼叫端給                                                                                                       |
| 說明           | 必填             | 指出是哪一筆、給下一步；無權限時要提到可以找誰（第 3、4 條；§無權限的畫面 第 1 條）。帶識別碼的句子由呼叫端用 `BlockedIdentifier` 把識別碼插進去                              |
| 返回去處與標籤 | 必填，**恰一個** | 去處是站內路徑，標籤寫出去處（第 5 條）。元件不提供第二個操作的位置，也不提供重試                                                                                             |
| 標題層級       | 選填，預設一級   | 那一頁保留自己的頁首一級標題時（例：任務詳情的頁首，03-03 §共用任務標頭 第 8 條）傳二級                                                                                       |
| 到達時移焦點   | 選填，預設是     | 工作頁籤切回時由 #725 依 07-02 的鍵盤規則決定要不要關掉                                                                                                                       |

`BlockedIdentifier`：把識別碼當**純文字**放進一個雙向隔離的行內元素，允許在任意字元處換行。識別碼只經 React 的文字節點輸出，不經 HTML 插入（`lib/i18n` 的 `escapeValue: false` 是交給 React 跳脫，所以**不得**把它丟進任何以 HTML 解讀的位置）。不截斷、不改寫，畫面上就是原值（07-03 §資料欄位「原值」、§邊界情況「識別碼過長或含奇怪字元」）。

## 資料來源

`BlockedScreen` 與 `NotFoundPage` **不送任何請求**，沒有 operationId、沒有查詢鍵、沒有 mutation，也沒有要 invalidate 的查詢（07-03 §使用角色「不持有任何業務資料」）。唯一的「資料」是識別碼，由使用它的那一頁從自己的網址讀出來（例：`task_id`）再傳進來，不寫進任何儲存（07-03 §資料欄位「只在這次瀏覽存在，不寫入資料庫」）。

| 區塊                                        | operationId                                                           | 快取鍵／失效時機                                                       |
| :------------------------------------------ | :-------------------------------------------------------------------- | :--------------------------------------------------------------------- |
| `BlockedScreen`                             | 無                                                                    | 無                                                                     |
| `NotFoundPage`（sa-2 B／C）                 | 無                                                                    | 無；登入者由外殼的 `getCurrentSession`（與守門共用快取）取得，本頁不讀 |
| 決定顯示哪一種的查詢（任務詳情、標記清單…） | 屬那一頁，例如任務詳情讀任務的 operationId 由 #763 的 api-contract 定 | 屬那一頁；見下方「給使用它的頁面」                                     |

**狀態的三個去處**（F4）：伺服器狀態無；網址狀態只有那一頁自己的識別碼參數；純 UI 狀態只有「到達時移焦點」用的元素參照。**不需要全域 store**。

**給使用它的頁面**（#763、#773、#725 照做，本單不實作）：

- 種類由那一頁的查詢錯誤決定，**不在前端依角色猜**（F8 禁止格）
- 進到這兩種畫面後，那個查詢不得因視窗取得焦點或重新連線就自動重查把畫面換回去：07-03 §無權限的畫面 第 3 條、07-02 §權限或資料失效 第 4 條要求等使用者下次切回才重新檢查。`createQueryClient()` 只關了 `retry`，`refetchOnWindowFocus` 仍是函式庫預設的開，所以那一頁的查詢要自己關掉
- 那一頁的頁首不得顯示那一筆的名稱或任何內容（03-03 §共用任務標頭 第 8 條；Hard Rule 6）

## 畫面狀態

`BlockedScreen` 本身就是那一頁的「無權限」或「找不到」狀態，不取資料，所以 F8 的四種狀態在它身上的意思如下。

| 狀態             | 呈現                                                                                                                                                                                                                                                                                    |
| :--------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| loading          | 不適用：元件不取資料。那一頁在判定完成前顯示**它自己的**骨架；骨架只畫形狀，不畫任何那一筆的內容或「測試集」之類的字樣，判定為拒絕或找不到後整塊換成 `BlockedScreen`。`NotFoundPage` 沒有載入期：守門判定登入前只畫頁面底色（`auth-guard`「畫面判定完成前不顯示任何頁面內容」）         |
| error            | 不適用：元件沒有會失敗的請求。那一頁的**一般**載入失敗（`5xx`、連不上、逾時）不是這兩種畫面（07-03 §不在本頁範圍 第 3 條），照那一頁的錯誤狀態顯示訊息與重試                                                                                                                            |
| empty            | 不適用。「有權限、那一筆也在、只是沒內容」是那一頁的空狀態，不得畫成找不到（07-03 §不在本頁範圍 第 3 條、Q&A「這兩種畫面和空狀態差在哪」）；反過來，找不到也不得畫成空白清單或空白詳情（Scenario「反向：不得用空白內容代替找不到」），所以 `BlockedScreen` 取代整個內容區，不疊在清單上 |
| 無權限（403）    | 就是 `BlockedScreen` 種類＝無權限：標題、說明（帶識別碼、提到可以找誰）、一個寫出去處的返回連結；**沒有重試**（F8；07-03 §畫面的組成 第 6 條）。`404` 與「本來就不該知道它存在」都畫成種類＝找不到，畫面上不出現任何暗示那一筆存在的字（07-03 §兩種畫面的分工 第 3 條、Q2）             |
| 欄位被遮蔽       | 不適用：畫面上沒有那一筆的任何欄位，所以沒有「已遮蔽」要呈現；唯一出現的是識別碼本身，而它是使用者自己帶進網址的值，不是後端回的資料                                                                                                                                                    |
| 沒帶識別碼       | 種類＝找不到，說明改用「未指定」那一種、不假造識別碼（07-03 §找不到的畫面 第 2 條）。標題用哪一句由那一頁定（標記清單用「尚未選擇任務」，G-48，#773）                                                                                                                                   |
| 表單驗證、送出中 | 不適用：畫面沒有任何可以改的東西，沒有表單、送出或儲存（07-03 §畫面的組成 第 6 條）                                                                                                                                                                                                     |

### 唯讀角色與測試集答案

- 三種系統角色看到的結構完全相同，沒有唯讀變體；畫面本來就沒有可寫的東西
- **Hard Rule 6**：標記員到得了這兩種畫面，所以畫面、它的標題、說明、骨架與錯誤字都**只能**出現識別碼本身與固定字面，不得出現那一筆的名稱、狀態、資料筆數、是否為測試集或任何答案；後端讀標準答案的操作一律回找不到（sa §兩條硬規則的交界），前端照樣只畫找不到，不加「這裡有東西但你看不到」之類的暗示

## 互動與無障礙

- **結構**：容器是一個以標題命名的區域（`section` ＋ `aria-labelledby` 指向標題），取代內容區；外殼的 `<main>` 不變
- **到達時焦點**：畫面掛上時把焦點移到標題（標題可被程式聚焦、不進 Tab 順序），螢幕閱讀器會讀出「是哪一種狀況」；標題被程式聚焦時不畫焦點框，因為它不是可操作元素。下一個 Tab 停在返回連結。**不用** prototype 的 `role="alert"`：焦點移過去已經會朗讀，兩者並用會讀兩次（U3）
- **返回連結**：原生連結，Enter 觸發；可存取名稱就是寫出去處的標籤（「回儀表板」），不加只有圖示的按鈕；焦點環沿用 Button 的 `focus-visible`
- **語言**：切換語言時標題、說明、連結跟著換（字面來自翻譯）；通用頁的瀏覽器標題一起換
- **不只靠顏色**：兩種畫面靠標題文字分辨，不靠顏色
- **對比**：`--color-ink`、`--color-ink-muted` 在 `--color-white` 上都過 WCAG AA（`tokens.css` 註解：`--color-ink-muted` 在白底 5.40:1）；返回連結用 Button `default` 的既有配對
- **減少動態效果**：沒有任何過場，不受影響
- **識別碼**：雙向隔離，含右至左控制字元的識別碼不會把整句翻轉；過長時在任意字元換行，不撐破容器、不出現水平捲軸
