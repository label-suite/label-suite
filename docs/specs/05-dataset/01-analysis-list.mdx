## 目標

| 目標 | 誰受益 |
| :--- | :--- |
| 讓:ref[專案負責人]{id="term.project-leader"}與:ref[審核員]{id="term.reviewer"}**一眼看到自己有哪些任務可以分析**，不必從任務列表裡自己挑 | 兩種角色——分析的入口與任務管理的入口是兩回事 |
| 讓人**用輸出類型找任務**，而且**複合任務也找得到** | 同時做多種標記的任務——它們最容易在單選式的篩選裡消失 |
| 讓 :ref[IAA]{id="term.iaa"} 的**狀態**在列表上就看得到，不必逐個任務點進去 | 要掌握整體品質的專案負責人 |
| 讓篩選與分頁**一個網址就能分享**，重新整理也還在 | 需要互相對照同一組條件的人 |
| 讓這一頁**只讀摘要、碰不到任何答案內容** | 整個標記品質管線——分析入口若能讀到答案，測試集保護就破了 |

## 使用角色

| 角色 | 這一頁能做什麼 | PRD §權限矩陣的上限 |
| :--- | :--- | :--- |
| :ref[專案負責人]{id="term.project-leader"} | R | 「05 資料集分析」給專案負責人 `R` |
| :ref[審核員]{id="term.reviewer"} | R | 同一列給審核員 `R` |
| :ref[標記員]{id="term.annotator"} | **進不來** | 同一列給標記員 `—` |

- 這一頁**完全唯讀**，沒有任何新增、編輯或刪除
- 看得到哪些任務，**依使用者在那個任務的:ref[任務角色]{id="term.task-role"}**：只有任務角色是專案負責人或審核員的任務才會出現
- 正式上線後另有一道**任務層級的權限**條件：「**看任務統計**」**或**「**看品質分析**」有一項成立即可（兩者之間是「或」）
- 上一條與前一條的**任務角色條件要同時成立**才列入；而這一頁不是作業頁，所以權限取使用者**各個生效成員身分的允許聯集**
- 這兩項權限是 PRD §權限矩陣那一格的**細化、不放寬**（依 `spec-migration.md` 的 D10）；種子設定只開給專案負責人與審核員，所以上線初期的可見範圍與任務角色那一條相同
- 受邀但還沒生效的成員身分**視同不存在**
- :ref[系統管理員]{id="term.system-admin"}沒有任務角色時進不來，和[規格 03-03](../03-task-management/03-task-detail.mdx)一樣
- 這一頁只是**入口**；進去之後各分頁各自的權限由[規格 05-02 §使用角色](./02-analysis-detail.mdx#使用角色)定義

這一頁的流程分兩段寫：先把範圍縮到「我有資格的任務」，再從那些任務裡挑一個。兩段各自有自己的例外，合成一段會超過流程圖的節點上限。

### 進到分析列表

1. 使用者從側欄點「資料集分析」（見[規格 07-01](../07-shared/01-sidebar.mdx)）
2. 系統列出他在**成員資格內**的任務
3. 載入成功嗎？
   - 成功 → 下一步
   - 失敗 → 保留表頭並顯示錯誤與「重試」，**不得顯示成「尚無可分析的任務」**，流程結束（例外流程 **E2**）
4. 有任務嗎？
   - 有 → 顯示任務名稱、輸出類型標籤、完成率、IAA 狀態與成員角色
   - 完全沒有 → 保留表頭並顯示「尚無可分析的任務」，流程結束（例外流程 **E1**）
5. 結果：使用者看到一張只含他有資格分析的任務的列表

### 從列表挑一個任務

1. 使用者用輸出類型、IAA 狀態或關鍵字縮小範圍
2. 有符合的嗎？
   - 有 → 下一步
   - 沒有 → 保留表頭並顯示空結果說明與「清除篩選」，清掉條件回到第 1 步（替代流程 **A1**）
3. 點某一列 → 進入那個任務的**統計總覽**
4. 結果：使用者離開這一頁，停在那個任務的統計總覽上

> 兩段的例外代號沿用原本的語意：**E1** 是「完全沒有符合成員資格的任務」、**E2** 是「列表載入失敗」、**A1** 是「篩完沒有符合的」。拆節只動了段落邊界，沒有重新編號。

## 規格

### 模組入口

<PrototypeFrame page="dataset/dataset-analysis-list" caption="分析列表" client:idle />

1. 這一頁是**資料集分析模組的入口**；沒有它，使用者沒有地方可以選要分析哪一個任務
2. 頁面副標題是 `資料集標記一致性與任務執行情形分析`
3. 主要入口是側欄的「資料集分析」；**儀表板的徽章深連結是合法的次入口**
4. 列表**只顯示使用者具成員資格的任務**（見[§使用角色](#使用角色)）

### 任務列表的欄位

<PrototypeFrame page="dataset/dataset-analysis-list" caption="分析列表" client:idle />

1. 列表是**表格式**的，視覺樣式與輸出類型標籤的語意**對齊[任務列表](../03-task-management/01-task-list.mdx)**
2. 每一列**至少**顯示這五欄：

| 欄 | 標題 | 內容 |
| :--- | :--- | :--- |
| 1 | `任務名稱` | 跟著語言切換 |
| 2 | `輸出類型` | 依設定的順序**逐一**顯示標籤，見[§輸出類型標籤](#輸出類型標籤) |
| 3 | `完成率` | 百分比，另有進度條；它是**上游算好的摘要**，這一頁不自己算 |
| 4 | `IAA 狀態` | 徽章，五種狀態之一，見[§IAA 狀態徽章](#iaa-狀態徽章) |
| 5 | `成員角色` | 使用者在那個任務的任務角色；身兼兩種時**兩個徽章都顯示**，見[§已確認決議](#已確認決議) Q1 |

3. 完成率與 IAA 狀態都是**上游算好的摘要**：這一頁**讀它們來顯示，但不得自行推導或計算**
4. 一個人在同一個任務**身兼兩種任務角色**時（例如既是專案負責人又是審核員），第 2 條第五欄**兩個徽章都顯示**，依設定的角色順序排列；**不得**只顯示其中一個，也不得改成「主角色＋其他」的省略寫法。見[§已確認決議](#已確認決議) Q1
5. 完成率**只有一份資料來源**，與[規格 04-01 §任務資訊卡](../04-annotation/01-annotation-list.mdx#任務資訊卡)的工作統計、[規格 02-01 儀表板](../02-dashboard/01-dashboard.mdx)的任務列同源；這一頁只讀來顯示、不自己算
6. 第 5 條說的是**來源**，不是同一個數字：**這一欄是任務層級的整體完成率**（這一頁只有專案負責人與審核員進得來，他們要看的是整個任務的進度），而規格 04-01 的任務資訊卡顯示的是**那一位標記員自己的**完成率。兩者是同一份來源的**不同聚合**；規則是「**同一個任務、同一個角色**的數值在各頁必須一致」，不是「全站只有一個數字」。見[§已確認決議](#已確認決議) Q2

### 輸出類型標籤

<PrototypeFrame page="dataset/dataset-analysis-list" caption="分析列表" client:idle />

1. **每一個輸出類型各自一個標籤**，依設定裡的**原順序**排列——**複合任務不得壓縮成單一固定類型**
2. 標籤是**唯讀**的
3. 標籤的文字與選項**由任務設定的輸出類型清單驅動**，**不得寫死任務名稱或固定的組合**
4. **顏色只能當輔助**：標籤**必須有可見文字**，而且整個標籤群要有**可存取名稱**
5. 欄寬不足時在同一格內**換行**，**不得截斷文字、不得互相重疊、不得造成整頁水平捲動**
6. 八種輸出類型的中文名與[術語表](../glossary.mdx)一致（由[規格 03-02](../03-task-management/02-task-new.mdx)定名）

### 搜尋

<PrototypeFrame page="dataset/dataset-analysis-list" caption="分析列表" client:idle />

1. 搜尋是**不分大小寫的「包含」比對**
2. 比對範圍是**四種東西**：

| 範圍 | 說明 |
| :--- | :--- |
| 任務名稱 | — |
| 每個輸出類型的**原始鍵名**與**目前語言的文案** | 兩者都比對，所以打英文鍵名或中文名都找得到**同一批**任務 |
| IAA 狀態 | **原始值與目前語言的文案都比對** |
| 成員角色 | 同上 |

3. 輸入之後要在 **300 毫秒內**把關鍵字同步到網址
4. 搜尋框的提示文字是 `搜尋`，輔助說明（給輔助科技讀的）是 `搜尋任務名稱、輸出類型、IAA 狀態與角色`
5. 篩選列上另有 **`清除篩選`**，**只要套了任何一個條件就出現**——不是只在「篩選後沒有結果」那個畫面才有

### 輸出類型篩選

<PrototypeFrame page="dataset/dataset-analysis-list" caption="分析列表" client:idle />

1. 篩選選項是 `全部輸出類型` **加上恰好 8 個**輸出類型，**由任務設定的輸出類型清單提供**
2. 選項的**值與顯示文案分離**：值是原始鍵名，顯示的是中文名
3. 比對採**「含有」語意**：只要任務的輸出類型**任一個**等於所選的那一個就命中
4. 第 3 條是這一節的重點——**不得只比第一個，也不得要求整組完全相等**。否則複合任務會在單選式篩選裡整批消失

### IAA 狀態徽章

<PrototypeFrame page="dataset/dataset-analysis-list" caption="分析列表" client:idle />

1. 徽章**只顯示上游品質分析算出來的摘要狀態**，**不顯示原始的 IAA 數值**
2. 列表**不得自己從標記答案重算** IAA
3. 五種狀態（中文名的定名理由見[§已確認決議](#已確認決議)）：

| 狀態 | 徽章文字 | 什麼時候 |
| :--- | :--- | :--- |
| 通過 | `通過` | 品質分析算出的結果達標 |
| 計算中 | `計算中` | 還在算 |
| 未通過 | `未通過` | 算出來沒達標 |
| 尚未開始 | `尚未開始` | 還沒開始算 |
| 不適用 | `不適用` | 這個任務的輸出類型**全部都不計入 IAA 達標分母**（兩個集合，見下方第 5 條） |

4. 第 3 條最後一列是硬規則：那種任務的徽章**必須顯示「不適用」**，**不得顯示通過、未通過、計算中、尚未開始，也不得留空白**
5. 不計入達標分母的是**兩個集合**，由[規格 05-02 §已確認決議](./02-analysis-detail.mdx#已確認決議) Q12 定案：**自由文字**（永久沒有自動指標）與**序列標註**（算得出數值、但平台還沒訂門檻）。所以只有自由文字、只有序列標註、或兩者兼有的任務，徽章都是「不適用」
6. 這一頁**只引用**第 5 條的結論，**不自己定義**那兩個集合；兩者的語意不同（見[規格 05-02](./02-analysis-detail.mdx#自由文字永久沒有自動指標)），但對這一頁的徽章而言效果相同
7. 篩選器的選項是 `全部 IAA 狀態` 加上那五種

### 分頁

<PrototypeFrame page="dataset/dataset-analysis-list" caption="分析列表" client:idle />

1. 分頁列在列表底部，含**總筆數與目前頁數**、每頁筆數切換、上一頁／下一頁，以及**有限數量的頁碼按鈕**
2. 分頁資訊的格式是 `共 〈總筆數〉 筆 · 第 〈頁碼〉 / 〈總頁數〉 頁`
3. 每頁筆數**預設 20**，可切換 **20、50、100**
4. 每頁筆數的選項顯示成「〈數字〉 筆/頁」
5. 位移**預設 0**

### 查詢條件保留在網址

<PrototypeFrame page="dataset/dataset-analysis-list" caption="分析列表" client:idle />

1. 網址**只允許這五個查詢條件**：關鍵字、輸出類型、IAA 狀態、每頁筆數、位移
2. **不支援的、或歷史留下的未知查詢條件，必須移除**
3. 這五個條件要在**重新整理、切換分頁、以及返回這一頁**時還原
4. **預設值可以省略**，不必寫進網址
5. **搜尋、輸出類型或 IAA 狀態改變時，位移重設為 0**；**每頁筆數改變時也重設為 0**
6. 第 5 條的理由很實際：不重設的話，使用者會停在一個新結果集裡不存在的頁數上，看到的是空白
7. 無效的值要**回退**並**用正規化後的條件更新網址**：

| 情況 | 怎麼回退 |
| :--- | :--- |
| 輸出類型、IAA 狀態不是認得的值 | 回退成**無篩選** |
| 每頁筆數、位移不是合法值 | 回退成**預設值** |
| 位移**超出結果範圍** | 正規化成**最後一個合法的位移** |

### 四種互斥的頁面狀態

<PrototypeFrame page="dataset/dataset-analysis-list" caption="分析列表" client:idle />

1. 結果區由**四種互斥的狀態**驅動，同一時刻恰好成立一種：

| 狀態 | 什麼時候 | 畫面 |
| :--- | :--- | :--- |
| 載入中 | 資料還沒到位 | — |
| 就緒 | 有結果 | 列表 |
| 空 | 使用者**完全沒有**符合成員資格的任務 | 標題 `尚無可分析的任務`、說明 `你目前沒有具分析權限的任務，請聯繫專案負責人確認成員資格。` |
| 錯誤 | 列表載入失敗 | 標題 `資料集分析載入失敗`、說明 `無法載入任務資料，請稍後再試。`，另有 `重試` |

2. 還有**第五種**畫面：**篩選後沒有結果**。它與「空」**不是同一種**——標題 `找不到符合條件的分析任務`、說明 `請調整搜尋條件或清除篩選，重新查詢。`，另有 `清除篩選`
3. 這三種「沒有列」的畫面**都要保留表頭**，而且**不得互相混用**：

| 不得混用的組合 | 為什麼 |
| :--- | :--- |
| 錯誤 ↔ 空 | 載入失敗時顯示「尚無可分析的任務」，會讓使用者以為**自己沒有權限**，而其實只是讀取失敗 |
| 空 ↔ 篩選後沒有結果 | 前者要去找專案負責人確認成員資格，後者只要清掉篩選 |

4. 「載入中」是來源明文要求的四態之一，但**目前的畫面沒有實作它**。這與[規格 04-01 §待釐清](../04-annotation/01-annotation-list.mdx#待釐清) Q13 之外的那一題（Q8：那一頁要不要有載入狀態）是同一類；**這一頁的來源有明文，所以照寫**，而畫面補不補由該題一併決定

### 點任務列進入分析詳情

<PrototypeFrame page="dataset/dataset-analysis-list" caption="分析列表" client:idle />

1. 點任一任務列就導向**那個任務的分析詳情**，而且**預設進入統計總覽那個分頁**
2. 整列都是可點的（不只任務名稱）
3. 用舊連結或無效的任務代號直接進詳情時，由[規格 05-02 §進來先驗兩件事](./02-analysis-detail.mdx#進來先驗兩件事任務代號與成員資格)處理並**退回這一頁**；退回後顯示的那句提示也由那一頁定義，這一頁只負責把它顯示出來

### 不同螢幕寬度的呈現

<PrototypeFrame page="dataset/dataset-analysis-list" caption="分析列表" client:idle />

1. 在 **375、768、1440** 三種寬度下，搜尋、篩選、分頁、選任務與導頁**都要能完成**
2. 手機版（寬度 **767 以下**）欄位空間不足時：**允許表格橫向捲動**，標籤在格內**換行**
3. 但**操作與文字不得重疊**，而且複合任務的多個標籤**不得造成整頁水平捲動**

### 列表碰不到的東西

<PrototypeFrame page="dataset/dataset-analysis-list" caption="分析列表" client:idle />

這一節是這一頁的**測試集保護**。

1. 列表的資料**只能包含任務與分析摘要**
2. **不得包含、也不得由列表推導**下列任何一種：:ref[標準答案]{id="term.ground-truth"}、參考答案、標記答案，或任何等價的答案內容
3. 第 2 條涵蓋**四個地方**：列表的資料、頁面上、搜尋的比對範圍、以及網址
4. 完成率與 IAA 狀態是**上游算好的摘要**；列表**不得自行推導或計算**它們（但當然要讀得到才顯示得出來）
5. 任務設定本身（各輸出類型的設定內容）**也不在這一頁的資料範圍內**

### 任何合法的輸出類型組合都要能用

<PrototypeFrame page="dataset/dataset-analysis-list" caption="分析列表" client:idle />

1. 新增一個**任意合法輸出類型組合**的任務時，列表的顯示、搜尋與篩選**都不得需要為它加一條分支**
2. 第 1 條**不得用任務名稱或固定的組合**來實作
3. 原型載入了 13 份示例任務當**驗收基線**——它們**只用於驗收**，**不代表**正式系統的任務筆數、名稱或合法組合的上限
4. 所以在示例資料加上第 14 筆任意合法組合時，**必須直接顯示得出來也篩得到**

### 資料欄位

| 欄位 | 型別 | 必填 | 規則 | 使用者看到 |
| :--- | :--- | :--- | :--- | :--- |
| 任務代號 | 文字 | 是 | 點列時用它導向詳情 | 不直接顯示 |
| 任務名稱 | 文字 | 是 | 跟著語言切換；搜尋的比對範圍之一 | 第一欄 |
| 輸出類型 | 清單 | 是 | **依設定的原順序**各自一個唯讀標籤；篩選採「含有」語意 | 第二欄的多個標籤 |
| 完成率 | 百分比 | 是 | **上游算好的摘要**，列表不得推導或計算；這一欄是**任務層級的整體**完成率，與規格 04-01、02-01 同一份來源但不同聚合（見[§已確認決議](#已確認決議) Q2） | 第三欄的數字與進度條 |
| IAA 狀態 | 單選：通過、計算中、未通過、尚未開始、不適用 | 是 | 只顯示摘要狀態，**不顯示原始數值**；輸出類型全為 IAA 排除類型時**必須是「不適用」** | 第四欄的徽章 |
| 成員角色 | 清單：專案負責人、審核員 | 是 | 使用者在那個任務的任務角色；**身兼兩種時兩個都帶**（見[§已確認決議](#已確認決議) Q1） | 第五欄的一或兩個徽章 |
| 關鍵字 | 文字 | 否 | 不分大小寫的「包含」；輸入後 **300 毫秒內**同步網址 | 搜尋框 |
| 輸出類型篩選 | 單選：全部，或 8 種之一 | 否 | 值是原始鍵名、顯示是中文名；無效值回退成無篩選 | 篩選器 |
| IAA 狀態篩選 | 單選：全部，或 5 種之一 | 否 | 同上 | 篩選器 |
| 每頁筆數 | 整數 | 否 | 預設 20，可選 20／50／100；改變時位移重設為 0 | 分頁列 |
| 位移 | 整數 | 否 | 預設 0；超出結果範圍時正規化成最後一個合法值 | 分頁列 |
| 總筆數 | 整數 | 是 | 篩選後的筆數 | 分頁列的「共 N 筆」 |

- 這一頁的欄位**全是唯讀摘要**；**沒有任何一欄含答案內容**（見[§列表碰不到的東西](#列表碰不到的東西)）
- 任務名稱、IAA 狀態與成員角色的文案**跟著語言切換即時更新**

## 卡控機制

| 條件 | 結果 |
| :--- | :--- |
| 使用者在某任務的任務角色不是專案負責人也不是審核員 | 那個任務**不出現**在列表 |
| 使用者在某任務**身兼兩種任務角色** | 成員角色欄**兩個徽章都顯示**，依設定的角色順序排列；只顯示一個、或用「主角色＋其他」的省略寫法即違規 |
| 成員身分是受邀但還沒生效 | **視同不存在** |
| 使用者完全沒有符合成員資格的任務 | 顯示「尚無可分析的任務」，**不顯示錯誤頁**、不導去別頁 |
| 使用者只有標記員的成員資格 | 同上——顯示空狀態，**不導回其他頁面** |
| 列表載入失敗 | 顯示錯誤與「重試」，**不得顯示成「尚無可分析的任務」** |
| 篩選後沒有結果 | 保留表頭，顯示空結果說明與**一鍵清除篩選** |
| 三種「沒有列」的畫面 | **都要保留表頭**，而且**不得互相混用** |
| 任務的輸出類型是空的、缺少、或含認不得的鍵 | 那一列的資料契約無效 → 顯示**可重試的錯誤狀態**，**不得猜一個預設的輸出類型** |
| 輸出類型篩選 | 採**「含有」語意**；**不得只比第一個**，也**不得要求整組完全相等** |
| 輸出類型標籤 | **每個輸出類型各一個**，依原順序；**不得壓縮成單一類型** |
| 標籤的呈現 | **必須有可見文字**，顏色只能當輔助；標籤群要有可存取名稱 |
| 欄寬不足 | 格內**換行**；**不得截斷、不得重疊、不得造成整頁水平捲動** |
| 選項與文案的來源 | **由任務設定的輸出類型清單提供**；**不得寫死任務名稱或固定組合** |
| 搜尋 | 比對任務名稱、每個輸出類型的**原始鍵名與目前語言文案**、IAA 狀態、成員角色 |
| 搜尋輸入 | **300 毫秒內**同步到網址 |
| 網址的查詢條件 | **只允許那五個**；不支援或未知的**必須移除** |
| 搜尋、輸出類型或 IAA 狀態改變 | **位移重設為 0** |
| 每頁筆數改變 | **位移重設為 0** |
| 輸出類型或 IAA 狀態是認不得的值 | 回退成**無篩選**，並用正規化後的條件更新網址 |
| 每頁筆數或位移不合法 | 回退成**預設值**，並正規化網址 |
| 位移超出結果範圍 | 正規化成**最後一個合法的位移** |
| IAA 徽章 | **只顯示摘要狀態**，**不顯示原始數值**；列表**不得自己重算** |
| 任務的輸出類型全是 IAA 排除類型 | 徽章**必須是「不適用」**；**不得**顯示通過、未通過、計算中、尚未開始，也**不得留空白** |
| 點任務列 | 導向那個任務的分析詳情，**預設進入統計總覽分頁** |
| 列表的資料、頁面、搜尋比對範圍與網址 | **都不得包含或推導**標準答案、參考答案、標記答案或等價內容 |
| 完成率與 IAA 狀態 | 是**上游算好的摘要**；列表**不得自行推導或計算**（禁止「載入」的受詞是答案內容，見上一列） |
| 新增任意合法輸出類型組合的任務 | 顯示、搜尋與篩選**不得需要為它加分支** |
| 三種螢幕寬度 | 搜尋、篩選、分頁、選任務與導頁**都要能完成** |

## 邊界情況（Edge Case）

| 情況 | 使用者看到什麼 |
| :--- | :--- |
| 使用者沒有任何符合成員資格的任務 | 「尚無可分析的任務」與「請聯繫專案負責人確認成員資格」；不是錯誤頁 |
| 使用者只有標記員身分 | 同上，而且**不會被導走** |
| 篩選條件組合得太細，沒有結果 | 「找不到符合條件的分析任務」與「清除篩選」 |
| 列表載入失敗 | 「資料集分析載入失敗」與「重試」；**不會**看到「尚無可分析的任務」 |
| 某任務的輸出類型是空的或含認不得的鍵 | 可重試的錯誤狀態；**不會**冒出一個猜出來的預設類型 |
| 複合任務（例如實體辨識 ＋ 關係識別） | 兩個標籤並列，而且**兩種篩選都找得到它** |
| 複合任務有三個輸出類型、而欄寬不夠 | 標籤在格內換行；文字沒有被截斷，整頁也沒有左右捲動 |
| 任務的輸出類型全是自由文字 | IAA 徽章是「不適用」，不是「尚未開始」 |
| 用英文原始鍵名搜尋 | 與用中文名搜尋得到**同一批**任務 |
| 搜尋到第 3 頁之後改了關鍵字 | 回到第 1 頁（位移重設為 0），不會停在空白頁 |
| 把每頁筆數從 20 改成 100 | 回到第 1 頁 |
| 網址帶了一個這一頁不認得的查詢條件 | 它被移除，網址被正規化 |
| 網址帶的位移超過結果總數 | 落在最後一頁，網址同步成那個合法位移 |
| 重新整理 | 篩選、搜尋、每頁筆數與頁碼都還在 |
| 從分析詳情返回這一頁 | 同上 |
| 示例資料加上第 14 筆任意合法組合 | 直接顯示得出來、篩得到，不需要改任何分支 |
| 作業中切換語言 | 欄位標題、篩選選項、標籤、IAA 與角色文案即時更新 |

## 驗收標準

| Scenario | Given | When | Then |
| :--- | :--- | :--- | :--- |
| 側欄進來是分析列表 | 使用者至少在一個任務是專案負責人或審核員 | 從側欄點「資料集分析」 | 進到分析列表，看到他可以分析的任務 |
| 身兼兩種角色顯示兩個徽章 | 使用者在某任務既是專案負責人又是審核員 | 查看那一列的成員角色欄 | 兩個徽章都在、依設定的角色順序排列，沒有省略成單一角色 |
| 單一角色只有一個徽章 | 使用者在某任務只是審核員 | 查看那一列的成員角色欄 | 只有一個徽章 |
| 只看得到自己有資格的任務 | 使用者只在其中一個任務有資格 | 開啟列表 | 只有那一個任務出現 |
| 標記員看到空狀態 | 使用者只有標記員身分 | 開啟列表 | 顯示「尚無可分析的任務」，而且**沒有**被導走 |
| 每一列的五個欄位 | 列表有結果 | 查看任一列 | 有任務名稱、輸出類型標籤、完成率、IAA 狀態與成員角色 |
| 複合任務逐一顯示標籤 | 某任務同時有實體辨識與關係識別 | 查看它的輸出類型欄 | 兩個標籤各自呈現，不是一個合成的 |
| 三個標籤的任務 | 某任務有三個輸出類型 | 查看它的輸出類型欄 | 三個標籤都在，各有可見文字 |
| 篩選採「含有」語意 | 同上那個複合任務 | 用「關係識別」篩選 | 它出現在結果裡 |
| 複合任務不會被篩掉 | 同上 | 改用「實體辨識」篩選 | 它**還是**出現 |
| 篩選選項恰好九個 | 開啟列表 | 查看輸出類型篩選器 | 「全部輸出類型」加上恰好 8 個輸出類型 |
| 原始鍵名與中文名同結果 | 某任務有實體辨識 | 分別搜尋 `entity_recognition` 與「實體辨識」 | 兩次得到同一批任務 |
| 搜尋比對角色與 IAA | 某任務的成員角色是審核員、IAA 狀態是通過 | 搜尋「審核員」與「通過」 | 兩次都找得到它 |
| 搜尋同步網址 | 使用者在搜尋框輸入文字 | 停手等一下 | 網址帶上那個關鍵字 |

### Q1. 一個人在同一個任務身兼兩種角色時，「成員角色」欄顯示什麼？（已定案，維護者裁定 2026-11-07）

- **結論**：**兩個徽章都顯示**，依設定的角色順序排列
- **依據**：`spec-migration.md` 通則步驟 4 的**第四個**依據（維護者明確拍板並記下日期）
- **為什麼不能由撰寫者決定**：來源把成員角色寫成**單一值**，畫面也是一個徽章（`design/prototype/pages/dataset/dataset-analysis-list.data.js` 的 `membershipRole` 是單一字串）——**來源與畫面一致**，衝突只在[規格 03-03](../03-task-management/03-task-detail.mdx)明寫「同一人在同一任務可能有多個角色 → 以兩者的聯集判定他看得到什麼」。兩份來源各說一套時由誰勝出不是撰寫者的判斷
- **理由（維護者採納的）**：這一欄的用途是讓使用者知道「我在這個任務是什麼身分」，而身兼兩種正是最需要說清楚的情況；而且本頁的權限判定本來就取**各生效成員身分的允許聯集**（見[§使用角色](#使用角色)），只顯示一個會與判定依據不一致
- **畫面要跟著改**：`membershipRole` 要能帶兩個值、第五欄要能放兩個徽章，由 Issue #157 處理——`design/prototype/` 不在規格搬移的可改範圍內

### Q2. 完成率由誰算出來？（已定案，維護者裁定 2026-11-07）

- **結論**：**只有一份資料來源**。與[規格 04-01](../04-annotation/01-annotation-list.mdx#任務資訊卡)的工作統計、[規格 02-01 儀表板](../02-dashboard/01-dashboard.mdx)的任務列同源；這一頁與[規格 05-02](./02-analysis-detail.mdx)都只**讀來顯示**，不自己算
- **「一份來源」不等於「一個數字」**：這一頁與規格 05-02 顯示的是**任務層級的整體**完成率（本頁來源的欄位名就是 `overall_completion_rate`），規格 04-01 的任務資訊卡顯示的是**那一位標記員自己的**完成率——同一份來源的兩種聚合。所以規則是「**同一個任務、同一個角色**的數值在各頁必須一致」
- **依據**：`spec-migration.md` 通則步驟 4 的**第四個**依據（維護者明確拍板並記下日期）
- **這條延伸既有規格，沒有放大它**：[規格 04-01 §任務資訊卡](../04-annotation/01-annotation-list.mdx#任務資訊卡)已經明寫「工作統計的數值**必須與儀表板同一個任務、同一個角色的列項一致**——同一份資料來源，**不得兩處各自維護**」。那一條帶著「**同一個角色**」這個限定詞，所以裁定延伸的是「**同一份來源**」這一半；各頁顯示哪一種聚合由各頁自己的來源決定
- **為什麼不能由撰寫者決定**：本頁來源只寫完成率是列表摘要、而且列表「**不得載入、推導或計算**」它，**誰算的、怎麼算的沒有交代**；05-02 的來源同樣沒交代（它的 Q9 是同一題）
- **同時結案**：[規格 05-02](./02-analysis-detail.mdx#已確認決議) 的 Q9 是同一題，那一頁依這條結案
- **影響**：[§任務列表的欄位](#任務列表的欄位)第 2 條第三列、第 3 與第 5 條、[§資料欄位](#資料欄位)的完成率列

## Q&A

### Q. 為什麼輸出類型篩選一定要用「含有」語意，不能比完整組合？

因為複合任務會整批消失。一個同時做實體辨識與關係識別的任務，如果篩選要求「整組完全相等」，那麼選「實體辨識」時它不會出現、選「關係識別」時它也不會出現——它只在使用者**剛好**同時選中兩者時才出現，而篩選器是單選的。而複合任務往往正是最需要看品質的那些。

### Q. 為什麼「載入失敗」與「尚無可分析的任務」一定要分開？

因為兩者要使用者做的事完全相反。看到「尚無可分析的任務」，他該去找專案負責人確認自己的成員資格；看到載入失敗，他該按重試。把前者顯示在載入失敗時，等於告訴一個其實有權限的人「你沒有權限」——而他會去做一件完全沒用的事。

### Q. 為什麼改篩選要把頁碼歸零？

因為頁碼是**舊結果集**的座標。在 35 筆的第 2 頁改了篩選、剩下 8 筆時，第 2 頁已經不存在了；不歸零的話使用者會看到一片空白，而那片空白看起來跟「沒有結果」一模一樣。
