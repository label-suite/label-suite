# Proposal

本份是 change `dashboard-shell`（Issue #722，Epic #713 共用介面外殼）的提案，摘要同目錄的 `system-analysis.md`（以下稱 sa，待決題號 sa-1～sa-9）、`system-design.md`（sd）、`ui-design.md`（ui，待決題號 U1～U4）與 `api-contract.md`，不與它們矛盾。operationId 與路徑以 `api-contract.md` 為準。

`clarification.md` 還沒寫。下列凡標「待 sa-N」「待 UN」的地方，本份只寫建議走的路與另一條路會改變什麼，**不替維護者決定**；specs、design、tasks 依 clarification 的決議撰寫。

## Why

登入成功、已登入的人開登入頁、開根路徑，都已經前往 `/dashboard/dashboard`，但那裡目前是 #719 的暫時落點（「你已登入」卡片加「儀表板還在建置中」，`openspec/specs/auth-guard` Requirement「暫時落點顯示目前登入者」）。規格 02-01 要求登入後的第一站依系統角色與任務角色給出各自的版面；#733、#736、#741 要在這層外殼裡補上任務、標記與審核、IAA 與提醒各區塊，所以外殼要先做（Issue #722 §使用情境 / 功能範圍、§驗收條件 第 2 項）。

## What Changes

- **取代暫時落點**：`/dashboard/dashboard` 網址不變，頁面由暫時落點換成儀表板；「你已登入」卡片、「儀表板還在建置中」、瀏覽器標題「Label Suite — 你已登入」一起拿掉，瀏覽器標題改為「Label Suite — 儀表板」（Issue #722 §驗收條件 第 2 項；ui §頁面與路由、§文案）。**BREAKING**（規格層）：`auth-guard` 的暫時落點 Requirement 移除，依賴「你已登入」字樣的既有測試要改；API 與資料庫不變
- **頁首**：主標題 `儀表板`、副標題 `掌握任務進度與團隊協作狀態`，在每一種版面最上方，隨語言切換（02-01 §這一頁顯示哪一種版面 第 5–8 條）。被側欄擋下回來時擋下說明與頁首的上下順序待 sa-5
- **依角色決定版面**：系統管理員（含 Seeder 管理員）→ 全平台版面，不讀任務角色；平台成員 → 依任務角色與優先序（專案負責人 > 審核員 > 標記員）決定一種版面；系統角色無效 → 不畫任何版面、導向登入頁（同節第 1–4 條）。三種任務角色版面本單**只有頁首**（維護者 2026-11-28）。角色無效時要不要同時結束登入狀態待 sa-7
- **讀取任務角色的骨架與錯誤**：讀取中顯示骨架，讀完直接換成版面；讀取失敗（伺服器錯誤或逾時）顯示 `儀表板載入失敗`、說明與 `重試`，且不改成其他版面、不清掉登入狀態、不導向登入頁；`401` 走既有的換發與守門，不進這個錯誤畫面（同節第 9–15 條；`api-contract.md` §端點總覽 的 `401` 說明）。任務角色從哪裡讀待 sa-1，重試期間畫什麼待 U1
- **還沒有任務角色的版面**：區塊標題、副標與三張行動入口卡（標題、說明、三步名稱、按鈕）；卡 A 去 03-01 任務列表，卡 B、C 去 04-01 標記清單並帶入口標記，從卡片進入不經側欄的擋下判斷（02-01 §還沒有任務角色的人看到什麼；`02-dashboard/index.mdx` §Logic Flow 分段一 第 4–6 條；07-01 §進入模組的條件 第 4 條、Q13；04-01 §路由上下文與回退 第 1、11 條）。卡 B 照規格寫「提交」（維護者 2026-11-28）。去處頁面尚未建置時按鈕怎麼表現待 sa-2
- **系統管理員的區塊 A**：`平台使用者統計` 四張指標卡 `總用戶`、`專案負責人`、`標記員`、`審核員`，單位人，都是示範值並以看得見的文字標示（02-01 §系統管理員看到的四個區塊 第 1、2、4 條；§審核概況那三張卡是示範值 第 6–8 條；Q4）。系統管理員版面本單**只有區塊 A**（維護者 2026-11-28）。示範值從哪裡來、是哪幾個數待 sa-3，標示文字待 sa-4
- **共用原語**：新增指標卡原語（跨三個 feature 會用到，放共用元件區），骨架原語加光帶變體；元件展示頁各加一節（ui §元件樹、§設計系統異動）
- **由 #720 移交**：規格 07-01「從儀表板行動入口卡進入不被擋下」（Issue #722 留言 2026-11-27）
- **語言、窄螢幕、鍵盤、資料邊界**：本次存在的區塊隨語言切換、缺翻譯不中斷；窄螢幕指標卡兩欄、任何寬度不需左右滑動、鍵盤走得完；這一頁看不到標準答案（02-01 §這一頁看不到標準答案、§導覽、語言與登出不在這一頁、§在窄螢幕上的呈現）
- **不包含**（接手 issue）：系統管理員區塊 B、D 與專案負責人版面的區塊（#733）；標記員、審核員版面的區塊、快速繼續、快速審核、排序、空狀態（#736）；「等待 IAA 確認」與區塊 C 最近提醒（#741）；真實的任務角色讀取（#766）；任務列表（#730）與標記清單（#773）本身；個人設定頁（#727，Scenario 83 的前提）；側欄、語言切換、登出（07-01，#720 已完成）；任何 `docs/specs/`、`design/prototype/` 的改動

## Capabilities

### New Capabilities

- `dashboard`：儀表板頁——依系統角色與任務角色決定版面與優先序、頁首、讀取任務角色時的骨架與錯誤、還沒有任務角色的行動入口卡與其去處、系統管理員的區塊 A 與示範值標示、語言與窄螢幕呈現、資料邊界。#733、#736、#741 之後在這個 capability 加各版面的區塊。來源：規格 02-01 §規格、§卡控機制、§邊界情況、§驗收標準；07-01 §進入模組的條件 第 4 條與 Scenario「從儀表板行動入口卡進入不被擋下」

### Modified Capabilities

- `auth-guard`：REMOVED Requirement「暫時落點顯示目前登入者」（整條被儀表板取代，ui §交給 planner／sd 的明確事項）。待 sa-7：選提案 B（導向前先結束登入狀態）時，另 MODIFIED 守門對角色無效的處理；選提案 A 則只有這一條 REMOVED
- `frontend-routing`：MODIFIED Requirement「每頁設定瀏覽器標題」，頁名清單的「暫時落點（你已登入）」改為「儀表板」
- `component-gallery`：MODIFIED Requirement「原語宣告的 variant 集合固定」（骨架的兩種動畫）與「展示頁列出每個宣告的項目」（區塊數與順序加指標卡）

視待決題而定、目前不列入的：

- `app-shell-sidebar`：sa-5 選 (b)「頁首在上、說明緊接在下」時，Requirement「沒有任務角色時從側欄進入標記作業被擋下」的「內容區最上方」要 MODIFIED（改規格字面要先走 `spec-writing`）；sa-1 選 B 且側欄改讀同一端點時，Requirement「角色標示與第三個導覽項依任務角色來源」要 MODIFIED。兩者都不成立時不改
- 不改：`frontend-i18n`（新增 `dashboard` 語言檔屬既有規則的範圍，缺翻譯備用規則沿用）、`account-login`（登入後去處不變）、`denied-and-not-found-screens`（「回儀表板」去處不變）、`permission-authorization`、`role-permission-matrix`（畫面不讀矩陣；sa-1／sa-3 選 B 時才掛 `dashboard.view`，屬既有鍵）、`login-session`（sa-7 選 B 也只是呼叫既有 `deleteCurrentSession`）

## Impact

- **後端**：sa-1、sa-3 選 A 時無。選 B 時見上表；兩案都沒有資料模型異動與 Alembic migration（sd §資料模型異動）
- **前端**：`/dashboard/dashboard` 的頁面元件換成新的儀表板頁（`frontend/src/pages/dashboard/`），儀表板專屬元件放 `frontend/src/features/dashboard/`（版面決定純函式、骨架佈局、錯誤面板、行動入口卡、區塊 A）；新增共用指標卡原語 `frontend/src/components/ui/metric.tsx`，骨架原語加光帶變體；新增 `dashboard` 語言檔並在啟動時預載；任務角色來源改成三態形狀（sa-1 A）；刪除暫時落點頁、`SignedInCard` 與 `auth` 語言檔的 `dashboard.*` 鍵；卡片連結與側欄共用同一組路徑常數（位置由 design 定）。檔案以 ui §元件樹 為準
- **API**：sa-1、sa-3 選 A 時沒有端點異動，只沿用 `getCurrentSession`（讀 `data.user.role`，與守門共用快取、不多送請求）
- **依賴**：不新增套件
- **常駐文件**：`docs/diagrams/architecture/frontend-routes.mdx` 已在規劃階段依 ui 改好（以 sa-2 (a) 的寫法），clarification 後依 sa-1、sa-2、sa-3 的決議校正。`backend-modules.mdx`、`error-codes.mdx`、`endpoint-authorization.mdx`、`data-table-dictionary.mdx` 只在 sa-1 或 sa-3 選 B 時改
- **設計系統**：apply 時同 PR 改 `design/system/components/metric.md`、`screen-inventory.md`、`components/skeleton.md` 的「程式實作」（ui §設計系統異動）。`brand.md` 是否登記「提交」例外待 C-1；`design/prototype/` 不改
- **規格書**：本次不改 `docs/specs/`。sa-4 若決定寫一句新的示範值標示文案、sa-5 若選 (b)，要先以 `spec-writing` 回寫 02-01 或 07-01
- **測試**：版面決定以純函式單元測試逐條驗證 02-01 第 1–4 條與優先序（三種任務角色版面本次正式環境到不了）；骨架與讀取失敗以測試替身製造；E2E 涵蓋登入後到達儀表板、兩種存在的版面、窄螢幕與鍵盤；依賴「你已登入」的既有 E2E 改寫
- **Hard Rule 5（任務設定驅動）**：版面與卡片不依任務類型或輸出類型分支；卡片連結只帶入口標記與角色參數，不帶任務類型（sa §角色與權限；ui §頁面與路由）
- **Hard Rule 6（測試集答案不外露）**：本次碰到的回應只有登入者自己的四個帳號欄位（選 B 時另有角色名稱集合或四個固定整數），沒有任務、資料集、項目、標準答案或測試集辨識資訊；區塊 A 是示範值（sd §權限檢查點；`api-contract.md` 各端點的測試集答案隔離）
- **後續單**：#733、#736、#741 在本次的版面裡補區塊並沿用骨架、示範值標示方式；#766 接上真實任務角色時側欄與儀表板一起改變；#773 依入口標記分辨站內進入；#730、#773 建好後補驗 sa-2 移交的部分（若選 (a)）
