# Proposal

本份是 change `dashboard-shell`（Issue #722，Epic #713 共用介面外殼）的提案，摘要同目錄的 `system-analysis.md`（以下稱 sa，待決題號 sa-1～sa-9）、`system-design.md`（sd）、`ui-design.md`（ui，待決題號 U1～U4）與 `api-contract.md`，並依 `clarification.md`（Q1～Q10 與「不需維護者決定」表）的決議撰寫，不與它們矛盾。operationId 與路徑以 `api-contract.md` 為準。

## Why

登入成功、已登入的人開登入頁、開根路徑，都已經前往 `/dashboard/dashboard`，但那裡目前是 #719 的暫時落點（「你已登入」卡片加「儀表板還在建置中」，`openspec/specs/auth-guard` Requirement「暫時落點顯示目前登入者」）。規格 02-01 要求登入後的第一站依系統角色與任務角色給出各自的版面；#733、#736、#741 要在這層外殼裡補上任務、標記與審核、IAA 與提醒各區塊，所以外殼要先做（Issue #722 §使用情境 / 功能範圍、§驗收條件 第 2 項）。

## What Changes

- **取代暫時落點**：`/dashboard/dashboard` 網址不變，頁面由暫時落點換成儀表板；「你已登入」卡片、「儀表板還在建置中」、瀏覽器標題「Label Suite — 你已登入」一起拿掉，瀏覽器標題改為「Label Suite — 儀表板」（Issue #722 §驗收條件 第 2 項；ui §頁面與路由、§文案）。**BREAKING**（規格層）：`auth-guard` 的暫時落點 Requirement 移除，依賴「你已登入」字樣的既有測試要改；API 與資料庫不變
- **頁首與擋下說明的順序**：主標題 `儀表板`、副標題 `掌握任務進度與團隊協作狀態`，在每一種版面最上方，隨語言切換（02-01 §這一頁顯示哪一種版面 第 5–8 條）。被側欄擋下回來時，擋下說明緊接在頁首下方、版面內容之上（Q4）；因此 `app-shell-sidebar` 一定要 MODIFIED，07-01 §進入模組的條件 第 3 條已由 `spec-writing` 回寫，先於 specs 提交
- **依角色決定版面**：系統管理員（含 Seeder 管理員）→ 全平台版面，不讀任務角色；平台成員 → 依任務角色與優先序（專案負責人 > 審核員 > 標記員）決定一種版面；系統角色無效 → 不畫任何版面、只導向登入頁，不另外結束登入狀態（同節第 1–4 條；sa-7 依 02-01 第 4 條與 `system-design.md` 處理）。三種任務角色版面本單**只有頁首**（維護者 2026-11-28）
- **讀取任務角色的骨架與錯誤**：任務角色沿用前端既有來源，本次不新增後端讀取（Q1）；來源補上讀取中、失敗（可重試）、完成三種狀態給儀表板用。讀取中顯示骨架，讀完直接換成版面；讀取失敗顯示 `儀表板載入失敗`、說明與 `重試`，不改成其他版面、不清掉登入狀態、不導向登入頁；`401` 走既有的換發與守門，不進這個錯誤畫面（同節第 9–15 條）。重試期間回到骨架，焦點移到骨架區的狀態提示，再失敗回到錯誤畫面（U1，依第 9 條）。真實的任務角色讀取待 #766 建好任務成員後接上
- **還沒有任務角色的版面**：區塊標題、副標與三張行動入口卡（標題、說明、三步名稱、按鈕）；三張卡的按鈕連到最終路徑（卡 A `/task-management/task-list`；卡 B、C `/annotation/annotation-list`，帶 `entry=nav` 與各自的 `role`），不經側欄的擋下判斷（02-01 §還沒有任務角色的人看到什麼；`02-dashboard/index.mdx` §Logic Flow 分段一 第 4–6 條；07-01 §進入模組的條件 第 4 條、Q13；04-01 §路由上下文與回退 第 1、11 條）。去處頁面還不存在，本次只驗連結去處與不出現擋下說明；「實際到達入口頁」移交 #730（卡 A）與 #773（卡 B、C）（Q3）。卡 B 標題與第 3 步說明句都用「提交」，英文維持 `submit`（維護者 2026-11-28、Q6）
- **系統管理員的區塊 A**：`平台使用者統計` 四張指標卡 `總用戶`、`專案負責人`、`標記員`、`審核員`，單位人，數值寫死在前端語言檔、**全部顯示 0 人**，不新增後端讀取，所以系統管理員版面沒有讀取中與失敗狀態（Q2、sa-8 不成立）。系統管理員、專案負責人、標記員的指標卡共用一句示範值標示：`示範用靜態值：這些指標卡尚未接上實際資料，算法另案定義。`／`Demo static values: these metric cards are not yet connected to real data; how they are calculated is defined separately.`，審核員那三張維持規格原句，本次只用在區塊 A（Q5；02-01 §系統管理員看到的四個區塊 第 1、2、4 條；§審核概況那三張卡是示範值 第 3、6–8 條）。系統管理員版面本單**只有區塊 A**（維護者 2026-11-28）
- **共用原語與設計 token**：新增指標卡原語（跨三個 feature 會用到，放共用元件區），骨架原語加光帶變體；元件展示頁各加一節（ui §元件樹、§設計系統異動）。行動入口卡的角色色由前端讀 `data-palette.css`，照 prototype 的綠、紫、靛三色，淺深兩組都要，token 抽取與 theme 對照一併擴充（Q8）；prototype 不在刻度上的字級照 G-66 取最接近且不大於的 token，版面寬度與圖示尺寸照 prototype 字面值（Q9）
- **由 #720 移交**：規格 07-01「從儀表板行動入口卡進入不被擋下」（Issue #722 留言 2026-11-27），本次只驗連結去處與不出現擋下說明
- **語言、窄螢幕、鍵盤、資料邊界**：本次存在的區塊隨語言切換、缺翻譯不中斷；窄螢幕指標卡兩欄、任何寬度不需左右滑動、鍵盤走得完；這一頁看不到標準答案（02-01 §這一頁看不到標準答案、§導覽、語言與登出不在這一頁、§在窄螢幕上的呈現）
- **不包含**（接手 issue）：系統管理員區塊 B、D 與專案負責人版面的區塊（#733）；標記員、審核員版面的區塊、快速繼續、快速審核、排序、空狀態（#736）；「等待 IAA 確認」與區塊 C 最近提醒（#741）；真實的任務角色讀取（#766）；任務列表（#730）與標記清單（#773）本身及「實際到達入口頁」；個人設定頁（#727，Scenario 83 的前提）；側欄、語言切換、登出（07-01，#720 已完成）；`design/system/brand.md` 按鈕用語（#814）；任何 `docs/specs/00-prd.mdx`、`design/prototype/` 的改動

## Capabilities

### New Capabilities

- `dashboard`：儀表板頁——依系統角色與任務角色決定版面與優先序、頁首、讀取任務角色時的骨架與錯誤、還沒有任務角色的行動入口卡與其去處、系統管理員的區塊 A 與示範值標示、語言與窄螢幕呈現、資料邊界。#733、#736、#741 之後在這個 capability 加各版面的區塊。來源：規格 02-01 §規格、§卡控機制、§邊界情況、§驗收標準；07-01 §進入模組的條件 第 4 條與 Scenario「從儀表板行動入口卡進入不被擋下」

### Modified Capabilities

- `auth-guard`：REMOVED Requirement「暫時落點顯示目前登入者」（整條被儀表板取代）。角色無效時只導向登入頁（sa-7），守門本身不改
- `app-shell-sidebar`：MODIFIED Requirement「沒有任務角色時從側欄進入標記作業被擋下」的擋下說明位置，由「內容區最上方」改為「頁首下方、版面內容之上」（Q4；規格 07-01 §進入模組的條件 第 3 條已回寫）。側欄的任務角色來源不改成新端點，Requirement「角色標示與第三個導覽項依任務角色來源」不動
- `frontend-routing`：MODIFIED Requirement「每頁設定瀏覽器標題」，頁名清單的「暫時落點（你已登入）」改為「儀表板」
- `component-gallery`：MODIFIED Requirement「原語宣告的 variant 集合固定」（骨架的兩種動畫）與「展示頁列出每個宣告的項目」（區塊數與順序加指標卡）

不改：`frontend-i18n`（新增 `dashboard` 語言檔屬既有規則的範圍，缺翻譯備用規則沿用）、`account-login`（登入後去處不變）、`denied-and-not-found-screens`（「回儀表板」去處不變）、`permission-authorization`、`role-permission-matrix`（畫面不讀矩陣）、`login-session`（角色無效不另外結束登入狀態）

## Impact

- **後端**：無。不新增端點、模組、資料表或 Alembic migration，`backend/openapi.json` 不變，也不需要 `[@dba]` 或後端群組
- **前端**：`/dashboard/dashboard` 的頁面元件換成新的儀表板頁（`frontend/src/pages/dashboard/`），儀表板專屬元件放 `frontend/src/features/dashboard/`（版面決定純函式、骨架佈局、錯誤面板、行動入口卡、區塊 A）；新增共用指標卡原語 `frontend/src/components/ui/metric.tsx`，骨架原語加光帶變體；新增 `dashboard` 語言檔並在啟動時預載，區塊 A 的 0 人與示範值標示放在其中；任務角色來源改成讀取中、失敗、完成三態形狀；刪除暫時落點頁 `pages/dashboard-placeholder/`、`features/auth/signed-in-card.tsx` 與 `auth` 語言檔的 `dashboard.*` 鍵；卡片連結與側欄共用同一組路徑常數（位置由 design 依 frontend-agent-rules F1 定）。檔案以 ui §元件樹 為準
- **前端 token 抽取**：`build/extract-tokens.ts` 與 theme 對照擴充，讀 `design/prototype/assets/data-palette.css` 的三色（淺深兩組）；確認在 ADR-005 D4 的範圍內，不在範圍內就停下回報（Q8）
- **API**：沒有端點異動，只沿用 `getCurrentSession`（讀 `data.user.role`，與守門共用快取、不多送請求）
- **依賴**：不新增套件
- **常駐文件**：`docs/diagrams/architecture/frontend-routes.mdx` 已依 ui 改好，並依 Q3、Q8 校正§路由、§已知限制與「design token 怎麼進到元件」。`backend-modules.mdx`、`error-codes.mdx`、`endpoint-authorization.mdx`、`data-table-dictionary.mdx` 不改
- **設計系統**：apply 時同 PR 改 `design/system/components/metric.md`、`screen-inventory.md`、`components/skeleton.md` 的「程式實作」（ui §設計系統異動）。`brand.md` 的按鈕用語不在本次改，由 #814 處理；`design/prototype/` 不改
- **規格書**：本次 change 不改 `docs/specs/` 需求；Q4（07-01 第 3 條）、Q5（02-01 示範值標示）已由 `spec-writing` 回寫，變更 #722，在 specs 之前提交
- **測試**：版面決定以純函式單元測試逐條驗證 02-01 第 1–4 條與優先序（三種任務角色版面本次正式環境到不了）；角色無效以前端假的工作階段驗，不在兩種資料庫繞過約束；骨架與讀取失敗以前端測試替身製造（Q1）；去處頁面以連結去處驗；E2E 涵蓋登入後到達儀表板、兩種存在的版面、窄螢幕與鍵盤；依賴「你已登入」的既有 E2E 改寫
- **Hard Rule 5（任務設定驅動）**：版面與卡片不依任務類型或輸出類型分支；卡片連結只帶入口標記與角色參數，不帶任務類型（sa §角色與權限；ui §頁面與路由）
- **Hard Rule 6（測試集答案不外露）**：本次碰到的回應只有登入者自己的系統角色；頁首、行動入口卡、區塊 A 是固定文案或寫死的示範值，錯誤畫面不顯示後端訊息，沒有任務、資料集、項目、標準答案或測試集辨識資訊（sd §權限檢查點；`api-contract.md`）。specs 要有負向 Scenario
- **後續單**：#733、#736、#741 在本次的版面裡補區塊並沿用骨架、示範值標示句與指標卡字級對應；#766 接上真實任務角色時側欄與儀表板一起改變；#773 依入口標記分辨站內進入；#730、#773 建好後補驗「實際到達入口頁」
