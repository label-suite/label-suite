表單內的錯誤橫幅：表單還留在畫面上、但送出失敗時，在表單上方說明原因。

## 何時使用

- 送出表單後伺服器回錯誤（帳密錯誤、連結失效），而使用者要留在同一張表單上修正。
- 錯誤屬於整張表單、不屬於單一欄位；單一欄位的錯誤用 `.field-error`。
- 動作的結果（成功、背景工作開始）用 Toast，不用 Alert Banner。
- 表單整個被結果取代（例如「請到信箱收信」）用 State Panel。

## 結構與使用方提供的內容

- 容器：`.alert-banner`，標記上加 `role="alert"`，讓報讀器在出現時唸出。`role` 是標記慣例，CSS 不會替你加。
- 前置圖示：可省略；用 `design/prototype/assets/icons/` 的 alert-circle 內嵌 SVG，加 `aria-hidden="true"`。
- 訊息：使用方提供一句可行動的錯誤說明，長訊息會自動換行。
- 顏色只用 token：`--color-error`、`--color-error-bg`、`--color-error-border`，圓角 `--radius-md`。

## 變體

- 正典只有 error 一種。
- G-07：使用者管理頁在本頁自行加了 `.alert-banner.warning`，角色設定頁也有自己的橫幅樣式；兩者都還不是正典，新頁面不要沿用。

## 狀態

- 出現：送出失敗時插入或顯示；沒有進場動畫。
- 沒有關閉按鈕，不能手動關掉；使用者重新送出成功、或改動欄位後由頁面移除。
- 沒有 hover、focus 狀態，它不是互動元件。

## 該做／不該做

- 該做：訊息寫原因與下一步（「帳號或密碼錯誤，請重新輸入」）。
- 該做：放在表單頂端、送出按鈕之上，讓錯誤和表單在同一個視線範圍。
- 不該做：拿它顯示成功或資訊訊息；那是 Toast 的工作。
- 不該做：自己加關閉鈕或新的顏色變體；需要時先回報設計缺口。
- 不該做：把每個欄位的錯誤都堆進橫幅；欄位錯誤放欄位下方。
