## 決議（Q）

### Q1. 任務角色從哪裡讀（sa-1）

- **來源**：`system-analysis.md` 待決問題 1；`system-design.md` 提案 A／B；`api-contract.md` 條件式端點 `getTaskRoleSummary`
- **問題**：任務與任務成員要到 #766 才存在；現有前端任務角色來源對每個人都回答「沒有任務角色」。本次要不要新增真的讀取。
- **決議**：提案 A。沿用前端既有的任務角色來源，本次不新增後端讀取；來源要能提供讀取中、失敗（可重試）、完成三種狀態給儀表板用。#766 建好任務成員後再接上真的讀取。
- **理由**：任務成員資料在 #766 之前不存在，新增端點只會固定回空集合；不動後端可讓本次範圍集中在畫面。
- **已回修**：`system-design.md`、`api-contract.md`（提案 B 改記為未採用）；`ui-design.md` §資料來源；`proposal.md`
- **日期**：2026-11-28

### Q2. 區塊 A 的示範值（sa-3；連帶 sa-8）

- **來源**：`system-analysis.md` 待決問題 3、8；規格 02-01 §已確認決議 Q4
- **問題**：區塊 A 四張卡的示範值從哪裡來、是哪幾個數。
- **決議**：寫死在前端語言檔，四張卡（`總用戶`、`專案負責人`、`標記員`、`審核員`）**全部顯示 0 人**。不新增後端讀取，系統管理員版面不需要讀取中與失敗狀態（sa-8 因此不成立）。
- **理由**：Q4 已定為示範值、算法另案；0 不像真實統計，較不會被誤讀。
- **已回修**：`ui-design.md` 區塊 A 與 §資料來源；`system-design.md`、`api-contract.md`（`getPlatformUserSummary` 改記為未採用）；`proposal.md`
- **日期**：2026-11-28

### Q3. 行動入口卡的去處頁面還不存在時（sa-2）

- **來源**：`system-analysis.md` 待決問題 2、需求矛盾 2；規格 02-01 §還沒有任務角色的人看到什麼 第 7 條、Scenario「三張卡的按鈕都走到模組入口頁」；07-01 Scenario「從儀表板行動入口卡進入不被擋下」
- **問題**：任務列表（#730）與標記清單（#773）都還沒建置，現行規則把未建置頁面導回儀表板。
- **決議**：三張卡的按鈕連到最終路徑（卡 A `/task-management/task-list`；卡 B、C `/annotation/annotation-list`，帶 `entry=nav` 與各自的 `role`），本次驗連結去處與「不出現擋下說明」。「實際到達入口頁」移交 #730（卡 A）與 #773（卡 B、C），見「移出本次的驗收標準」。
- **理由**：不擴大範圍、不違反第 7 條；去處頁面建好時由該頁的 change 補驗。
- **已回修**：`ui-design.md` §路由；`frontend-routes.mdx` §路由與§已知限制；`proposal.md`
- **日期**：2026-11-28

### Q4. 擋下說明與頁首的順序（sa-5）

- **來源**：`system-analysis.md` 待決問題 5、需求矛盾 1；規格 02-01 §這一頁顯示哪一種版面 第 6 條；07-01 §進入模組的條件 第 3 條與 Q20；主規格 `app-shell-sidebar`「內容區最上方」
- **問題**：02-01 要頁首固定在最上方，07-01 要擋下說明在落點頁最上方顯示一次。
- **決議**：頁首在最上方，擋下說明緊接在頁首下方、版面內容之上。
- **理由**：頁首在五種版面上位置固定，較穩定；擋下說明仍是使用者進頁後第一眼看到的內容。
- **已回修**：規格 07-01 §進入模組的條件 第 3 條（以 `spec-writing` 回寫，變更 #722）；`ui-design.md` 元件樹順序；`app-shell-sidebar` 由 specs 以 MODIFIED 處理
- **日期**：2026-11-28

- **理由**：一句通用的文案讓 #733、#736 不必各自再定；審核員的原句已寫進驗收標準，不動。

### Q8. 行動入口卡的角色色（U2）

- **來源**：`ui-design.md` U2；`design/prototype/assets/data-palette.css`；`design/system/brand.md` §色彩角色；前端 `build/extract-tokens.ts`
- **問題**：prototype 的三色來自 `data-palette.css`，前端只讀 `tokens.css`。
- **決議**：前端也讀 `data-palette.css`，照 prototype 的綠、紫、靛三色，淺深兩組都要；token 抽取與 theme 對照一併擴充，確認在 ADR-005 D4 的範圍內（不在範圍內就停下回報）。
- **理由**：與 prototype 一致，且 #733、#736 之後也會用到角色色。
- **已回修**：`ui-design.md` U2 與 token 表；`frontend-routes.mdx` §前端骨架「design token 怎麼進到元件」
- **日期**：2026-11-28

### Q9. 不在刻度上的字級（U3）

- **來源**：`ui-design.md` U3；先例 G-64（#719）、G-66（#720 Q13）
- **問題**：prototype 的字級不在 `tokens.css` 刻度上，兩個先例方向不同。
- **決議**：照 G-66，取最接近且不大於的 token：28px → `--text-h2`（24）、1.05rem → `--text-body`（16）、11px 與 13px → `--text-label`（12）、1.35rem → `--text-h3`（18）、1.0625rem → `--text-body`（16）、0.8125rem → 12、0.6875rem → 12（以 `tokens.css` 實際名稱為準）。版面寬度（300px、150px）、圓形與圖示尺寸（72、44、32、20px）與箭頭不透明度不屬品牌刻度，照 prototype 字面值。#733、#736 的指標卡沿用同一套。
- **理由**：規則明確、不會出現等距要再定的情況。
- **已回修**：`ui-design.md` token 表
- **日期**：2026-11-28
