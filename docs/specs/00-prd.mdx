# Label Suite PRD

:badge[草稿]{variant="warning"}

Label Suite 是給學術 NLP 研究團隊用的資料標記與品質評估平台：研究人員用設定組出標記任務，再由團隊在同一個平台完成試標、正式標記、審核與資料品質分析。

## 專案概述

### 問題背景

- 研究團隊現在要靠多個工具才能做完一次標記：一個工具建任務、一個工具標記，品質分析還要另外寫程式。資料在工具之間搬來搬去，流程很難重現。
- 現有的標記工具對非工程背景的研究人員門檻太高：換一種任務，就要重新學一套設定方式，或者請工程師改程式。
- 資料品質要等標記全部做完才看得到。如果標記員對規則的理解不一致，往往到最後才發現，只能整批重標。
- Label Suite 是碩士論文 Demo Paper 的核心成果，要在論文中展示「用設定驅動的標記流程」與「標記過程中就能看到資料品質」。

### 目標

| 目標 | 受益角色 | 衡量方式 |
| :--- | :--- | :--- |
| 讓研究團隊在同一個平台走完一次標記：建立任務、試標、確認一致性、正式標記、審核、匯出 | :ref[專案負責人]{id="term.project-leader"} | 可以實際示範一次完整的標記流程 |
| 讓專案負責人只改 :ref[任務設定]{id="term.task-config"} 就能換一種研究任務，不必改平台 | 專案負責人 | 至少五種研究示例只靠任務設定建立，平台不需要修改 |
| 讓專案負責人建立任務的步驟比現有工具少 | 專案負責人 | 建立同一個任務的操作步驟數少於 Label Studio |
| 讓專案負責人與 :ref[審核員]{id="term.reviewer"} 在標記過程中就看到資料統計 | 專案負責人、審核員 | 句數、詞數、標籤數的統計和人工計算結果完全一致 |
| 讓 :ref[標記員]{id="term.annotator"} 與審核員覺得平台好上手 | 標記員、審核員 | 5～10 位實驗室成員填寫 SUS 問卷，整體分數達 75 分以上 |
| 讓專案負責人能向論文讀者重現平台的使用情境 | 專案負責人 | 示範影片完整呈現 2～3 個使用情境 |

## 使用者角色

### 角色清單

每個使用者恰有一個 :ref[系統角色]{id="term.system-role"}，在各個任務裡另外有 :ref[任務角色]{id="term.task-role"}；兩者互不影響，系統角色不代表任務成員身分。

| 角色 | 在系統裡主要做什麼 |
| :--- | :--- |
| :ref[平台成員]{id="term.platform-member"} | 自行註冊或由系統管理員邀請加入；建立自己的任務、參與被指派的任務 |
| :ref[系統管理員]{id="term.system-admin"} | 管理平台帳號、系統角色與角色權限；可以看到所有任務的列表 |
| :ref[Seeder 管理員]{id="term.seeder-admin"} | 平台部署時建立的第一位系統管理員，權限同系統管理員，但不能被停用、降級或移除 |
| :ref[專案負責人]{id="term.project-leader"} | 建立任務的人自動取得；設定任務、指派成員、啟動試標與正式標記、確認一致性結果、匯出標記結果 |
| :ref[審核員]{id="term.reviewer"} | 審核標記結果、處理 :ref[爭議]{id="term.dispute"}；被指定的審核員同時擔任 :ref[仲裁者]{id="term.arbiter"} |
| :ref[標記員]{id="term.annotator"} | 在被指派的資料上產出標記結果；看不到 :ref[標準答案]{id="term.ground-truth"} |

### 權限矩陣

:::tip{title="權限代號"}
R：Read（可讀取）　C：Create（可新增）　E：Edit（可編輯）　D：Delete（可刪除）　(o)：只限自己的資料　—：無權限
:::

| 01 帳號（自己的帳號與個人設定） | R/E (o) | R/E (o) |
| 02 儀表板 | R (o) | R |
| 03 任務列表 | R (o) | R |
| 03 新增任務 | C | C |
| 06 使用者管理 | — | R/C/E |
| 06 角色設定 | — | R/E |
| 07 共用介面 | R | R |

**依任務角色**（只限自己參與的任務）

| 模組／功能 | 專案負責人 | 審核員 | 標記員 |
| :--- | :--- | :--- | :--- |
| 03 任務詳情（設定、成員、試標與正式標記的推進） | R/E | R | — |
| 03 匯出標記結果 | C | — | — |
| 04 標記清單與標記工作區（產出標記） | — | — | R/C/E (o) |
| 04 標記清單與標記工作區（審核與仲裁） | R | R/E | — |
| 05 資料集分析 | R | R | — |
| 05 資料匯入與版本 | R/C | R | — |

- 這兩張表是預設值，也是上限：系統管理員在角色設定（規格 06-02，未撰寫）只能在表內收窄權限，不能放寬；「06 系統管理」兩列固定，系統管理員可用、平台成員不可用
- 平台成員在任務列表與儀表板只看得到自己參與的任務；系統管理員看得到所有任務的列表，但沒有任務角色時，進不了該任務的詳情、標記與分析
- 帳號沒有刪除，只有停用與啟用（見 [規格 06-01](./06-admin/01-user-management.mdx)）
- 標記員只看得到被指派給自己的資料；標記員能接觸到的任何地方，都看不到標準答案與測試集資訊
- 專案負責人在標記工作區只處理審核員無法收斂的例外，不產出標記
- 匯出只在任務「已完成」後開放

規格書的「使用角色」只能比這張表更嚴，不能更寬。

## 專案範圍

### 範圍內

- 帳號：Email 與密碼登入、註冊、忘記與重設密碼、個人設定、登入狀態與安全；登入頁保留 Google SSO 入口
- 儀表板：登入後依使用者在各任務的角色，彙整自己的任務並快速回到標記或審核
- 任務管理：用任務設定建立任務（上傳 JSON 資料集），管理成員，推進 :ref[試標]{id="term.dry-run"} 與 :ref[正式標記]{id="term.official-run"}，任務完成後匯出 JSON／JSON-MIN
- 標記作業：標記員依任務設定作答，審核員審核、處理爭議與仲裁
- 資料集：資料統計、品質監控（含 :ref[IAA]{id="term.iaa"}）、資料匯入的來源與版本追溯
- 系統管理：使用者管理、角色權限設定
- 共用介面：側欄導覽、工作頁籤、繁體中文與英文切換

### 範圍外

- 介面上的批次資料匯入精靈：這期由部署者直接匯入；任務建立時的上傳仍在範圍內
- AI 輔助標記建議：列為未來工作
- 大規模並發壓力測試：平台定位是研究原型，不是生產規模服務
- CoNLL／BIO／JSON-L 等標準格式匯出：列為未來工作
- 第三種以上的介面語言與翻譯營運：繁體中文與英文切換已在範圍內
- 開放其他系統串接與第三方整合：這期以展示平台能力為主
- 手機原生 App：平台是網頁應用，行動裝置用瀏覽器操作
- 說明按鈕（平台說明入口）：最新的 prototype 沒有這個入口，這期不做

:badge[待確認]{variant="warning" icon="warning"} 說明按鈕是否永久排除

:::warning{title="待確認：說明按鈕是這期不做，還是永久不做？"}
- 選項：這期不做，下一期再議／永久排除
- 建議：這期不做，下一期再議。先看 SUS 問卷是否反映需要說明入口。
- 需要決定的人：論文作者
- 來源：舊 PRD §7 Q-01
:::

### 假設與限制

- 任務類型完全由任務設定決定；新增一種任務不需要修改平台。不成立時，目標二無法達成
- 使用者主要是實驗室成員，人數在數十人以內；不成立時，要重新評估效能與招募方式
- 平台部署時由部署者建立 Seeder 管理員；不成立時，沒有人能管理帳號
- 資料集上傳只接受 JSON；要支援其他格式時，先修改規格 03-02

- **任務從建立到匯出**
  - 起點：專案負責人在任務管理用任務設定建立任務並上傳資料集，任務是「草稿」
  - 交接：
    1. 任務管理 → 標記作業：專案負責人啟動試標，被指派的標記員在標記清單看到試標資料
    2. 標記作業 → 資料集：試標的標記結果送出後，資料集計算 IAA
    3. 資料集 → 任務管理：專案負責人在任務詳情查看 IAA，決定接受、退回草稿修改設定，或再開一輪試標；IAA 只供參考，不會自動擋下
    4. 任務管理 → 標記作業：專案負責人啟動正式標記，標記員開始正式作答，審核員開始審核
    5. 標記作業 → 資料集：審核定稿的結果與爭議處理結果進入資料集，計算統計與品質分數
    6. 資料集 → 任務管理：全部條件達成後，任務進入「已完成」，專案負責人匯出標記結果
  - 替代：
    - A1 專案負責人退回草稿：回到起點修改任務設定
    - A2 專案負責人再開一輪試標：回到交接 1
  - 終點：任務「已完成」，匯出 JSON／JSON-MIN
  - 細節：見規格 03-03、04-02、05-02 的業務流程（都還沒撰寫）

| :--- | :--- | :--- | :--- |
| 06 系統管理 | 停用帳號、變更系統角色 | 01、02、03、04、05 | 停用後該帳號登入狀態失效；角色變更從下一次操作起生效 |
| 06 系統管理 | 修改角色權限 | 03、04、05 | 各模組依新的權限顯示與擋下操作 |
| 03 任務管理 | 任務設定、成員指派 | 04 標記作業、05 資料集 | 決定標記員看到什麼資料與作答方式、分析依哪些標籤統計 |
| 03 任務管理 | 任務狀態改變 | 02 儀表板、04 標記作業 | 儀表板與標記清單顯示新的狀態與可做的事 |
