本份是 change `login-auth-guard`（Issue #719）的前端設計：登入頁、前端的頁面守門，以及登入後的落點。畫面長相以 `design/prototype/pages/account/login.html` 為準，元件與狀態以 `design/system/` 為準，業務規則以規格 01-01 為準；這裡只寫前端要照著做的結構。`system-analysis.md` 標為待決、需要維護者決定的事，這裡寫成**提案**（見 [§待決問題](#待決問題)），不當成已定案；本份沒有新增任何 prototype 以外的畫面。

### 進入、離開與返回

依規格 01-01 與帳號模組 `docs/specs/01-account/index.mdx` §Logic Flow 分段一：

| 節點／連線       | 前端行為                                                                                                                                          |
| :--------------- | :------------------------------------------------------------------------------------------------------------------------------------------------ |
| S → D1           | 打開 `/` 或任何需要登入的路由時，先查「目前的登入狀態」；判定完成前不畫任何一頁的內容                                                             |
| D1 是 → X5       | 以取代歷史紀錄的方式到 `/dashboard/dashboard`；按瀏覽器上一頁不會回到登入頁                                                                       |
| D1 否 → P1       | 以取代歷史紀錄的方式到 `/account/login`；是否帶上原本要去的頁面見待決 sa-10                                                                       |
| P1 → D2 是 → X5  | 登入成功 → 等「目前的登入狀態」更新為已登入，再以取代歷史紀錄的方式到落點（避免守門還讀到舊的未登入結果、又把人彈回登入頁）                       |
| D2 否 → 停在 P1  | 留在同一頁，兩欄內容不清空（01-01 §用 Email 與密碼登入 第 13 條）                                                                                 |
| P1 → X1 → D3     | 點「使用 Google 帳號繼續」→ 整頁導向後端的 Google 登入起點（瀏覽器導覽，不是 `fetch`）；回來時由後端導回 `/`（成功）或 `/account/login`（E1、E2） |
| D3 否 → P1       | E1（取消或不通過）：回到登入頁，**不顯示錯誤**；E2（沒有對應帳號、Email 未驗證）：回到登入頁並顯示 Google 那一句                                  |
| P1 → P2、P1 → P4 | 「前往註冊」到 `/account/register`、「忘記密碼？」到 `/account/forgot-password`；兩條路由本次都不存在，見待決 sa-6                                |
| X7 → P1          | 任何請求回 `401` → 回 `/account/login`；登入頁是否顯示被動登出的兩句見待決 sa-2                                                                   |

## 元件樹

元件以語意名稱描述；能直接對到 shadcn/ui 的標在括號裡（放 `components/ui/`），其餘是 `features/auth/` 或頁面自己的組合。

### 守門

```text
Router
├─ "/"                     RootRedirect：讀目前的登入狀態 → 導向落點或登入頁
├─ 只給未登入的人（PublicOnlyRoute）
│  └─ "/account/login"     LoginPage
├─ 需要登入（RequireAuthRoute）
│  └─ "/dashboard/dashboard" 落點（內容待決 sa-5）
└─ 開發模式："/dev/health"、"/dev/gallery"（不經守門）
```

- 兩種包裝讀**同一個**「目前的登入狀態」查詢，不各自發請求
- 判定中：畫面只有頁面底色（`--color-surface`），不畫登入卡、不畫落點，也不顯示任何帳號資訊；對應 prototype 「在畫面畫出來之前就決定，避免閃一下本頁再跳走」的意圖（`login.html:497`–`:503` 的註解）
- 守門只決定「讓不讓進、往哪裡去」，不自己判斷角色能看到什麼；權限一律由後端擋（architecture §前端、F8）

## 畫面狀態

### 守門：目前的登入狀態

| 狀態          | 呈現                                                                                                                                                                                                  |
| :------------ | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| loading       | 只有頁面底色，不畫任何頁面內容（見 §元件樹 › 守門）；不用 skeleton——登入頁與落點長得不一樣，骨架會猜錯版面                                                                                            |
| error         | `401`（含不存在、已失效、屬於別的帳號、帳號已停用）→ 在需要登入的路由：回登入頁、**不說明原因**（規格 01-05 §不能通行的登入狀態不說明原因）；在登入頁：照常顯示登入頁。連不上、逾時或 `5xx` → 待決 U6 |
| empty         | 不適用：「沒有登入」就是 `401`，沒有第三種結果                                                                                                                                                        |
| 無權限（403） | 不適用：這個查詢對任何人都不回 `403`。登入後各頁的 `403` 交給該頁（規格 07-03），守門不處理                                                                                                           |
| 欄位被遮蔽    | 無遮蔽欄位；回應裡不得出現登入狀態以外的帳號資訊供畫面顯示（見下方「刻意不揭露」）                                                                                                                    |

### 登入頁：部署能力

| 狀態          | 呈現                                                                                                                                                              |
| :------------ | :---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| loading       | 登入卡照常顯示；底部註冊那一列**先不渲染**，回來確認開放自行註冊才出現，不會先出現再消失。Google 鈕照常顯示（規格 01-01 §用 Google 帳號登入 第 1 條：按鈕一定在） |
| error         | 註冊那一列不渲染（寧可少一條路，也不要顯示一條點了才發現不能用的路）；Google 鈕的行為見待決 sa-8；不顯示錯誤橫幅——錯誤橫幅留給使用者自己的動作                    |
| empty         | 不適用                                                                                                                                                            |
| 無權限（403） | 不適用：未登入就能讀，對任何人都不回 `403`                                                                                                                        |
| 欄位被遮蔽    | 無                                                                                                                                                                |

### 登入表單（送出）

| 狀態                                      | 呈現                                                                                                                                                                                                                                                                                                         |

### 刻意不揭露（取代「欄位被遮蔽」）

本次沒有被後端遮蔽的欄位，但有三處**刻意不說原因**，畫面上一律用固定的一句，不得用空白或「無資料」代替：

- 帳號不存在、密碼錯誤、帳號停用 → 同一句（01-01 Q1、Q2）
- Google 沒有對應帳號、Email 未驗證 → 同一句（01-05 Q18）
- 登入狀態不能通行 → 回登入頁、不說明原因（01-05 §不能通行的登入狀態不說明原因）；被動登出的兩句（01-05 Q4）只分「時間到了」與「憑證不再有效」，不帶帳號資訊

錯誤橫幅、欄位錯誤與守門判定中的畫面，都不得出現使用者輸入的 Email、帳號識別碼或任何其他裝置的資訊。

### 測試集答案不外露（Hard Rule 6）

本次的畫面（登入頁、守門、落點）都沒有任何任務、資料或標準答案；守門判定中與錯誤訊息也只帶上面那幾句固定文案。守門是日後答案隔離檢查所在的共用位置（`security-agent-rules` S3、S5），但檢查本身在後端，本次畫面端沒有要做的事。

## 無障礙

- 地標：頁首是 `<header>`（banner），主區是 `<main>`，登入卡是有名稱的 region（「登入」／`Sign in`）
- 欄位：每一欄有可見的 `<label>` 關聯；欄位錯誤以 `aria-describedby` 關聯到欄位，錯誤出現時欄位標成無效
- 錯誤橫幅：`role="alert"`，出現時被朗讀（同 prototype `login.html:397`）
- 只有圖示的按鈕都有名稱：密碼切換鈕的名稱隨狀態改變（「顯示密碼」／「隱藏密碼」），切換語言時依目前狀態重算（01-01 §用 Email 與密碼登入 第 19、20 條）；Google 鈕的名稱「使用 Google 帳號繼續登入」含可見文字；品牌連結名稱「Label Suite 首頁」
- 所有無障礙名稱與可見文字一樣有兩種語言（`brand.md` §錯誤與驗證訊息 最後一條）；Spinner 的英文名稱 prototype 沒有，見待決 U3
- 語言切換時一併更新 `<html lang>`（`zh-TW`／`en`）與瀏覽器頁籤的標題（`Label Suite — 登入`／`Label Suite — Sign In`），`tokens.css` 的中英行高依 `html[lang]` 切換
- 焦點：所有可互動元素都要有看得見的焦點外框（G-05 已登記 prototype 多處缺焦點樣式，實作照 F9 補上，不另列）；Tab 順序依畫面順序：品牌連結 → 語言切換 → Google 鈕 → 電子郵件 → 忘記密碼？ → 密碼 → 密碼切換 → 登入 → 前往註冊。prototype 的 DOM 順序是「忘記密碼？」在密碼欄之前，照 prototype
- 狀態不只靠顏色：欄位錯誤有文字、錯誤橫幅有圖示加文字、送出中有 Spinner 加名稱
- 送出中整頁不可互動時，被凍結的控制項要真的對鍵盤也無效，不能只是看起來停用
