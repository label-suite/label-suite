## 目標

- 讓 :ref[專案負責人]{id="term.project-leader"} 在**一個頁面**裡把一個任務從草稿推到已完成，不必在多個畫面之間找線索
- 讓他看得出「現在卡在哪、下一步該做什麼」，而不是自己推敲狀態
- 讓 :ref[審核員]{id="term.reviewer"} 取得足夠的資訊做審核，但**碰不到成員與推進**這些不屬於他的操作
- 讓每個人的工時與完成筆數**只按真正可信的紀錄算**，不替任何人補時數

## 使用角色

:::tip{title="權限代號"}
R：Read（可讀取）　C：Create（可新增）　E：Edit（可編輯）　D：Delete（可刪除）　(o)：只限自己的資料　—：無權限
:::

這一頁的三個任務角色**讀取邊界差很大**，是本頁最容易寫錯的地方。

- :ref[專案負責人]{id="term.project-leader"}：R／E（六個分頁全看得到，設定與成員與推進都能操作）／C（匯出，見階段四）
- :ref[審核員]{id="term.reviewer"}：R（**看得到五個分頁，看不到成員管理**）；他在看得到的分頁上**一律唯讀**
- :ref[標記員]{id="term.annotator"}：**無權限**——直接開這一頁會被帶回 [規格 03-01 任務列表](./01-task-list.mdx) 並顯示無權限提示
- 這和 PRD §權限矩陣 的「03 任務詳情：專案負責人 R/E、審核員 R、標記員 —」一致，沒有超出
- 同一個人在同一個任務裡可能有多個角色（例如既是專案負責人又是審核員）→ 以**兩者的聯集**判定他看得到什麼
- :ref[系統管理員]{id="term.system-admin"} 沒有任務角色時**進不了這一頁**，即使他在 [規格 03-01](./01-task-list.mdx) 看得到這個任務（PRD §權限矩陣 的註記）

- **進入任務詳情**
  - 觸發：使用者從 [規格 03-01 任務列表](./01-task-list.mdx) 點某個任務
  - 前置條件：使用者已登入
  - 主流程：
    1. 系統確認使用者在這個任務裡有什麼角色
    2. 他有專案負責人或審核員的角色 → 顯示共用的任務標頭與六個分頁，停在「概覽」
    3. 概覽顯示現在到哪一個階段、最新的一致性指標、樣本池怎麼分，以及**下一步該做什麼**
  - 替代流程：
    - A1（第 2 步）他只有審核員的角色 → 看得到五個分頁、**看不到成員管理**，而且每個分頁都是唯讀，回到第 3 步
    - A2（第 2 步）他用網址直接開成員管理 → **導回概覽**並顯示無權限提示，而且**網址也改寫成概覽的參數**，回到第 3 步
  - 例外流程：
    - E1（第 1 步）他只有標記員的角色，或在這個任務完全沒有角色 → 帶回任務列表並顯示無權限提示，流程結束
  - 結果：使用者停在概覽，看得出現況與下一個該做的決定

- **看自己的工時**
  - 觸發：使用者點「工時紀錄」
  - 前置條件：使用者已在這一頁
  - 主流程：
    1. 使用者選日期區間與任務階段
    2. 他是專案負責人 → 還可以選成員，看得到全部人的工時
    3. 明細表與上方的匯總**依完整的篩選結果**計算，不是只算目前這一頁

## 規格

### 共用任務標頭

<PrototypeFrame page="task-management/task-detail" caption="任務詳情" client:idle />

六個分頁上方有一塊**共用的標頭**，不論切到哪一個分頁都在。

1. 麵包屑顯示「任務管理 / 這個任務的編號」，前半可以回到 [規格 03-01 任務列表](./01-task-list.mdx)
2. 主標題顯示**任務名稱**，取代固定的「任務詳情」那種標題
3. 主標題右側以一般文字顯示現在的階段（例如「試標階段 · 第 2 回合」）
4. 那段階段文字和概覽**用同一份判定**，不會兩邊說法不一樣
5. 標頭上**不放任何主要操作**——要做的事都在分頁裡
6. 任務不存在 → 沿用找不到任務的呈現，而且標頭**不顯示一個不存在任務的名稱**

- 第 3 條用一般文字而**不是徽章**是刻意的：階段文字會變長（含回合數），徽章會被擠壞
- 第 5 條讓標頭保持單純：使用者不會在標頭和分頁裡找到兩個做同一件事的按鈕

### 六個分頁

<PrototypeFrame page="task-management/task-detail" caption="任務詳情" client:idle />

1. 分頁依固定順序排列：**概覽、設定、成員管理、標記進度、標記結果、工時紀錄**
2. 預設停在「概覽」
3. 切換分頁是**頁內行為**，不會整頁重新載入
4. 分頁列可以用方向鍵在分頁之間移動
5. 「成員管理」的可見性依 [§誰進得來、誰看得到哪些分頁](#誰進得來誰看得到哪些分頁)

- 這一頁的標題是「概覽」，不是「任務概覽」
- 階段一只展開概覽與工時紀錄兩個分頁；設定在階段二，成員管理與標記進度在階段三，標記結果在階段四

### 誰進得來、誰看得到哪些分頁

<PrototypeFrame page="task-management/task-detail" caption="任務詳情" client:idle />

| 使用者在這個任務裡的角色 | 進得來嗎 | 看得到哪些分頁 | 能不能操作 |
| :--- | :--- | :--- | :--- |
| :ref[專案負責人]{id="term.project-leader"} | 可以 | **六個都看得到** | 設定、成員、推進都能做 |
| :ref[審核員]{id="term.reviewer"} | 可以 | 五個（**沒有成員管理**） | **一律唯讀** |
| :ref[標記員]{id="term.annotator"} | **不行** | — | — |
| 在這個任務沒有任何角色 | **不行** | — | — |

1. 標記員或沒有角色的人直接開這一頁 → **帶回任務列表**並顯示無權限提示
2. 審核員用網址直接開成員管理 → **導回概覽**並顯示無權限提示；而且**網址一併改寫成概覽的參數**，不再留著成員管理那一段與它的頁碼
3. 同一個人在同一個任務有多個角色 → 以**聯集**判定（例如既是專案負責人又是審核員，就看得到六個分頁且能操作）
4. 審核員在看得到的分頁上，該角色不能用的按鈕**保持在原位但不可用**，不是整個拿掉——避免版面跳動

- 第 2 條的「網址也改寫」是刻意的：否則他重新整理又會跳一次無權限，或把一個對他無效的網址分享給別人
- 第 4 條的「保持在原位」讓審核員與專案負責人看到的版面一致，只有可用與不可用的差別

### 概覽

<PrototypeFrame page="task-management/task-detail" caption="任務詳情" client:idle />

概覽回答一個問題：**這個任務現在在哪、下一步該做什麼。**

1. 由上而下依序是：階段進度指示、判定框、四張數字卡、樣本池分配、「下一步」卡片、試標回合表
2. 階段進度指示顯示四個節點：草稿、試標階段、正式標記中、已完成
3. 判定框用一句話說現在的判定（例如「R2 已達標，可啟動正式標記」）與一行說明
4. 四張數字卡是：**目前回合、最新 IAA、已用試標、正式標記池**
5. 「已用試標」顯示的是**已用筆數 / 資料總筆數**（例如 `20 / 100`）
6. 樣本池分配用一條色帶顯示總筆數怎麼分：**每一個試標回合各有自己的顏色與圖例，正式標記池用另一組顏色**，任一回合的顏色不會和正式標記池混淆
7. 「下一步」卡片左側是「下一步：…」的狀態句與一行說明，右側是那個狀態該按的按鈕
8. 試標回合表列出每一個已完成的回合；每一筆之間**不畫垂直連接線**，日期**保持一行**不折行
9. 概覽**不含設定**——那五個區塊在設定分頁（階段二）
10. 概覽**不顯示達標條件**（一致性指標、標準差、最少標記者那幾個），那些在設定分頁

- 第 4、5 條裡**沒有**「已完成試標回合」這張卡：那個資訊由標頭的階段文字與試標回合表承擔
- :ref[IAA]{id="term.iaa"} 在這一頁是**唯讀的指標**，怎麼算與門檻定在哪裡由規格 05-02 資料集分析詳情（未撰寫）擁有；這一頁不另定一套算法
- 審核員看到的概覽**整頁唯讀**：判定框與數字都看得到，推進的按鈕不可用

### 工時紀錄

<PrototypeFrame page="task-management/task-detail" caption="任務詳情" client:idle />

1. 上方是篩選列：**日期區間、任務階段**，專案負責人另有**成員**
2. 日期區間是**一個**區間選擇器，不是兩個獨立的日期欄位
3. 下方是「工時明細表」，欄位依序為日期、成員、角色、登入／登出時間、上線時長、工作時長、標記筆數、審核筆數、仲裁筆數、平均速度、標記階段
4. 完成筆數**拆成三欄**：標記筆數、審核筆數、仲裁筆數；角色用不到的那一欄顯示 `—`（標記員只有標記筆數，審核員只有審核筆數與仲裁筆數）
5. 上方有四張匯總卡：總工時、總標記筆數、總審核筆數、各類工作速度
6. 速度**逐類顯示**（標記、審核、仲裁各自一個），各以該類的完成筆數與可信的工作時長計算；**沒有可信時長或分母為零時顯示 `—`**
7. 另有「異常提醒」區塊，比較時**按同一類、同一單位**比，不混合三類的完成筆數
8. 匯總卡與異常提醒**依完整的篩選結果計算**，不是只算目前這一頁
9. 表格底部有分頁列，格式和 [規格 03-01 §排序與分頁](./01-task-list.mdx#排序與分頁) 一致
10. 篩選條件一改 → **回到第一頁**
11. 這一頁的分頁狀態**獨立**，不和其他分頁共用
12. 一筆都沒有 → 顯示「尚無工時紀錄」與一個回到概覽的入口

**日期區間選擇器**

13. 在同一個日曆介面裡框選起訖日；已選範圍**即時高亮**，起訖日與中間的日期看得出差別
14. 控制項顯示已選的範圍（格式 `YYYY-MM-DD ～ YYYY-MM-DD`）；還沒選時顯示提示文字
15. **只點了起點、還沒點終點 → 不套用**：明細表與匯總維持套用前的結果
16. 使用者**先點了較晚的日期也可以**：系統把順序正規化成有效的區間，不會因為點選順序產生無效的篩選
17. 選好之後**含起日與訖日**；可以清除回到沒有區間

- 審核員的工時紀錄**只看得到自己的資料**，而且**沒有成員那個篩選**
- 第 6 條的 `—` 是刻意的：寧可不顯示，也不要用不可信的時長算出一個看起來精確的數字

### 網址與畫面狀態同步

<PrototypeFrame page="task-management/task-detail" caption="任務詳情" client:idle />

使用者應該能把「我現在看到的這個畫面」複製網址分享給同事。

1. **目前分頁**與各分頁的篩選、排序、頁碼都寫進網址
2. 使用者重新整理或用那個網址重新進來 → 回到**同一個畫面座標**
3. 使用者把網址貼給同事 → 對方看到同樣的分頁與篩選（看得到什麼仍依他自己的角色）
4. 網址上的分頁值無效 → 回到概覽
5. 審核員拿到一個指向成員管理的網址 → 導回概覽，**而且網址改寫掉那一段與它的頁碼**

- 各分頁的參數**各自獨立**（標記進度的排序不會影響標記結果的篩選）
- 階段一只定「有這個同步」與它的通則；每一個分頁各自同步哪些東西，隨該分頁在後面的階段寫

### 載入中、空的與載入失敗

<PrototypeFrame page="task-management/task-detail" caption="任務詳情" client:idle />

每一個分頁都要有這三種狀態，而且**都不能把其中一種顯示成另一種**。

| 狀態 | 使用者看到什麼 |
| :--- | :--- |
| 載入中 | 骨架（灰色佔位），不是空白也不是空狀態 |
| 空的 | 那個分頁自己的空狀態說明與一個往下走的入口 |
| 載入失敗 | 錯誤說明與「重試」，**不得顯示成空的** |

1. 某個分頁的內容載入失敗 → 那個分頁顯示錯誤與重試，其他分頁不受影響
2. 整頁的任務資料載入失敗 → 顯示整頁的錯誤
3. 任務不存在 → 顯示找不到任務，標頭不顯示名稱

### 不同螢幕寬度的呈現

<PrototypeFrame page="task-management/task-detail" caption="任務詳情" client:idle />

1. 在手機、平板與桌機都做得到：進入這一頁、切換分頁、看得出推進的權限、成員管理、工時篩選、匯出
2. 任何寬度下**資訊都不重疊**
3. 窄螢幕下表格可以左右捲動或改成卡片，但不能讓內容互相壓到

### 資料欄位

階段一只列共用標頭、概覽與工時紀錄用到的欄位；其餘隨各分頁在後面的階段補上。

| 欄位 | 型別 | 必填 | 規則 | 使用者看到 |
| :--- | :--- | :--- | :--- | :--- |
| 任務名稱 | 文字 | 是 | 由 [規格 03-02](./02-task-new.mdx) 建立時指定，在設定分頁可改（階段二） | 標頭的主標題 |
| 任務的編號 | 文字 | 是 | 不可編輯 | 麵包屑的第二節 |
| 任務狀態 | 單選：草稿、試標中、等待 IAA 確認、正式標記中、已完成 | 是 | 以 PRD §共用狀態機 為準；轉換規則在階段三 | 階段進度指示與標頭的階段文字 |
| 目前回合 | 整數 | 是 | 試標的第幾回合 | 概覽的第一張數字卡 |
| 最新 IAA | 數值 | 否 | **唯讀**；怎麼算由規格 05-02（未撰寫）擁有 | 概覽的第二張數字卡 |
| 已用試標筆數 | 整數 | 是 | 顯示成「已用 / 總筆數」 | 概覽的第三張數字卡與樣本池分配 |
| 正式標記池筆數 | 整數 | 是 | 總筆數扣掉已發布的試標之後的剩餘 | 概覽的第四張數字卡與樣本池分配 |
| 上線時長 | 時間 | 否 | 和工作時長是**兩個不同的數**；只採信可信的紀錄 | 工時明細表 |
| 工作時長 | 時間 | 否 | 速度的分母；不可信時相關的速度顯示 `—` | 工時明細表 |
| 標記筆數／審核筆數／仲裁筆數 | 整數 | 否 | 三欄分開；角色用不到的顯示 `—` | 工時明細表與匯總卡 |

- 這一頁**不顯示也不編輯**任何標記內容本身；標記結果的檢視在階段四
- 工時的原始紀錄怎麼產生（什麼時候開始、什麼時候算閒置）屬實作，規格只定使用者看到的數字與「不替任何人補時數」這條

## 卡控機制

階段一只列這幾個大項的卡控；其餘隨各分頁在後面的階段補上。

| 條件 | 結果 |
| :--- | :--- |

| 日期區間只點了起點 | 不套用，維持套用前的結果 |

## 邊界情況（Edge Case）

| 情況 | 使用者看到什麼 |
| :--- | :--- |
| 同一個人既是專案負責人又是審核員 | 看得到六個分頁而且能操作（取兩個角色的聯集） |
| 專案負責人被移出這個任務之後重新整理 | 依他當下的角色重新判定；沒有角色就被帶回任務列表 |
| 審核員把帶著成員管理與頁碼的網址貼給專案負責人 | 專案負責人看得到那一頁與那個頁碼 |
| 專案負責人把帶著成員管理的網址貼給審核員 | 審核員被導回概覽，而且他的網址不再含那一段 |
| 任務還是草稿、一個試標回合都還沒有 | 概覽的目前回合與最新 IAA 沒有值；樣本池分配整條都是可進正式 |
| 任務已完成 | 階段進度指示停在最後一個節點；「下一步」卡片顯示已完成該做什麼 |
| 試標做了很多回合 | 樣本池分配上每一個回合各有自己的顏色，不和正式標記池混淆 |
| 試標回合表的日期欄很窄 | 日期**保持一行**，不折成兩行 |
| 工時篩選之後一筆都沒有 | 顯示「尚無工時紀錄」與回到概覽的入口，不是一張空表 |
| 工時有紀錄但工作時長不可信 | 筆數照顯示，速度顯示 `—` |
| 某個成員只做審核沒有做標記 | 他的標記筆數顯示 `—`，不是 0 |
| 先點了較晚的日期再點較早的 | 系統正規化成有效的區間，不會變成無效的篩選 |
| 在手機上切換六個分頁 | 都切得到，資訊不重疊 |
| 整頁資料還沒回來 | 顯示骨架，不是空白也不是「尚無資料」 |

## 待釐清

### Q1. 審核員看不看得到「設定」分頁？

- [ ] 看得到，但整個分頁唯讀
- [ ] 看不到，比照成員管理
- [ ] 其他（請說明）

> 建議：第一個。來源的 `AC-2.1` 列出審核員看得到的分頁是「概覽、標記結果、標記進度、工時紀錄」——**四個，沒有設定**；而 `FR-003` 說六個分頁裡「成員管理的可見性依 `FR-006`」，**只點名成員管理一個**，沒有說設定也要隱藏。
> 兩條合起來讀不出設定分頁對審核員是「看不到」還是「看得到但唯讀」。
> 時間點是線索但不是答案：`AC-2.1` 寫在設定分頁還不存在的時候（設定是後來從概覽拆出來的），所以它沒有列到設定很可能只是還沒有那個分頁，不是刻意排除。
> 建議第一個的理由：審核員需要知道這個任務怎麼設定的（要標什麼、標記說明寫了什麼）才能審，而那些內容現在都在設定分頁；唯讀就足夠保護職責邊界。
> 需要決定的人：維護者

### Q2. 審核員看不看得到別人的標記進度？

- [ ] 看得到整個成員進度表
- [ ] 只看得到自己審核過的部分
- [ ] 其他（請說明）

> 建議：第一個。`AC-2.1` 明寫審核員看得到標記進度分頁，但來源對「審核員在那個分頁看得到什麼範圍」**只說唯讀，沒有說範圍**。
> 對比之下，工時紀錄那一邊**明確限制了範圍**（`AC-2.3`、`FR-007`：只看得到自己的），所以「標記進度沒有同樣的限制」有可能是刻意的，也有可能是漏寫。
> 建議第一個的理由：審核員要安排自己的審核順序，需要知道哪些標記員已經做完；而標記進度顯示的是**完成度**，不是標記的內容本身。
> 這一題的答案會影響階段三的範圍，請在那之前決定。
> 需要決定的人：維護者

### Q3. 麵包屑顯示任務的編號，而主標題就在它下面顯示任務名稱——要不要改成名稱？

- [ ] 維持編號（來源與畫面現況）
- [ ] 改成任務名稱
- [ ] 其他（請說明）

> 建議：第二個，但請確認。來源的 `FR-028` 明寫麵包屑顯示「任務管理 / `{task_id}`」，畫面也照做。
> 但那個編號對使用者沒有意義，而**它正下方的主標題就是任務名稱**——所以麵包屑那一節既不幫助辨識，也和主標題重複了位置。
> 選第二個的話，麵包屑會變成「任務管理 / 那個任務的名稱」，和側欄導覽的語意一致。
> 要改的是 `design/prototype/`（本 skill 不改）。
> 需要決定的人：維護者

- [x] 六個：概覽、設定、成員管理、標記進度、標記結果、工時紀錄；預設停在概覽
- [ ] 其他組合

> 理由：來源的 `FR-003` 明訂六個分頁與固定順序，並明寫「原分頁名稱『任務概覽』必須改為『概覽』」；規格常數 `TASK_TABS` 在 v12.2.0 一併補上設定分頁並對齊順序。
> 來源自己的 Clarifications（2026-05-22）當時定的是五個分頁的順序，設定分頁是 v12.0.0 從概覽拆出來的；依 D5 以現況為準，所以採六個（#76）。

### Q5. 標記員進得了這一頁嗎？（已定案，沿用舊來源）

- [x] 不行；直接開會被帶回任務列表並顯示無權限提示
- [ ] 可以，但唯讀

> 理由：來源的 `FR-002a` 明寫無權限角色（含標記員）造訪時要導回任務列表並顯示無權限提示，`AC-2.4` 驗收一次。
> 和 PRD §權限矩陣 的「03 任務詳情：標記員 —」一致。標記員的入口是標記清單（規格 04-01，未撰寫）（#76）。

### Q6. 審核員在這一頁能做什麼？（已定案，沿用舊來源）

- [x] 一律唯讀；看不到成員管理；工時只看得到自己的、也沒有成員篩選
- [ ] 其他組合

> 理由：來源的使用者故事 2 行為規則逐條定了這些，`FR-006` 定成員管理不可見、`FR-007` 定工時只能看自己，`AC-2.1`～`AC-2.5` 各驗收一次。
> 「按鈕保持在原位但不可用」也出自同一組行為規則，理由是避免版面跳動。
> 審核員看不看得到設定分頁與別人的標記進度，來源沒有交代，見 [§待釐清](#待釐清) Q1 與 Q2（#76）。

### Q7. 同一個人有多個任務角色時怎麼算？（已定案，沿用舊來源）

- [x] 取他所有角色的聯集
- [ ] 取最嚴格的那一個

> 理由：來源的 `FR-002` 明寫「同一人在同一任務有多個 active role 時，非工作區詳情頁可用允許權限聯集」，但仍要通過任務、狀態與各項資源的條件（#76）。

### Q8. 最新 IAA 在這一頁是唯讀的嗎？（已定案，沿用舊來源 2026-08-27）

- [x] 是；這一頁只顯示指標，不定義怎麼算、也不定義門檻
- [ ] 這一頁也定義算法

> 理由：來源的 Clarifications（2026-08-27）拍板「IAA 語意為顧問性警示，計算方式與門檻正典移至資料集分析那一份規格，本規格僅顯示唯讀指標與使用者可覆寫門檻，不得另行定義計算規則」。
> 所以這一頁的概覽只顯示數字；怎麼算由規格 05-02 資料集分析詳情（未撰寫）擁有。可覆寫的門檻在設定分頁（階段二）（#76）。

### Q9. 工時的速度算不出來時顯示什麼？（已定案，沿用舊來源）

- [x] 顯示 `—`，不用不可信的時長算出一個數字
- [ ] 顯示 0 或估算值

> 理由：來源的 `FR-007b` 明寫「無可信時長或分母為零時顯示 `—`」，並要求速度逐類計算、異常提醒按同類同單位比較。
> 這和 [規格 01-05 §登出紀錄只記真正的登出](../01-account/05-login-state.mdx#登出紀錄只記真正的登出) 是同一條原則：**不替任何人補時數**——那一頁明寫不能用登入狀態失效的時間回推在線多久（#76）。

## Q&A

### Q. 為什麼設定從概覽拆出去了？

因為概覽要回答的是「現在在哪、下一步做什麼」，而設定要回答的是「這個任務怎麼設的」。兩件事混在一個分頁時，專案負責人每次只是想看進度，都要滑過一大段設定；而他真的要改設定時，又得在同一片區域裡找。拆開之後，概覽短到一眼看完，設定則可以把五個區塊攤開。

### Q. 為什麼審核員看不到成員管理，但看得到概覽？

因為他需要知道這個任務進行到哪裡才能安排自己的審核，但「誰在這個任務裡、誰該被移除」是專案負責人的職責。概覽給他現況，成員管理給的是人事決定權——後者和他的工作無關。

### Q. 為什麼速度算不出來時寧可顯示破折號？

因為一個看起來精確的數字會被當真。工時的原始紀錄會有失聯、閒置、切換任務這些情況，時長不可信的時候用它去除，得到的速度可能差好幾倍；而專案負責人會拿這個數字判斷誰做得慢。顯示破折號至少誠實地說「這一格算不出來」。

### Q. 為什麼網址要帶著分頁與篩選？

因為這一頁最常見的用法是「我發現一個問題，想讓同事看同一個畫面」。如果網址只指到任務詳情，對方進來要自己切到那個分頁、重設那些篩選，而且很可能設不出一樣的。把座標寫進網址，貼過去就是同一個畫面。
