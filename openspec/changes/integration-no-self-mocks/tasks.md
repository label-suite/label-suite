# Tasks

本 change 沒有 schema 變更、沒有 API 變更、沒有畫面變更（`api-contract.md`、`ui-design.md`、system-design §資料模型異動），所以沒有 `[@dba]` task，也不重新產生 `openapi.json` 與前端型別；動到 `backend/` 的群組以後端契約漂移指令確認「沒有差異」收尾。JavaScript 指令在 repo 根目錄以 `pnpm` 執行，Python 在 `backend/` 以 `uv`；不得出現 npm install 或 pip install，本 change 不新增任何相依套件。

**Semgrep 的本機指令**：本機沒有 `semgrep` 執行檔（design D11），以下凡寫「以映像執行」都是在 repo 根目錄執行 `docker run --rm -v "$PWD:/src" -w /src semgrep/semgrep:1.186.0 <指令>`，`<指令>` 與 CI 逐字相同：

- 樣本驗證：`semgrep --test .semgrep/`
- 既有專案禁令掃描：`semgrep scan --error --config .semgrep/label-suite.yml backend/ frontend/ e2e/`
- 測試替身邊界檢查：`semgrep scan --error --x-ignore-semgrepignore-files --config .semgrep/test-boundaries.yml backend/`

**提交規則**：每個群組完成後提交一次，訊息依 AGENTS.md §Commits（`<type>: <subject> (#562)`、body 每點以粗體動詞開頭、動詞後不加冒號），結尾**恰好一個** `Co-Authored-By` trailer 標明模型。commit 被 hook 擋下時修正後重新 `git commit`，**不得** `--amend`；push 前以 `git log origin/main..HEAD` 確認只有本分支的 commit。各組的「故意弄壞再還原」以暫時修改做，還原後 `git diff` 只剩本 task 的改動，指令與失敗輸出摘要記在該組的提交訊息（issue #562 工作項 5，design D9）。

**不在 worktree 執行 NoteCraft build**（`pnpm exec notecraftapp build docs --rebuild`）：這是對 `openspec/config.yaml` operations.apply 的明示偏離，理由與替代檢查見 design D11。動到 `docs/` 的 task 以 `node scripts/check-specs.mjs docs`、`node scripts/check-citations.mjs --strict` 與 `pnpm format:check` 收尾，渲染驗證交給 CI 的 `docs-site` job。

新增的 Python 測試檔每個不超過 400 行（#561 的 B11，由既有 `backend/tests/unit/test_size_limits.py` 檢查），函式也受 B11 的 ruff 上限約束。

順序：第 1 組建立規則與接線；第 2 組的兩支 pytest 落在第 1 組的掃描範圍內，收尾時要以第 1 組的指令確認零違規，所以排在後面；第 3 組寫的是前兩組已成立的行為與指令，排在最後。
