# UI Design

本份是 change `denied-and-not-found`（Issue #721）的前端設計：規格 07-03 的兩種整頁畫面（找不到、無權限）的元件樹、資料來源、畫面狀態、design token、文案與無障礙。脈絡基準是同目錄的 `system-analysis.md`（以下稱 sa，待決題號寫成 sa-N）；後端側見 `system-design.md`（以下稱 sd）。本份自己的待決問題寫成 U-N，見 [§待決問題](#待決問題)。

上游 sa-1～sa-5、SD-1～SD-3 與本份的 U1～U5 已由 `clarification.md` 的 Q1～Q9 決議（2026-11-27，依維護者授權採用主 session 建議）。本份已依決議收斂成一條，不再分支：

- **只做共用骨架**（Q1）：本單不新增任何產品路由，也沒有通用找不到頁；兩種畫面在本單只畫在元件展示頁的一節（Q8）
- **未註冊的網址維持導回暫時落點**（Q2）
- **骨架不自帶字面與去處**，由呼叫端傳入；展示頁的範例用儀表板當去處、字面取 07-03 的示例句（Q3）
- **錯誤分類放 `api/api-error.ts`**，只分類、不決定畫成整頁與否（Q4）
- **容器以 Card 為準**、**到達時焦點移到標題、不用 `role="alert"`**（Q7）

## 頁面與路由

這兩種畫面**不是頁面**，是「某一頁在擋下使用者時取代內容區的狀態」（規格 07-03 頁首、§業務流程）。本單的核心交付是一個**共用畫面元件** `BlockedScreen`，由會定址到「那一筆」的頁面在自己的路由裡畫它。目前 `main` 上沒有任何一頁定址到「那一筆」（sa §跨模組依賴），所以本單**不新增、不改任何產品路由**，也**不做通用找不到頁**（Q1、Q2）；兩種畫面在本單唯一畫得出來的地方是元件展示頁的一節（Q8）。

| 路由                       | 頁面                                                                  | 對應的規格                                                                                                           | 需要的角色                                   |
| :------------------------- | :-------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------- | :------------------------------------------- |
| `/dev/gallery`（開發模式） | `DevGalleryPage`：新增一節「無權限與找不到」，畫 `BlockedScreen` 樣本 | 無 `docs/specs/` 規格（`component-gallery` 出 MODIFIED）；樣本照規格 07-03 §畫面的組成、§找不到的畫面、§無權限的畫面 | 不經守門，與既有展示頁相同；正式建置時不存在 |

之後由各頁畫它（本單不實作，只供接手單照做）：

| 誰會畫它     | 路由                                     | 種類與去處（由那一頁的規格定）     | 07-shared Logic Flow          | 接手 |
| :----------- | :--------------------------------------- | :--------------------------------- | :---------------------------- | :--- |
| 任務詳情     | `/task-management/task-detail?task_id=…` | 找不到、無權限；回任務列表         | 模組 03 分段四；07-shared X11 | #763 |
| 標記清單     | `/annotation/annotation-list?task_id=…`  | 找不到（帶與沒帶識別碼）；回儀表板 | 模組 04；07-shared X11        | #773 |
| 工作頁籤切回 | 頁籤裡的那一頁                           | 找不到、無權限；頁籤不自動關閉     | 07-shared 分段四 `D7 否 → P3` | #725 |
| 通知點進去   | 07-04 未指定（07-shared 缺口一）         | —                                  | —                             | #740 |

**角色**：三種登入後的系統角色（平台成員、系統管理員、Seeder 管理員）看到同一套結構，沒有任何角色多出或少了控制項（規格 07-03 §使用角色、Scenario「權限：每一種角色都看得到同一套結構」）。不需要任何任務成員身分；任務角色只影響那一頁決定顯示**哪一種**。未登入的訪客到不了這兩種畫面：守門先帶回登入頁（`auth-guard`「未登入的訪客被帶回登入頁」）。

**進入、離開與返回**（07-shared 分段五）：

- **進入**：由那一頁在判定「拒絕」或「找不到」後畫出來（P3）；本份不定何時（規格 07-03 §不在本頁範圍 第 4 條）
- **離開**：畫面上唯一的返回連結 → 那一頁指定的去處（`P3 → D9 → X11`）。它是連結，Ctrl／⌘ 或中鍵點擊交給瀏覽器開新分頁；側欄照常可用
- **返回之後**：去處那一頁自己再判一次（`D9 否 → P3`）。本單沒有產品頁面畫它，Scenario「邊界：返回之後仍被擋下」移交 #763、「邊界：被權限矩陣帶回的那一頁也擋下他」移交 #730（clarification §移出本次的驗收標準）
- **瀏覽器上一頁**：照路由歷史回上一頁，畫面不攔

**未註冊的網址**（Q2）：維持現狀，登入後開一個沒有註冊的網址，仍以取代歷史紀錄的方式導向 `/`、再回到暫時落點；不顯示找不到。規格 07-03 §兩種畫面的分工 只涵蓋「網址定址到的那一筆」查不到，不涵蓋「這個網址不是一個頁面」。側欄上還沒做的導覽項點下去照舊回到暫時落點。

## 元件樹

### 共用畫面 `BlockedScreen`

依 `docs/development/rules/frontend-agent-rules.mdx` F5：用到這個畫面的 prototype 產品畫面是 `task-management/task-detail` 與 `annotation/annotation-list`，分屬兩個 feature，所以是**共用元件，放 `frontend/src/components/`**。設計系統沒有它的元件規格（`state-panel.md` §用到它的畫面 已註明這兩個面板「是各自的實作」，不是 State Panel），所以下表寫「設計系統無」；缺規格已登記為 `design-gaps.md` G-68，元件規格等下次 `design-handoff` 補（Q8）。檔名最後一個字是 `screen`，`design/system/components/` 沒有同字尾的規格，`scripts/check-component-reuse.mjs` 不會把它認成重造；它也不在 `features/`、`pages/`，不在掃描範圍。

```text
BlockedScreen                 設計系統無（G-68）：新建，放 frontend/src/components/blocked-screen.tsx
├─ 容器（取代內容區的一塊）    card.md：沿用 frontend/src/components/ui/card.tsx（Q7）
│  ├─ 標題                    設計系統無：原生標題元素，層級由呼叫端指定（預設一級）
│  ├─ 說明                    設計系統無：原生段落；內含識別碼時插入下一列
│  │  └─ BlockedIdentifier    設計系統無：新建，同檔匯出（frontend/src/components/blocked-screen.tsx）
│  └─ 返回連結                button.md：沿用 frontend/src/components/ui/button.tsx（variant default、size sm，以 asChild 包 React Router 的 Link）
```

元件的輸入（語意描述，不是程式碼）：

| 輸入           | 必填             | 說明                                                                                                                                                                          |
| :------------- | :--------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 種類           | 必填             | 找不到或無權限二選一；畫在容器的 `data-kind` 上，讓測試分得出兩種畫面（Scenario「反向：兩種畫面不得互換」）。兩種**外觀相同**（prototype 兩個面板同一組 class），差別只在字面 |
| 標題           | 必填             | 一句話說出狀況，不帶識別碼（07-03 §畫面的組成 第 2 條）；字面由呼叫端給（Q3）                                                                                                 |
| 說明           | 必填             | 指出是哪一筆、給下一步；無權限時要提到可以找誰（第 3、4 條；§無權限的畫面 第 1 條）。帶識別碼的句子由呼叫端用 `BlockedIdentifier` 把識別碼插進去                              |
| 返回去處與標籤 | 必填，**恰一個** | 去處是站內路徑，標籤寫出去處（第 5 條）；兩者都由呼叫端給，元件不預設儀表板（Q3）。元件不提供第二個操作的位置，也不提供重試                                                   |
| 標題層級       | 選填，預設一級   | 那一頁保留自己的頁首一級標題時（例：任務詳情的頁首，03-03 §共用任務標頭 第 8 條）傳二級                                                                                       |
| 到達時移焦點   | 選填，預設是     | 元件展示頁的樣本關掉（一頁三個樣本，不能搶焦點）；工作頁籤切回時由 #725 依 07-02 的鍵盤規則決定要不要關掉                                                                     |

`BlockedIdentifier`：把識別碼當**純文字**放進一個雙向隔離的行內元素，允許在任意字元處換行。識別碼只經 React 的文字節點輸出，不經 HTML 插入（`lib/i18n` 的 `escapeValue: false` 是交給 React 跳脫，所以**不得**把它丟進任何以 HTML 解讀的位置）。不截斷、不改寫，畫面上就是原值（07-03 §資料欄位「原值」、§邊界情況「識別碼過長或含奇怪字元」）。識別碼的長度與格式檢查不在這裡，由擁有那一筆的模組在送請求前做（Q6）。

### 元件展示頁的一節「無權限與找不到」（Q8）

```text
DevGalleryPage                         沿用 frontend/src/pages/dev-gallery/（不是新頁面）
└─ 區塊「無權限與找不到」               沿用展示頁既有的區塊外框（gallery-section.tsx）；排在「Skeleton · Empty」之後、「Token 對照」之前
   ├─ 樣本：找不到（帶識別碼）          BlockedScreen：種類＝找不到、標題層級二級、不移焦點、返回＝儀表板
   ├─ 樣本：無權限（帶識別碼）          BlockedScreen：種類＝無權限，其餘同上
   └─ 樣本：識別碼很長                  BlockedScreen：種類＝找不到，說明帶一個很長、不含空白的示意識別碼
```

- 區塊是以區塊標題命名的 `section`，元件目錄多一個指向它的錨點（`component-gallery` 的區塊數十個變十一個，順序依上）
- 每個樣本帶 `data-gallery-item`（元件 `blocked-screen`、維度 `kind`、值 `notFound`／`denied`／`longIdentifier`），E2E 以它找到樣本（Q1）
- 區塊標頭的計數照既有寫法，由樣本清單算出
- 標題層級用二級：展示頁已有自己的一級標題「元件展示」
- 沒帶識別碼的變體不放展示頁（Q8 只列兩種畫面與長識別碼），由元件測試驗
- 返回連結是真的連結，點下去到 `/dashboard/dashboard`；展示頁不經守門，未登入時由守門帶回登入頁，這是既有行為

### 拒絕回應的分類（Q4）

在 `frontend/src/api/api-error.ts` 既有的 `isAuthError` 旁加一個分類函式，只讀 `ApiError`：

| 條件                                                                         | 分類   |
| :--------------------------------------------------------------------------- | :----- |
| `kind` 為 `http`、`status` 為 `403`、`code` 為 `PERMISSION_DENIED`           | 無權限 |
| `kind` 為 `http`、`status` 為 `404`、`code` 為 `NOT_FOUND`                   | 找不到 |
| 其他（含 `403 CSRF_FAILED`、`401`、`5xx`、連不上、逾時、回應不是外層、取消） | 其他   |

- 「其他」交給那個區塊自己的錯誤狀態（F8：`403` 不顯示重試只指無權限那一種）
- 分類**不決定**要不要畫成整頁、去處在哪：同一個 `403 PERMISSION_DENIED` 在規格 03-03 §誰進得來 第 1 條是「帶回任務列表並顯示提示」，所以由擁有那一頁的模組決定（SD-2 的 A）
- 放 `api/` 而不放 `lib/`，因為它只讀 `ApiError`，和 `isAuthError` 是同一類；不 import `pages/`、`features/`
- 「成員身分停用後顯示哪一種」不在本單：前端只照回應分，後端目前回 `404` 就畫找不到（Q5，交 #763）

## 資料來源

`BlockedScreen` 與展示頁的一節**不送任何請求**，沒有 operationId、沒有查詢鍵、沒有 mutation，也沒有要 invalidate 的查詢（07-03 §使用角色「不持有任何業務資料」）。唯一的「資料」是識別碼，由使用它的那一頁從自己的網址讀出來（例：`task_id`）再傳進來，不寫進任何儲存（07-03 §資料欄位「只在這次瀏覽存在，不寫入資料庫」）；展示頁的識別碼是固定的示意值。`api-contract.md` 確認本單無 API 變更。

| 區塊                                        | operationId                                                           | 快取鍵／失效時機                   |
| :------------------------------------------ | :-------------------------------------------------------------------- | :--------------------------------- |
| `BlockedScreen`                             | 無                                                                    | 無                                 |
| 展示頁「無權限與找不到」                    | 無                                                                    | 無                                 |
| 決定顯示哪一種的查詢（任務詳情、標記清單…） | 屬那一頁，例如任務詳情讀任務的 operationId 由 #763 的 api-contract 定 | 屬那一頁；見下方「給使用它的頁面」 |

**狀態的三個去處**（F4）：伺服器狀態無；網址狀態只有那一頁自己的識別碼參數；純 UI 狀態只有「到達時移焦點」用的元素參照。**不需要全域 store**。

**給使用它的頁面**（#763、#773、#725 照做，本單不實作）：

- 種類由那一頁的查詢錯誤經上面的分類函式決定，**不在前端依角色猜**（F8 禁止格）
- 進到這兩種畫面後，那個查詢不得因視窗取得焦點或重新連線就自動重查把畫面換回去：07-03 §無權限的畫面 第 3 條、07-02 §權限或資料失效 第 4 條要求等使用者下次切回才重新檢查。`createQueryClient()` 只關了 `retry`，`refetchOnWindowFocus` 仍是函式庫預設的開，所以**那一頁的查詢要自己關掉**；本單不改全域設定（Q9，`ops` 歸檔時寫進移交說明）
- 那一頁的頁首不得顯示那一筆的名稱或任何內容（03-03 §共用任務標頭 第 8 條；Hard Rule 6）

## 畫面狀態

`BlockedScreen` 本身就是那一頁的「無權限」或「找不到」狀態，不取資料，所以 F8 的四種狀態在它身上的意思如下。

| 狀態             | 呈現                                                                                                                                                                                                                                                                                    |
| :--------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| loading          | 不適用：元件不取資料。那一頁在判定完成前顯示**它自己的**骨架；骨架只畫形狀，不畫任何那一筆的內容或「測試集」之類的字樣，判定為拒絕或找不到後整塊換成 `BlockedScreen`。展示頁的樣本沒有載入期                                                                                            |
| error            | 不適用：元件沒有會失敗的請求。那一頁的**一般**載入失敗（`5xx`、連不上、逾時）分類為「其他」，不是這兩種畫面（07-03 §不在本頁範圍 第 3 條），照那一頁的錯誤狀態顯示訊息與重試                                                                                                            |
| empty            | 不適用。「有權限、那一筆也在、只是沒內容」是那一頁的空狀態，不得畫成找不到（07-03 §不在本頁範圍 第 3 條、Q&A「這兩種畫面和空狀態差在哪」）；反過來，找不到也不得畫成空白清單或空白詳情（Scenario「反向：不得用空白內容代替找不到」），所以 `BlockedScreen` 取代整個內容區，不疊在清單上 |
| 無權限（403）    | 就是 `BlockedScreen` 種類＝無權限：標題、說明（帶識別碼、提到可以找誰）、一個寫出去處的返回連結；**沒有重試**（F8；07-03 §畫面的組成 第 6 條）。`404` 與「本來就不該知道它存在」都畫成種類＝找不到，畫面上不出現任何暗示那一筆存在的字（07-03 §兩種畫面的分工 第 3 條、Q2）             |
| 欄位被遮蔽       | 不適用：畫面上沒有那一筆的任何欄位，所以沒有「已遮蔽」要呈現；唯一出現的是識別碼本身，而它是使用者自己帶進網址的值，不是後端回的資料                                                                                                                                                    |
| 沒帶識別碼       | 種類＝找不到，說明改用「未指定」那一種、不假造識別碼（07-03 §找不到的畫面 第 2 條）。標題用哪一句由那一頁定（標記清單用「尚未選擇任務」，G-48，#773）；本單以元件測試驗                                                                                                                 |
| 表單驗證、送出中 | 不適用：畫面沒有任何可以改的東西，沒有表單、送出或儲存（07-03 §畫面的組成 第 6 條）                                                                                                                                                                                                     |

### 唯讀角色與測試集答案

- 三種系統角色看到的結構完全相同，沒有唯讀變體；畫面本來就沒有可寫的東西
- **Hard Rule 6**：標記員到得了這兩種畫面，所以畫面、它的標題、說明、骨架與錯誤字都**只能**出現識別碼本身與固定字面，不得出現那一筆的名稱、狀態、資料筆數、是否為測試集或任何答案；後端讀標準答案的操作一律回找不到（sa §兩條硬規則的交界），前端照樣只畫找不到，不加「這裡有東西但你看不到」之類的暗示
- 展示頁的樣本只用固定的示意字面與示意識別碼，不取任何任務資料（`component-gallery`「展示樣本不含測試集答案」）

## 互動與無障礙

- **結構**：容器是一個以標題命名的區域（`section` ＋ `aria-labelledby` 指向標題），取代內容區；外殼的 `<main>` 不變
- **到達時焦點**（Q7）：畫面掛上時把焦點移到標題（標題可被程式聚焦、不進 Tab 順序），螢幕閱讀器會讀出「是哪一種狀況」；標題被程式聚焦時不畫焦點框，因為它不是可操作元素。下一個 Tab 停在返回連結。**不用** prototype 的 `role="alert"`：焦點移過去已經會朗讀，兩者並用會讀兩次。展示頁的樣本關掉移焦點
- **返回連結**：原生連結，Enter 觸發；可存取名稱就是寫出去處的標籤（「回儀表板」），不加只有圖示的按鈕；焦點環沿用 Button 的 `focus-visible`
- **語言**：切換語言時標題、說明、連結跟著換（字面來自翻譯）
- **不只靠顏色**：兩種畫面靠標題文字分辨，不靠顏色
- **對比**：`--color-ink`、`--color-ink-muted` 在 `--color-white` 上都過 WCAG AA（`tokens.css` 註解：`--color-ink-muted` 在白底 5.40:1）；返回連結用 Button `default` 的既有配對
- **減少動態效果**：沒有任何過場，不受影響
- **識別碼**：雙向隔離，含右至左控制字元的識別碼不會把整句翻轉；過長時在任意字元換行，不撐破容器、不出現水平捲軸（展示頁的長識別碼樣本就是用來看這一條）
