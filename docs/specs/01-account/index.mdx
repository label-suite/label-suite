# 01 帳號

所有使用者的帳號入口：登入、註冊、用一次性連結設定密碼、個人設定，以及登入狀態的維持與失效。
帳號本身的管理（新增、停用、指派系統角色）屬系統管理，見 [規格 06-01 使用者管理](../06-admin/01-user-management.mdx)。

| 01-02 | [註冊](./02-register.mdx) | :badge[已定案]{variant="success" size="sm"} | 自行填寫姓名、Email 與密碼建立帳號，成為平台成員 |

## Logic Flow

帳號模組的頁面只有一個出口通往平台：不論從登入、註冊驗證還是 Google 驗證進來，成功的人都落在儀表板；而任何讓登入狀態結束的事（登出、時間到、換 Email、連結 Google、被停用），都把人送回登入頁。

這一節只畫頁面之間怎麼走，以及決定往哪一頁走的判斷；同一頁裡的操作細節看各規格的業務流程。連線依方向分三類判：離開本模組一律畫，進入與返回只在本模組自己的規格定了那個入口、或定了「回來之後這一頁顯示什麼」時才畫，模組內兩頁之間的移動本來就要畫。每一條連線都對回規格的條文，規格裡找不到出處的連線不畫（這個模組目前每條連線都找得到出處，所以沒有缺口摺疊區塊）；三類判準逐條盤點的結果，列在本節最後那個摺疊區塊。唯一沒有規格出處的是起訖連線（S 與 E 接上的線），它們只標出流程從哪裡開始、到哪裡結束。

### 節點

同一個節點出現在不同分段時用同一個編號。

- 起訖
  - S 開始：使用者打開平台
  - E 結束：進入平台
- 頁面（矩形）
  - P1 [01-01 登入頁](./01-login.mdx#業務流程)
  - P2 [01-02 註冊頁](./02-register.mdx#業務流程)
  - P3 [01-02 驗證連結的落地頁](./02-register.mdx#業務流程)（帳號已建立，或連結無法使用）
  - P4 [01-03 申請頁](./03-reset-password.mdx#業務流程)（忘記密碼）
  - P5 [01-03 重設頁](./03-reset-password.mdx#業務流程)（設定新密碼；受邀者設定密碼也是這一頁）
  - P6 [01-04 個人設定頁](./04-profile.mdx#業務流程)
- 判斷（菱形）
  - D1 已經登入？
  - D2 兩欄都有填、帳號密碼也對得上？
  - D3 Google 驗證通過？
  - D4 四欄都通過檢查？
  - D5 註冊驗證連結可用？
  - D6 有填 Email？
  - D7 重設連結還能用？
  - D8 新密碼兩欄都有填且一致？
  - D9 換 Email 的驗證連結還有效？
- 其他流程或外部系統（雙邊框）
  - X1 Google 驗證（外部）
  - X2 收信：註冊驗證信
  - X3 收信：重設密碼信
  - X4 [06-01 系統管理員邀請新帳號](../06-admin/01-user-management.mdx#業務流程)，寄出設定密碼信
  - X5 [02-01 儀表板](../02-dashboard/01-dashboard.mdx#業務流程)
  - X6 收信：換 Email 的驗證信
  - X7 [01-05 登入狀態結束](./05-login-state.mdx#業務流程)
  - X8 [06-01 系統管理員停用帳號](../06-admin/01-user-management.mdx#業務流程)

### 分段一：進入與登入

1. S → D1（起訖連線，無規格條文）
2. D1 是 → X5 儀表板（01-01 §導向其他頁面 4、Q3；01-02 §使用角色；01-03 §使用角色）
3. D1 否 → P1 登入頁（01-01 業務流程「用 Email 與密碼登入」觸發：未登入的訪客要進入平台；§登入頁的內容）
4. P1 點「登入」→ D2（01-01 業務流程「用 Email 與密碼登入」主流程）
5. D2 是 → X5 儀表板（01-01 主流程、§導向其他頁面 3）
6. D2 否 → 停在 P1（01-01 E1、E2；§登入失敗）
7. P1 點「使用 Google 帳號繼續」→ X1 Google 驗證 → D3（01-01 業務流程「用 Google 帳號登入」主流程）
8. D3 是 → X5 儀表板（01-01「用 Google 帳號登入」主流程）
9. D3 否 → P1 登入頁（01-01「用 Google 帳號登入」E1；被停用的帳號也登不進來，01-05 §帳號被停用或重新啟用 3）
10. P1 點「前往註冊」→ P2 註冊頁（01-01 §導向其他頁面 2）
11. P1 點「忘記密碼？」→ P4 申請頁（01-01 §導向其他頁面 1）
12. X5 儀表板 → E（起訖連線，無規格條文）

### 分段二：註冊

1. P2 點「建立帳號」→ D4（01-02 業務流程「送出註冊表單」主流程）
2. D4 否 → 停在 P2（01-02「送出註冊表單」E1、E2）
3. D4 是 → 顯示「驗證信已寄出」→ X2 收信（01-02「送出註冊表單」主流程；帳號此時還沒建立）
4. X2 點信裡的連結 → P3 → D5（01-02 業務流程「用驗證連結完成註冊」觸發與主流程）
5. D5 是 → 帳號建立 → X5 儀表板（01-02「用驗證連結完成註冊」主流程、§註冊成功 1～2、§導向其他頁面 2）
6. D5 否 → 「連結無法使用，請重新申請」→ P2 註冊頁（01-02「用驗證連結完成註冊」E1、§註冊成功 3 與該節的文案裁定）
7. P2 點「返回登入」→ P1 登入頁（01-02 §導向其他頁面 1）

### 分段三：重設與設定密碼

1. P4 點送出 → D6（01-03 業務流程「申請重設」主流程）
2. D6 否 → 停在 P4（01-03「申請重設」E1）
3. D6 是 → 「若此 Email 已註冊，重設連結已寄出」→ X3 收信（01-03「申請重設」主流程）
4. X3 點信裡的連結 → P5 重設頁（01-03 業務流程「用連結設定新密碼」觸發）
5. X4 受邀者點設定密碼信裡的連結 → P5 重設頁（01-03 §使用角色、Q6；06-01「邀請新帳號」主流程）
6. P5 → D7（01-03「用連結設定新密碼」主流程第 1 步）
7. D7 否 → 連結無法使用的面板，點「重新申請」→ P4 申請頁（01-03「用連結設定新密碼」E2、「從失效的連結重新申請」、§導向其他頁面 2）
8. D7 是 → 填新密碼並送出 → D8（01-03「用連結設定新密碼」主流程）
9. D8 否 → 停在 P5（01-03「用連結設定新密碼」E1）
10. D8 是 → 重設成功面板，點「前往登入」→ P1 登入頁（01-03「用連結設定新密碼」主流程、§導向其他頁面 3）
11. P4 或 P5 點「返回登入」→ P1 登入頁（01-03 §導向其他頁面 1）

### 分段四：登入之後

1. 未登入的人直接打開 P6 → P1 登入頁（01-04 §頁面的內容 4）
2. P6 送出新 Email → X6 收信 → 點信裡的連結 → D9（01-04 業務流程「送出新的 Email」「用驗證連結換掉 Email」）
3. D9 是 → Email 換成新的 → X7 登入狀態結束（01-04「用驗證連結換掉 Email」主流程、§換 Email 8；01-05「安全事件撤銷」A1）
4. D9 否 →「連結無法使用，請重新申請」面板；已登入點「回個人設定」→ P6 個人設定頁，未登入點「前往登入」→ P1 登入頁（01-04 §換 Email 9、Q19；01-04「用驗證連結換掉 Email」E1）
5. P6 連結 Google 帳號 → X1 Google 驗證 → 連結成功 → X7 登入狀態結束（01-04 §連結 Google 帳號 2～3；01-05「安全事件撤銷」A1）
6. X1 在 Google 那一側取消或驗證不通過 → 回到 P6 個人設定頁，Google 區塊維持未連結並顯示說明，登入狀態不變（01-04 §連結 Google 帳號 7、Q20）
7. 登入後任何一頁點登出，或時間到了 → X7 登入狀態結束（07-01 §登出 1；01-05 業務流程「自己登出這一台」「時間到了自然結束」）
8. X8 系統管理員停用帳號 → X7 登入狀態結束（01-05 §帳號被停用或重新啟用 1～2；01-05「時間到了自然結束」A2）
9. X7 → P1 登入頁（01-05「自己登出這一台」主流程與 A1、「安全事件撤銷」A1、「時間到了自然結束」主流程）

<summary>三類判準逐條盤點：哪些畫了、哪些沒畫</summary>

- **頁內操作**：各頁的語言切換、密碼的顯示與隱藏與送出中的狀態，註冊頁的「改正後重送」，個人設定頁的「改個人資料」「改密碼」與換 Email 時的「重新寄送」——都不跨頁，規則在各規格自己的節裡（[規格 01-02](./02-register.mdx#業務流程) §業務流程 的「改正後重送」；[規格 01-04](./04-profile.mdx#業務流程) §業務流程 的「改個人資料」「改密碼」與「用驗證連結換掉 Email」A1）。改密碼成功時「目前這一台維持登入」（同一段主流程第 4 步），所以也不畫成一條到 X7 的連線。
- **模組內兩頁之間的移動**：分段一的 `P1 → P2`（前往註冊）與 `P1 → P4`（忘記密碼？），分段二的 `D5 否 → P2` 與 `P2 → P1`，分段三的 `D7 否 → P4`、`D8 是 → P1` 與兩條「返回登入」，分段四的 `D9 否 → P1`（未登入時）、`D9 是 → X7` 與 `X7 → P1`（X7 是規格 01-05，仍在本模組裡）——使用者從頭到尾沒有離開帳號模組，所以照樣畫。
- **離開**：成功進入平台的四條都落在 X5 儀表板：分段一的 `D1 是`、`D2 是`、`D3 是` 與分段二的 `D5 是`（[規格 01-01](./01-login.mdx#導向其他頁面) §導向其他頁面 第 3、4 條；[規格 01-02](./02-register.mdx#導向其他頁面) §導向其他頁面 第 2 條）。交給外部系統或寄信的五條也畫：`P1 → X1`、`D4 是 → X2`、`D6 是 → X3`、`P6 → X6`、`P6 → X1`。
- **算得上入口、所以畫了的進入**：
  - 未登入的訪客打開平台（分段一的 `S → D1`、`D1 否 → P1`）：[規格 01-01](./01-login.mdx#業務流程) §業務流程 的「用 Email 與密碼登入」觸發「未登入的訪客要進入平台」
  - 點信裡的連結進來的三條：`X2 → P3`（[規格 01-02](./02-register.mdx#業務流程) §業務流程 的「用驗證連結完成註冊」觸發「使用者收到驗證信」）、`X3 → P5`（[規格 01-03](./03-reset-password.mdx#業務流程) §業務流程 的「用連結設定新密碼」觸發「使用者收到信並點開裡面的連結」）、`X6 → D9`（[規格 01-04](./04-profile.mdx#業務流程) §業務流程 的「用驗證連結換掉 Email」觸發「使用者到新信箱收到驗證信」）
  - 受邀者點 06-01 寄出的設定密碼信進來（分段三的 `X4 → P5`）：[規格 01-03](./03-reset-password.mdx#使用角色) §使用角色 的「受邀的使用者「設定密碼」那個畫面由這一頁擁有」（同頁 §已確認決議 Q6）
  - 未登入的人直接用網址打開個人設定頁（分段四的 `P6 → P1`）：[規格 01-04](./04-profile.mdx#頁面的內容) §頁面的內容 第 4 條「未登入的人直接開這一頁 → 被帶到登入頁」
  - 在登入後的任何一頁登出或時間到了（分段四的 `X5 → X7`）：[規格 01-05](./05-login-state.mdx#業務流程) §業務流程 的「自己登出這一台」觸發「使用者點「登出」」，與「時間到了自然結束」觸發「使用者做任何一次操作」
  - 系統管理員停用帳號（分段四的 `X8 → X7`）：同一節「安全事件撤銷」的觸發列了「系統管理員停用帳號」
- **沒畫的進入**：從儀表板點側欄的「個人設定」進到個人設定頁（`X5 → P6`）。這個入口只寫在[規格 07-01](../07-shared/01-sidebar.mdx#導覽項目與可見性) §導覽項目與可見性（第 1 條的側欄項目「個人設定」，與該節「個人設定對 01-04」的註），而[規格 01-04](./04-profile.mdx#業務流程) §業務流程 的四個觸發（「改個人資料」「送出新的 Email」「用驗證連結換掉 Email」「改密碼」）沒有一個是從側欄進入，其中三段的前置條件只寫「使用者已登入並在個人設定頁」。
- **返回**：本模組自己定了「回來之後顯示什麼」的五條都畫了——從 Google 回來的 `X1 → D3` 與 `D3 否 → P1`（[規格 01-01](./01-login.mdx#業務流程) §業務流程 的「用 Google 帳號登入」主流程第 2 步「回到平台並進入儀表板」與 E1「回到登入頁，可以改用 Email 與密碼登入」）、`X1 → X7` 與 `X1 → P6`（[規格 01-04](./04-profile.mdx#連結-google-帳號) §連結 Google 帳號 第 3 條與第 7 條的「回到這一頁」），以及換 Email 連結失效時已登入的 `D9 否 → P6`（[規格 01-04](./04-profile.mdx#換-email) §換 Email 第 9 條的「回個人設定」）。登入、註冊、重設三頁 §語言切換 的「回到登入頁」只定回來之後維持同一種語言，回來走的路就是已經畫的「返回登入」與 `X7 → P1`，不另畫連線。

</details>
